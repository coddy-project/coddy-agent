The keystone (path-based mount, no id-mangling) is the right protocol bet, but the draft overclaims "existing clients unchanged" and the federation cursor/loop story is not implementable as written.

## Verdict: APPROVE_WITH_CHANGES

## Findings

1. **[blocker]** (§3.3, §3.6, §3.7) - "Existing console/ACP/SPA can point at `https://relay/swarm/nodes/{node}` unchanged" is true only for a **single-node** mount. Aggregation does not work that way. `internal/remote.Handler` has one `BaseURL` for every session (`handler.go:24`, `handler.go:41-50`; `newRequest` concatenates `BaseURL+path` in `rest.go:43-46`). `HandleSessionList` always hits `/coddy/sessions` (`rest.go:215-224`), never `/swarm/sessions`. ACP `SessionListInfo` has no node field (`internal/acp/types.go:220-225`). The SPA shim rewrites only `/v1/*`, `/coddy/*`, `/openapi*` (`remoteEnv.ts:158-192`); `/swarm/*` is never rewritten, and `connectRemote` reloads the whole app (`remoteEnv.ts:145-155`). `loadSessionsList` always calls `/coddy/sessions` and dedupes by `s.id` (`App.tsx:1848`, `App.tsx:1861-1866`). **Recommendation:** rewrite §3.3/§3.6/§3.7. Mount = `--remote https://relay/swarm/nodes/{node}` only. Aggregation is a **new client mode**: Handler must carry a per-session mount prefix (or one Handler per node); SPA must keep env at the **relay origin** and route by `(node, sessionId)`, not flip `env.baseUrl` per session. Parallel turns on two nodes (`postAbortBySidRef` in `App.tsx:752`) cannot share one global base.

2. **[blocker]** (§3.4, §3.3 cursor) - Federation cursor is specified as `{node_id: node_offset}` over **integer** offsets. Leaf `GET /coddy/sessions` cursors are decimal strings of the offset (`coddy_coddy.go:679-693`, `coddy_coddy.go:766-768`). A child **relay** returns an opaque cursor. A parent cannot treat that as `node_offset`. Diamond topology (`A→B, A→C, B→D, C→D`) is not a cycle, so the UUID loop header will not stop **double-counting** D's sessions. Loop guard is defined only for fan-out `/swarm/sessions`, not for transparent path chaining (`/swarm/nodes/B/swarm/nodes/A/...`). **Recommendation:** store per-child **opaque cursor strings**; k-way merge must record how many rows were **consumed** from each child, not that child's `nextCursor` after a full `limit` fetch. Dedup federation rows by visited swarm UUID (and by `(node_path, sessionId)`). Attach `X-Coddy-Swarm-Path` (or a hop count) on **proxied** requests too, with a depth cap; reject cyclic mounts at register time.

3. **[blocker]** (§3.2, §3.5, §6) - A new fleet proxy that defaults **client** auth off, copies `httpserver.auth_token` posture, and injects each node's bearer is a superuser front door. Pairing protects **registration**, not readers. `GET /swarm/nodes` omitting tokens does not help if `/swarm/nodes/{id}/...` proxies the whole `/coddy/*` surface, including `PUT /coddy/config`, MCP trust, and workspace. `advertise_url` is caller-controlled SSRF unless pinned. `node_id` is unspecified; a random id dies on relay restart (stateless registry). Session ids collide across hosts (`ValidateFolderSessionID` is `[A-Za-z0-9_-]{1,256}`, `validate.go:10-21`; operators use `--session-id`). Hash route is `#/s/<sessionId>` (`hashRoute.ts:2-3`). **Recommendation:** require `swarm.auth_token` (or refuse non-loopback bind without it). Treat the client token as fleet-admin; document that, or deny-list mutating global routes on the mount. Pin `advertise_url` (https only, no userinfo, block link-local/metadata unless allowlisted). Make `node_id` deterministic (operator `name` / join `id`, folder-safe). Swarm UI identity = `(nodeId, sessionId)` in list keys, hash, and activity maps. Hijack of `name`+URL needs generation + proof (pairing is not enough to replace an existing lease).

4. **[major]** (§3.1, stage 3) - Join client in `coddy http` cannot import `external/swarm` if that package is `//go:build swarm` (architecture rule: default/`http` must not import a tagged optional module). `pairing_tokens` is **not** in `configSecretPath` (`path.go:518` matches `auth_token`/`token`/`secret`, not `pairing_token(s)`). Plan claims "httpserver listener hardening"; `ListenAndServe` is still bare `http.ListenAndServe` (`listen.go:8-9`). CORS `Allow-Headers` is `Authorization, Content-Type, X-Coddy-Session-ID` (`cors.go:20`) - fine for browser-to-relay, irrelevant to federation. **Recommendation:** put register DTOs in a tag-free shallow package (or in `internal/config`). Add `pairing_token`, `pairing_tokens`, and join `token` to redaction. Stop citing hardening that does not exist, or land `http.Server{ReadHeaderTimeout,...}` first. Proxy **replaces** `Authorization` with the node bearer (do not forward the client token); ignore leftover `?access_token=` on SSE routes (`auth.go:57-61`, `auth.go:94-97`) or rewrite it. Forward `Last-Event-ID` / `?last_event_id=` (`composer_stream_http.go:61-93`).

5. **[major]** (§3.3 activity, §3.7 Q4, §4) - Cutting aggregated `/swarm/events` without specifying the poll fallback will freeze activity badges. `subscribeServerEvents` uses `fetch("/coddy/events")` (`serverEvents.ts:50`); `App.tsx:1946` polls only when `hasBackgroundTurn && !serverEventsConnected`. A relay origin has no `/coddy/events`. Health probes `baseUrl+"/v1/models"` (`activeHealth.ts:31`, `EnvironmentChip.tsx:84`). `<img src="/coddy/.../thumbnail">` bypasses the fetch shim. Serving SPA via `swarm,ui` duplicates `spa_embed_ui.go` (`http && ui`) and still needs `/coddy/config` for the remotes list (`EnvironmentChip.tsx:55` uses `localFetch`). **Recommendation:** in swarm mode, never mark events "connected"; keep `include_activity` polling. Probe `/swarm/info`. Rewrite thumbnail URLs to the node mount (or fetch-as-blob). Decide Q4 in the doc: either relay serves SPA **and** grows swarm-native config/health routes, or SPA stays on `coddy http` and the shim learns `/swarm/*`.

6. **[major]** (§4, §5 stage 4) - Test plan never requires a **permission/question** round-trip through the proxy, though that is the HTTP contract the tunnel design was trying to reinvent (`prompt.go:273-313`; already specified in `features/remote_client.feature:23-28`). Stage 10 e2e is too late for SSE flush bugs. Makefile matrix (`Makefile:88-105`) does not include `gateway`; adding only `swarm` / `http,swarm` / `swarm,ui` misses `cli` and the full `http,scheduler,ui,memory` intersections. **Recommendation:** stage 4 BDD must include permission + question + composer-stream reattach + cancel while SSE is open. Put a thin live python mount+stream test with stage 4. List exact `make test` / `check-windows` tag tuples (include `cli` if `features/cli_swarm.feature` exists). Add vitest for `isApiPath` + base URL **with a path**.

7. **[minor]** (§1 facts) - Environment chip **is** in the composer bar (`EnvironmentChip.tsx:28-33`); `docs/remote-control.md:20-21` still says Settings. Session search **is** title OR first user message (`filesystem.go:365-387`); plan's line `:365` is close enough. `Resolve` **does** keep a path (`resolve.go:49-56`). `include_scheduler` exists on the list endpoint and is omitted. **Recommendation:** cite the shipped chip location; pass `include_scheduler` through aggregation or say it is out of v1.

8. **[minor]** (§3.1 Q3 naming) - Draft mixes `relay` / `swarm` / deferred `coddy rc` hub (`docs/remote-control.md:298-304` forbids `coddy hub`). **Recommendation:** lock user-facing `swarm` (`external/swarm`, tag `swarm`, `coddy swarm`, `swarm:`). Use "relay" only as the role (stateless proxy). Keep `transport` on the lease for a later tunnel so you do not mint a second command family.

## Answers to the 6 judgment questions

1. The per-node mount is the right keystone for **protocol reuse** (no new wire, no `node:sess` ids). SSE pass-through plus HTTP POST permission/question already works on one hop (`prompt.go:107-111`, `prompt.go:273-313`; SPA uses `fetch`, not `EventSource`, `serverEvents.ts:34-36`). The hidden flaw is **client routing**, not SSE: auth header replacement, `Last-Event-ID`, `?access_token=` leftover, `<img>` thumbnails, a fetch shim that does not know `/swarm/*` or per-session bases, and integer cursors at the leaves. Do not flip to a WebSocket tunnel for v1; fix the client/proxy contract.

2. Recursive `/swarm/sessions` plus path chaining is sound **one level down** if each hop talks only to direct children. As specified it is not: integer cursor maps break on child relays, the UUID header does not cover proxy loops or diamonds, and `node_path` must be the only way to open a row. Fix those three before coding stage 6.

3. In-memory leases rebuilt by heartbeats are acceptable for v1 **if** `node_id` is stable, TTL/grace are documented, and operators accept an empty window after relay restart. Do not persist `Online`. Optional `agents.json` can wait; unstable ids cannot. In-flight proxied SSE dies with the process; clients already reconnect.

4. Unit + godog + cli feature + vitest + live python + screenshots match repo practice (`features/remote_*.feature`, `cli_remote.feature`, `examples/httpserver/http_e2e_remote.py`). Missing: permission/question through the mount, composer-stream resume, two-node parallel UI turns, session-id collision, opaque federation cursors, SSRF/advertise_url, redaction of `pairing_tokens`, shim+path baseUrl, thumbnail `<img>`, and swarm-mode events/poll. Playwright UI e2e is not in the pyramid; workflow still wants screenshots of the running SPA (`ui-verification.mdc`).

5. Stages 2-5 order is right (registry → join → mount → aggregate). De-risk SSE/permission in stage 4 with a live python, not only httptest. Move client-routing design (Handler + fetch shim) into stage 4/5 so stage 8 is not a rewrite. Federation (6) after a working one-level aggregate. Console (7) can follow 5 without waiting for 6. Do not duplicate SPA embed until Q4 is closed. Stage 1 docs + schema/skill sync in stage 2 match `workflow.mdc`.

6. Three credentials match `docs/remote-control.md` §4.5. Pairing required by default is correct. Copying "client auth defaults off" from `coddy http` is wrong on a proxy that injects node bearers. Redaction must cover join tokens and `pairing_tokens` (`path.go:518` will miss them). Never echo dial-back tokens on `/swarm/nodes`. Log the same cleartext-token warning `Resolve` already sets (`resolve.go:60`, `handler.go:32-34`).
