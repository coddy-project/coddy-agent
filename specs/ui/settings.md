# UI design: settings

[Design index](../../DESIGN.md)

### Statistics

The page has Overview and Limits tabs. Limits lists every configured provider and every reported window, including a zero-use day, plus rate, cooldown, wallet and model restrictions. Unsupported, disabled, unavailable and stale states remain visible. The current limits ignore historical filters; swarm quotas stay separate per dataset and provider. Reads run only while the tab is open, every 30 seconds while the page is visible, with four concurrent node reads and cancellation on exit. The server limits provider reads to four at once under a 15-second request budget and retains the manager's cache and refresh floor.

The Coddy brand opens an anchored menu with Statistics; the plus keeps new-chat navigation. `#/statistics` opens the lazy StatisticsView over the previous screen, and the rail's shared Escape table closes it. The page reuses the docs dock for desktop and phone placement. It shows the token calendar, daily and weekly activity, cumulative usage, retained totals, period filters and breakdowns. The calendar scrolls inside its own box on a phone. The heading follows the shared panel head height, typography and framed close control; its actions button opens CSV, JSON and statistics settings. The period stays visible; Filters opens project, provider, model and source filters, plus node scope in swarm. Selected filters remain visible as chips after closing. A native Currency select in the sheet chooses USD or RUB for display; USD is the default. The select is absent for aggregate swarm reports because the relay response carries no shared display-currency or exchange-rate settings. Four leading counters show period tokens, active time, estimated cost in the selected currency and the current streak (two columns on phones). The cost card shows the current USD/RUB rate below the amount. Statistics settings keep a manual exchange rate, default 90. Each custom model tariff selects USD or RUB and defaults to USD; RUB tariffs convert to canonical USD for accounting. Stored costs and exports remain in USD. Tokens, activity and skills use label/value lists below the calendar. Days, Weeks and Total share a segmented control. Filters and the first-import prompt use a centered panel on desktop and a bottom sheet on phones; statistics settings opened from the page use a bottom sheet on phones too. Sheets trap focus, return it to their opener and consume Escape before the underlying page. Cleanup confirmation opens above the settings sheet.

The first visit offers a background historical import. CoddyWorkIndicator, a native progress element and processed/total chat counts remain visible while it runs. The same page reads the persistent import status on return. A swarm summary starts imports through authenticated leaf mounts and combines their progress. Unavailable nodes appear beside the partial summary.

Settings has a Statistics tab, with indexed blocks for time zone, USD/RUB exchange rate, model prices, historical import and cleanup. Each custom model price selects its own currency, USD by default. On phones, the three rates share one row and the currency selector gets a row of its own. The page-level display currency lives in the Statistics Filters sheet. It uses shared settings buttons, inputs and comboboxes. Cost uses the embedded models.dev prices automatically; custom tariffs fold under Custom prices, with the model above input, output, cached and currency fields plus a separate remove control. Statistics sheets keep the shared head and close button; import actions use the shared confirmation buttons. This tab edits the independent statistics store through its own Save button. Cleanup uses the shared destructive confirmation dialog. Every string is localized; every colour uses existing theme tokens. The store, nullable historical readings, export and swarm identities are described in `docs/features/statistics.md`.

### Settings drawer (tabbed master–detail)

**ReAct loop → Prompt suggestions** is an enabled-by-default switch in **Model and turns**,
backed by `agent.prompt_suggestions`. Saving it off stops the extra model calls in the web UI
and local console. A suggestion appears only in the idle, empty composer; Tab or Right copies
it into the draft. A new turn, session change or config reload retires pending and visible hints.

The **Settings** drawer (**`#/settings`**, **`Settings.tsx`**) is **tabbed**, not one long sheet. Tabs are derived from the live config JSON Schema (**`deriveSettingsSections`** over **`/coddy/config/schema`**): each top-level property is a tab (label from its **`title`**, or from **`settings.section.<id>.label`**) in the schema's own order (**`rootOrder`** in **`internal/config/ui_schema.go`**, pinned by **`TestUISchemaRootPropertyOrder`**), which reads in groups of meaning: where the models come from (**LLM providers**, **Logical models**), the loop that runs them (**ReAct loop**, **Context compaction**, **Memory**), what the agent can do (**Tools and permissions**, **MCP servers**, **Skills**, **Subagents**, **Hooks**), what runs it without a person at the composer (**Scheduler**, **Gateways**), and the operation of the process (**Logger**, **Metrics**, **Prompts**). A section the binary cannot run is left out of the schema (**`config.UISchemaJSONHiding`**, fed by **`httpserver.Options.UnbuiltSections`**: the **Metrics** tab in a build without the **`metrics`** tag), while it still travels in the settings document, so a save writes it back to the file untouched. The rarely edited tail (**`prompts`**, **`instructions`**; **`SYSTEM_KEYS`** in **`settingsSections.ts`**) folds into a single **Prompts** tab (id **`system`**, **`#/settings/system`**: the address and the id kept their old name), which always closes the list wherever its keys stand; the scheduler, the logger and the gateways are features with tabs of their own, and the **`sessions`** section (where the bundles are stored) is edited on the **Sessions** tab (**`SESSIONS_CONFIG_KEY`**). Three client-side tabs are placed **first**, the head group - **Appearance** (the default tab), **Sessions** (**`sessions_manager`**, the session management table below) and **System** (**`status`**, *System tab* below, after Sessions). All render before the schema has loaded; the Sessions tab adds its **Storage** fieldset once it has. **System** sits in the head group and **Metrics** in the operation group, after **Logger**. There is no separate Appearance/Skills flyout or **`settings-dock-cluster`** side panel — both are tabs now.

- **Saving**: there is **no per-section save button**. The drawer footer keeps only **Reload** (**`data-testid="settings-reload"`**) and **Save all** (**`data-testid="settings-save"`**, PUTs the whole config after `/coddy/config/validate`). **Appearance** is client-side only and never touches the config PUT. **A save that went through says so on the Save button alone**: it turns green (**`.is-saved`**: green border, wash and a 2px halo, a short scale pop) for **`SAVE_SUCCESS_MS`** (2 s, **`Settings.tsx`**) and eases back to its own colour, with no line of text on screen (a screen reader hears **Saved** from an **`.sr-only`** status). The green is a state rather than a frame of the pop, so it holds under **`prefers-reduced-motion`**, where only the pop goes. **A failed save says why in words** in the lead pane (**`.settings-lead-pane`**, **`.settings-error`**), which stands between the head and the tabs only while a failed read or a failed save needs saying; the Save button stays as it was. The success line that used to sit in that pane (**All sections saved**) stayed on screen for as long as the drawer did, and it is gone. **Unsaved edits** (issue #485): a change applies only after Save, so while the form differs from the config it was read from or last saved (**`settingsFormDirty`** in **`settings/settingsDirty.ts`**: values compared as the form means them - empty values, a switch at its default and key order are no edit, the revision is left out) the Save button stands out (**`.settings-btn-primary.is-dirty`**: a solid accent fill, a white glyph and a 3px accent ring that breathes; the fill and the ring are the state and hold under **`prefers-reduced-motion`**, where only the breathing stops) and the footer opens with a line that says so (**`.settings-save-status`**, **`data-testid="settings-save-status"`**, **Unsaved changes**, empty otherwise, **`min-width: 0`** so it never pushes the buttons off a phone). Closing over unsaved edits - the close button, Escape through **`useRailEscapeStep`** and a click on the backdrop beside the drawer through **`useRailCloseGuard`** (**`nav/railEscape.ts`**) - asks first (**`ConfirmDialog`**, **`data-testid="settings-close-dialog"`**: **Save and close** / **Keep editing**), and a page reloaded or closed over them asks the browser (**`beforeunload`**), except for the reload of a switch to another environment: the form remembers the server it was read from, and Save on a page whose reload onto another server was stopped, or that switched while the save ran, refuses with a reason instead of writing there. An edit typed while a save runs stays unsaved against what was sent (a value put back included), and **Save and close** keeps the drawer open over it; a newer copy of the config does not replace a form edited during a save. Unsaved wins over the green of a save that just went through, and a close asked for while a save runs closes the drawer once that save leaves nothing unsaved. Contract: **`Settings.unsaved.test.tsx`**, **`App.settingsUnsaved.test.tsx`**, **`settingsDirty.test.ts`**, **`settingsSaveStateCss.test.ts`**, **`features/web_ui_settings_unsaved.feature`**; live check **`npm run check:settings-unsaved`**.
- **Loading**: the app keeps the schema and the config the drawer reads (**`settingsConfigStore.ts`**), so **only the first open of the page reads them**; every later open draws the tab the address names from that copy in its first frame, with no request and no other tab in between. The copy follows the server: **`config_reloaded`** and every reconnect of the events stream read it again in the background (**`noteSettingsConfigReloaded`** from **`App.tsx`**), and an open form takes the new copy while it holds no edits of its own - unsaved edits stay, and **Reload** is the deliberate way to drop the ones the form held when it was pressed (a field typed into while its read is on its way keeps what was typed). A save turns the button green only when the form was not edited while the request ran; a copy the untouched form took in the meantime is no edit. A save puts a redacted baseline into the copy at once (**`noteSettingsConfigSaved`**), so a reopen before the read after the save lands, or after that read failed, draws the saved values rather than the ones the save replaced; submitted OIDC client secrets and logout URLs leave both the form and the copy after a successful PUT, with only their configured flags kept and any newer unsaved edits left in the open form; a read older than the save is dropped, and a copy older than a read that failed is read again by the next open. The first open, and an open after a first read that failed, shows **the requested tab as a skeleton** (**`SettingsSkeleton`**, **`data-testid="settings-skeleton"`**: a frame of grey label and input bars tinted from **`--text`**, shimmering unless **`prefers-reduced-motion`**), with grey rows in the rail (**`.settings-nav-item--placeholder`**) or the tile grid (**`.settings-tile--placeholder`**) for the tabs the schema will bring; the narrow shell's head names the section from the dictionary (**`knownSectionLabel`**). Appearance, which needs no schema, no longer stands in for the tab a deep link asked for. A copy that lands is taken **while rendering**, not in an effect after it: a frame drawn from an empty document showed a list with no rows, and the list read the **`?id=`** of the address as a stale row and rewrote it.
- **Layout**: on **`min-width: 1200px`** the drawer is **`min(680px, …)`** wide - as wide as the section rail plus a content column that holds **three theme cards a row** on Appearance (**`repeat(3, minmax(0, 1fr))`** on the desktop shell, **`auto-fill, minmax(130px, 1fr)`** below it, 10px gap), the cards keeping their size and the drawer giving way; **`appearanceSettingsLayout.test.tsx`** computes the column count from the two rules - with a vertical section rail on the left (**`.settings-nav`**) and the content panel on the right (**`.settings-tabs-layout`** is `display:flex; row`). On **`max-width: 1199px`** (same breakpoint as the rest of the shell, via **`isMobileShell`** / **`shellBreakpoint.ts`**) the nav is a **2-wide tile grid** master–detail (**`SettingsTileGrid`**, **`.settings-tile-grid`**): each tile (**`data-testid="settings-tile-<id>"`**) shows the section **title** on top and a short 3–5 word **description** below (**`SECTION_DESCRIPTIONS`** in **`settingsSections.ts`**) styled after the Scheduler job rows. The description clamps to two lines with an ellipsis (**`-webkit-line-clamp: 2`**) and the full text shows in a native **`title`** tooltip on hover. Tapping a tile opens that section with a **← Back to sections** arrow in the drawer's head (**`.settings-head-back`**); the desktop rail (**`SettingsNav`**) is unchanged. On that shell the drawer has **one inline inset**, **14px**, set by the head and the lead pane: the tile grid, the section content (**`.settings-scroll`**) and the reload / save footer all ride it (**`padding-inline: 14px`** inside the **`max-width: 1199px`** block), and the tile grid keeps the same **14px** off the head's rule above it, so every band of the panel starts and ends on the same edge. The wide layout keeps the content panel's own **8px**, because there its left edge is the seam against the section rail rather than the drawer's edge.
- **Search** (**`settings/settingsSearch.ts`**, **`SettingsSearchView.tsx`**, **`settingsReveal.ts`**, **`SETTINGS_TEXTS`** in **`settingsSections.ts`**): one field finds a setting in any tab, and choosing a result takes the operator to it. It is client-side and reads what the drawer already holds - the served schema, both dictionaries, the tabs and the document - so it adds no config key, no route and no Go production code. Searching and choosing a result never write the form's document: **Unsaved changes** and the highlighted Save stay as they were.
  - **Placement.** On **`min-width: 1200px`** the field (**`.settings-search-input`**) is the first child of **`.settings-nav-wrap`**, at the top of the section rail inside its 8px inset (padding **`8px 8px 0`**); the results (**`.settings-search-results`**, a **`.settings-scroll`** of its own) take the section content's place, and the rail shows no active tab while they show. On **`max-width: 1199px`** the field stands over **`.settings-tile-grid`** inside the 14px inset and the results take the tiles' place; with a tab open the field is not drawn, and the head's back arrow leads back to it, and so does **`/`**. **The `/` badge** (**`.settings-search-kbd`**) advertises the key that puts the cursor in the field: it shows inside the field while the field is empty and does not have the focus (after a jump, for one, the focus sits in the revealed setting), on every width, since a narrow desktop window has a keyboard; it is hidden while the field has the focus or holds text, and it is never drawn on a touch-only device (**`snapshotTouchOnly()`**, read through **`useSyncExternalStore`**). **The results take the content column and are not a dropdown under the field**: the documentation reader and the swarm screen use a dropdown, but this field sits in a 200px rail, and a result needs a name, where it lives and a config key. A dropdown that narrow is unreadable, and a wider one would cover the content column anyway, over a form that may hold unsaved edits. A band across the whole drawer under its head was set aside: it costs a row of height on every view. The field and the results share the documentation search's rules (the settings selectors join the selector lists of **`styles/screens/_docs.scss`** that style the docs search field and **`.docs-hit`**: rows **`.settings-hit`** with padding **`8px 10px`** and a 10px radius, hover at 6% text, **`.is-selected`** at 14% accent with a 32% border, the name at weight 500, lines 2 and 3 at 12px and 58% text, the config key in **`ui-monospace`** 11.5px with **`overflow-wrap: anywhere`**, **`mark`** as **`.docs-hit-snippet mark`**) and introduce no token or colour.
  - **The query's life.** The query lives in a store the drawer owns (**`createSettingsSearch`**: the text, whether the results show, the highlighted row and the chosen result), so **`Settings`** re-renders only when the results start or stop showing (**`useResultsShowing`**) and typing never re-renders the tab under them. **Typing** shows the results. **Choosing a result** hides them, keeps the query, remembers the chosen result and asks **`Settings`** for a **trip** to it (one state, **`{entry}`**, a new object per request, which an address that names a setting sets too): every choice is a request of its own, so choosing the same result again reveals it again. **Clicking, tapping or focusing the field**, or **`/`** outside a text field, shows the results again with the chosen result highlighted - only while they are hidden: a click or focus while they show leaves the highlighted result where it is. **Emptying the field** (the clear button of a search field, or deleted text) clears the search as Escape does: the query and the chosen result go. A rail click or a tile tap hides the results and keeps the query. **Closing the drawer** forgets the query. A query of whitespace searches nothing. The field is disabled while the first read of the schema is on its way; when that read failed it searches what is drawn without a schema; a newer copy of the config or a language switch rebuilds the index and the query and the results follow it. A rename of a row rebuilds the index too (**`settingsIndexRowsKey`**: the names and types of the rows, and nothing else).
  - **Keys.** **`/`** follows the documentation reader's and the swarm screen's: it is matched on **`e.key`** (so Shift does not matter) and does nothing with Ctrl, Meta or Alt held, on a **`defaultPrevented`** event, with the focus in a text field or a **`<select>`** (over a checkbox or a button it fires), or while a modal dialog (**`[aria-modal="true"]`**) is open. It puts the cursor in the field and shows the results; on the narrow shell with a tab open it goes back to the tiles first and focuses the field once it is drawn. No two **`/`** handlers are live together: the rail keeps one screen at a time. In the field **ArrowDown** and **ArrowUp** move the highlighted result, wrapping at both ends and scrolling it into view (**`block: "nearest"`**), and **Enter** opens it; while an input method composes, Enter and Escape belong to it and the field leaves them alone. **Escape** has three steps: with results showing it clears the query wherever the focus is (the first step of Settings' Escape chain, **Escape and the screens of the rail**; Telegram's Back dispatches an Escape at the focused element, so it takes the same step); in the field with the results hidden and a query in it, the field claims the key in its own **`onKeyDown`** and clears the query; anywhere else the drawer takes its usual step. When the results change, the highlight stays on the chosen result if it is still among them and otherwise moves to the first. The highlight follows the pointer only when the pointer moves to another spot (**`mousemove`**, not **`mouseenter`**): a pointer resting over the results does not take the highlight when new results come in under it, and the first move seen after the results change only records where the pointer is.
  - **Matching.** The index is a flat list in the drawer's order, built by walking the served schema with the drawing's own layout function. Its entries are the **tabs** (the tile blurb is their second line), the **rows** of the two list tabs (the names as the list trims them), the **blocks** (every block of fields is a result in its own right and is found by its name: a schema group such as a provider's **Advanced settings** or the groups of the **ReAct loop**, a nested object or a list, a hand-drawn block, and the groups of a provider's or a model's row form), the **fields** (every field **`SchemaField`** draws, object and list fieldsets included) and the **landmarks**. A field of **LLM providers** or **Logical models** is indexed once per (row, field), under that row's name, for the rows the address can reach only: a row without a name and rows that share a name are not indexed (a row opens by its name, and the server refuses two of one name, so they exist only as unsaved edits), and neither is a field the row does not draw (an override decides, through **`overrideTexts`**). A field inside a list of objects (a Telegram user group's name, a web search engine's fields) is indexed once and remembers its list; its box repeats once per entry and the index keeps no count. The query is split at whitespace; case does not matter and **ё** matches **е**, and nothing else is folded. Every word has to occur, as a substring, in the entry's **own names** (the names drawn in its box, the primary one first, then the second names such as **Ignore system proxy** in a proxy box or **Provider** in a model's id box; a row's name; a block's or landmark's heading), its **config key** (the dotted YAML path, which two landmarks carry too: **`skills.auto_discovery`** and **`mcp.project_trust`**), its **surrounding names** (the tab, the row and the legends of the blocks it stands in) or its **descriptions** (every (i) text drawn in its box; a block's or landmark's heading's (i)), as the page draws them in its current language. Other locales are not matched: a match has to be shown marked, and other-language text is not on screen; the config key carries the English vocabulary of **`config.yaml`**, **`coddy -t`** and the docs, and where a Russian entry is missing **`schemaFieldLabel`** falls back to the English title, which the search reads too. Results fall into three **tiers**, each in the drawer's order: every word in the own names or the config key (tabs, blocks - a form group, a nested object, a list or a map - and landmarks first, then rows and fields); some word needed the surrounding names; some word needed the descriptions. At most **`SETTINGS_SEARCH_LIMIT`** (**50**) results show, followed by a line that counts the rest. There is no debounce: the text is normalized once, when the index is built. **Never indexed**: values (the only values read are the two lists' row labels, which the list renders anyway; secrets, URLs, prompts and header names and values never reach the index, their names do), the keys the form hides (**`uiHiddenConfigKeys`**), a tab the binary cannot run (**Metrics** without the `metrics` build tag: the server leaves the section out of the schema, **`config.UISchemaJSONHiding`**, and the index is built from that schema, so the tab and its fields are neither indexed nor offered), records (MCP servers, installed skills, subagent definitions, stored sessions, a provider's listed models), fuzzy matches and synonyms, and what a surface does not draw (the **Notifications** block inside Telegram, through **`notificationsShown()`**).
  - **A result row** is a **`button`** with **`role="option"`** (**`aria-selected`**, **`tabIndex={-1}`**, **`data-settings-target`** - the entry's anchor, or **`tab:<section>`** for a tab - and, for a row, **`data-settings-row`**) of up to three lines. **Line 1** is the **primary name**; when a matched word occurs only in a second name, ` · <second name>` is appended, and the matched words are marked. **Line 2** is where the setting is - the tab, the row and the blocks joined by ` › ` - muted at 12px, and the config key follows in monospace on a line of its own, so every row has the same shape whatever the length of the path. **Line 3**, for tier 3 only, is the description, starting at most **`SNIPPET_LEAD`** (**40**) characters before the first word found there, with an ellipsis where it is cut and a two-line clamp. The option's accessible name is lines 1 and 2; line 3 is its description through **`aria-describedby`**. On a touch shell a row is at least 44px tall. An empty result says **No matching settings; try other or fewer words**, and more than 50 end with **N more settings match - add a word to narrow the list**.
  - **Every target is a real box**, because an element with **`display: contents`** has no box to ring or focus. A field is wrapped by **`SchemaField`** in **`div.settings-field`** with **`data-settings-anchor="<domain>:<path>"`** (**`fieldAnchor`**; **`display: flex`**, column, the parent's gap, **`min-inline-size: 0`**, a 10px radius, no padding and no margin so every row keeps its height, **`settingsDrawerRhythmCss.test.ts`**); a fragment override such as the proxy switch plus the URL row gets one box. A group is its fieldset (**`group:<domain>:<id>`**, **`groupAnchor`**). A row form is **`.settings-detail`** with **`row:<domain>`**, **`data-settings-row`**, **`role="group"`** and **`aria-label="<row name>"`**, because a row form draws its name nowhere as text. A landmark is its root (**`landmark:<tab>:<id>`**, **`landmarkAnchor`** from **`settingsSections.ts`**). The **entry frame** of a list of objects (the unlabelled **`.settings-array-entry`**) gets **no** box - its children are the targets - and neither does a field **`overrideTexts`** hides. A **tab** is the one entry with no box: the reveal takes the tab's scroll area, **`.settings-scroll[data-settings-tab=<id>]`**, instead. Anchors are built from schema keys and fixed ids only.
  - **The reveal** (**`settingsReveal.ts`**; **`revealWhenReady(root, entry, {touchOnly, reducedMotion})`** returns the function that cancels it, the ring included, which a new choice or a closed drawer calls). Choosing a result runs these steps in order. (1) The results hide and a new trip is set; an address that names a setting hides results that show as well, or the setting would wait under them until the reveal gave up. (2) The tab opens through **`selectSection`**, a row through the same call with the row (**`setSettingsSectionHash(section, {item: row})`**). (3) The drawer **finds the mounted box**, waiting with a **`MutationObserver`** (child changes, and the **`hidden`** attribute) until it is in the document, at most **`REVEAL_WAIT_MS`** (**1 s**) in all, and giving up quietly when it never comes. A box that is mounted but hidden inside a folded block counts as found, since a folded body stays mounted; so does a block that is itself folded. The lookup compares **`dataset`** values as strings and never builds a selector from user text; a row's box is looked up only inside the row form whose **`dataset.settingsRow`** equals the row; a repeated box resolves to the **first one in document order**, and only when the list draws no entry to the list's own box (a folded entry is not an empty list). A **tab** has no box: the reveal takes its scroll area, **`.settings-scroll[data-settings-tab=<id>]`**. (4) **A folded block unfolds before the wait for visibility**: while something above the box is **`hidden`**, or the box is itself a shut fold (a group chosen by its name, **`.settings-fieldset--collapsible:not(.is-open)`**, whose body is hidden under it), the drawer dispatches **`SETTINGS_REVEAL_EVENT`** from the box (the fold it reaches first is the box itself), and dispatches it again at every mutation - a fold that is already open ignores it, one that was not listening yet hears the next, and the **`hidden`** attribute going away is the mutation that brings the next attempt. The fold (**`CollapsibleFieldset`**) listens in a **layout effect**, because the reveal asks the moment the box is in the page, before passive effects have run; it opens with an ordinary state update. Once nothing above the box is hidden, the drawer **waits a frame** so the page has laid out what opened, looks the box up again and only then goes on, all within the same second. (5) The box scrolls into the middle of its scroll area (**`scrollIntoView({block: "center"})`**, smooth unless **`prefers-reduced-motion`**), or is aligned by its top (**`block: "start"`**) when it is taller than the scroll area, so its name and its first fields are what shows; every box keeps a 12px scroll margin (**`[data-settings-anchor] { scroll-margin-block: 12px }`**), so the ring is never cut at the edge of the scroll area; a tab's scroll area scrolls to its top. (6) The box is **ringed** for **`SEARCH_TARGET_MS`** (**1.6 s**), a tab is not: **`.is-search-target`** paints a **2px outline** of the accent mix (**`outline: 2px solid color-mix(in srgb, var(--accent) 55%, transparent)`**) standing **3px off the box** (**`outline-offset: 3px`**, following the box's radius, so the switch and the label of a field never touch it) over a **light wash** (the inset shadow **`inset 0 0 0 100vmax color-mix(in srgb, var(--accent) 10%, transparent)`**, so no ground of the box is painted over); both come in over the first 8% of the time, hold, and fade over the last 0.6 s. The ring is declared as the state itself and the fade is only the animation, so under reduced motion it holds still and the script takes it off; its rule joins the existing reduced-motion block of the settings section (**`styles/settings/_tabs.scss`**). A box the reveal focused by script is no tab stop, and the ring is its indicator, so once the ring has faded the browser's own focus ring does not take its place (**`[data-settings-anchor]:focus-visible:not(.is-search-target)`** has no outline); a box focused from the keyboard shows no second ring. The ring is never the only signal. (7) The **focus** moves. For a field on a **fine pointer** it goes to the control whose accessible name equals the entry's **primary** name (from its **`aria-labelledby`**, its **`aria-label`** or its **`<label>`**; disabled controls and **`.field-hint`** are skipped), so **Proxy URL** focuses the URL input and not the **Ignore system proxy** switch drawn before it, and a model's id box focuses the id input and not the **Provider** combobox; with no such control, or with the URL input disabled, the box itself takes the focus. On a **touch-only device** (**`snapshotTouchOnly()`**, **`(any-hover: none) and (any-pointer: coarse)`**), and for every row, block and landmark, the **box** takes the focus (**`tabIndex={-1}`**) and no keyboard rises. A **tab** result focuses the tab's scroll area; it is a focus target and not a tab stop, so its outline shows only where the keyboard put the focus (**`.settings-scroll:focus:not(:focus-visible)`**). The focused box always has an accessible name: a fieldset is named by its legend, a row form is a **`role="group"`** named by its row, and any other box, a tab's scroll area included, gets **`role="group"`** and an **`aria-label`** with the primary name (the tab's name for a tab) for as long as it holds the focus.
  - **Link to a setting.** The Settings address names the setting the operator was taken to: **`#/settings/<tab>?id=<row>&field=<anchor>`** (**`appNavHrefSettingsSection`** takes one **`SettingsAddress`**, **`{item, field, historySidebar}`**; **`id=`** only for a row of **LLM providers** or **Logical models**; the anchor is URL-encoded, a colon as **`%3A`**; **`history=1`** stays last). It is written with **`replaceState`**, so it adds no history entry. A choice that has a box - a field, a group, a block, a row - writes it; a tab result writes none, since a tab has no box. The address **loses** the setting when the operator goes elsewhere: a rail click or a tile tap, the head's back arrow, another row, closing the drawer; a new choice replaces it. **Opening an address that names a setting** - a pasted link, a reload, a change of the hash, a relay's own Settings, the Telegram Mini App (whose launch capture keeps it) - opens the tab and the row through the route and takes the operator to the setting exactly as a choice does: the drawer finds the entry in the index by its anchor, tab and row, asking again whenever the index changes, because the first read of the schema may still be on its way, and the address read back after a choice is not a second trip. An anchor the index does not know - a link written by another version - opens the tab and the row and does nothing else. To share a setting, choose its result and copy the address. The address names the setting and never the query: a query in the address stays a non-goal.
  - **The hidden tab.** On the wide drawer the tab under the results is hidden (the **`hidden`** attribute, **`.settings-scroll[hidden] { display: none; }`**), not unmounted, so the drafts of a tab survive a query that is cleared without a choice: an MCP JSON being edited, a waiting device sign-in, an unnamed map row, the Skills install query and the fold states. **`display: none`** also hides a **`position: fixed`** element inside the tab; only portals and document- or window-level listeners escape it. The drawer sets **`PaneHidden`** (**`components/PanePortal.tsx`**, a context that defaults to **`false`**) to **`true`** around the hidden tab, and **two chokepoints** read it. **`PanePortal`** draws its children into **`<body>`** through **`createPortal`** and draws nothing while the pane is hidden; **`FieldHint`** (the tip) and **`SessionTagEditor`** draw their portals through it. **`useEscapeCloses`** does not listen while the pane is hidden. **`FieldHint`** also reads the context for its own listeners and placement: its close-on-scroll, resize and outside-pointer listeners run only while its pane is shown, so scrolling the results cannot close a pinned tip that is hidden, and the tip is placed again when the pane is shown. The rule: **while results show, the tab under them is hidden and deaf** - its portals are not drawn, its Escape layers do not listen, and its state (drafts, an open tip, an open tag editor) is kept. The layers a hidden tab can hold today: the tip of **`FieldHint`** (also pinned by a touch), the Skills install results (**`useEscapeCloses`**; the results themselves are inline and hide with the tab, the query is kept), the tag editor of the Sessions table, the confirmation dialog of the Sessions table (a modal: nothing behind its backdrop can be reached and **`/`** does nothing, so results cannot show over it) and **`Combobox`** (its list is inline, hides with the tab and folds on a press elsewhere as before). **Tested**: one behavioural test in **`Settings.test.tsx`**, parameterized over the layers (a tip pinned by a touch, an open tag editor, the Skills install results), renders each under a hidden pane and checks that it draws nothing in **`<body>`** and claims no Escape; for the pinned tip it also scrolls the results before they go and checks that the tip is still pinned and placed against its (i) afterwards; **`components/useEscapeCloses.test.tsx`** covers the two pieces (a layer in a hidden pane leaves Escape to the screen under it, and **`PanePortal`** draws into the page and nothing while its pane is hidden). **By construction**: any future portal drawn through **`PanePortal`** and any future Escape layer built on **`useEscapeCloses`**. **Not guaranteed**: a future component under Settings that calls **`createPortal`** directly or adds a **`document`** listener of its own - catching that statically would take a TypeScript parser that follows imports, re-exports and dynamic imports and counts calls per owner and event, which is more machinery than the risk warrants. Draw a portal under Settings through **`PanePortal`**, build an Escape layer on **`useEscapeCloses`**, and let review check the rest. On the narrow shell no tab is mounted under the results: they replace the tiles.

Such a field is a password input that is **empty** while a value is set and says so in its placeholder (**Set. Leave empty to keep it**, else **Not set**); leaving it empty keeps the stored value, typing replaces it. A list of secrets says how many are set and hidden in a state line under its legend (**`settings.secret.listSet`**, counted per locale), and the values entered in it replace them all. - **The relay's own Settings.** On a relay's home (the app on a relay, not on a node behind it) the drawer edits the relay's deployment: **`GET /coddy/config/schema`** answers with the relay's form (**`config.RelayUISchemaJSON`**: **`swarm`** and **`logger`** only, **`x-coddy-relay: true`** at the root), and **`deriveSettingsSections(schema, {relay: true})`** draws **Appearance** and those two tabs; the **Sessions** and **System** tabs, which manage and report one agent's installation, are left out, even before the schema has arrived. The document is scoped the same way (**`configapi.Backend.Sections`**): **`GET /coddy/config`** serves only **`swarm`**, **`logger`** and the revision, and a save takes only those and refuses any other section, so a relay client never reads the host's provider keys or writes its other settings. **Save all** PUTs that document, and the relay applies the **`swarm`** section at once (a listen address that moved takes a restart); the **`logger`** section is read when the process starts next, as an agent's is. A node reached through a relay shows that node's own Settings; a node that is itself a relay refuses a write sent through the mount (**403**), so a relay is edited only on its own page.
- **Section form layout** (**`SchemaForm`** **`groups`**, **`SchemaFormGroup`** **`{id, legend, description?, paths?, collapsible?}`**): a settings form is fieldsets by meaning, not a column of loose fields. A section's own **`enable`** switch opens the form **outside every fieldset**, above everything, wherever the schema puts it (Subagents, Hooks, Memory, Command safety, Context compaction, Scheduler). A group with **`paths`** takes exactly those keys; the **first** group without **`paths`** is the catch-all and takes every key no group names, except a list or a nested object, which stands as a **block of its own** beside it rather than inside it. Every group stands **where its first field stands** in the schema order, blocks stand in place, and a key no group takes (one added to the schema later) still renders in place, so nothing silently leaves the form. A group's **`description`** is the (i) of its legend, folded or open: a folded group that dropped it left a name with no way to find out what the block holds. ### System tab

The **System** tab (**`SystemSection.tsx`**, section kind **`status`**, id **`status`**, **`#/settings/status`**; **`system`** stays the Prompts tab's id) is the read-only page of the installation behind the drawer, drawn by hand like **Sessions**: it renders before the schema has loaded, it is absent on a relay's home, and it exists in every **`http ui`** build. Through a relay mount it shows the node, in a remote environment the remote. It is the SPA's first lazy chunk (**`React.lazy`**, **`chunks/SystemSection-<hash>.js`**): the section, **`Sparkline`** and the formatting (**`systemStatus.ts`**) live in it, while the fetch helper, the **`Document`** type and the ordered store (**`systemStatusApi.ts`**) stay in **`app.js`**, so **Save all** reads the status without pulling the chunk in. It edits nothing and never marks Settings unsaved.

- **Blocks, top to bottom** (mockups: desktop and phone, Dark): the summary banner, the restart notice, **Last hour**, **This installation**, **Subsystems**, **Disk**, **Activity**, **Model providers since start** and the footer. **Last hour** and the providers table are drawn only when the document has a **`metrics`** member (a binary built with the **`metrics`** tag); without it there is no placeholder and no empty chart. Each block has a heading that takes the focus (**`tabIndex={-1}`**), and the four always-drawn ones (**This installation**, **Subsystems**, **Disk**, **Activity**) are the search landmarks.
- **Summary banner.** The first block and the only **`aria-live="polite"`** region of the page. It is one of the app's notices. With problems it is the composer's usage banner (**`.usage-banner`**: its amber border and ground, the text in **`--text`**; **`N need attention:`** and the items, each a link-styled button that focuses its block's heading, joined by **`·`**; **Relay unreachable**, one for each relay that has been offline for 5 minutes, focuses the **Subsystems** heading); with none it draws nothing: the region stays in the page, empty, with no frame and no gap of its own (**`.system-summary:empty`**), so what comes next is announced, and the blocks below already show that nothing needs attention. Every other state is that quiet frame with quiet text (the border and the ground of a settings fieldset, **`--coddy-glass-panel-border`** and **`--coddy-surface-fieldset`**): **partial** alone (a block in **`unavailable`** or missing), **stale** (the last refresh failed), a 404, a 401, a node offline behind a relay and a first read that failed. Partial and stale add a muted line, never leave the summary empty, and partial combines with problems (its line stays muted inside the usage banner).
- **Restart notice.** An information notice under the banner, framed as the composer's edit banner frames one (the accent at 55% in the glass border, the text at 78%) on the fieldset ground: **Saved address {address} applies after Coddy restarts.** when a listener moved, **A saved change applies after Coddy restarts.** when no row carries a **`pendingAddress`**, and a link to the serve guide (**`#applying-a-saved-address`**); with **`restartRefused`** the frame takes the error tone (**`data-tone="error"`**), **The saved settings can't start:** and the message, wrapping. It never names **`coddy serve restart`**: which restart applies depends on how the process was started, and the guide says so.
- **Last hour** (a 2×2 grid of cards on desktop, each framed like a settings fieldset, one-line rows with no frame on a phone). The heading row carries a muted **in memory, cleared on restart**; the 15 s step is the axis. A card has its title, the latest value at the right, the chart and a muted legend: **Attempts per minute** (ok in the ok tone, errors in the error tone), **Attempt time** (**Avg time**, the accent), **Tokens per minute** (in, out) and **Load** (turns, tasks). The title keeps at least its longest word and the value wraps into the room left beside it (**`minmax(min-content, 1fr) minmax(0, max-content)`**), so the two never run into each other, in Russian or with four-digit rates. A time under a second is told in milliseconds (**250 ms**), never as **0 sec**. On a phone each is a row with the same title: label, a one-line sparkline and the value right-aligned.
- **Label/value grid** (**This installation**, **Subsystems**, **Activity**): a muted label column and the value, monospace for the version, addresses and the config path, with the revision muted beside the version; a phone right-aligns the value. Addresses and paths use **`overflow-wrap: anywhere`**, so nothing makes the page scroll sideways at 390px. A subsystem row is a state chip (**running** in the ok tone, **stopped** in the error tone, **starting** and **kept** (retained) muted), its address, and for a saved address that waits **`→ <address> after restart`** in the warn tone; the exporter's row adds **`/metrics`** and **token set** or **no token**, never the token. A relay registration offline for 5 minutes adds a warn-tone line, **Not registered with the relay {relay} for {duration}**, the duration formatted as **Running for** is. **Activity** lists turns, the prompts waiting for an answer (permission and question, a line each, **0** included) and background tasks.
- **Disk.** One meter (**`.system-meter`**, a 6px track shaped like the usage meter's): the fill is the share used, the accent until **512 MiB** free (a fixed constant, the Go side's **`DiskLowBytes`**), then the warn tone; the summary says **Disk full** at zero. It is **`role="meter"`** with a name (**Sessions disk used**), **`aria-valuemin`**, **`aria-valuemax`**, **`aria-valuenow`** and **`aria-valuetext`**, beside the label **Sessions** and the visible text (**380 MB free of 250 GB**, on a phone too, where the meter takes a line of its own). On a desktop the meter keeps at least 96px and the text wraps beside it. The 512 MiB line is a Go constant, so the page states no threshold of its own. A failed read draws **Not available** in its place; there is no home volume.
- **Model providers since start**: a table of provider, attempts, provider errors in percent, average time and last failure as a relative time (**-** for none).
- **Colours.** Four tokens on **`.settings.drawer`**: **`--system-ok`** and **`--system-error`** are the theme's own green and red (**`--coddy-todo-completed`**, **`--coddy-danger`**) drawn a quarter towards white on every dark canvas and towards **`--text`** on Light (**`--system-lift`**), so each preset keeps its palette and the text reads on its band; **`--system-warn`** is the app's amber, as the usage meter's (**`#fbbf24`** on every dark canvas, **`#92400e`** on Light, dark enough for its band); **`--system-quiet`** (labels, headings, legends, the footer, chart values) is **`--text`** at 80%, as the settings rail mixes it, never **`--muted`**, which reads 2.1:1 on Nord. A stopped subsystem's chip and failed attempts are the error tone, a subsystem that runs the ok tone.
- **Footer.** **Updated N s ago** (muted, not live: no **`aria-live`**, updated by a timer) and at the right a link to the monitoring guide. The copy button, with a hit area of at least 44px, sits on the config file row and copies its path; the exporter's address is on its Subsystems row.
- **Degraded states** replace or dim the blocks and never draw a zero for a number the document lacks: **404** a muted notice, **This server does not report its status (version X)**; **401** a refused notice; a node offline behind a relay, offline with its last-seen time; a failed refresh keeps the last values, greyed, under a stale summary; a missing block, **Not available**.
- **Attention badge.** One number, **`attention.length`** of the document on screen, so a relay offline counts once; the SPA has no rule of its own and draws none at 0, after a 404, a 401 or a failed read. The desktop rail shows it after the **System** label as the app's count pill, the one the main rail draws on History (**`.rail-active-count`**: the accent with **`--coddy-on-accent-fg`**, bold); the phone tile shows it at the top right, and the tile's description line reads **N need attention** in place of the blurb. The number is **`aria-hidden`** and the text is plural through **`tp()`**. The tile, a **`role="listitem"`** button that takes no name from its content, is named by its title (**`aria-labelledby`**) and described by that line (**`aria-describedby`**), as every tile is; the rail button keeps its name and is described by a visually hidden copy. Neither is a live region, and the search never indexes the badge.
- **Reads.** One read when Settings opens (for the badge), none while it is closed, one after **Save all** (the restart notice shows in the drawer's lead pane; a 404 is ignored), and every 15 seconds while the tab is shown and the page visible (**`document.visibilityState`**). The opening read serves as the tab's first read while it is in flight or younger than **`SYSTEM_STATUS_REUSE_MS`** (5 s). The badge, the tab and the Save read share one store per environment (**`systemStatusApi.ts`**): a generation raised on a switch of environment drops older answers, a sequence number drops any answer, success or failure, older than the last applied, and a read in flight is shared except after **Save all**.
- **Budgets.** **`app.js`** stays at or under **2,000,000 B** (the constant in **`bdd_diagrams_test.go`** is not raised), the System chunk at or under **20,000 B**, and **`Sparkline`** stays out of **`app.js`**: **`features/web_ui_diagrams.feature`** asserts all three.
- **Telegram Mini App**: the tab is drawn there for admins, the only people who open the app.

### Sparkline

**`Sparkline`** (**`ui/settings/Sparkline.tsx`**, about 50 lines, imported only by **`SystemSection`**) is the one chart of the SPA: an inline SVG, with no chart library and no stored points, since the line is computed from the values it is given.

- **Props**: **`values`** (**`(number | null)[]`**, oldest first), **`label`** (the metric's name) and **`latest`** (its latest value, already formatted).
- **Gaps.** It draws one **`<polyline>`** for each run of non-null points, so a **`null`** (a first rate point, a missed sample, a mean over a window with no attempt) is a gap and never a dive to zero.
- **Colour** comes from the tokens of the System tab (*Colours* there): the accent, the ok and error tones drawn from the theme, the quiet text and the warn amber, so every preset keeps its own palette and Dark and Light both read.
- **Accessibility.** The SVG is **`role="img"`** with an **`aria-label`** that names the metric and its latest value; the strokes are decoration.
- **Size.** It fills the width of its slot at a fixed height (the card's chart on desktop, a one-line row on a phone). It lives in the lazy System chunk (budget in *System tab*).
