# UI design: workflow

[Design index](../../DESIGN.md)

## States

- Idle composer: bordered textarea.
- Streaming assistant: progressively grows final assistant bubble; token HUD updates concurrently.
- Error streaming: surfaced inside assistant transcript with HTTP status text fallback.
- **Working**: for the whole turn, a Coddy-logo work indicator carries a **live status line** to its right (**`TypingDotsMessage.tsx`**, classes **`typing-dots-status*`**). It names the current step and nothing else, for example **`Reading a file`** or **`Running a command`**, followed by an elapsed counter (**`· 12s`**). **The line carries the phase and never what the step acts on.** No path, no command, no pattern, no url, no tool id: what a step acts on is named once, by the transcript row above the line, and repeating it in a running caption only fills the row with a value nobody can read at that width. **Every phrase must therefore be complete on its own** - **`Running a command`**, not **`Running`** followed by the command; **`Выполняю команду`**, not **`Выполняю`**. A new phrase that reads as a fragment without an object beside it is a phrase that belongs to the transcript row, not to this line, and the dictionary test (**`external/ui/src/ui/i18n/statusPhrases.test.ts`**) fails it in every locale. The one phrase that takes slots is **`status.mcp`**, and it names the server and the tool of a call Coddy does not define - the identity of the step, not its arguments. The **turn's own numbers lead the line** (**`.typing-dots-turn`**): the turn clock, the tokens the model has generated in this turn, the background tasks running right now, each closed by a middle dot, so a long turn reads **`15m 08s · 13.5k tokens · 1 running task · Thinking…`**. The clock and the tokens come from the server's **`turn_progress`** (**`chat/turnProgress.ts`**: the turn stream, plus **`GET /coddy/sessions/{id}/activity`** for a tab that joined late, because the relay does not replay a frame the transcript snapshot covers); the start is counted back from the local clock by the elapsed time the server reported, so a wrong clock on either machine does not move it. A reading names its turn by the server's **`startedAt`** and is dated by the turn's age on the server's clock: the newer one wins whichever way it came, and only a clearly earlier start replaces the known one. Until the server has reported - an older server never does - the clock counts from the creation time of the turn's user message. The tokens segment hides at zero, so a turn that has not heard from the model reads **`57s · Waiting for the model`**. Generation speed follows the token count (`1.2k tokens · 9.8 tok/s`), from **`turn_progress.tokensPerSecond`**: a fresh 200-token window per model call, then 500 tokens once the call has written 500, with steps of 50 and 100 and display updates every five seconds. Speed appears at the call's 200th token and stays for the rest of the call, because most calls of an agent stop short of 500 and a gap between the windows hid it from them; a stalled stream keeps its last value. Blocking (non-streaming) providers and ACP agent models show live output counts without speed: neither exposes measurable per-model streaming boundaries. A streamed call delivered in a single output chunk contributes neither tokens nor time to the speed average, while its output still counts toward the turn total. A completed turn that wrote anything leaves a compact caption, backed by a UI-only **`uiLog.generation`** record; its token count includes all calls. The **speed is one segment of that caption**, not the reason for it: it joins the line only where at least one call had a measurable generation interval, and a turn with none - a blocking provider, an agent behind an **`acp`** row - keeps the clock and the count and says no speed (**`tokensPerSecond`** absent in the frame and zero in the record). Dropping the whole caption there left a turn an agent ran with nothing at all under its answer. It survives reload, cancellation and errors. The first-token wait, tools and permission waits are excluded. Tokens shorten past a thousand (**`1.2k`**, **`13.5k`**, **`240k`**, **`1.2M`**) and never round up. The tasks segment (**`typing-dots-turn-tasks`**) counts through **`countRunningTasks`** (**`tasks/taskStatus.ts`**) - rows that say **`running`**, the goal supervisor's own children left out - the same count the header control uses; it is a **`button`** in the accent colour with no chrome of its own and opens the Tasks panel. **The same indicator holds the tail once the turn has ended and its tasks have not**: **`TypingDotsMessage`** takes **`tasksOnly`**, which drops the turn clock and the tokens - there is no turn to time - and leaves the count alone beside the indicator, closed by no middle dot (**`.typing-dots-status--tasks-only`**); it opens the same panel, and when nothing runs nothing stands. Under **`prefers-reduced-motion: reduce`** and in the invisible idle slot, the indicator uses a static Coddy **C** with a fixed inner ring. With the turn clock in front, the **step counter stays only on a step that runs something other than the model** - a tool call (**`stepShowsItsOwnClock`**): a second clock equal to the first reads as a glitch. One ticker drives both clocks, aligned to the turn's second boundary. On a phone (**`max-width: 599px`**) the task count is compact (**`1 task`** / **`2 tasks`**, **`1 задача`** / **`2 задачи`** / **`5 задач`** in Russian), during the turn and while tasks outlive it. **`TurnTasksSegment`** uses the shared phone subscription and **`tasks.runningCompact`** plural entries; its button keeps the full running-task accessible name, and tablets and desktops keep the full visible label. On a phone the line takes two rows: the turn's numbers keep the first one next to the indicator, the last of them closed by no dot, and the phrase goes under them at **11px** with the step counter, so the numbers stay where they stand when the turn ends and only the phrase goes. Derivation of the phrase is pure and lives in **`chat/liveStatus.ts`**: it reads the transcript the SPA already holds, scanning back to the last **`user_message`** so a stale row from a finished turn cannot drive the label. Priority is unresolved **permission** prompt → unresolved **question** prompt → running **tool_call** → in-progress **thinking** (**`Thinking…`**) → the turn's newest row is answer text (**`Writing the answer`**, kind **`writing`**, no target) → waiting on the model. A status line is never empty: the indicator does not render without a phrase beside it. The two prompt states show **no step counter**: nothing is running, so a climbing number would be a lie (same reasoning as the frozen **`ToolCallMessage`** timer). They keep the turn clock, which is wall time since the prompt. A plain wait escalates its phrase with time: **`Waiting for the model`** → **`The model is taking longer than usual`** (15s, **`typing-dots-status--slow`**) → **`Still no response from the server`** (60s). Before that, a turn that has shown nothing since its message (**`opening`** on the status) reads **`Preparing the session…`** (kind **`preparing`**, **`withPreparingPhase`**) until the server reports that it talks to its model: a turn announces itself with a **`turn_progress`** in the **`preparing`** phase as soon as it is taken, while it brings in its MCP servers and waits for its model's context window, and the loop's own report ends the phase. The preparing phrase does not escalate, because it is not the model that is slow (issue #357). Layout: the **phrase** is the only thing that gives ground when space runs out - the turn's numbers and the counter are **`flex: none`**, and a phrase too long for the row ellipsizes (**`.typing-dots-status-verb`**) rather than wrapping it onto a second line. The indicator is a **14px SVG** (**`.coddy-work-indicator`**) with a cropped logo **`viewBox`** that optically matches the workspace **`FolderIcon`**. The root SVG stays still, and the dim inner ring (**`.coddy-work-indicator-ring`**) stays fixed. The outer **C** contour (**`.coddy-work-indicator-c`**) rotates and grows from a short arc to a near-full circle, then shrinks, looping continuously. The CSS animation **`coddy-work-orbit`** rotates the contour; **`coddy-work-arc`** changes its **`stroke-dasharray`** and **`stroke-dashoffset`**. It has no plate, background or shadow, and the row height stays unchanged. The row keeps its **`typing-dots`** and **`typing-dots-status*`** hooks; the status node follows the SVG. The interactive console (**`external/cli`**) shows the same phrases next to its spinner, from the Go twin of the table in **`external/cli/status.go`**. The line **stands in the transcript's own rhythm** (**`.typing-dots`**, **`padding: 1px 17px 4px`**), and the padding is what buys it: the rows around it are text, whose glyphs sit about **3.5px** inside their line box, while this row is a flex box whose ink reaches its own edges. Measured in a browser, that puts it **13.7px** under the step it reports on and **13.9px** over what follows at 1280 px, where two ordinary rows stand **13.7px** apart, and **16px** and **15.6px** at 390 px against their **15.7px**. With no padding at all the row below came within **9.9px**, which read as the card climbing onto the line; a whole row gap on top and nothing underneath, and an even split, were the two tries before that. Those **17px** are the plate's **1px** border and its **16px** padding, so the mark stands on the vertical line of the folder icon on the plate over the composer and the numbers on the line of its name, the checklist aligned in the same two columns; the **6px** between the mark and the first number is the plate's own gap, and the status carries no margin of its own. There is **one padding whatever stands under the line**: the rule that took 4px off the column without a todo checklist was compensating for the margin the checklist card used to add, and that margin is gone, so nothing animates the line's padding either. Between turns the line keeps its room: **`MessageList`** renders an empty slot of its shape at the tail (**`.typing-dots-slot`**, **`data-testid="live-line-slot"`**, the indicator, the numbers and the phrase the phone puts under them, **`opacity: 0`**, **`aria-hidden`**); the slot keeps its base height between turns, and the live line itself still mounts afresh at every turn. The slot and the tasks-only line stand before the todo checklist when it is shown, so no invisible row separates the checklist from the composer. **A finished turn keeps the line** (**`data-testid="generation-summary"`**, **`SystemNoticeMessage`**, built of the same **`.typing-dots-turn*`** parts): the Coddy mark at rest (**`.typing-dots--finished`**), how long the turn ran (**`uiLog[].generation.elapsedMs`**, the clock the line showed), the tokens and, where the turn had a window to measure, the average speed - **`1m 21s · 1.2k tokens · 9.8 tok/s`**, or **`1m 51s · 890 tokens`** without one - with no phrase, since no step is under way; the time it finished is the line's tooltip. **It is the live line's box, to the pixel** (**`.typing-dots--summary`** marks it and changes none of its spacing): it takes that line's place in one frame, so a padding of its own would move the whole transcript by the difference the moment a turn ended - which is what **`npm run check:queue`** measures as *the end of a turn moves nothing, the numbers included*. Both keep the same rhythm. While tasks the turn started still run and this row stands last, it carries their count (**`TurnTasksSegment`**) and the mark keeps turning, in place of a second line at the tail with a mark of its own. **The line simply stops**: the row takes the live line's place in one frame, the same height, and nothing moves. While the turn is still being released (the completed frame comes a moment before **`generating`** goes false) the row is not drawn and the live line stands alone; a chat ending in this row keeps no empty slot under it (**`.typing-dots-slot`**), and on a phone the row keeps the live line's two rows **at the tail only** (**`.messages-inner > :last-child .typing-dots-status--finished`**), because a row and a slot together grew the transcript by 37px and scrolled a phone by 78px at the end of every turn. Only at the tail, because that is where the finished line takes the live line's own place; with a row under it (a system notice, the rest of the conversation) the room is held by the empty slot instead, and the second row, blank, stood between the numbers and whatever followed - **31.9px** of it against the **15.7px** two ordinary rows keep. **`npm run check:queue`** measures it. It stands as far under the answer as the live line does: a message ending in a list has no bottom margin, on the list or its last item (**`.md > :where(ul, ol):last-child`**), as one ending in a paragraph has none. It replaces the separate caption, which read as a stray footer in a style of its own; a row saved before the duration was kept has no duration.

The live line hides a finished summary when no visible transcript row separates them, even if invisible wake records follow it. It also hides a summary identified as the running turn by its server start time, including when later tool rows follow. Other summaries remain in the history and return when the turn stops.

## Non-goals for this milestone

Server-side SSR routes per session, BFF auth, CDN-hosted Swagger, and editing **`agentMemory`** via REST remain out-of-scope (`session.json` slot remains agent-managed).

## Dev workflow

To iterate on UI without rebuilding the Go binary:

Backend:

```bash
make build TAGS=http
./build/coddy serve --config config.yaml --home /tmp/coddy-ui-dev-home --sessions-dir /tmp/coddy-ui-dev-sessions -H 127.0.0.1 -P 12345
```

Frontend:

```bash
npm --prefix external/ui install
npm --prefix external/ui run dev -- --host 127.0.0.1 --port 5173
```
