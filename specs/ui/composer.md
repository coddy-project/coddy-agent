# UI design: composer

[Design index](../../DESIGN.md)

### Composer pill

Muted **Auto** pill tracks future modality toggles; UI copy stays English everywhere.

### Composer service tier

- **Placement.** The service tier chip follows Permission and precedes Toolset in the composer selector strip. It uses the existing `composer-tab mode-btn` style and theme tokens.
- **Visibility.** Show the chip only when the server supplies service tier choices for the selected model. Hide it in a subagent's read-only transcript.
- **Labels.** The chip shows the selected value: **Standard**, **Fast**, **Ultrafast**, or **Flex**. Its accessible name and tooltip are **Service tier**. Translate all labels through the interface dictionaries. An unset session shows one selected Standard item; there is no separate Auto item or hidden empty row.
- **Menu.** Use the existing `mode-menu` portal, anchored to the chip on desktop and shown as a bottom sheet on narrow shells. Keep the chip in the horizontally scrollable selector strip; keep the context ring and Send fixed. The menu lists only server-provided choices, filters the empty choice of an older server and marks the selected row with `is-selected`. `gpt-6.2-sol` and `gpt-6.2-astra` offer only Standard and Fast. Selection closes the menu. Escape and a press outside close it through the shared menu controls.
- **Meaning.** An unset session omits the request parameter while showing Standard; explicitly selecting Standard requests `default`, including after Fast. The chip shows the user's selection, which can differ from the provider's actual tier. A change during a turn applies to the next turn.
- **State.** An existing chat uses its saved session selection and receives changes from other clients. The `coddy_service_tier` cookie remembers the user's last choice for new chats only. Opening a chat or receiving another client's change does not replace that preference. A model without the remembered choice leaves the session unset and shows Standard.
- **Verification.** `App.sessionSettings.test.tsx` covers session restoration and updates from another client. `chat/serviceTier.test.ts` covers choice selection and cookie preferences. The screenshots in [Service tier](../../docs/surfaces/web-ui.md#service-tier) show the dark, light and narrow layouts.

### Composer permission chip, toolset chip and turn overrides

- **Permission chip** (**`composer-tab mode-btn mode-permission`**, **`data-testid="composer-permission"`**) follows **Reasoning** and the optional service tier, before toolset chips, and names the session's permission mode: **Ask** / **Accept edits** / **Bypass** (**Спрашивать** / **Правки без вопросов** / **Без вопросов**). Its **`title`** names the mode new sessions start in (*new sessions start in: bypass*), the one chosen last on any surface; the permission mode is not configuration, so no Settings tab has a field for it. Ask is the quiet default (the plain tab recipe); **`perm-accept_edits`** takes an amber hairline (**`rgba(234,179,8,.6)`**); **`perm-bypass`** takes the danger tone - red text (**`#b91c1c`** light, **`#f87171`** on every dark canvas), a **`rgba(239,68,68,.7)`** border and a **3px** **14%** red glow, the family of the plan/ask mode outlines - so a session that approves everything never looks like one that asks. The menu is the **`mode-menu`** family (anchored portal on desktop, bottom sheet on narrow shells); the bypass row carries the same red text. Hidden in a subagent's read-only transcript.
- **Toolset chip** (**`composer-tab mode-btn mode-toolset`**, **`data-testid="composer-toolset"`**) follows the permission chip while the configuration has a **`toolsets[]`** preset, and is not rendered otherwise (no placeholder, no disabled chip): it names the session's toolset, **All tools** (**Все инструменты**) for none, in the plain tab recipe, and its **`mode-menu`** lists the presets and **All tools** last, the current one **`is-selected`**. A preset added on a configuration reload brings it without a page reload. Hidden in a subagent's read-only transcript.
- **Turn overrides** (**`.composer-overrides`**, **`data-testid="composer-overrides"`**) follow the selectors when **`--once`** / **`--count=N`**, a skill or the model's **`switch_model`** changed a setting for some turns: **11px**, **62%** muted, one line (**`max-width: 240px`**, ellipsis) naming the first override ("gpt-oss-120b this turn and 2 more", "off, 1 turn left") with **`+N`** for the rest; the **`title`** lists them all. Nothing renders without overrides.
- Both mirror the session's settings snapshot (**`event: session_settings`**): a change made anywhere - a command, the permission dialog, a console - shows up in every tab.

### Session goal

A session can carry a goal (`/goal <objective>`, **`docs/features/session-supervisor.md`**): the supervisor checks every turn against it and starts the next turn itself until a check finds it met. The composer shows where the goal stands and is where the operator acts on it; the transcript shows the turns nobody typed as goal rows. The model and the parsers live in **`chat/goal.ts`**, the popover in **`chat/GoalPopover.tsx`**, the row in **`messages/GoalTurnMessage.tsx`**, the target glyph in **`components/TargetIcon.tsx`**.

- **One snapshot, four deliveries.** The goal arrives whole with a version, in one envelope (**`{sessionId, goal, version, notice}`**, `goal: null` once cleared), from **`GET /coddy/sessions/{id}/messages`** (`goal`), from the turn stream (**`event: session_goal`**), from **`GET /coddy/events`** (**`event: session_goal`**, parsed in **`chat/serverEvents.ts`**) and from the answers of **`PATCH`** / **`DELETE /coddy/sessions/{id}/goal`**. **`App.tsx`** keeps it for the viewed session the way it keeps the settings snapshot (**`applySessionGoal`**, **`isNewerGoal`**): the highest version wins, a snapshot of another session is dropped, and a new session on screen starts from nothing until its read lands.
- **Mark** (**`.composer-goal`**, **`data-testid="composer-goal"`**, on the plate over the composer card, left of git's **`+A −D`** and 8px from it, or at the plate's right edge when git reports nothing): shown only while the session has a goal, the one **`/goal`** set. A **24px** button with **7px** corners, the improve-prompt wand's size so the two read as a pair (**`goalCheckerCss.test.ts`** holds them equal), holding the target glyph (**15px**) in the status's tone and nothing else; **`Goal: <status>`** is its name; on a phone or a touch screen an invisible **40px** hit area lies over it, as over git's count. The plate reaches the mark as a function: **`ChatScreen`** hands **`cardTop`** as **`(goalMark) => <WorkspaceBar goal={goalMark} … />`**, so the mark and its popover stay the composer's, and a session with a goal gets a plate even outside a repository (the folder alone, then the mark). Its tip is the context ring's (**`rail-tip`**, above the mark): the status line in the tone, then the objective (cut at 200 characters), its right edge the mark's so it stays over the card, shown on hover where there is one (**`@media (hover: hover)`**) and on keyboard focus, and never while the popover is open. A touch opens the popover straight away. The mark's host carries the tone class too, so the tip, a sibling of the button, reads the same **`--goal-tone`**.
- **Tones** come from the theme's own tokens through **`--goal-tone`** (**`.goal-tone-*`**), never a colour of their own: **active** the accent (**`--accent`**), **paused** and **limited** the muted text (**`--muted`**), **blocked** the danger tone (**`--coddy-danger`**: there is no per-theme warning token, and blocked is the state that needs the operator), **complete** the done green of the todo list (**`--coddy-todo-completed`**). The mark's glyph and its tip's status line are the tone. Status words: active, paused, needs you, complete, out of budget (в работе, на паузе, ждёт вас, выполнена, бюджет исчерпан).
- **Popover** (**`GoalPopover`**, **`role="dialog"`**, **`data-testid="goal-popover"`**), opened by the mark and by a bare **`/goal`**: the context popover's shell (**`slash-menu-surface`** glass, **`sessions-head`** head with the **×**). On a desktop it is a portal anchored to the mark (to the composer card when there is no goal), **400px** wide at most, its right edge the composer card's (**`alignRef`**) and pulled inside the window, above the anchor when there is room and below otherwise, never taller than that room. On the stacked shell it is a bottom sheet over the scrim (**`.goal-popover--sheet`**, **`max-width: min(560px, 100vw)`**, at most **80vh**, on **`--coddy-keyboard-inset`** so the on-screen keyboard does not cover it; a Mini App lifts it with the other sheets). The head and the actions stay put and the body scrolls between them, which keeps the actions in reach at **320px** and in a **568x320** landscape phone. **Escape** leaves an edit first, then closes; a press outside closes on a desktop, the scrim on the sheet; while the Clear confirmation asks, both are the dialog's. Opening focuses the set form's field where a keyboard is at hand (**`composerAutoFocusAllowed`**), the panel otherwise; closing gives the focus back to the mark.
- **Contents**: the objective whole, in its own box that scrolls past nine lines; the status as a badge in its tone and the reason the supervisor gave (paused, blocked, limited); the **last check** - its verdict, a **verified** badge when the verifier confirmed a met verdict in the workspace, its reason and the items it left open; the **checklist**, one row per requirement with a drawn status mark (a ticked circle in the done green, an open circle, a dashed circle for unverified) and its evidence folding out under the row on a tap (a disclosure with the app's chevron, never a hover); the **numbers** - continuations *N of M*, checks, the time worked (**`formatElapsedSeconds`**, the turn clock's format) and the tokens, against the budget when one is set (**`formatTurnTokens`**) - and closing the same grid, **Checked by** and **Reasoning**: six cells, each one column wide, three to a row on a desktop and a tablet (**`repeat(3, minmax(0, 1fr))`**) and two on a phone (**`repeat(2, minmax(0, 1fr))`** under **`max-width: 599px`**), so the rows come out full and every label stands on the grid's column lines; a model id wraps inside its cell, after the provider first (**`ModelId`** puts a **`<wbr>`** after the slash). **Checked by** (**`goal-checker`**) is the model the next check runs on, the server's **`checkModel`**; **Reasoning** (**`goal-reasoning`**) is the level alone, the one **`/goal -r`** chose, else the model's default level as it is, **default** when the model configures none, and absent for a model without levels (**`checkerLevel`**).
- **Actions** (**`.goal-popover-actions`**): icons, rounded squares of **36px** with **10px** corners (**`.goal-icon-btn`**, glyphs in **`chat/goalActionIcons.tsx`**), each named in its **`title`** tip and its **`aria-label`** - Resume a filled play triangle on the accent ground (**`--primary`**), Pause two bars, Edit a pencil, Clear a bin in the danger tone (**`--danger`**). The edit and set forms keep worded buttons. **Pause** while active (**`PATCH .../goal {"status":"paused"}`**); **Resume** while paused, blocked or limited, which sends **`/goal resume`** as a prompt of the chat, since resuming starts a turn; **Edit**, an inline field filled with the objective whose **Save and start** sends **`/goal <objective>`** (it replaces the goal and starts working on it at once) and **Cancel** goes back; **Clear**, in the danger tone, asks through **`useConfirm`** and then **`DELETE .../goal`**. Without a goal the popover is the set form: a line on what a goal does, the field and **Set goal**. The field counts the objective in runes against the server's **4000** and refuses more. A prompt waits while a turn runs - Resume and the form's button are disabled and a note says why - and goes the way a typed message goes (**`sendGoalPrompt`** in **`App.tsx`**, like the plan card's Run plan), without touching the draft or an edit in progress. A refused Pause or Clear says so in the popover.
- **`/goal` in the composer**: a bare **`/goal`** (Send, Enter or the queue key) opens the popover and sends nothing, like **`/docs`** and **`/mcp`** (**`runLocalCommandFromDraft`**); **`/goal`** with anything after it - an objective, **pause**, **resume**, **clear** - is the server's and goes as typed. The **`/`** menu row is the server's (**`GET /coddy/commands`**).
- **Length of a typed goal** (**`.composer-goal-validation`**, **`data-testid="composer-goal-count"`**, under the field): while the draft is a **`/goal`** that sets a goal, **`N / 4000`** counts its objective the way the server does - without the leading options, trimmed, in code points (**`goalDraftObjective`** and **`objectiveLength`** in **`chat/goal.ts`**, shared with the popover). Attached files change nothing: the server sets the goal and the files ride with its first turn. Over the limit the count takes the danger tone, the popover's length alert (**`goal.objectiveTooLong`**) stands under it, Send is disabled and Enter sends nothing, so the draft stays to be shortened.
- **A refused goal comes back**: setting a goal starts a turn, so a settings-only answer to a **`/goal`** that sets one is a refusal, and the draft returns to the composer with its files, ahead of anything typed since (**`giveBack`** in **`App.tsx`**).
- **Goal rows** (**`GoalTurnMessage`**, **`data-testid="goal-turn-row"`**): the first message of a turn the supervisor started is the instruction the model reads, and nobody typed it, so it is never a user bubble. A compact row stands in its place, on the thinking row's frame: the target and one line mirroring the server's note - *Goal set: <objective>*, *Goal resumed: <objective>*, *Goal continuation N of M: <reason>*, *Goal recovery N of M: <reason>*, *Goal budget used up, wrapping up: <reason>* - cut at two lines. When the check left items open the row says how many and folds them out (the chevron at its start, like a thinking row); a line the two lines cut at the row's width (measured, so a phone folds what a desktop shows whole) folds out whole. Live the row comes from the **`goal_turn`** frame (**`applyGoalTurnToItems`**: it takes the place of the **`/goal`** prompt this tab sent for a kickoff or a resume, since the server stores no such message, and a frame for the row already there changes nothing); after a reload from the message's **`goal_turn`** field (**`chat/transcriptFromMessages.ts`**), the instruction text never shown.
- **A goal row opens a turn and counts like one** (**`opensTurn`**): the live status line counts from it, a failed goal turn offers no retry, and the index of a later prompt counts it the way the server counts user-role messages (**`userMsgIndices`**, the rewind and the edit), as a wake does. The row itself has no edit or copy control.
- Checks: **`chat/goal.test.ts`**, **`chat/ComposerGoal.test.tsx`**, **`App.goal.test.tsx`**, **`chat/consumeComposerSse.goal.test.ts`**, **`chat/transcriptFromMessages.test.ts`**, **`messages/MessageList.test.tsx`**, **`messages/userMsgIndices.test.ts`**, **`chat/serverEvents.test.ts`**.

### Workspace picks on the plate (folder / branch / worktree)

The composer card has no chip row: before the chat starts, the folder, the branch and the worktree are **picks** on the plate over the card (**Bar over the composer**, below), built by **`Composer`** in pick mode (**`WorkspaceBar`**, **`.workspace-bar--pick`**). **`WorkspaceChips.tsx`** (helpers in **`chat/workspaceContext.ts`**) renders them inside **`.workspace-bar-picks`**; data from **`GET /coddy/workspace/context`** (session header, or **`?path=`** preview before a session exists).

- **Applied after the message is on screen** (issue #357) — the first send draws the chat with its message and the live line (**`Preparing the session…`**) first, and applies the picks after (**`applyPendingWorkspace`**, which answers why a pick did not take). A pick that does not take sends nothing into another workspace: the route leaves the new chat and the start screen comes back as it was sent from - the picks still made, the text and the files in the composer (**`startScreenRestoreRef`**, taken by the effect that sees the route go home, which then does not reset the new chat's settings) - with the reason under the composer card (**`.hero-start-notice`**, **`role="alert"`**, the danger colour), cleared by the next send. The text goes back to the start screen wherever the operator is by then: into its composer at once, or on its next opening after they went on to another chat. Whatever the send gave the session it never created goes back with it: the naming in flight is cancelled (**`TitleSuggestHandle.cancel`**: no name shown, no **`PATCH`**), its History row is dropped, and the start screen's **`@`** recents move back to **`WORKSPACE_AT_RECENTS_NO_SESSION_KEY`**. Do not keep a failed first send on its chat route: a retry from there is no first send, applies no pick, and runs in the server's default folder.
- **One line** — **`.workspace-bar-picks`** is **`display: contents`**, so the picks are the plate's own flex items: the folder and the branch shrink with an ellipsis (the branch is shown whole while the plate has room for it and cut in the middle only when it has not, **`FitMiddleText`**), the worktree checkbox keeps its size. Each pick is a button (the checkbox a label) of the plate's look with **1px 6px** padding and a **7px** radius; a lighter ground (**9%** of the text colour) marks it on hover and while its menu is open, never the accent; the plate's left padding drops to **10px** so the folder still starts on the placeholder's left edge (**16px** in from the border, the field's own padding, and the running chat's plate keeps **16px** for the same reason). No git count is shown before a session. On a phone and on any touch screen (**`(max-width: 599px), (any-hover: none) and (any-pointer: coarse)`**) the picks and the checkbox are **36px** tall with **10px** side padding and **13px** text, the checkbox **16px**: they have no ground at rest, so only the plate grows. Git's count keeps its slim framed look there - a tall framed box read as a stray square - and an invisible hit area **40px** tall (**`::after`**, **6px** wider on each side) is laid over it, so a finger lands on it.
- **Folder pick** (**`composer-workspace-chip`**) — the plate's folder outline plus workspace basename (full path in **`title`**). Click opens the **Recent** menu (**`workspace-folder-menu`**, **`mode-menu`** family): a **`Recent`** header, MRU folder rows from **`localStorage`** **`coddy_workspace_recents_v1`** (**`chat/workspaceRecents.ts`**, cap 8) with the current workspace marked by a **✓** (**`is-selected`**), a separator, and **`Open folder…`** at the bottom.
- **Open folder…** opens the project-styled **folder browser modal** (**`WorkspaceFolderModal.tsx`**, **`workspace-modal`**, centered over a dim backdrop, **`min(560px, 100vw - 48px)`** wide from the tablet tier up; a **phone** (**`max-width: 599px`**) opens it where History opens, with the box and the glass of **`.sessions.drawer`** on the stacked shell: **`position: fixed`**, **`top: calc(var(--coddy-mobile-top-inset) + 6px)`**, **10px** from the sides (**`max(10px, env(safe-area-inset-*))`**), **14px** from the bottom, the **`--coddy-glass-panel-*`** background, border, blur, radius and shadow. The inset variables are declared on **`:root`** in the stacked-shell block, not on **`.shell`**, because this dialog is portalled into **`<body>`**): editable path field, **`..`** row, subfolder rows from **`GET /coddy/workspace/folders`** (row click **navigates into** the folder; a directory **symlink** wears the folder glyph with a bent arrow cut out of its body, **`workspace-modal-symlink-icon`**, drawn with **`fill-rule: evenodd`** so no mask or **`id`** repeats per row, and names its target after the name, **`→ <target>`**), footer **New folder** and **Show hidden** on the left, **Cancel** / **Open** (picks the currently browsed folder) on the right. The head is the drawers' head (**`sessions-head`**: 12px bold capitals, as History and the Scheduler open with) and **`workspace-modal-head`** only keeps it from shrinking - it must not set a font of its own. Every control of the dialog (path field, rows, the new-folder field, buttons) carries **`font: inherit`**: inputs and buttons do not inherit the page font, and without it they were drawn in the browser's control font. The browser starts at the **parent** of the current workspace. **Escape** folds an open new-folder row first and then cancels the dialog, as **Cancel** does.
  - **Path field** (**`workspace-modal-path`**, an **`input`** on the **`.mode-menu-filter`** token recipe — never **`direction: rtl`**, which breaks the caret): **Enter** browses to the typed path. While it holds a path that has not been visited, the primary button reads **Go** and navigates; otherwise it reads **Open** and picks.
  - **New folder** (**`workspace-modal-btn--add`**, first in the footer: a **32px** square with the scheduler's plus glyph on the scheduler add button's colours - the colour rules are shared with **`.scheduler-btn-primary`**, light theme included, so the two cannot drift apart) and **Show hidden** right after it; the switch's **`margin-right: auto`** pushes the **Cancel** / **Open** pair to the right edge. New folder opens an inline name row **between the path field and the list** (**`workspace-modal-row--new`**: folder glyph, **`workspace-modal-new-name`** field on the path-field token recipe, **Create folder** and a **×**). It is a **`flex: none`** sibling of the list, deliberately **not** a row inside it: a child of the scrollport scrolls away under the operator, and on the shortest viewport the checker drives (**1024x300**, where the list has already shrunk to zero) it would be taller than the port that holds it. For the same reason it is tighter than a folder row (**`padding: 2px 8px`**) - it is chrome, and chrome is what a short dialog runs out of. The row is a form, so it does not take the row hover. **Enter** / **Create folder** posts **`POST /coddy/workspace/folders`** and the dialog adopts the answer — the listing of the **new folder** — so **Open** picks it without another step. **Escape** / **×** closes the row. Disabled on the **drive level** and while the row is open; **Create folder** is disabled on an empty name. A taken name (**409**) keeps the row and its text and reports the clash in the same inline error slot as a failed listing.
  - **Drive level** (Windows) — a drive root has no parent directory, so the server answers **`"parent": ":drives:"`** and **`?path=:drives:`** lists the volumes (**`drives: true`**, drive glyph rows, `No drives` empty state, **Open** disabled). This is the only way out of a drive in the SPA; hosts without drive letters never see the level.
  - **Height and scroll** — the dialog is a column flex box bounded by **`min-height: min(520px, 80dvh)`** and **`max-height: min(80dvh, 760px)`** (on a phone the History box sets its height instead) (each with a **`vh`** line first, for engines without **`dvh`**; Safari keeps its dynamic chrome inside **`vh`** but outside **`dvh`**). Head, path row and actions are **`flex: none`**; the folder list (**`workspace-modal-list`**) is the **only** scrollport and carries **`min-height: 0`**, so it — and nothing else — gives up height on a short window. A floor on the list instead would push the action row past **`max-height`**, where the dialog's **`overflow: hidden`** clips it beyond reach (issue #159). The list contains its own **`overscroll-behavior`**, so a wheel gesture past the last folder does not scroll the page behind the modal, and styles a thin scrollbar on the settings-list recipe.
- **Branch pick** (**`composer-branch-chip`**) — the plate's branch glyph plus the current branch; rendered **only** when **`is_git_repo`**. Click opens the branch list (**`workspace-branch-menu`**), current branch first and marked **`is-selected`**. Picking a branch calls **`POST /coddy/sessions/{id}/workspace`** with **`{"branch", "worktree": <checkbox>}`**.
  - **Refresh in the background** - each opening calls **`POST /coddy/workspace/fetch`** (**`onRefreshBranches`**, owned by **`App.tsx`**) without hiding the list: the rows the context already holds - the local branches and the remote ones as the last fetch left them - stay on screen and pickable while the fetch runs, so the menu keeps the size it opened with instead of shrinking to a placeholder and growing back. The spinner (**`workspace-branch-refreshing`**, a **12px** ring, **`role="status"`**) sits in the right padding of the filter field and takes no layout space; while there are rows it is the only mark of the refresh, and *Fetching branches from the remotes…* (**`workspace-branch-refreshing-empty`**) fills the scroll area only while there is nothing to list yet. Fresh remote rows join the list when the fetch answers; an answer from an earlier opening, or one that lands after the list closed, is dropped, and **`App.tsx`** does not apply a fetched context over a folder or a branch picked while the fetch ran.
  - **One list** — the branches only on a remote (**`remote_branches`**, named as a local branch would be) are rows of the same list as the local ones: the current branch first, then both kinds in one alphabetical order (**`branchRows`**), every row **`workspace-branch-row-<name>`** (**`.workspace-branch-item`**, a flex row with an **8px** gap, the name in **`.workspace-branch-name`** cut with an ellipsis). A remote-only row opens with a **14px** cloud (**`RemoteBranchIcon`**, **`workspace-branch-remote-icon`**, the muted colour, **`aria-label`** *On the remote only*) and its tooltip says that picking it creates the local branch tracking the remote one. While the list has any remote-only branch every row keeps the icon's **14px** slot (**`.workspace-branch-mark`**, empty on a local row), so the names stay in one column as the filter narrows it; with none, the rows are as they always were. The filter and the empty notes (*No branches*, *No branches match*) treat both kinds alike.
  - **Failed refresh** — **`workspace-branch-refresh-warning`** (**`.workspace-branch-warning`**, **`role="status"`**) between the filter and the list: an amber note in the tone of **`.context-usage-note--warn`** (**`#b45309`** on light, **`#fbbf24`** on every dark canvas, a **10%** wash of the same colour behind it, **8px** radius, **12px** text), the sentence on the first line and git's first line of the reason under it in the muted text colour, one line with an ellipsis, the whole reason in the tooltip. The rows under it are the cached ones and stay pickable.
  - **Scroll** — the folder and branch menus keep the **`mode-menu-scroll`** cap (**175px**) and, inside **`.workspace-menu`**, take the folder browser list's thin scrollbar (**`scrollbar-width: thin`**, a **6px** WebKit thumb at **20%** of the text colour, **34%** on hover, no track) and **`overscroll-behavior: contain`**: with the remote group the branch list scrolls in most repositories, and the platform's arrows read as a foreign control.
- **Worktree checkbox** (**`composer-worktree-chip`** label + real **`input[type=checkbox]`** **`composer-worktree-checkbox`**, the browser's own checkbox in the theme's accent) — the **open-branch-switches-in-a-worktree** preference, only when **`is_git_repo`**. It is one choice for every folder in this browser (cookie **`coddy_worktree`**): ticked once, it stays ticked in any folder with git, across chats and reloads. When the session already runs inside a worktree it is **checked and disabled** (state, not a choice). Branches already checked out in another worktree jump there regardless of the checkbox.
- **Chosen once** — folder, branch, and worktree are fixed at session start. As soon as the conversation has messages (**`workspaceLocked`**) the picks give way to the plate of a running chat, which names where the chat works without offering a choice (**Bar over the composer**, below); the server enforces the same rule with **409** on **`POST .../workspace`**.
- **Pre-session (draft/home)** — the start screen opens on the folder last picked in this browser (cookie **`coddy_workspace_dir`**, one per environment, written whenever a folder is picked there or from a History heading; **`chat/workspaceCookies.ts`**), else on the server's default; a folder that is gone is forgotten and the default shown. A chat left for the start screen hands it nothing of its own workspace, a linked worktree included. The branch is the one the folder is on now: the start screen reads its folder again on arrival and when the page gets the focus back, so a **`git switch`** in a terminal shows; a branch picked there is that new chat's choice. Choices are kept client-side (**pending**) and previewed via **`GET /coddy/workspace/context?path=`**; the first send applies them to the fresh session id (**`POST .../workspace`**, whose answer becomes the chips' context) before **`POST /v1/responses`**. Navigating to another session drops pending choices.
- **What a new chat lists follows its folder** — the picked folder is the scope of everything the composer lists while you type: the **`/`** menu, **`@`** (files, rules, **`@agent:`** subagents), the mention highlight and the file a line range previews all carry **`cwd=<folder>`** next to the session header (**`chat/workspaceScope.ts`**). The known skill names that chip a **`/name`** in the composer and the transcript belong to the chat's folder and session: another pick or another session drops them at once and asks again, a late answer is discarded, and the first send of a new chat keeps them because its folder does not change.
- Menus follow the **`Mode`**/**`Model`** conventions: anchored to the pick, **`mode-menu--portal`** (**`opens-down`** on the start screen, **`opens-up`** when docked) on desktop, full-width bottom sheet (**`mode-menu--sheet`**) on narrow shells.

### Native image generation

A logical model with `models[].image_generation: true` exposes the **Images** chip (`composer-imagegen`) after the toolset chip. It starts off and stays in its selected state for later sends; an enabled send carries `metadata.image_generation`. A selected logical model without the flag shows a CTA (`composer-imagegen-cta`, accent text) in the same slot instead; it opens the model's row in Settings → Logical models, and after a save the toggle takes its place. This capability is independent of `multimodal` image input. The chat path accepts `openai` API-key and `codex` providers with an explicitly enabled model and a compatible provider. Codex is tested against a fake backend; live account entitlement is unverified. Direct model requests are refused. Generated images belong to the assistant message and are saved as session assets, so the answer can show them live and after reload. They are not automatically included as visual context in later prompts; to request an edit, download and reattach the image as input with a multimodal model. See `docs/surfaces/web-ui.md` for the operator workflow.

### Composer attachments (multimodal ingress)

Attachments row (**`.composer-attachments`**) renders **inside** **`.composer-card`**, below workspace chips and above the field. All ingress paths are gated on the selected model's **`multimodal`** flag (paperclip picker, clipboard paste in **`textarea#composer`**, drag & drop onto **`.composer-card`**). Functional contract and regression table: **`docs/surfaces/web-ui.md`** (**Composer file attachments (multimodal)**).

- Chips (**`.composer-attachment-chip`**, 140px, 10px radius) show the file icon plus name. Locked edit-mode chips stay icon-only (metadata has no bytes).
- An `image/*` attachment is a **preview card**, not a chip: **`.composer-attachment-card`**, **128×96**, 12px radius, the picture filling it (**`.composer-attachment-thumb`**, `object-fit: cover`, local object URL revoked on remove/unmount). Hover and **`:focus-within`** lift the border and the surface on the repo's `color-mix(in srgb, var(--text) N%, var(--coddy-blend-base))` recipe; the picture's cursor is **`zoom-in`** and a click opens it in **`ImageLightbox`**. The **remove** control (**`.composer-attachment-chip-remove`**, 20px round) sits at the card's top-right, over the picture: **`opacity: 0`** until hover - never `display: none`, so it keeps its place in the tab order - and **`opacity: 1`** on **`:focus-visible`**. A disabled card (non-multimodal model) greys and desaturates the picture instead of the icon.
- The **sent user bubble** echoes image attachments with the same card (**`.msg-user-file-card`**, **128×96**), filled first by an **optimistic `previewUrl` blob** created at send time (`optimisticUserFiles.ts`). Once the server snapshot includes **`files[].preview_url`**, that durable session thumbnail replaces the blob and the blob URL is revoked, one picture at a time: a server file with nothing to show yet keeps the picture the row has; reloads keep the image preview. A message the agent read from the queue has no blob of its own: its row opens the picture from **`files[].url`**, built from the **`<coddy_session_assets>`** note of the **`user_message`** frame, whose assets are saved before the frame goes out (`queuedUserMessage.ts`), so it is a picture at once and never a bare icon until the turn ends. The card opens **`files[].url`** - the original bytes, **`GET /coddy/sessions/{id}/assets/{name}`** - and falls back to **`preview_url`** for a message sent before that field existed, rather than losing the click.
- **The picture menu** (**`ui/components/ImageMenu.tsx`**, **`ImageMenuHost`** mounted once in **`main.tsx`**): a right click on a picture of the app - a file in the Files window, an attachment or a tool's picture in the chat, a diagram, the documentation, the image viewer - or a long press on a touch screen opens a small menu at the pointer with **Copy image** and **Save image** (the **`mode-menu`** family, portalled, **`z-index: 900`**, over the viewer's **400** and under the settings field tips' **1000**, flipped left or up at an edge). One listener on the document serves every picture: only the app's own (a **`blob:`** or **`data:`** address, or the page's origin) take it, a picture from another site and anything under **`[data-native-image-menu]`** keep the browser's menu, and a right click something else already answered (a shared file's card opens its own menu) is left to it. **Copy** writes a PNG (a PNG as it is, any other picture drawn onto a canvas first), handing **`ClipboardItem`** a promise so the write starts inside the click as Safari requires, and is offered only where the clipboard takes pictures; **Save** downloads the bytes under **`data-image-name`** (the Files window sets the file's name), else the alt text when it reads as a file name, else **image**, with the extension of the type. A press beside it, a scroll, a resize, the page losing focus or **Escape** close it; its Escape is heard on the window in the capture phase, so it closes the menu and not the viewer under it. The outcome shows for a moment at the pointer (**`.image-menu-notice`**, **`role="status"`**).
- **`ImageLightbox`** (**`ui/components/ImageLightbox.tsx`**) is the SPA's one image viewer: the documentation reader, the composer cards and the sent bubble's all open it. Fitted to the window first, then zoom levels 1 / 1.5 / 2 / 3 with the buttons, **+ / - / 0**, or a click; the **wheel** over the picture and a **pinch** of two fingers zoom between the fitted size and 3 as a factor of its own, off the ladder, and the buttons then take the next level above or below it. A zoomed picture is **dragged** with the pointer (mouse, pen or one finger), cursor **`grab`** / **`grabbing`**, and a press that travelled more than **`DRAG_SLOP_PX`** (4px) swallows the click it ends with, so a drag never also toggles the zoom. **Esc**, the close control or a click beside the image closes it; portal into `document.body`. Its **`.docs-lightbox*`** class names are older than that shared role and stay as they are.
- Pasted clipboard images get deterministic names **`pasted-<n>.<ext>`** (browsers hand every clipboard image over as `image.png`).
- **Every attachment is copied into memory as it is attached** (**`attachFiles`**, **`chat/attachmentCopy.ts`**). The **`File`** a drop, a paste or the picker hands over can be only a path on disk, and a screenshot tool deletes its temporary file at the next capture (Spectacle keeps one per folder): the earlier picture then fails to show and **`FileReader`** refuses it at send, so one stale file held the whole message back. The card appears at once and in order, and the copy takes the original's place when it is read; a file removed or sent by then is left alone, and one that cannot be read is taken off with a hint naming it. jsdom has no such files: **`npm run check:attachments`** (**`scripts/attachments-check.mjs`**) drives real files on disk in a browser and follows them to the model byte for byte.
- **Picture markup** (**`ui/markup/ImageMarkupDialog.tsx`**, model in **`markupModel.ts`**, drawing in **`markupCanvas.ts`**): one picture pasted into the field opens in the markup editor before it is attached, as **ctrl+v** in the console opens the X window of **`external/cli/markup`**; the two editors share the tools, the palette, the line and label sizes and the meaning of the buttons. The editor is a full-window layer (**`.markup-dialog`**, portal into `document.body`, **`z-index: 400`** like the viewer, the viewer's frosted ground) with the picture fitted into **`.markup-stage`** and never enlarged, and the toolbar along the bottom (**`.markup-bar`**): **Cancel** on the left (a text button), the tools and the palette in one rounded group in the middle (**`.markup-tools`**: pencil, ellipse, rectangle, arrow, text, a separator, crop, rotate a quarter turn clockwise, undo, a separator, seven swatches - red, orange, yellow, green, blue, white, black), **Done** on the right (accent ground). The chosen tool is a lighter ground (**`.markup-tool.is-active`**), never the accent; the chosen swatch a ring in the text colour. A label is typed into a field over the picture (**`.markup-label-input`**, dashed accent outline, the label's font and colour); the press that opens it is cancelled so the browser does not hand the focus to the dialog and close the field. Done renders the history onto a canvas and hands back a PNG named after the original; Cancel and **Escape** hand back nothing. A pasted picture is attached only on Done; an attached one opens from the pencil in the card's top-left corner (**`.composer-attachment-card-markup`**, the remove control's twin: **`opacity: 0`** until hover or **`:focus-visible`**), and Done replaces it in place. A browser that cannot draw (no **`CanvasRenderingContext2D`**, asked through **`markupSupport.ts`** without loading the editor) attaches a pasted picture at once and shows no pencil. The editor is a lazy chunk (**`React.lazy`** in **`Composer.tsx`**), fetched before a picture first opens (**`openMarkup`**), so the canvas code stays out of **`app.js`** and its budget, and a chunk that cannot be fetched attaches a pasted picture as it is instead of failing a render. A press on a control of the toolbar keeps the focus on the editor (**`mousedown`** cancelled), so Enter after it is still Done; Enter on a control focused from the keyboard is that control's press, Tab is wrapped inside the editor, and the shortcuts read **`KeyboardEvent.code`**, so they hold in any layout. A shape is drawn onto the current raster; undo, a crop and a turn replay the history onto a fresh canvas and release the old one (**`releaseCanvas`**: zero size), since Safari caps the memory of a page's canvases together. Cancel, Escape or leaving the screen while the PNG is encoded hands nothing back. On a phone the actions stand over the group, which scrolls sideways.
- Paste/drop against a non-multimodal model attaches nothing and flashes the inline notice **`.composer-attach-hint`** (**`role="status"`**, auto-clears) below the attachments row.
- Switching to a non-multimodal model does not discard existing files: chips use **`.composer-attachment-chip--disabled`** (muted, grayscale, dashed border), attachment-only Send is disabled, and text sends omit while retaining them for a later multimodal selection.
- The server repeats this capability check against the effective YAML model and drops any client-supplied **`inline_files`** when **`multimodal`** is false, so disabled files cannot reach the provider or session assets through a stale/custom client.
- While files are dragged over the card it carries **`.composer-card--dragover`** (inset ring accent) as the drop-target affordance.
- **Attachment-only send** is valid: an attachment alone unlocks **Send** (see **Composer primary action**).

### Composer context meter

Ring to the **left** of **Send** in **`Composer.tsx`**. Implemented by **`ContextUsageRing`**: inner stroke always visible; outer progress arc only when usage **> 0**, flat color (no gradient or shadow), fill from **12 o'clock** clockwise. Colors use **`--coddy-context-ring-inner`** and **`--coddy-context-ring-fg`** (the theme files under **`styles/themes/`**). Dark outer arc **`#f5f3ff`** (logo stroke); light outer arc **`var(--accent)`**.

- Do **not** put a percent label **on** the ring. Percentages and counters belong **only** in the tooltip (**`rail-tip`** family), above the ring, centered, wide enough via **`composer-context-tip`** CSS.
- **The tooltip is one line**: how much of the window is used and the two numbers that say it, **`20.1% · 201k / 1M`** (**`composer.contextTipShort`**, the counts through **`formatTurnTokens`**, so they shorten past a thousand and never round up). Everything else - input, output, the breakdown by category, the compaction threshold - is in the popover the ring opens, and the five lines the tip used to be repeated it badly.
- **It draws no shadow** (**`box-shadow: none`**). The tip stands **12px** above the ring it belongs to, and a shadow of the rail's shape reaches past that gap: the downward one - 10px down over 28px of blur - washed grey over the ring and the bar under it, and cast upward it still spilled under its own bottom edge. The opaque plate and its border are what tell it from the transcript (**`tooltipTouchCss.test.ts`**).
- Idle home (**`contextIdle`**): inner ring only (no outer arc); tooltip **`Context is empty`** / **`Контекст пуст`** alone (no **`Model …`** line and no window: there is nothing to measure yet).
- Active session: arc fills from stats; live **`usage_update`** SSE replaces both the current total (`used`) and the session's context window (`size`) immediately and refreshes detailed stats, so manual and automatic compaction reduce the displayed window without a reload. The live size overrides the initial model listing, including when a provider listing arrives late, survives stats refreshes, and is scoped to the session, selected model and configuration version. The tooltip takes its used count from the context breakdown, or estimates it from an explicitly supplied percentage; without either it says **Context usage unavailable · max 128k** rather than substituting the session's cumulative usage. It **never** has a **`Model …`** line that duplicates **Mode** (the mode dropdown).
- **Click** (or **Enter** / **Space** when focused) on **`.composer-context-tip-host`** opens **`ContextBreakdownPopover`** (**`data-testid="context-breakdown-popover"`**). Its head is the drawers' head (**`.sessions-head`**: 12px bold capitals, like **Settings** and **History**). Right over the stacked bar stands one row: the percent used at the left and the tokens at the right (**`540.6k / 1M`**, shortened and never rounded up, the exact numbers in its tooltip). Under the bar the legend (**System prompt**, **Tool definitions**, **Rules**, **Skills**, **MCP**, **Conversation**), and at the foot, over a divider, when compaction starts by itself and how to start it now: **`Auto-compact at 80% · 104.8k`** (the percent of the model's window and what it comes to) or **`Auto-compact is off`**, and the **Compact now** button. Everything keeps one left and one right edge, **12px** in from the panel's, and the two dividers span the panel (**`contextBreakdownPopoverCss.test.ts`**). **Escape** or **Close** dismisses; hover tooltip returns when closed. Data from **`GET /coddy/sessions/{id}/stats`** field **`contextBreakdown`** (estimated tokens per category).

See the paired UI rule ([Cursor](../../.cursor/rules/ui-spa.mdc), [Claude Code](../../.claude/rules/ui-spa.md)) for the full wording.

- **Banner** (`UsageBanner.tsx`, **`.usage-banner`**,

  .composer-wrap`**), which is also what **`blockEdgePaddingTop`** already

- **The banner's plate is opaque.** It stands in **`.chat-bottom`**, over the
  transcript that scrolls under the docked composer, and a translucent tint

  **`#ef4444`** for **error**; **`--bg`** is a solid colour in all eight

  text is **`var(--text)`** and the **×** hover plate the **6%** text wash:
  the **`--fg`** and **`--border`** the rules used to name exist in no theme.
- **The transcript makes room for it.** The usage read answers after the
  transcript is on screen, so the banner rises into the block over a
  transcript already parked at its newest message. The reserve under the
  transcript (**`--chat-composer-reserve`**, **`chat/composerReserve.ts`**)
  puts the newest row of a parked transcript above the block's first visible
  edge - its card, or the banner over it: the block's height less its empty
  padding over that edge (none while the banner is that edge,
  **`blockEdgePaddingTop`**), plus two row gaps (**10px** each, **12px** on

  above the block's bottom the scroll content ends (on the stacked shell the

  reader who scrolled away keeps their place. Without it the opaque plate
  would cover the last lines of the answer.
- Data flow (`useProviderUsage.ts`): REST `GET /coddy/providers/{name}/usage`
  at session open and model change (a cache read on the server), a refresh
  after every finished turn of the viewed session, one hub read after a
  window's reset, one cache read when the server deferred a refresh
  (`refreshPending`/`refreshInSec`), one follow-up when a passed reset still
  shows; `provider_usage` frames on `GET /coddy/events` replace the snapshot
  between turns, and the same frame on the turn stream carries the
  auto-resume countdown. Nothing polls otherwise. Snapshots order by the
  server's `fetchedAt`: a REST answer issued before a pushed frame, or a
  frame that crossed a later read, never brings older numbers back, and
  only the latest read issued applies. A row that answered "unsupported" is
  left alone for five minutes. The snapshot is account-wide; the model's
  selector suffix is compared with `unlimitedModels` client-side, and with
  `blockedModels` the same way: a model the account may not call right now
  reads as blocked even while the account itself is healthy.

### Transcript scroll-to-bottom button

- **Placement** - `button.chat-scroll-bottom` (`data-testid="chat-scroll-bottom"`) is a child of **`.chat-bottom-inner`**, positioned **`absolute`** with **`right: 0`** and **`bottom: 100%`** plus a **`10px`** margin. It is anchored to the composer's column, **not** to the viewport, so one rule carries it through the absolute desktop dock, the **`position: fixed`** composer below **`1200px`** and the **`padding-right`** the background tasks panel adds. Its right edge is flush with **`.composer-card`** where there is no composer (a read-only transcript); under a composer it stands one slot over the expand control and on the same line (**Composer field height and expand**). Do **not** re-anchor it to `.chat-stack`, `.chat-scroll` or the viewport.
- **The button** is a **34x34px** circle (**`border-radius: 50%`**) on the shared glass tokens (**`--coddy-glass-panel-bg`** / **`-border`** / **`-backdrop`**), so all eight themes carry it without a per-theme rule. Its glyph is a **16px** stroked down arrow in **`currentColor`**. Its shadow is its **own, small** one (**`0 3px 10px`** plus **`0 1px 2px`**, lighter under **`[data-theme="light"]`**) and **not** **`--coddy-glass-panel-shadow`**, whose **`0 14px 44px`** cast is drawn for a composer-sized card and reads as a smudge under a circle this size.
- **When it shows** - only while the transcript has stopped following the newest output, which is the same band that drives stick-to-bottom: **`TRANSCRIPT_BOTTOM_THRESHOLD_PX`** (**80px**) in **`chat/transcriptScrollPosition.ts`**. Keep both readings on that one module; the distance was previously inlined twice in **`ChatScreen`**, once per scroll surface, and drifting copies would let the button contradict the follow behaviour. The empty hero renders no button at all.
- **Both states live on one mounted node.** While a chat is open the button stays in the DOM and **`is-visible`** carries **`opacity`**, **`transform`** and **`pointer-events`** - an unmounted node cannot animate its way out, and the reader should see it leave as well as arrive. It enters over **`0.14s`** ease-out with a **`0.2s`** **`cubic-bezier(0.2, 0.9, 0.3, 1)`** on the transform and leaves over **`0.12s`** ease-in. Hidden, it is **`inert`**, **`aria-hidden`** and **`tabIndex=-1`**, and a click blurs it before it goes, so focus is never left on a hidden control.
- **The jump is animated**, in **`requestAnimationFrame`** rather than **`scrollTo({ behavior: "smooth" })`**, so the curve is this repository's decision and not the engine's: **`transcriptJumpDurationMs`** (**220-460ms**, by distance) and **`easeTranscriptJump`** (ease-out cubic - leaves at speed, settles into the last pixels). Two rules keep it honest. The end is **re-read every frame**, so a turn still streaming does not leave the travel short of the newest message. And **`syncTranscriptPosition`** stands back while a frame is pending, because reading the position mid-flight would put the button back on screen for every frame above the band - the reason the first draft of this control jumped instantly instead.
- **The reader always wins**: a **`wheel`**, **`touchstart`** or **`mousedown`** cancels the travel where it stands and re-reads the position immediately, so the button comes back if they stopped short.
- **A parked transcript stays parked while it grows by itself.** The transcript changes its height without a new item: the todo checklist comes in, folds and leaves by its height, the live line comes and goes. A **`ResizeObserver`** on **`.messages-inner`** follows every such change to the end while the reader is at the newest message (**`followTranscriptEnd`**), and leaves a reader who scrolled away where they are. A resize within **500ms** of the reader's own click or key inside the transcript is theirs - a row they opened - and is not followed: the position is read again, so the button shows that the end moved away (the checklist's head is the exception, since its list belongs at the end). A follow's own scroll event is read a frame later, when the transcript may have grown again: a position still where the last follow put it is content growing under a parked reader, not the reader leaving the end, so stick-to-bottom holds and the next follow takes it there; any other position drops that mark. The follow used to run on new items only, and the checklist growing after it left the last line under the composer and the reader no longer at the end.
- **It only ever goes down.** A measured end at or above where the page already is means the reader is at the newest message: the jump writes nothing and re-reads the position, and a frame never turns back up past where the travel started. The end used to be **`scrollHeight - innerHeight`** on the stacked shell, and an on-screen keyboard that overlays the page (iOS Safari ignores **`interactive-widget=resizes-content`**) leaves **`innerHeight`** alone while the page scrolls on past that end: the button sent the reader up by the keyboard's height.
- **Measured against what the reader sees.** On the stacked shell the distance and the end come from the **visual viewport** (**`visualViewport.height`** and **`offsetTop`**, **`innerHeight`** without the API), so a keyboard that shrinks it counts. The docked block itself, fixed to the layout viewport's bottom, rose under that keyboard with the button on it: it sits on **`bottom: var(--coddy-keyboard-inset, 0px)`**, which **`ChatScreen`** sets on the root from **`keyboardInset`** (**`innerHeight - visualViewport.height - offsetTop`**, zero during a pinch zoom) on every **`resize`** and **`scroll`** of the visual viewport. Where the keyboard resizes the page (Chrome with **`resizes-content`**) the inset is zero and nothing moves.
- **`prefers-reduced-motion: reduce`** writes the end position in one step and drops both button transitions.
- **Copy** - accessible name and tooltip are both **`chat.scrollToBottom`**.
- **A conversation opens on its newest message.** When the session id changes, **`ChatScreen`** cancels a jump in the air, re-arms stick-to-bottom and hides the button in a layout effect that runs before the follow, so the new rows land on their end. Without it a reader who had scrolled up in one chat opened the next at the old offset, the button showing, on both scroll surfaces (issue #342).

### Quote from the transcript

A text selection inside **`.messages-inner`** offers itself as a quote for the next message (issue #342, **`chat/TranscriptQuoteButton.tsx`**).

- **The button** - **`button.transcript-quote-btn`** (**`data-testid="transcript-quote"`**), portalled to **`<body>`** and **`position: fixed`** by the selection's box: a **32px** pill on the scroll-to-bottom button's glass (**`--coddy-glass-panel-*`**, its small shadow, lighter in the light theme), a **14px** quote mark and **`chat.quoteSelection`** in **13px** type, **`chat.quoteSelectionTitle`** as its title. It appears once the selection rests (**120ms** after the last **`selectionchange`**) and follows it on scroll and resize, and, while it is out, on a change of size of the transcript column or the docked block (**`watch`**, a **`ResizeObserver`**): a stream growing the transcript, a draft cleared or the composer expanded move the selection or the band without a scroll event, and the button used to stay where the selection had been.
- **Placement** - centred on the selection, **10px** away from it: **above** with a pointer, **below** on a **`touchOnly`** device, whose own selection menu takes the space above; the other side when the preferred one does not fit, and the foot of the band when neither does. The band is the chat header's bottom to the docked block's top, so the button never covers either; a selection out of that band offers nothing.
- **What it takes** - only a selection whose common ancestor is inside **`.messages-inner`**: the chat's title, the composer and the rest of the page offer nothing, and so does a chat with no composer (a read-only subagent transcript, an archived chat). A mouse's **`pointerdown`** on the button is **`preventDefault`**-ed so the selection and the caret stay; a finger's is **not**, because WebKit sends no click after a touch whose **`pointerdown`** was cancelled (a tap on Quote did nothing on an iPhone that way), and the text quoted is the one read when the button appeared, since a touch browser may take the selection down under the finger. **`npm run check:long-prompts`** taps it in WebKit.
- **The quote** - **`quoteMarkdown`** (**`chat/quoteDraft.ts`**, shared with the documentation reader's **Ask about the selection**) turns the passage into **`> `** lines, a bare **`>`** for a blank line, runs of blank lines collapsed; **`appendQuoteToDraft`** puts it after the draft with a blank line on both sides and an empty line under it. The draft stays the only record: nothing beside the text holds quotes. **`ChatScreen`** bumps the composer's **`caretToEndEpoch`**, which puts the caret at the end and, through **`composerAutoFocusAllowed`**, the focus in the field.
- **In the bubble** - **`splitQuoteBlocks`** cuts a sent prompt into quote and text blocks for **`UserMessage`**: **`blockquote.msg-user-quote`** (**`data-testid="user-message-quote"`**) has a **2px** bar in a **26%** text tint, **10px** of left padding and **72%** text; **8px** separate adjacent blocks; the blank lines that only separated a quote from its neighbours are dropped. Only a marker followed by a space, or alone on its line, opens a quote. Skill chips and mentions render inside both kinds of block; copy and the edit control still use the raw prompt.

### Transcript window

A long conversation keeps a bounded slice of its rows in the DOM and holds only the end of its history until the reader scrolls up (issue #338; behaviour and the numbers: **`docs/surfaces/web-ui.md`**, **Long sessions**).

- **Rows are found by id.** Every row root carries **`data-row-id`** with its transcript item id (**`rowId`** prop on the row components, set by **`MessageList`**); the window measures and anchors by it. A new kind of row does the same, and it must be a **direct child** of **`.messages-inner`**: no wrapper, or the window cannot see it.
- **The window** lives in **`chat/TranscriptList.tsx`** (**`useTranscriptWindow`**, pure arithmetic in **`chat/transcriptRenderWindow.ts`**): it opens on the last **8** rows, grows by **4** per frame toward the edge within a screen of the view, and past **120** (plus **8** of slack) drops rows more than a screen out of view on the far side. A row the reader is typing in (a focused text field) is never dropped; a focused button is no reason to keep a row. While a permission or question prompt of the turn in flight waits for its answer - in the transcript, or a background subagent's card after it - the bottom is never dropped (a prompt an older turn left unresolved holds nothing), so the prompt keeps its choices and typed text however far up the reader goes. Its state stays in that component, so a frame that adds rows does not re-render the chat screen or the composer. Do not grow in bigger chunks: a chunk is one frame of layout on a slow phone.
- **Nothing moves under the reader.** A change above the visible area is measured and committed in one task (**`flushSync`**), then the first visible row is put back where it stood - or, for a reader following the newest message, the end is. The correction is the window's own, not the engine's scroll anchoring, which WebKit lacks. The transcript still carries no **`content-visibility`** (see **Multi-session streaming and Stop**).
- **The control above the rows** - **`div.transcript-earlier`** (**`data-testid="transcript-earlier"`**, **`data-state`** **`idle`** / **`loading`** / **`error`**) is the first child of **`.messages-inner`** whenever anything is above the window, and the sentinel the window watches. It is a centred line of **12px** text in a **48%** text tint, **32px** tall: **`chat.transcriptEarlier.show`** as a pill button (**`.transcript-earlier-button`**: a **10%** tint border, a **4%** tint fill on the glass panel colour, **999px** radius, **5px 14px** padding, **7%** fill and **78%** text on hover, the accent focus ring); **`chat.transcriptEarlier.loading`** as a **`role="status"`** line; **`chat.transcriptEarlier.failed`** as a **`role="alert"`** line followed by the **`chat.transcriptEarlier.retry`** pill. Scrolling to it does what the button does.
- **The lower edge** of a window cut short of the newest rows is **`div.transcript-window-edge`**: **1px** tall with a negative top margin of the column's gap (**`--coddy-transcript-row-gap`**, which **`.messages-inner`** sets to **10px**, and to the phone's stack gap on the stacked shell), so the rows above end where they would. While the window is cut short, the live line, the tasks line and the subagent permission cards - which belong under the newest row - are not rendered.

### Composer field height and expand

The field follows its text (issue #342): **`chat/useComposerFieldHeight.ts`** sets its height from **`chat/composerHeight.ts`** on every change of the draft, a change of the field's width, a window resize and a visual viewport resize. The floor is read off the field (its inline height dropped for a moment, so **`rows`** and the **76px** CSS minimum decide), the text's height is **`scrollHeight`** at that size, and the ceiling is **eight lines** or **40%** of the visible viewport, whichever is less, never under the floor. The stylesheet carries **no `max-height`** on **`textarea#composer`**: a cap there would cut the expanded field short. A field that is not laid out keeps the height it had. The hook runs before the mirror's effects, so the mirror reads the new height in the same frame (see **Composer mirror and caret sync**).

- **Expand** - **`button.chat-expand-composer`** (**`data-testid="composer-expand"`**, **`chat/ComposerExpandButton.tsx`**) is the scroll-to-bottom circle's twin: **34x34px**, the same glass, border and small shadow, **10px** over the composer's first block (**`.chat-bottom-inner`**, **`bottom: 100%`**, the margin **`calc(10px - var(--coddy-composer-wrap-pad))`**, since the wrap's top padding is not the composer) and centred on the improve-prompt wand's vertical line (**`right: 8px`**: the wand's centre is 25px from the card's outer edge, 12px, half of 24px and the 1px border), rendered by **`ChatScreen`**, which owns the state. It **never moves**; the jump to the newest message stands one slot **above** it, 10px apart and on the same line (**`.chat-bottom-inner:has(> .chat-expand-composer) > .chat-scroll-bottom`**: **`right: 8px`**, **`calc(54px - var(--coddy-composer-wrap-pad))`**), so the arrow down is the upper of the two. A usage banner over the composer is the block's top, and the two keep their 10px over it. The transcript offers no jump up. The glyph tells the two apart: two arrows spreading to the corners to expand, coming back together to fold, never a chevron or an arrow pointing up or down, which read as another scroll control when the first version stood in the field's corner. Pressed it carries **`aria-pressed`**, the text colour and the label **`composer.collapse`** (else **`composer.expand`**); it keeps the caret in the field (**`preventDefault`** on **`mousedown`**), so a phone keeps its keyboard. Do not put it back into the field or onto the card's edge.
- **Expanded height** - the room from the top of the docked block (measured with the field at its floor, so a usage banner and the queue count) up to the line under the chat header, less the strip the control stands in: one step of the top rhythm (**`--coddy-top-rhythm`**: **10px** on the stacked shell, **14px** on a desktop), the control's **34px**, one step again. Expanded, the composer wrap drops its top padding (**`.composer-wrap--expanded`**) and the control stands **`--coddy-top-rhythm`** over the card, so header, control and card stand one step apart, the step from the window's edge to the top bar. The jump to the newest message is hidden while expanded. Never less than the floor; a longer text scrolls inside it. **`ChatScreen`** hands that room to the docked composer as **`expandRoomPx`**; the start screen gets none and draws no control. The hook also watches the docked block's own height and fits the field again on every change of it, so a banner, an attachment or an error rising into the block takes its height from the field instead of pushing the block over the header - whether the field is expanded or grew by itself. A fit caused by the field's own growth lands on the same height (the room is measured with the field at its floor), so the observer settles after one extra fit.
- **On-screen keyboard** - the line under the header is the header's bottom or the top of the visible area (**`visualViewport.offsetTop`**), whichever is lower: where the keyboard overlays the page (iOS Safari) and the page was pushed up under it, the expanded composer keeps to what can be seen, between that line and the keyboard, where the chat screen lifts the docked block. Where the keyboard resizes the page (Android with **`interactive-widget=resizes-content`**) the window is simply shorter. Viewport changes fit the field a frame later, once the block stands where it will stay. With less room than the field's floor (a small phone held sideways, keyboard open) the field stays at its floor.
- **Pickers in an expanded field** - the skills, mention, line-range and command option pickers open **inside** the field, at its foot over the composer's bar, instead of above the card, where they rode over the top bar: the sheet's bottom is the bar's top (**`measureSheetBottom`**), the desktop portal's the field's foot, and their height is the field's (**`--slash-sheet-room`**, **`maxH`**).
- **Folding** - the control, an unclaimed **Escape** in the field (before Escape leaves an edit), a send, a queued message and another session id. Nothing is persisted: every chat opens folded.

### Composer primary action (**Send** **/** **Stop**)

- Control **`#btn-send`** (**`.composer-icon`**) sits **directly right** of the context ring (**`.composer-context-tip-host`**), **10px** apart (**`.composer-bar-actions`**) and **20px** wherever the pointer is coarse (**`max-width: 599px`** or **`(any-hover: none) and (any-pointer: coarse)`**): a finger is wider than a cursor and this control stops the turn, so 10px put a miss away from stopping a turn somebody only meant to read the context of.
- **Circular button** (**not** pill or squircle): fixed equal **width** and **height**, **`border-radius: 50%`**, **`box-sizing: border-box`**. Intended diameter **42px** in production CSS (**may track token scale**, but stays a **circle**).
- **Glyphs** live in **`composer-send-glyph`**. **Play** state is an **SVG triangle**, **17×17px**, its path set right of centre for optical balance (a text **▶** sat wherever the platform's font put it); **stop** uses **`.composer-stop-square`** (**14×14px** filled block, centered in the circle by **`.composer-run-icon--stop .composer-send-glyph`**, which fills the button and zeroes **`font-size`** and **`line-height`** so no text baseline is left to push the square off centre; the composer, the background task cards and the scheduler's job rows share that one rule). **Every stop glyph is that drawn square, never a text character**: the same rule zeroes the font, so a **`■`** written into the wrapper renders nothing - which is how a running scheduler job came to show an empty red circle. Ring + stop stay **right-aligned** in **`composer-bar-actions`** (same row as mode tabs). Keep contrast high (**`composer-send-play`** vs **`composer-send-stop`**).
- **Focus.** The app puts the caret in the composer by itself on the start screen, on switching to a conversation and on closing History, except on a **touch-only** device (**`(any-hover: none) and (any-pointer: coarse)`**: phones and tablets without a pointer), where a focused field opens the on-screen keyboard over half of the screen; there the keyboard waits for a tap on the field (**`chat/composerFocus.ts`**, **`composerAutoFocusAllowed`**). Like Enter below, this follows the input device, not the width: a narrow desktop window keeps the focus.
- **Keyboard.** Enter sends (or queues while a turn runs) wherever a keyboard is attached, a narrow desktop window included; **Shift+Enter** is the browser's newline and **Ctrl+Enter** / **Alt+Enter** put a newline at the caret. On a **touch-only** device (**`(any-hover: none) and (any-pointer: coarse)`**) Return stays a newline and this button sends, since a phone keyboard has no Shift+Enter; **`enterkeyhint`** is **`send`**, or **`enter`** there. Enter that confirms an input-method candidate never sends. Rule: **`chat/composerEnter.ts`**.
- Idle **disabled** when the message field is empty **and no sendable files are attached** (a disabled attachment under a non-multimodal model does not unlock Send); an active session turn shows **Stop** with an empty draft and **Queue** with text or sendable files, whether or not this tab has a stream reader (see **`docs/surfaces/web-ui.md`**, section **Composer primary action**).

### Composer message queue

A turn in flight no longer locks the composer. Enter queues in the saved `agent.queue_mode`, Tab in the other mode; the first use asks for the Enter preference. Each waiting card shows whether it steers the current turn or starts after it, and a click changes the mode. Text and attached images travel together. Behaviour and the wire contract: **`docs/features/message-queue.md`**, functional checklist: **`docs/surfaces/web-ui.md`** (**Composer message queue**).

- **Placement** — the queue is a **`ul.composer-queue`** (**`data-testid="composer-queue"`**) inside **`composer-wrap`**, directly **above** **`.composer-card`** and below the transcript. It renders only when something is waiting; an empty queue draws nothing at all (no header, no placeholder).
- **One gap for the whole stack** — **`--coddy-composer-stack-gap`** (**`4px`**) is the distance between two queued rows *and* between the lowest block standing over the composer card and the card itself, whichever block that is: a queued message, the first-use question (**`.composer-queue-choice`**), the edit banner (**`.composer-edit-banner`**) or the usage notice (**`.usage-banner`**). While the rows stood **`4px`** apart and the last of them **`6px`** over the card, the stack read as crooked right where it meets the composer. Held by **`composerQueueCss.test.ts`**.
- **A card** — **`li.composer-queue-item`** (**`data-testid="composer-queue-item"`**) is cut from the **frosted glass panel** the composer card is cut from (**`--coddy-glass-panel-bg`**, **`--coddy-glass-panel-backdrop`**, its border and shadow), **`12px`** radius, **`6px 12px`** padding, **12px** type at **1.45** line height in a **78%** text tint. The **12px** on the right is the improve-prompt wand's inset in the field's corner, so the card's **×** stands on the vertical line of the wand of the card below - the same 24px control at the same inset from the same edge (pinned by **`composerQueueCss.test.ts`**). It used to be a 6% wash of the text colour, nearly transparent over a dark transcript, so the words scrolling under the queue read through it. The rows stack in **reading order** with the stack's gap between them: the top card is the one the agent reads first.
- **The text** clamps to **3 lines** (**`-webkit-line-clamp`**) and wraps on anything (**`overflow-wrap: anywhere`**), so a pasted path cannot widen the composer.
- **The cross** — **`button.sessions-close.composer-queue-remove`** (**`data-testid="composer-queue-remove-<id>"`**, accessible name **`Remove from the queue`**) is **the app's close control** (see **Close control** below) at **24×24px** with an **8px** radius and a **15px** **×**, in the card's **top-right corner** (**`align-self: flex-start`**). The text carries **3px** of top padding, which centres its first line on the 24px control: a one-line message sits level with its **×** at a **38px** card, a longer one hangs from the same line. Besides it the card holds one more control, the mode; the text itself is not clickable.
- **The mode** — **`button.composer-queue-mode`** (**`data-testid="composer-queue-mode-<id>"`**) names the message's mode, **Steer** or **After turn**, in the frame the first-use buttons share (the glass panel's border and fill, **8px** radius, **3px 8px** padding), and its title says what a click does; a click switches the mode through **`PATCH /coddy/sessions/{id}/queue/{message_id}`**.
- **The images** — a message with images shows **`span.composer-queue-files`** (**`data-testid="composer-queue-files-<id>"`**) before the mode: the paperclip (**`PaperclipIcon`**, the glyph of the composer's attach button, **12px**) and the count in the muted tint, labelled **N images attached**. Never a thumbnail and never an emoji: the queue names its images and never carries their bytes.
- **The first-use question** — while **`agent.queue_mode`** is unset, the first message written during a turn opens **`div.composer-queue-choice`** (**`data-testid="composer-queue-choice"`**, a labelled group) between the queue and the card, with **Steer now** and **After this turn**; the answer is saved as the Enter mode and sends the message, in the other mode when it was sent with Tab.
- **Taking a message back returns it to the field.** A queued message is still the operator's until the agent reads it, and taking it back is how it gets edited: when **`DELETE /coddy/sessions/{id}/queue/{message_id}`** succeeds, its text goes back into the composer - ahead of anything typed since, separated by a blank line - and its images go back into the attachments, from the **`inline_files`** of that answer (**`chat/dataUrlFile.ts`** decodes them, it never fetches a URL). A **404** means the agent read it first; it is already in the conversation and nothing returns.
- **The primary control** (**`#btn-send`**) keeps its circle and swaps only its meaning. While generating with a **non-empty** draft it carries the **play** glyph on an accent fill (**`.composer-run-icon--queue`**, **`data-queue="true"`**, accessible name **`Queue this message`**); with an **empty** draft it is the **stop** square exactly as before. Never render a third glyph for this, and never remove Stop: emptying the field exposes the control that interrupts the current run and requests queue continuation where eligible.
- **Stop and the waiting batch.** For an ordinary **`agent`**, **`plan`** or **`ask`** profile prompt running in the server process, an accepted **`continue_queue`** request reserves all waiting messages. The server cancels the current run's child context, waits for partial assistant persistence and tool results to settle, appends every reserved message as an individual user row in original FIFO order, including duplicates and retained images regardless of mode, and starts a fresh child run under the same admission and turn generation. There is one writer and no empty, synthetic or combined user prompt. Empty queues and unsupported paths (direct completions, saved-plan runs, permission resumes and supervisor commands) fall back to full cancellation. A second Stop while the accepted batch is unread wins as full cancellation and retains that batch. External cancellation, errors and shutdown never resume it automatically; unaccepted messages keep legacy cancellation rules. Later messages follow normal loop-boundary queue rules, and waiting state is still lost on process restart. Default cancellation without **`continue_queue: true`** drops unread steer messages and keeps after-turn messages idle, preserving ACP, remote-console and HTTP-client behavior. No route or configuration key is added.
- **The field** keeps focus and its content rules while generating; only the placeholder changes (**`composer.placeholderQueue`**).
- **State recovery** - session open and reconnect read **`GET /coddy/sessions/{id}/queue`**, without waiting for another queue mutation or a History row. HTTP responses and **`message_queue`** events carry a list and version from one server snapshot; **`QueueDeliveryOrder`** (**`chat/messageQueueState.ts`**) keeps the highest version per session for ordinary deliveries. A fresh queue GET captures the delivery revision and recovery epoch before the request. The SPA rejects a snapshot crossed by any queue delivery; otherwise it may establish a lower version (including **`0`**) after a server restart. A lower-version snapshot advances the local recovery epoch, so mutation responses and own/relay stream queue frames captured in earlier epochs are ignored. Replayed **`turn_started`** events preserve waiting messages and their version, and closing a reader does not clear the queue. These controls use the existing same-server routes and events; transcript relay and permission/question ownership stay unchanged.

### Chevron

The app has **one chevron**, **`<Chevron />`** (**`ui/components/Chevron.tsx`**), at **70%** opacity, that a transcript row folds with. It points **right while closed** and turns **down when open** (**`.coddy-chevron.is-open`**, a 90° rotation over 140ms, none of it under **`prefers-reduced-motion: reduce`**); a back control is the same mark pointing **left** (**`.coddy-chevron--left`**, the settings list forms' way back); a dropdown indicator is the same mark pointing **down while closed** and **up when open** (**`pointing="down"`**). The transcript row's **`.thinking-chevron`** and **`.coddy-chevron`** are **one component**, so they cannot drift apart: **`.thinking-chevron`** is a class on **`<Chevron />`**, not a pseudo-element with a glyph of its own. History group headings, the **Finished N** toggle of the Tasks panel, the History filter rows and the settings combobox all use it - the headings used to draw a small solid triangle, the Tasks panel a border triangle and the combobox a third glyph, and each read as a different kind of control. **Any new disclosure, submenu or dropdown uses `<Chevron />`**; drawing **`▸`**, **`▾`** or a border triangle is a defect, and **`chevronContract.test.tsx`** fails on one. Pager arrows (**`‹`** / **`›`** buttons of the settings tabs) and the **▶** of a Run control are not chevrons.

It is an **inline SVG**, never a text glyph and never a triangle. A **stroked polyline** on a **14×14** viewBox - the points **`5.5,4 8.5,7 5.5,10`** at **1.6** stroke width, **round** cap and join, **`currentColor`** - mirrors about the centre of that viewBox on both axes, so its ink is centred in the box by construction and the box is the only thing the CSS has to place. The reason is the whole history of this mark: as the text **`›`** its ink sat wherever the platform's font put it inside the line box, so the same CSS placed the chevron differently on every machine and every fix that nudged **`top`** was undone by the next font. **`chevronContract.test.tsx`** fails if the geometry stops being symmetric, if a stylesheet puts a chevron back into **`content`**, or if a second implementation appears; **`external/ui/scripts/chevron-align-check.mjs`** measures the result in a real browser, which is the only place layout exists.

Its vertical placement is **centred on the first line of the label beside it**, never on the row's box: **`.thinking-chevron`** is placed at **`top: 10px`** - half the **20px** line box of **`.thinking-label`** - with **`translateY(-50%)`**. The row's box is not one line tall on every row: a tool row aligns its 14px label, 12px monospace target and 12px duration on one baseline (**`.thinking-head`**), which lowers the smaller boxes by a pixel or two and makes the box taller than the label's line, and a phone wraps a background chip onto a second line. Centred on that box (**`top: 50%`**) the chevron sank below the label on every tool row while the thinking row kept it level. The two numbers move together; **`toolRowBaselineCss.test.ts`** holds the chevron's **`top`** to half the label's **`line-height`**, and the browser check above measures the chevron's ink centre against the ink centre of the label's text - within **1px** on a transcript row and on the Tasks panel's finished counter.

- **Title row** is the shared **`slash-menu-title`**, **`composer.workspaceFilesTitle`** (**Mention** / **Упоминание**).
- **Rows** are **`.slash-row-btn.mention-row`** inside one **`.slash-row-line`** (two-line clamp, as the slash rows): a kind label **`.mention-kind`** first - **10px** uppercase text at **16px** line height, **44px** minimum width, **6px** radius, a **7%** text-tint plate with **62%** text; the meta kinds (**`.mention-kind--session`**, **`--rule`**, **`--agent`**, **`--plan`**, **`--doc`**, **`--scheme`**) take the accent on a **14%** accent plate - then the label in **`.slash-row-name`** (a scheme hint prints **`@session:`**), then **`.slash-row-desc`**: nothing for a path (its label is the whole path), the id and date for a session, the description for a rule or a subagent, a localized sentence for a scheme hint.
- **Highlight**: **ArrowUp** / **ArrowDown** move **`is-active`** (the slash picker's accent tint) and **`aria-selected`**, wrapping, and scroll the row into view; the pointer moves it too (**`onMouseEnter`**). **Enter** and **Tab** take the highlighted row, while a turn runs as well; **Escape** closes the picker.
- **Taking a row** replaces **`@`** plus the query with its **`insert`**. A folder, a folder **`@rule:`** offers or a scheme hint (**`continue`**) adds no space and the picker stays open on the new query; anything else ends the mention with a space.
- **Cut list**: when the server matched more than it returned, **`.mention-more`** on the right of the title row (**`.mention-title`**) says **50 of 1204, type to narrow** (**`composer.mentionMore`**): the rows scroll, the title is what the reader sees when the picker opens. The **`.at-range-menu-hint`** footer (a **`:`** after a file picks lines) shows only while a file row is listed.
- **Empty query**: recent picks of the session (**`localStorage`**) first, then the server's scheme hints and the top of the workspace; **`Type after @ to search`** only when the list is empty, **`Nothing matches`** for a query with no match.
- **Chips in the draft**: a typed mention takes the **`composer-at-chip-inline`** chip only once **`POST /coddy/mentions/check`** has said sending would attach it, and only over the part that resolves; a token that names nothing (**`@google/genai`** in **`npm install @google/genai`**, a handle) keeps the text colour. The draft at the caret keeps its chip while the picker is open on it, and a picked row is chipped at once.

### Line-range picker (**`@path:N-M`**)

A workspace mention can narrow a file to a **1-based inclusive** line range, **`@Dockerfile:21-31`**. The composer text stays the only input: typing the **`:`** after a file token closes the **`@`** mention picker (**`:`** is not a **`MENU_PATH_CHAR`** outside the **`session:`** / **`rule:`** / **`agent:`** hints) and the range panel takes its place, reusing the picker chrome one for one - **`slash-menu-surface`** plus **`slash-menu-scroll`**, the **`slash-menu--portal`** node under **`document.body`** on desktop and the **`slash-menu--sheet`** bottom sheet with **`slash-sheet-backdrop`** on stacked shells. Draft logic lives in **`external/ui/src/ui/skills/draftAtRange.ts`**; functional checklist in **`docs/surfaces/web-ui.md`** (**Line ranges**).

- **Automation**: root **`data-testid="at-range-picker"`** with **`role="group"`** (the file and slash pickers keep **`listbox`**), rows **`data-testid={`at-range-line-${n}`}`** with **`data-line`**, list **`data-testid="at-range-lines"`**, current range **`data-testid="at-range-current"`**.
- **Title row** is the shared **`slash-menu-title`**: the caption, then the path in **`.at-range-title-path`** (600 weight, no uppercase transform), then the typed range as an accent pill **`.at-range-title-range`** (**`color: var(--accent)`** on a 16% accent tint, tabular numerals). A hint line (**`.at-range-hint`**, **`slash-muted`**) explains the entry: type the range or, on desktop, click and drag the rows; the mobile copy only asks to type it.
- **Rows** (**`.at-range-lines`** > **`.at-range-line`**) are one logical line each in the monospace stack (**`--mono`**, 12px, line-height 1.5): a right-aligned gutter **`.at-range-line-no`** (min 3ch, 50% opacity, tabular, not selectable) and the code in **`.at-range-line-code`** with **`white-space: pre`**. Long lines never wrap; **`.at-range-lines`** scrolls horizontally inside the panel so the page keeps **`scrollWidth === clientWidth`**. Selected rows use **`.at-range-line--sel`** (accent at 18% over **`--coddy-blend-base`**); a start typed without an end highlights that one line.
- **Desktop** rows are **`button`**s (pointer cursor, 6% text-tint hover): **`mousedown`** anchors the range and calls **`preventDefault`** so focus stays in **`#composer`**, dragging over rows extends it, and every step rewrites the **`:N-M`** suffix through **`replaceAtRangeSuffix`**. On **`isMobileShell`** the rows are plain **`div`**s with no hover or pointer affordance - there is no mouse to drag with, so the range is typed.
- The panel counts as **open** only once the file loaded (**`GET /coddy/workspace/file`**, one fetch per settled path), so a colon in prose never flashes an empty panel; a path that does not resolve leaves it closed. **`Escape`** dismisses it for that mention, **`Enter`** is left alone and still sends. The **`@`** file menu gains one footer line **`.at-range-menu-hint`** (top border at 12% text tint) telling the user that **`:`** after a file picks lines.
- Truncation: the route caps the preview (default 2000 lines); a truncated file adds a **`slash-muted`** line naming how many of the total lines are shown.

#### Composer mirror and caret sync (contract)

The textarea uses **transparent** glyphs when the draft is non-empty; the user-visible line is the **mirror** (`.composer-mirror-inner`) that must be **pixel-aligned** with **`#composer`** for the same string. The **caret** position is computed **only** by the textarea engine on the raw characters, so any styling in the mirror that **changes horizontal advance** of the same code points **breaks** perceived caret placement.

Rules for **`.composer-skill-chip-inline`** (composer only):

- **MUST** use the **same effective font metrics** as **`#composer`**: **`font-family`**, **`font-size`**, **`line-height`**, **`font-weight`**, **`letter-spacing`**, **`font-style`** inherited or explicitly matched (current gate: **400** weight on both mirror and textarea in **`styles/composer/_field.scss`**).
- **MUST NOT** add **horizontal** **`padding`**, **`margin`**, or a **`border`** that participates in the inline box width. Use **`box-shadow: 0 0 0 1px …`** for a ring and **`padding: 0`**, **`margin: 0`** so chip width tracks the underlying `/name` glyphs.
- **MUST** keep **`scrollbar-gutter: stable`** on **`#composer`** and on **`.composer-mirror`** (with **`overflow: hidden`**), and the textarea's padding on **`.composer-mirror-inner`** as the stylesheet sets it. The browser then takes the same scrollbar width out of both text boxes, to the fraction of a pixel, at every page zoom and screen density. Do not size the mirror's padding from **`offsetWidth - clientWidth`** in script: it rounds to whole pixels and goes stale when the zoom or the density changes, because a classic scrollbar keeps its device pixels (13.6 CSS px at 110%, 8.6 at 175%). That is what put the caret beside the text it stood in, and the mirror's old **`16px`** plus the scrollbar, written before the wand took **44px** on the right, left it 28px wider than the field.
- **MUST** scroll the mirror as a scroll container of its own (**`mirror.scrollTop = textarea.scrollTop`** on the field's **`scroll`**), never by a **`transform`** of its text: the two snap a fractional offset (214 CSS px at 125% is 267.5 device px) to the same device pixel, a translated layer does not. The mirror takes the textarea's own height (**`getComputedStyle(textarea).height`**, 131.5px for five rows), because the stack under the inline-block textarea is a few pixels taller and a mirror filling it showed the next line where the field had clipped it.
- **MUST** line the mirror up again on a window **`resize`** and on a change of **`(resolution: <dpr>dppx)`**: a page zoom or a window dragged to a screen of another density lays the text out again without resizing the field in CSS pixels, which is all its **`ResizeObserver`** reports. **`npm run check:caret`** measures the result in a real engine (**`docs/surfaces/web-ui.md`**, *Checking the composer caret at every zoom*).

Transcript chips (**.md .coddy-skill-chip**) are **not** bound by this contract; they may use monospace, heavier weight, and pill padding because they are not paired with a transparent textarea.

### Command option picker (**`/compact --model`**, **`/goal --reasoning`**)

Once **`/compact`** or **`/goal`** opens the draft, the composer completes the options the command takes and their values; it is the third face of the picker chrome - **`slash-menu-surface`**, **`slash-menu-scroll`**, the **`slash-menu--portal`** node on desktop and the **`slash-menu--sheet`** bottom sheet with **`slash-sheet-backdrop`** on stacked shells - and it sends no request. Draft logic: **`commandArgDraftAtCaret`** in **`external/ui/src/ui/skills/draftCommandArg.ts`**, which mirrors **`parseCompactCommand`** (**`internal/agent/compact.go`**) and **`ParseGoalCommand`** (**`internal/session/goal_command.go`**) down to the separators allowed after the command word and the short spellings **`-m`** (**`--model`**) and **`-r`** (**`--reasoning`**); functional checklist: **`docs/surfaces/web-ui.md`** (**Composer command options**).

- **Automation**: container **`data-testid="command-arg-menu"`** (**`role="listbox"`**, aria label **`composer.commandArgAriaLabel`**), rows **`data-testid={`command-arg-row-${value}`}`** (non **`[a-zA-Z0-9_-]`** runs replaced by **`_`**) with **`data-arg-idx`**.
- **What opens it**: a token starting with **`--`** in the options offers **`--model`** and **`--reasoning`** (a lone **`-`** opens nothing: the instructions may be a list) (title **`composer.commandArgOptionsTitle`**, each row carries its description as its **`.slash-row-desc`**: **`composer.commandArgModelFlagDesc`** / **`composer.commandArgSummaryReasoningFlagDesc`** for **`/compact`**, **`composer.commandArgGoalModelFlagDesc`** / **`composer.commandArgReasoningFlagDesc`** for **`/goal`**); the value after **`--model `**, **`--model=`** or **`-m `** lists the models of the composer's Model menu (**`props.llmModels`**, title **`composer.commandArgModelsTitle`**, **`composer.commandArgGoalModelsTitle`** for **`/goal`**), filtered by **`filterLlmModels`**, each row its full id in **`.slash-row-name`** and nothing else; the value after **`--reasoning `**, **`--reasoning=`** or **`-r `** lists **`default`** and the levels of the model the draft's **`--model`** names, else of the session's (**`commandReasoningChoices`**, title **`composer.commandArgSummaryReasoningTitle`** for **`/compact`**, **`composer.commandArgReasoningTitle`** for **`/goal`**). A bare **`/compact `**, a complete value, an option typed where the value goes and the instructions open nothing, so **Enter** still sends.
- **Empty filter**: the model list stays open with **`composer.noModelsMatch`** in **`slash-muted`**, and **Enter** is left alone, so the command goes to the server, which answers with the configured ids.
- **Keys** follow the mention picker: **ArrowUp** / **ArrowDown** move **`is-active`** and **`aria-selected`**, wrapping, and scroll the row into view; the pointer moves it too; **Enter** and **Tab** put the row into the draft followed by one space; **Escape** closes the picker and leaves the draft alone. Picking **`--model`** opens the models at once. A key an input method is composing with never reaches it (see the slash picker).
