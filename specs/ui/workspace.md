# UI design: workspace

[Design index](../../DESIGN.md)

### Session identifier in URL

`#/s/<sessionId>` survives reload/share as long as the browser hits the **same Coddy http instance** backing the **`sessions`** root hash. SPA keeps **`X-Coddy-Session-ID`** synced with whichever id anchors the fragment.

### Multi-session streaming and Stop

- The SPA may run **more than one** **`POST /v1/responses`** at a time, each with its own **`X-Coddy-Session-ID`**, while the user switches **`#/s/...`** quickly. Each session keeps a **shadow transcript** in memory so streamed rows from session **A** are never appended to session **B**. Routing uses **`pickStreamMutationBase`** in **`external/ui/src/ui/chat/streamMutationBase.ts`**.
- **Server activity and local reader lifetime are separate.** On session open and reconnect, the SPA reads **`GET /coddy/sessions/{id}/activity`** for the selected id, independently of the filtered or paginated History list. **`chat/useSessionTurnActivity`** skips both activity and queue hydration while this tab's own POST awaits admission. An active turn keeps Stop and queue controls available without a local reader. A reader closing does not mark the server idle; a **`turn_ended`** overlapping this tab's pending or admitted POST requires fresh REST activity confirmation before the SPA declares idle.
- The shadow transcripts form a **small LRU** (**`ShadowTranscriptCache`** in **`external/ui/src/ui/chat/sessionTranscriptCache.ts`**, cap **`SHADOW_TRANSCRIPT_CACHE_CAP`** = 3 non-pinned entries). The **viewed** session and every session with a **live composer stream** (own **`POST`** or a relay attach) are **pinned**; the least recently used entries beyond the cap are dropped whenever a session is picked, the user goes home, a stream finishes, or **`loadMessages`** stores a fresh snapshot. An evicted session is simply **re-fetched** from **`GET /coddy/sessions/{id}/messages`** on the next visit, the path a finished dialog already takes today, so eviction costs no extra request. A **`loadMessages`** response that lands after the viewer moved to another session only refreshes that session's shadow; it never paints under the current route.
- Message rows (**`UserMessage`**, **`AssistantMessage`**, **`ThinkingMessage`**, **`ToolCallMessage`**, **`SystemNoticeMessage`**, **`CompactionMessage`**) and **`Markdown`** are **`React.memo`** components, so unchanged rows skip rendering and markdown re-parsing while a token streams. **`MessageList`** itself still maps the transcript on every update, and the plan document, permission and question rows are not memoized. Handlers passed into the rows go through **`useStableHandler`** (**`external/ui/src/ui/components/useStableHandler.ts`**) to keep their identity across shell re-renders.
- **Attaching to a running turn replays only what the loaded transcript lacks.** A tab that opens or reloads a session mid-turn loads **`GET /coddy/sessions/{id}/messages`** first and attaches to **`GET .../composer-stream`** second. The relay used to replay the **whole** turn on top of that transcript: the reasoning and the answer of every finished step landed a second time at the foot of the column, and each finished tool row was re-stamped by the burst - its start and its end replayed in the same millisecond - so it read **`0ms`**, until the turn ended and a reconcile put things back. Now every relay frame is stamped with the revision of the session's message history it was written at (**`State.MessagesRev`**), the messages response carries the revision it was read at (**`messagesRev`**), and **`rejoinComposerLiveStream`** passes it back as **`?since_rev=`**: every frame written before that revision describes something the transcript already holds and is left out. The revision is remembered per returned transcript (**`snapshotRevByTranscript`**, a **`WeakMap`**) and only for one that is the server's snapshot and nothing more; a transcript that kept local rows past the snapshot, and a reconnect that holds a frame cursor (**`Last-Event-ID`**), attach as before. A frame older than **250ms** when it reaches a subscriber carries an **`age:`** field, and **`consumeComposerSse.ts`** dates every row it touches by it (**`eventNow`**) rather than by its arrival, so the reasoning block still streaming after a reload keeps its real start and a replayed tool call its real duration. Covered by **`features/composer_live_watch.feature`**, **`composer_stream_resume_test.go`**, **`consumeComposerSse.order.test.ts`** and **`App.stopQueue.test.tsx`**.
- **Every transcript row lays itself out**: no **`content-visibility`** on the rows, so the scrollport's height is the transcript's real height from the first frame. Off-screen rows used to skip layout and paint behind **`content-visibility: auto`** with **`contain-intrinsic-size: auto 120px`**, but the last remembered height only exists for a row rendered at least once, and a session opens scrolled to its end - so every row above the first screen was the fallback guess. Measured on a 360-row transcript, the scrollport reported **42114px** against a real **50342px**; scrolling up materialised those rows a screen at a time, the height grew under the reader, and **scroll anchoring** pushed the position down by the difference on every wheel notch. Row memoisation and the bounded shadow cache above carry the long transcripts instead. Covered by **`transcriptRowContainmentCss.test.ts`**.
- **Stop** (**`#btn-send`** as stop) always calls **`POST /coddy/sessions/{id}/cancel`** with **`{"continue_queue":true}`** and aborts this tab's own streaming **`fetch`** of the turn (the POST or the relay) as soon as the request is sent, not after the answer: over HTTP/1.1 a browser keeps six connections to a host for all of its tabs, a few open tabs can hold every one of them with event and turn streams, and the cancel request then waits for the connection this reader holds. The server turn does not depend on the reader. A failed request leaves a visible error and Stop available for a retry, and the tab rejoins the still running turn through the relay. **`queueContinued: true`** acknowledges an accepted queue continuation, so the tab reattaches to the same turn generation through the composer relay without waiting for another **`turn_started`**. The client never drains or resubmits the queue itself. Without that flag, success acknowledges full cancellation, not turn completion; server activity confirms idle. Existing generation guards remain in place. The server **persists** assistant tokens already received for that turn when cancel lands mid-stream (**`internal/llm`** stream implementations return a partial **`Response`** with **`context.Canceled`** wrapped, then **`internal/agent`** **`Run`** appends **`RoleAssistant`** before surfacing **`StopReasonCancelled`**).
- Right after Stop, **`GET /coddy/sessions/{id}/messages`** can briefly omit or shorten the in-progress assistant row versus what is already on screen. **`loadMessages`** merges the server snapshot with the **local shadow** or **visible items** when the server list is a strict prefix of local (or the last **`assistant_message`** is a shorter prefix of local); see **`mergeTranscriptPreferLocalSuffix`** in **`external/ui/src/ui/chat/transcriptServerSnapshot.ts`**. A full page reload still converges once persistence matches **`messages.json`**.

### Scheduler hash routes

- The scheduler jobs drawer footer is a single **Add job** control (**plus icon**, native **`title`** tooltip), **right-aligned** in the drawer (no manual **Refresh** button, list still reloads when the drawer opens and after saves). The job editor uses the same **`sessions-head`** / **`sessions-close`** chrome as **History** and the scheduler list. The job editor footer uses **pause or resume**, **delete** as icon buttons with the same **`title` / `aria-label`** pattern; on **`max-width: 1199px`** those actions are **end-aligned** for reach. While the drawer stays open, the client **polls `GET /coddy/scheduler/jobs` about every 12 seconds** (silent, no list loading chrome) so **running**, **next_run_utc**, and **paused** stay in sync with the server.
- Each scheduler job row uses **two lines** - **job_id** on the first line with either the **paused** badge or **`Next … (UTC)`** beside it (same line, muted), then **description** on the second line. The row body is a real **`href`** to **`#/scheduler/jobs/<job_id>`** so **middle-click** opens that job in a **new tab**.
- The job editor footer keeps **Resume** or **Pause** and **Delete** on the **left** for shorter pointer travel.
- **`#/scheduler`** opens the **Scheduler** jobs list drawer. **`#/scheduler/new`** opens the list with the **new job** editor (Add job sets this hash). **`#/scheduler/jobs/<job_id>`** opens that drawer with the **job editor** docked **next to** the list on desktop (**no** fullscreen scrim over the list). Encode **`job_id`** in the path segment when it contains special characters. The job row open in the editor uses the same **`session-item active`** highlight as **History** for the current chat. On **`max-width: 1199px`**, the **`.scheduler-dock-cluster`** matches **History** (**same `left` / `right` / `top` / `bottom` inset pattern**, full viewport height between insets). The jobs list alone fills that height. When the job editor is open, **`.scheduler-dock-cluster-editor-active`** hides the list and shows only the editor at **full cluster height** so it covers the list (**stacked overlay**, not a short bottom sheet). The cluster sits **above** the shared dim **`.backdrop`** (**`z-index: 70`**) so controls stay clickable while the drawer is open.
- **`#/history`** opens the **History** drawer alone. On **`min-width: 1200px`**, opening **History** while **Scheduler** is already open keeps both drawers by adding **`?history=1`** to the scheduler hash (example **`#/scheduler/jobs/<job_id>?history=1`**). Choosing another chat from the list keeps the drawer open by using **`#/s/<sessionId>?history=1`** while **History** stays visible. The main chat shell still uses the shared dim **backdrop** when a drawer is open.
- Deleting the **active** chat from **History** moves the shell to the **new chat** home (empty start screen), clears the session route, and **closes** the **History** drawer. Deleting **another** row removes it from the list and **keeps** the **History** drawer open; the URL and transcript stay on the chat that was on screen. After **`window.confirm`**, the client **briefly ignores** shell **backdrop** closes so a stray pointer event does not dismiss **History** or change the route. The row **trash** control calls **`stopPropagation`** on **`click`** before **`deleteSession`** so an **`async`** delete cannot bubble to the row and accidentally **`pickSession`** the deleted id.
- Field edits in the job editor **auto-save** with a short debounce (no separate **Save** button) without a footer status line. **`job_id`** is editable in the editor; changing it renames the on-disk job via PATCH. **Pause**, **Resume**, and **Delete** stay explicit.
- The URL still carries **one** primary route at a time for **`#/s/...`** vs **`#/scheduler...`** vs **`#/history`**; the optional **`history=1`** query only augments scheduler (or session) URLs for the dual-drawer desktop case.
- **`404`** from **`GET /coddy/scheduler/jobs`** means the server build has no scheduler HTTP surface; **`503`** means **`scheduler.enable`** is false for that process. The drawer shows a plain-language line instead of crashing.
- The job **`body (markdown)`** field uses the shared **`MarkdownLineEditor`** (see **Markdown line editor** below). Gutter, active-line highlight, wrap-aware numbering, and content-driven height match the plan card markdown pane.
- **Project jobs.** With a session (or a picked folder) the list carries the project jobs too, and the drawer groups the rows under small uppercase headings (**`.scheduler-job-group-head`**): **Global** (the user jobs), **This project · `<folder>`** for the chat's workspace, then **Project · `<folder>`** for every other workspace the scheduler runs, the full path in the heading's **`title`**. With no project job at all there are no headings and the list looks as before. A row that does not run carries a trust badge in place of the next-run text (**`.scheduler-job-trust--<state>`**: amber **needs approval**, red **denied**, **id conflict**, **invalid**; the reason in its **`title`**) and its run circle is disabled; a row that **needs approval** shows an amber shield (**`.scheduler-job-approve-icon`**, **`IconShield`**) in place of the run circle, which opens the job. Inside the SPA a project job is addressed by a **reference**, **`<workspace>/<job_id>`** (a job id never contains a slash), so its routes are **`#/scheduler/jobs/<encoded reference>`** and the API calls carry **`scope=project&workspace=`** (**`schedulerJobUrl`**); a user job keeps its bare id and its address. The editor of a project job opens with the **approval block** (**`.scheduler-trust-block`**, bordered amber or red by state): the state, the shield toggle (approve the digest it showed, or withdraw; under **`project_trust: ask`** only, the subagents shield's classes), where the job comes from, the reason, and for a job that is not trusted the raw file in a monospace box (**`.scheduler-trust-raw`**, max 260px, scrolls). A new job has a **Where the job lives** radio pair above the id (**Global** / **This project (`<folder>`)**); the project option is disabled without a session, and picking it empties **cwd** (a project job's cwd is relative to its workspace).
- **Runs of a job.** A run is a background agent task under the job's own session, so a job's history is the **background tasks panel** (**`BackgroundTasksPanel`**, unchanged) docked in the scheduler cluster where the editor docks (**`.bgtasks-panel.scheduler-runs-dock`**: relative, the editor's width rule, full cluster height; on **`max-width: 1199px`** it covers the list like the editor). Route **`#/scheduler/jobs/<job_id>/runs`** (**`.../runs/<task_id>`** is parsed, opens that run's card through the panel's **`focus`**, and is never written); the panel's heading reads **Runs of `<job_id>`** and its empty copy says no run happened yet. A run's card is the same card a chat's agent task gets. Each job row carries a **Runs** control (**`SchedulerIconRuns`**, a real **`href`** to the runs route, same-tab handler for a plain click) before the run/stop circle, and a **last-run mark**, absent until the first run: the panel's **`bgtask-dot`** in the status tone on the name's line, in a marks column laid out like a History row's (**`.scheduler-job-row-mark`**, the 24px first track of **`.scheduler-job-row-text-block`**, every line under the name indented to that column), and, once the run has ended, the status word with the local clock under the description (**`.scheduler-job-row-last-run`**); a running job has no such line, its pulsing dot and the Stop button say it. The editor footer carries the same Runs control first. Data comes from **`GET /coddy/sessions/{job session}/background-tasks`** on the panel's cadence (2.5 s while a run is in flight, 15 s idle); a run in flight is stopped from the job's row (its circle is Stop while the job runs) and the panel is given no **`onStopTask`**, so a run card carries no Stop of its own, **Clear** is **`DELETE /coddy/scheduler/jobs/{job_id}/runs`** (the transcripts go with the records), **Open transcript** opens the run session, whose read-only notice names the job and links back to the runs route instead of a parent chat.
- The job editor has two more fields after **`model`**: **`agent`** (a subagent definition name, free text with the definition help line) and **`permission mode`** (a select: **bypass (default: unattended)**, **accept_edits**, **ask**, **bypass**); both autosave like the rest.

### Background tasks panel

**`#/s/<sessionId>/tasks`** opens the panel. **`#/s/<sessionId>/tasks/<task_id>`** is still parsed - it opens the panel with that task's card open - but never written: which cards are open is the panel's state, and the address drops the id as soon as the card is open. The route hangs off the **session segment** on purpose: a task belongs to one chat, so an address that does not carry the chat reloads into a panel with no session behind it. Closing the panel writes the plain **`#/s/<sessionId>`** back over an address that names the panel. On a desktop, where the panel stands beside a screen of the rail, the address is that screen's and closing the panel leaves it alone, not even for a moment (**`closeTasksDrawer`**, held by **`App.railEscape.test.tsx`**).

The panel is **docked inside the session**, to the right of the transcript, rather than floating over the shell like **History** or **Scheduler**. A background task belongs to the conversation that started it, so being part of that conversation is what tells the operator which session a process came from; there is no session label to add. Implementation lives in **`external/ui/src/ui/tasks/`** (**`BackgroundTasksPanel.tsx`**, pure helpers in **`taskStatus.ts`**, REST client in **`api.ts`**).

- **Placement.** **`.bgtasks-panel`** is **`position: fixed`** against the right viewport edge (14px inset, full height), **380px** wide, using the shared **`--coddy-glass-panel-*`** tokens. On **`min-width: 1200px`** the chat column yields **only what the panel actually takes from it** (**`.shell-main.shell-tasks-open`** derives **`--coddy-tasks-reserve`** and pads **`#messages`** and **`.chat-bottom`** with it): while the centred transcript stripe still clears the panel the reserve is **`0`** and **nothing moves**, and once the stripe would run under the panel the reserve grows to exactly that overlap and stops at the panel's own band. Opening the panel must not slide the transcript sideways on a window that has room for both. The composer pays the scrollbar gutter back on its end edge so it stays on the transcript's centre line. It carries **no backdrop**: it sits beside the chat, it does not block it. On **`min-width: 1200px`** it belongs to the chat on screen and not to the rail, so it **stays open** while History picks another chat and shows that chat's tasks (the address follows, **`#/s/<sessionId>/tasks`**), across the rail's screens, and when the **backdrop** takes History or another screen down (**`closeAllShellDrawers`** leaves it alone there). On the stacked shell the panel is full screen, and a rail screen or its backdrop closes it.
- **Polling, not SSE.** A background task outlives the turn that started it, so the SSE stream cannot keep the panel honest. The shell polls **`GET /coddy/sessions/{id}/background-tasks`** every **2.5s** while anything runs and every **15s** otherwise (**`tasksPollIntervalMs`**), and the open cards read their output on a timer of their own (**`loadOutput`**, below). A poll against an unreachable server degrades to a normal error result, never an unhandled rejection once per tick.
- **Ordering** is **purely by start time, newest first** (**`sortTasksByStart`**), among the live cards and inside the finished history alike. Running tasks are **not** floated to the top of the history: they stand above the **Finished N** counter already, and mixing two orderings makes a list that never sits still to read.
- **One step, 10px**, separates every seam of the list: the head to the first live card, the last card to the **Finished N** counter, and the head to that counter when nothing is running. The cards carry **8px** under them, so the counter tops that up rather than adding its own; the empty note, the loading line and a list error sit on the same step and share the list's inline padding instead of nesting a second one.
- **One card for every task** (**`.bgtask-card`**, **`TaskCard`** in **`BackgroundTasksPanel.tsx`**) - a shell command, a subagent run, a preview server, running or finished. Every card has the same parts in the same place, so a column of them reads at a glance: a **status dot** (**`.bgtask-dot--running|success|danger|warning|muted`**, the same vocabulary as the MCP server rows; the running dot pulses and the pulse is dropped under **`prefers-reduced-motion`**), a **tag** (**`.bgtask-tag`**, accent wash, **`taskTag`**) that says what stands behind the task - the agent's name (**`explore`**, **`general`**, **`memory`**), **`server`** for a preview server, **`shell`** for a command; left out when the title already begins with that name (**`taskCardHeading`**: the title is the name, or the name and **` · `**, the shape of a scheduled run's **`<job> · <trigger> <when>`**), so a name is never written twice, and left out for an agent run that names no agent rather than reading a bare **`agent`**, which every agent card is - then the **title**; a scheduled run's title is its job alone, the trigger and the fire slot going to the hover text, so its first line is the dot and the job (**`taskTitle`**: the command, or the description of an agent run without the **`agent <name>:`** prefix the pool writes, because the tag already says that half), and under them a **meta line** (**`.bgtask-card-meta`**) indented to the title. Its left part (**`taskMetaLine`**) is **start · elapsed · est. · overdue** while the task runs (**`12:49 · 1m 28s`**) and **`12:49 · 20s · 12:50`** - when it started, how long it ran, when it ended - once it has finished; a day other than today puts the date in front, and an end on another day than the start is dated too. The full start and end, date and seconds, are lines of the card's hover text (**`taskTimesTitle`**: *Started …*, *Finished …*), under the task's whole label. **How a task ended is not written on a folded card**: the dot says it in colour, and the open card names it first in its foot; a word next to a green dot only repeated it. A running task that will wake the agent when it ends (**`notify_on_finish`**) carries a **bell** right after the title (**`.bgtask-notify`**, the shared **`BellIcon`**, **13px**, the tag's accent tint; **`title`** and accessible name *Wakes the agent when it ends*), and a finished task whose end did wake it (**`woke_agent`**) keeps the bell (*Woke the agent when it ended*): the title gives way before the bell does. A finished task that was to wake the agent and has not - the turn has not begun yet - carries none. The bell is the one place the web UI says what woke the agent, since the woken turn shows nothing of its own ([Woken turn](#woken-turn)). An agent run - a subagent, a scheduled run, the memory subagent - carries on the right of the same line the **model** it runs on, the **reasoning level** it calls it with when the model has levels, and the **tokens** its calls spent (**`.bgtask-card-usage`**, **`agentUsage`**, from **`agent.model`**, **`agent.reasoning`**, **`agent.input_tokens`** and **`agent.output_tokens`** of the row): **`qwen3.8-27b · High · 212k tokens`**, the model by its short name (the vendor prefix of **`vendor/model`** dropped), the level written as the composer's chip writes it (**`.bgtask-card-reasoning`**, which, like the tokens, never gives way), the tokens as input and output together, shortened like the turn line (**`212k tokens`**), the way a table of agents reads Model and Tokens across. The usage is muted and keeps its colour on an overdue card. A row with **`agent.usage_incomplete: true`** hides the token total and its input/output hover breakdown, but keeps the model and reasoning when available; a zero total is also omitted. An older row without the marker keeps the existing display of its positive counts. When status and usage do not fit side by side the usage drops under the status **whole**, still at the right edge (**`flex-wrap`**), instead of cutting the model's name; only a name too long for a line of its own is clipped. The full model id and the exact input / output split are the card's hover text: the opener is stretched over the summary, so its **`title`** is the only one that can show, and the card stays one control. Under the status and the usage the card carries **the way into the task**, and at most one of them, because a task is one kind or the other. An agent run carries **Show transcript** (**`.bgtask-card-transcript`**, **`data-testid="bgtask-open-transcript-<id>"`**, accent text with no border, plate or tab: the attached tab it once was under the output read as a stray flap of the card, and it hid the action behind an expansion), a real link that routes to **`#/s/<child session id>`** through the same in-place session open as a History pick, a modifier click going to a new tab, and plain text with a title saying why until the child session is known; a running preview server carries **its address** (**`.bgtask-card-link`**, **`data-testid="bgtask-link-<id>"`**, the same accent text, **`target="_blank"`**, **`rel="noopener noreferrer"`**), which opens the page in a new tab. The run **is** that conversation and the server **is** that page, and an operator who had to open a card to find either was made to take a step on the way to the one move the panel exists for. Both stand above the stretched opener the way **Stop** does, so they open the transcript or the page and not the card under them, and both take a **row of their own** (**`.bgtask-card-transcript-row`** and **`.bgtask-card-address-row`**, **`flex: 1 0 100%`**): in a 380px panel a control sharing the meta line would be paid for by the model's name, the one thing there that cannot be cut down to something still readable. Until the row carries **`agent.session_id`** the transcript control is disabled with a title saying why, rather than absent, so the card does not change shape under the reader when the id arrives. An address is as long as it is and **wraps whole** rather than trailing off in an ellipsis that names no port, and a server that has **stopped** carries none at all: the page it named answers nothing now. Titles are set in the UI face at **13px / 600**; monospace is kept for the command block of the open card. A progress bar is drawn **only** while running **and** when the model supplied **`expected_seconds`**: the UI never implies knowledge it does not have.
- **The card is one control.** Its summary (**`.bgtask-card-summary`**) is the click surface: the opener button (**`.bgtask-card-open`**, **`aria-expanded`**) is stretched over the whole summary by an **`::after`** at **`inset: 0`**, so a click anywhere expands the card, and the summary answers the pointer with a **5%** text tint. **Stop** (**`composer-run-icon--stop`**, **24px** here, sized to the title row; **30px** on phones) is a sibling of the opener, not a child, and stands above the stretched surface (**`z-index: 1`**), so it keeps working on its own and never toggles the card.
- **A card opens in place.** There is no second pane and nothing to go back from: the open card (**`.bgtask-card-body`**, outside the stretched opener so its text selects) shows, top to bottom, the **command** in a monospace block with the shared copy control (**`CodeBlockCopyButton`**) in its top right corner - neither an agent run nor a preview server has a shell behind it, and nothing to put there - then the **error** - unless it only repeats the exit code, as the **`exit status 2`** the pool records for a command that exits 2 does (**`taskErrorText`**) - the captured **output** in a box of its own height (**56px** to **260px**, **46vh** on phones, its own scroll, following the tail unless the reader scrolls up; a dropped in-memory window is flagged **truncated**), and once the task has finished a **foot**: how it ended (**Succeeded**, **Failed**, **Timed out**, **Stopped**, **Orphaned**) and the **exit code** - **`Failed · Exit code 2`**. The exit code is said here and nowhere else on the card, and **how long the task ran is not repeated here**: the summary says it, folded or open. Neither an agent run nor a preview server has a process behind it, so their foot carries the outcome alone: the pool's exit code for them is synthetic. The way into the task is not said again here either: **Show transcript** and the address are the folded card's, like the elapsed time. **Any number of cards are open at once**, each reading its own output (**`loadOutput`**), again every **2.5s** while its task runs and once more when it ends. Which cards are open is the panel's own state and is **not part of the address**: the route says only that the panel is showing (**`#/s/<id>/tasks`**). The shell can still point at a card - a link that names a task (**`#/s/<id>/tasks/<task_id>`**, parsed, never written) - through the panel's **`focus`** prop: the card opens, its section with it, scrolls into view, and the address drops the id. The pointer names its chat and is spent once honoured (**`onFocusHonoured`**), because every session numbers its tasks from **`bg_1`** and the panel unmounts with the drawer; a card that is open renders even past the **40**-card cap of the finished list. An open card whose task has just ended moves under the counter, and the **Finished** section opens with it, so the card the reader was watching does not vanish.
- **Finished N** is a **counter** (**`.bgtask-section-toggle`**); expanding it renders the same cards, capped at **`FINISHED_RENDER_CAP`** (40) with a muted note naming what stays on disk. This is how "keep every log" and "do not load the app" hold at once: the history is counted, cards render on demand, and a task's output is fetched only when its card is opened. Running tasks carry **no heading of their own**: everything above the counter is running.
- **Clear** (**`.bgtask-section-action`**) appears only when there is history, and drops the finished tasks of this session via **`DELETE /coddy/sessions/{id}/background-tasks`**. Running tasks are untouched.
- **Empty state** names the chat, not the app: *No background tasks in this chat yet*.
- **Phones** (**`max-width: 1199px`**) give the panel the screen between the standard insets — there is no room to sit beside a transcript, and the output is what the operator came for. The cards take **12px** of padding and the output box up to **46vh**.
- **Tasks button** (**`.chat-view-btn--tasks`**, **`data-testid="chat-views-tasks"`**, the last of the view buttons in **`ChatHeader.tsx`**, below, at the right edge of the sticky chat header) is the opener of the panel and the one place a chat says how much runs in its background. The panel belongs to one chat, so its opener lives in that chat and not in the nav rail; the header does not scroll away, so the button stays in reach however far the reader has gone. Its tooltip and **`aria-label`** spell it out (**`Background tasks: 1 running, 3 in total`**). While a turn runs the **live line** names the running tasks too and opens the same panel (**`typing-dots-turn-tasks`**, see **States → Working**), and it stays at the tail with that count alone while tasks outlive the turn. Nothing is rendered under the transcript: the chip that used to sit there is gone.

### Workspace files window

**`external/ui/src/ui/files/FilesView.tsx`** (window, tree, tabs), **`FilePreview.tsx`** (one open file), REST client **`api.ts`**, the key in **`filesHotkey.ts`**. The window is framed like the documentation reader (**`.docs-dock-cluster`**), because both are a document read beside a conversation rather than a panel of it: the same glass sheet (**`.files-dock-cluster`**, **`--coddy-glass-panel-*`**), right of the rail, no wider than **`--coddy-dock-width`** and centred in what is left, over the shell's backdrop, which closes it on a click. **Expanded** (**`is-expanded`**, the arrows in its head) it takes the whole window, the rail included (**14px** from every edge), so the control does something at 1280px too, where the sheet already spans the space right of the rail.

- **Head** (**`.files-header`**): on the left the **tree switch** (a list icon, **`aria-pressed`**, accent-tinted while the tree shows) and the title spelled like the documentation's (**FILES** in small capitals, **12px**, a **72%** text tint) over the workspace folder's name (**11px**, its full path in **`title`**); on the right **More** (**⋮**), **Expand** and the close control (**`.sessions-close`**, **30px**). The icon controls are **30px** squares. **More** is a **`mode-menu`** hung inside the window (never clipped by the sheet): **Show hidden files** and **Wrap lines** as checkable rows, and **Preview** as a third one while the file on show is an SVG or an HTML file (below), then, with a file open, **Reload**, **Copy path** and **Download**.
- **What is on show brightens, it is never in the accent**: the pressed tree switch (**`.files-icon-btn.is-active`**, in the edits window too) takes the text at full strength, a border at **22%** and a ground at **9%** of the text colour, like the view buttons of the chat header; the file on show in the tree (**`.files-tree-row.is-active`**) a **9%** ground with a **1px** inset outline at **18%**. Pinned by **`chat/viewsLookCss.test.ts`**.
- **Tree** (**`.files-sidebar`**, **220-300px**): the filter on top, the rows as wide as it (the same **10px** side padding, the marked row's frame included, here and in the edits window), then one folder level at a time from **`GET .../workspace/tree`**, which lists **folders first, then files**, each by name, and pages with an opaque cursor (**`d/<name>`** / **`f/<name>`**). A folder is read when it opens, on its own; the open folders are read again when the page comes back into view, after a tool call, on Reload and on the hidden-files switch, each as far as it was read (**`rereadTree`**: the rows **Load more files** added stay; a page that brings nothing ends the walk), and a folder that is gone or refused folds away instead of failing the rest (**`Promise.allSettled`**). The answers are merged into the tree, never put in its place, so a folder opened or paged while they were on their way keeps its rows. Rows are **28px**, **13px** text, indented **14px** a level, and the column reads as one edge from the filter down: a top-level row's glyph stands where the filter's magnifier does (**20px** from the sidebar's edge) and its name starts where the filter's text does (**43px**), here and in the edits window (**`files/treeGeometry.ts`**, held to the stylesheet by **`files/filesWindowCss.test.ts`**): a folder carries the fold chevron (**`Chevron`**), a file an icon by what it holds (source, document, picture, other). A symlink or a special file is listed with **↗** and is not opened. The active file's row is brighter, with a light outline (above).
- **Filter** (**`type="search"`**, a magnifier inside it) searches the **whole workspace by name**, folders nobody opened included, through the same ranked index as the composer's **`@`** picker (**`GET /coddy/mentions`**, scoped like every cwd request with **`workspaceScope`**); only files and folders inside the workspace come back (the index also browses the disk for **`/`**, **`~/`** and **`../`** queries; those hits, and rooted or UNC Windows paths, are dropped). A new query clears the hits of the one before at once. A hit that is a folder opens the tree down to it. **Escape** with text in the filter clears it and is claimed; the next one closes the window. The filter takes the focus as the window opens, except on a touch-only device (**`composerAutoFocusAllowed`**).
- **Open files** are **tabs** (**`.files-tabs`**, **`role="tablist"`**, the close **×** a sibling of the **`role="tab"`** button), on a strip that stands as far under the head as the filter beside it (**10px**); a tab is **33px** and the strip's **1px** line under it makes the filter's **34px**, so the line the file starts under is level with the filter's bottom edge. Tabs that do not fit scroll sideways with no scrollbar and **no arrows**: the wheel turned over the strip moves it sideways, a finger swipes it, an end that has more fades out (**`has-more-left`** / **`has-more-right`**), and the tab on show is brought into the strip's view whenever it changes, by the strip alone (**`TabStrip`**): a file picked in the tree or a path clicked in the conversation opens a tab or shows its own; closing the tab on show shows the one beside it; a middle click closes one; two tabs with one name add their folder. The tabs outlive the window for the life of the page, per chat (its workspace is chosen once), each with its line (**`openFilesMemory`**, forgotten on an environment switch), so reopening the window finds them where they were, and the address learns the file on show. With none open the area says so in the middle: a folder icon, **Open files appear here**, and where they come from.
- **An open file** (**`FilePreview`**) is its body and nothing over it: the tab names the file, so there is no second name, no size or modification time, no switch over it between a rendering and the source (the one there is, **Preview**, is a row of **More**) and no line field (the address and the links set the line). Text is read **300 lines** at a time with line numbers and the chat's highlighting: the grammars of its code blocks (**`markdown/syntaxLanguages.ts`**), chosen by the extension or the file name (**`changes/diffLanguage.ts`**, every name of which is a registered grammar, **`diffLanguage.test.ts`**), and the lines on screen coloured **as one text** (**`highlightLines`**), so a comment or a string that spans lines keeps its colour on each; a line past **4096** characters stays plain and the text on either side of it is coloured on its own, and past **200000** characters on screen nothing is coloured, and a long file **scrolls through**: the next 300 lines are read as the reader nears the end of those on screen (**600px** ahead), the ones before as they near the top when the file opened at a line further down, the view kept where it was as lines go in above it; there are no pages to click. A file rewritten while it is read on answers **409**, is checked again, says so and starts over at its top. For now a file is only read, so the line an address names is scrolled to and not painted. A line's number and its text are one line box: **`.files-code`** sets one monospaced stack (the diffs'), **12px** at **1.6**, and the code element inherits it instead of the browser's own monospace, so the numbers never drift from their lines (**`files/filePreviewCss.test.ts`**; a **`var()`** naming a property nobody defines voids the whole declaration, which is how they once drifted, so **`cssVarsDefined.test.ts`** refuses one). **Markdown is text like any other**, its source with line numbers, so a picture or raw HTML in it is a line to read and nothing is loaded or run; a raster picture comes as bounded authenticated bytes (**20 MiB**) with fit / actual size; audio and video play natively from a **signed address** valid for at most an hour, which a swarm relay carries to the node without vouching for it (**`docs/operate/swarm.md`**). A **PDF** opens in the browser's own viewer where **`navigator.pdfViewerEnabled`** says the browser has one (**`FilePdf`**): bounded authenticated bytes (**50 MiB**), taken only when the node serves them as **`application/pdf`**, in a **`blob:`** address an **`<iframe>`** shows **without `sandbox`**, since every engine's viewer refuses to run in a sandboxed frame, so the viewer itself is the boundary; the **`blob:`** document belongs to the web UI's origin, where the raw route would serve the PDF in the node's origin under its sandbox policy, so a flaw in a browser's viewer would reach further, a risk the operator accepted for the preview; elsewhere (Chrome on Android) and when the read fails, a PDF downloads. **An SVG is a picture and an HTML file its source**, and **Preview** in **More** switches the kind to its other view for every file of the kind, remembered in this browser (cookie **`coddy_files_preview`**, **`files/previewPrefs.ts`**): an SVG drawn is an **`<img>`** of its bytes typed **`image/svg+xml`** (the node serves it as a download), which runs nothing the SVG holds and loads nothing it names, never SVG markup in the page, from a **`data:`** address and never a **`blob:`** one (a blob carries the page's origin, so the SVG opened from it in a tab of its own - dragged to the tab strip, or through a browser's own menu - would run its script beside the tokens; a **`data:`** document has an opaque origin), and not draggable; an HTML page drawn is read whole through the text reader (at most **2000000** characters, a longer one says so) and shown in an **`<iframe sandbox="">`** over the **`srcdoc`** **`htmlPreviewDocument`** builds (**`files/htmlPreview.ts`**): a policy first in its head that loads nothing but inline styles and **`data:`** pictures and fonts, its scripts, **`base`**, **`link`** and **`http-equiv`** metas dropped, a declarative shadow root kept an inert template and an SVG animation of a link's **`href`** or **`target`** removed, a link out of the page (an inline SVG's included) asking for a window the sandbox refuses; the page's relative pictures and stylesheets are not loaded, and it draws on a white canvas whatever the theme. The frame of a PDF or a page fills the file's place (**`.files-file-body--frame`**). Other binaries download. Each renderer shows only its own content, so a file rewritten as another kind under the same path never keeps the old text on screen. A failed read shows the server's message; the download hint goes with it only for a file that is not text (**415**). Returning to the page and a finished tool call check the file with its ETag, and a file that did not change is **not read again**: the text keeps its place and a playing sound or film keeps its address. A file rewritten under the preview says so, until another file opens or Reload, and starts over at its top. **Reload** reads it again whatever the ETag says, a picture, a PDF and a page included (they take **`epoch`**), so a read that failed on its way is not stuck; a media address is signed again after **50 minutes** at the next check, and once a minute at most when the media element fails.
- **Opened from** the Files button of the chat header, **`Ctrl+Shift+F`** / **`Cmd+Shift+F`** (matched on **`code === "KeyF"`**, so the Russian layout works; a second press closes it), a workspace mention in a sent message, a file tool's path, a permission preview's path, the card of a shared file and a path an answer names (**`openWorkspaceFile`**, **`files/fileBus.ts`**; *Markdown*, *Shared file cards*). Opening it puts the edits window (**`EditsView`**) away, and opening that one puts it away, so one Escape never closes two layers. **`#/s/<id>/files?path=<relative-path>&line=<one-based-line>`** is its address: a reload opens it on that file and line, and closing it gives the address back to the chat (**`#/s/<id>/tasks`** while the tasks show under it on the stacked shell). The window is built once per chat and folder (**`useFilesWindowKey`**, **`files/filesWindowKey.ts`**): an address opens it before the chat's workspace context answers, and that folder becoming known must not build it again, which read the open file a second time; only a folder that gives way to another one (a worktree the first send moved the chat into) starts it over.
- **Escape** closes the window when nothing nearer claimed the key (**`useRightDockEscape`**); the dock's own Escape waits while the window is open, so Escape takes the window first and the dock next. A click on the backdrop beside the window closes it the same way, the address going back to the dock's. Closing gives the focus back to whatever opened the window.
- **Stacked shell** (**`max-width: 1199px`**): the sheet is inset like the documentation's (below the top bar, **8px** from the sides) at **`z-index: 72`**, over the dock (**70**), which the window leaves open under it and which the address of the window keeps (**`applyLocationHash`**); expanded (**85**) it also covers the top bar (**80**). The tree keeps its column (**200-260px**) while it fits beside the file. On a **phone** (**`max-width: 599px`**) one column shows at a time: the tree until a file opens, then the file; the tree switch brings the tree back over it. A file opened by its address shows at once, not under the tree.

### Terminal window

**`external/ui/src/ui/terminal/TerminalPanel.tsx`** (the window), **`terminalFrame.ts`** (where it stands and how big it is, all of it pure). One host shell belongs to each chat and the server owns the process, so closing the window and opening it again keeps the working directory, the exports and the output already printed. It is opened by the Terminal icon of the header toolbar and closed by its own control, and by nothing else: it is not a view of the dock, it takes no Escape and no backdrop covers it, because a terminal is watched while the conversation goes on next to it.

- **A window on a desktop, the screen on a tablet or a phone.** From **1200px** up it is a small window the person moves by its head and resizes by any of its eight edges and corners (**`.terminal-grip--<edge>`**); the opposite edge stays where it was, a drag past the minimum (**320x200**) stops rather than turning the window inside out, and nothing leaves the viewport. **Maximize** in the head sends it to the **14px** inset of every other window, a double click on the head does the same, and on the stacked shell (**`max-width: 1199px`**) it is the whole screen with no head controls for a geometry there is no room to change. Where it stood and whether it was maximized are kept for this browser (**`coddy.terminal.frame`**, **`coddy.terminal.maximized`**); a frame remembered from a larger screen opens narrowed inside a smaller one rather than off it, and a window the viewport outgrows comes back inside on the next resize.
- **Over the chat, under its menus** (**`z-index: 86`**): above the top bar (**80**) and the expanded Files sheet (**85**), so a window dragged there stays reachable, and below the composer's menus (**90**). It is framed like the Files window - the glass panel tokens, a head of **`--coddy-panel-head-height`** on **`--coddy-panel-head-inline`** - and its colours come from the theme, so it is not a dark box in a light one.
- **The command line** has a prompt and an input, and **Enter** runs it: there is no Run button. The last **100** commands of that chat are kept in the browser (**`coddy.terminal.history.<id>`**), so Up and Down recall them after the window has been closed and opened; the shell's own history is on as well, so `history` lists what was typed here. **Restart** replaces the shell with a clean one. The input is **16px** on a phone, or iOS Safari zooms into it.
- **Whose prompt it is.** A shell that prints its own prompt and the line it read - PowerShell, even reading a pipe - is left to do it, and the **`❯`** echo is written only for the shells that do not (**`Shell.EchoesInput`**), so no command appears twice.
- **What it is not.** The shell reads a pipe, not a terminal device, so a program that draws a screen (an editor, `top`) has nothing to draw on; what it prints is shown as text with its escape sequences stripped. The output is capped at the last **512 KiB**.
- **`GET/POST/DELETE /coddy/sessions/{id}/terminal`** read it, write a line to it and replace it. A shell that ended stays until the next command, which starts a fresh one, so its last words and the reason it stopped can be read first. The server stops every shell when the HTTP surface drains, and a sweep of its own stops one nobody has read or written for **30 minutes**, so a long-lived server does not keep a process per chat that was open once.

### Edits of a chat

**`external/ui/src/ui/changes/`** (**`workingCopy.ts`**, **`EditsView.tsx`**, **`EditsTree.tsx`**, **`useDiscard.ts`**, REST client in **`api.ts`**, pure helpers in **`sessionChangesText.ts`**, **`diffRows.ts`**, **`contextExpansion.ts`**, **`viewedFiles.ts`**, **`richDiff.ts`**, **`fileTree.ts`**, **`diffLanguage.ts`**, **`highlightLine.ts`**).

- **The edits are git's report of the folder**, never a recording: every tracked file that differs from **`HEAD`**, staged or not, and every new file git does not ignore (**`GET /coddy/sessions/{id}/changes`**, **`internal/gitws`**). Whoever made a change - the agent, a shell command, an editor beside Coddy - it reads the same. A folder in no repository has no edits, and the views say so instead of showing an empty diff. Without the git binary the server answers through its built-in implementation (go-git), which detects no renames. A repository nested in the folder is one entry, read and discarded as nothing.
- **One read per chat** (**`workingCopy.ts`**: a store keyed by session, **`useSyncExternalStore`**): git's count on the plate over the composer and the edits window share it. It reads when a view of the chat mounts, on the server's word about any chat (**`turn_ended`** after any turn, whichever surface ran it, and **`session_changes`** after a discard, both put on **`sessionChangesBus.ts`** by **`App.tsx`**; chats share folders, so another chat's turn moves this one's too), **400 ms** after the last of a burst of finished tool calls, and when the page gets the focus back, since the folder may have been edited elsewhere. A read asked for while one is in flight runs once after it; a failed read keeps the last answer on screen and says why (**`error`**), so a window with nothing known yet shows the reason instead of a blank; another environment forgets every chat's (**`onEnvironmentSwitch`**).
- **The edits window** (**`EditsView.tsx`**) is the one view of the edits, a window over the chat **framed and headed like the Files window** (**Workspace files window**, above), so the two read as one kind of window: the same glass sheet (**`.files-dock-cluster`**: right of the rail, **14px** from the top and the bottom of the viewport like the documentation and the files, no wider than **`--coddy-dock-width`**, the same inset on the stacked shell), over the shell's backdrop, which closes it on a click; **Expand** takes the whole window. Git's count on the plate over the composer (**Bar over the composer**) opens it; **Escape** closes it when nothing nearer claimed the key (the confirmation dialog over it answers its own, the tree's filter clears itself, the menu closes first; **`useRightDockEscape`**). **`#/s/<id>/changes`** is its address, so a reload opens it again; closing it gives the address back to the chat. The dock under it stays as it was. Layout: the head, then the tree of the changed files beside one scrolling document of file sections (**`.files-layout`**).
  - **Head** (**`.files-header`**): on the left the **tree switch** and the title (**EDITS**, spelled like the Files window's) over the folder's name and git's **`+A −D`** (where the line is short, on a phone, the folder's name takes the ellipsis and the count stays whole); on the right **More** (**⋮**), **Expand** and the close control, the Files window's **30px** squares. **More** holds **Side by side** (a checkable row; not offered on the stacked shell), **Collapse all** / **Expand all**, and after a separator **Discard all** in the colour of a deletion. Nothing else stands in the head: no toolbar of the window's own and no go-to-file list, which the tree replaces.
  - **Tree** (**`EditsTree.tsx`**, the Files window's **`.files-sidebar`** with its filter and rows): **only the files git reports as changed and not committed**, in their folders (a run of single folders is one row, **`fileTree.ts`**), each with an icon by what it holds and git's letter at the right end of the row (**`.edits-tree-status`**: **A** in the colour of an addition, **D** of a deletion, **M** muted). The filter narrows it by path; a folder folds on a click. The diffs read in the tree's order (**`treeOrder`**), so the mark walks the tree from top to bottom: the file at the top of the diffs is marked like the file on show in the Files window, a file picked scrolls the diffs to its section and highlights its card with an accent frame; selecting a Viewed file unfolds its body without clearing Viewed, and as the reader scrolls the mark follows, the tree bringing the marked row into its own view when many files make it scroll. A pick scrolls the diffs alone (never **`scrollIntoView`**, which moves every scrollable box around them), the file's card **10px** under their top, and **pins** it there while the diffs above it load or fold, until the reader scrolls away; a pick made while the patches were still on their way was otherwise carried down by every one that landed above it. The tree shows as the window opens; on a **phone** the window opens on the diffs, the tree switch brings the tree over them, and a file picked there gives the screen back to the diffs.
  - **The diffs' column keeps the tree's distances**: **10px** from its sides and its top (**`.dv-scroll`**), like the filter in the tree's column, the cards **10px** apart; the first card starts where the filter does.
  - **File section** (**`.dv-file`**) has a **sticky** header **33px** tall; left to right: the fold chevron, the muted folder and the bold file name, then **copy path** and **Expand all lines** beside the name, and a source/rich switch for Markdown to the right of the counts or sizes. Binary files have no source/rich switch. **Viewed** and a three-dot file-actions menu close the row. The checkbox folds the file while checked, expands it again when unchecked and restores the fold on reopening. It remembers the content digest in localStorage and is withdrawn when the digest changes, even if the line counts did not. The window header shows **`ViewedProgress`**, a `viewed / total` count and circular ring that turns green when every listed file is viewed; a phone hides the long label and keeps the compact counts and accessible full summary. A changed digest immediately removes that file from the count. The body renders **unified** (default) or **split** from **`toUnifiedRows`** / **`toSplitRows`**; a run of removals is zipped against the following run of additions, and context ends a run so unrelated edits are never drawn as a replacement.
  - **Rich diff** is available for Markdown and supported raster images. Markdown shows the rendered before and after versions. An added or deleted image shows its one version; a modified image shows before in a red frame beside after in a green one, stacked in one column on a phone. Exact byte sizes in the old and new colours replace line counts for an image. Raw image bytes come from the authenticated detail route, through **`useApiImageSrc`**, so remote environments and relays work without credentials in the URL.
  - **Line numbers** stand in cells as wide as the file's widest number (**`.dv-num`**, **`--dv-num-digits`** set on **`.dv-diff`** from **`lineNumberDigits`**, two digits at least), never as their own number: a cell sized by its content put the code of a removed or an added line, whose other cell is blank, and of a row of shorter numbers a few pixels left of the context around it. So the code starts at one edge on every row of a file, in either view (**`editsWindowCss.test.ts`**, **`DiffFileSection.test.tsx`**; measured in a real engine by **`npm run check:diff-gutter`**). Inside a change the removed lines come first, then the added ones, the way git writes them (**`internal/linediff`**, **`removalsFirst`**), which is the order the split view pairs.
  - **Between hunks** is a separator (**`.dv-gap`**) with up, down and both-direction controls that reveal **10** lines at a time from the complete before/after text already returned by the detail route. **Expand all lines** reveals every remaining line, including the file ends, and becomes **Collapse all lines**. Collapsing restores the original hunks and discards context revealed through either control without folding the file card. Overlapping expansions never duplicate a row, and a separator disappears when expansion makes its hunks contiguous. A server-truncated patch offers neither control.
  - **Syntax colouring** comes from **`lowlight`** - highlight.js behind a tree API, the same engine the markdown renderer already uses, with the same grammars (**`markdown/syntaxLanguages.ts`**) - so the **`hljs-*`** classes already in the stylesheet apply and no markup is ever injected. The grammar is chosen from the file extension (**`diffLanguage.ts`**), never auto-detected: a diff hands the highlighter a few lines at a time and detection on a fragment that short changes its mind between hunks. An unknown extension renders as plain text. Colouring is per line, so a construct spanning lines is coloured as if it began on the line drawn - the trade every line-addressed diff view makes.
  - **File actions** (**`FileActionsMenu.tsx`**, immediately right of **Viewed**) hold **Discard changes** and **Delete file**, each behind the shared danger confirmation dialog. The menu is portaled, so it works while the file is folded. Discard puts a file back at **`HEAD`** through **`.../changes/revert`**; delete removes it through **`.../changes/delete`**, leaving a tracked file reported as deleted and removing an added file from the change set. **Discard all** in **More** discards every change. The window reads again whatever the answer (**`useDiscard.ts`**). A commit is not offered. With nothing left the window says the folder is clean.
  - **Binary and image metadata.** Any binary file carries the old and new byte sizes in place of line counts, with exact counts in tooltips. A rich image diff shows a red **Before** beside a green **After**, or only the version that exists. The coloured label and the loaded width and height stand outside the image frame as **`W … · H …`**, and images scale down to 320px high without distortion. Markdown rich preview renders only the new version with the chat's Markdown component; deleted Markdown keeps its old version.
  - **Patches load per file**, four at a time, so the list and its counts paint at once and one huge file cannot hold up the rest; when git's report moves, only the files whose state moved are read again. The view choice persists in the **`coddy_diff_view`** cookie. On the stacked shell (**`isMobileShell`**) the split option is hidden and every diff reads inline.

### Canvas

**`external/ui/src/ui/canvas/`** (**`CanvasBoard.tsx`**, **`CanvasFrame.tsx`**, **`CanvasNodes.tsx`**, **`CanvasPromptBar.tsx`**, the camera in **`cameraStore.ts`**, the board read in **`useCanvasBoard.ts`**, REST client in **`api.ts`**, pure helpers in **`camera.ts`**, **`bridgeProtocol.ts`**, **`pickPrompt.ts`**, **`jsonCanvas.ts`**). The guide is **`docs/features/canvas.md`**.

- **A tab of the Files window.** A canvas is a `.canvas` file of the workspace, and it opens where every file opens: a tab of the Files window (**Workspace files window**, above), whose body is the board instead of the file's text (**`.canvas-pane`**, a column: the board, then the prompts strip, then the prompt bar). There is no window, no header button and no address of its own: the address is the Files window's, **`#/s/<id>/files?path=<file>.canvas`**. The board is a chunk of its own (**`lazy(() => import("../canvas/CanvasBoard"))`** in **`FilesView.tsx`**), so **`app.js`** carries only the Files window, the tool card and the API client. **Preview** in the window's **More** shows the file's JSON instead (**`coddy_files_preview`**, kind **`canvas`**, a board by default). The Files window opens on the file by itself when the agent puts a page on a canvas (never on a phone, never over another window or screen), from the canvas_show card, and from **Open on canvas** in **More** for an HTML file, which puts the page on the chat's canvas and opens that file on its frame. Opening the tab makes the file the chat's canvas (**`POST .../canvas/open`**).
- **The board** (**`.canvas-board`**): a dotted ground (**22px** grid, a **13%** text tint). The wheel zooms it at the pointer and a drag of the empty board pans it, two fingers pinch it, **5%** to **200%** (**Zoom**, below). It is fitted when it first shows something and on the frame the agent's last show points at; until the person moves or zooms it, a resize fits it again. Where **`overflow: clip`** is supported, only the camera moves it: the board is no scroll container, so a page's **`focus()`** in a frame off screen cannot scroll it there behind the camera (issue #679). An **`overflow: hidden`** fallback preserves clipping where **`clip`** is unsupported; there the board remains a scroll container and the older focus scrolling stays possible. The mode switch (**Interact** / **Comment**, **`.canvas-mode`**) stands at its top left, the zoom controls at its top right, both opaque (no **`backdrop-filter`** over a board that moves).
- **One world layer.** Everything on the board stands at its own size in board units inside **`.canvas-world`**, a point at the board's origin whose transform the camera writes (**`CameraStore`**: once per animation frame, outside React, with **`--canvas-scale`** and **`--canvas-inv`** on the board for what keeps its size on screen). A pan or a zoom renders nothing: frames, nodes and edges are memoized and change only when the board read says so; the level of the zoom controls is the only subscriber. While the board moves it is one compositor layer (**`.is-moving`**, **`will-change: transform`**, dropped **160ms** after the last move so the pages are drawn sharp again). While a board shows, the Files window is opaque and the chat it covers drops its glass (**`.files-dock-cluster:has(.canvas-pane)`**, **`:root:has(.canvas-pane)`**): a blur over or under a moving board is drawn again on every frame, which cost about a hundred milliseconds a frame.
- **A frame** is an **`<iframe>`** of its page at the page's own size in the world layer, never transformed itself, under **`sandbox="allow-scripts allow-forms allow-modals"`** and **`referrerpolicy="no-referrer"`**, never **`allow-same-origin`**, on a white ground whatever the theme. Its title bar (**`.canvas-frame-bar`**) stands on its top edge scaled back by **`--canvas-inv`**, as wide on screen as the frame and never under **180px**, the size giving way before the title; it moves the frame, and holds its size menu (**`.canvas-frame-menu`**), reload and remove. The bar stands over the pages (**z-index 2**, **3** while its menu is open), so the menu is never under a page. A frame reloads only when its stamp, its generation or its page moves, or its address nears its end (renewed on the page's own clock); a board read again that changed nothing draws nothing again (**`boardFingerprint`**, the fresh signatures aside, which the board takes every **10 minutes**).
- **Nodes of the file** (**`CanvasNodes.tsx`**) are drawn in Obsidian's order: groups first (**`.canvas-group`**, a **2px** border at **28%** of the text or **70%** of its colour, a **5%**/**9%** wash, its label as a chip above its top left edge, scaled back like a title bar), then the edges, then the cards (**`.canvas-node`**, **8px** radius, a faint border and a lifted ground, a coloured node taking its colour for the border and **10%** of it for the ground), then the frames. A card's body stands at the node's own size: a text card is its Markdown at **16px**, a `.md` note shows its name and its Markdown (read again every **10 s** on the card's own clock, the last text kept meanwhile), a picture fills the node, any other file and a link are a card (kind in small capitals, the name, the folder or the address, **Open in Files**), and a link opens only an `http(s)` address. A text card and a note read a single line break as a line break, as Obsidian does with its default "Strict line breaks" off (**`Markdown`** with **`breaks`**, the **`remarkSoftBreaks`** pass): code keeps its newlines, and every other Markdown body keeps CommonMark's soft break. Colours are the six presets of JSON Canvas (**`PRESET_COLORS`**, Obsidian's red, orange, yellow, green, cyan and purple) or a hex value; anything else is ignored, never put into a style. Dragging a card moves it, dragging a group moves it with every node inside it, in board units (the pointer's travel over the scale at the press); the pointer is captured only once a drag passes **4px**, so a click on a link inside a card stays a click, and a moved node stays where it was put until the board read after the change says so.
- **Edges** (**`.canvas-edges`**, one SVG in the world layer, **`pointer-events: none`**) are Obsidian's curves in board units: from the middle of the side an edge names, or the side facing the other node, out along that side and into the other node the same way, a **2px** stroke on screen (**`vector-effect: non-scaling-stroke`**) at **45%** of the text or the edge's colour, an arrowhead at the end unless it says none and at the start when it says so, and the label as a chip at the middle of the curve, scaled back like a title bar.
- **Comment** picks an element of a page: the bridge outlines it, a note opens beside it (**`.canvas-popover`**, opaque so the page does not show through, placed in screen units from the camera at the pick), **Add** makes it a chip of the prompt bar. **The prompts strip** (**`.canvas-prompts`**) shows the permission and question cards the turn waits for above the bar, since the window covers the chat. **The prompt bar** (**`CanvasPromptBar`**) under the board is the chat's composer in small: **Chat** closes the Files window, the field, and one action button as the composer's (Send, Queue while a turn runs and the field holds text, Stop while it runs and the field is empty); its draft is kept per chat and file for the life of the page, and a request the server never took comes back to it. The bar takes at most **60%** of the pane and its chips at most **90px** (about three rows), which scroll; at least one chip row stays visible, and the bar itself scrolls when a shorter pane cannot hold it and the field together. The row of the field and the button never shrinks, so on a short screen (a phone with its keyboard open) many picks and a long prompt never push Send out of reach (issue #569). A file that cannot be read says so in a banner at the top of the board (**`.canvas-link-error`**, a danger-tinted ground).
- **A page that waits** (**`CanvasTrust.tsx`**): a frame the server marks **`held`** - a page of a board that came with the workspace that no receipt lets run (**`tools.canvas.project_trust`**) - has no address and loads nothing. Its place is an empty frame (**`.canvas-frame--held`**: the theme's ground, a **1px** dashed border at **30%** of the text) with a block in its middle scaled back by **`--canvas-inv`** (**`.canvas-held`**, **320px**) but never past its frame: below that zoom it shrinks with the frame (**`--canvas-held-fit`**, the frame's size over **320x200**), so a phone's fitted board keeps it inside: what it is, the page's path, the folder it would read, and **Run the pages of this board**, which under **`deny`** is a line saying so instead. The button opens **`.canvas-trust`**, a dialog over the middle of the board, opaque like the note: every waiting page with the folder it reads, **Cancel** and **Run pages**, which sends the board's **`trust.digest`**; a **409** keeps the dialog with the board read again and says the list changed. **Hold pages** (**`.canvas-hold`**, the board's bottom left corner, the mode switch's ground and border, no shadow) shows while the policy is **`ask`** and a page runs, and makes every page of the board wait again.
- **Escape** closes the trust dialog or the note first, then leaves Comment, then closes the window.

### Zoom

Every surface that zooms - the picture viewer (**`ImageLightbox`**), a canvas board, the swarm map - zooms one way and shows one set of controls (**`ui/components/zoom.ts`**, **`ui/components/ZoomControls.tsx`**).

- **The wheel** zooms at the pointer, continuously: **`wheelFactor`** reads the delta in pixels (lines **16px**, pages **400px**) and **500px** of wheel double or halve what is under the pointer (**`WHEEL_DOUBLING_PX`**). A pinch zooms around the point between the fingers; a drag pans.
- **The controls** (**`.zoom-controls`**) are one group at the top right of what they zoom - the canvas board's and the swarm map's corner, the picture viewer's bar beside its close control (**`zoom-controls--inline`**): minus, **the level** (**`.zoom-control--level`**: the percentage, or the fit glyph while the view is fitted; a click fits) and plus, each **28px** square at every viewport width (the level is at least **48px** wide and may grow for the percentage, and the bordered group is **36px** tall), on an opaque ground with the glass border, never a **`backdrop-filter`**. The buttons and **`+`** / **`-`** step by **`ZOOM_STEP`** (**1.25**) on the board and the map; the picture viewer keeps its 100 / 150 / 200 / 300 ladder. **`0`** fits.

### Background task on a transcript row

A **run_command** call with **`background: true`** returns the instant the task starts, so the call's own duration (**`0ms`**) is not the duration of anything. When a transcript tool call matches a task's **`tool_call_id`**, **`ToolCallMessage`** puts the **task's clock** in that slot instead (**`.thinking-dur`**, **`data-testid="tool-bgtask-elapsed-<id>"`**, ticking with the shared poll while the task runs), and the row's label already says the run is in the background. That is all the transcript says about it.

- **The outcome is not on the row.** The status (**Running**, **Succeeded**, **Failed**, **Timed out**, **Stopped**, **Orphaned**), the estimate and the exit code belong to the **task**, and are read where a task is read: its card in the **Tasks panel** (the meta line, and in the open card the error, the captured output and the foot). A transcript is a log of what the agent did, not a status board - a row that kept re-writing its own outcome made a background run look like a different kind of row.
- **Expanded**, the body keeps the task's clock and gains nothing else: there is no way into the task and no Stop on the row (no **`.tool-bgtask-actions`**). The task is opened and stopped where it lives, on its card in the **Tasks panel**, which a link that names it (**`#/s/<id>/tasks/<task_id>`**) opens at that card.
- The mapping comes from the same poll that feeds the drawer (**`backgroundTasksByToolCallId`** in **`App.tsx`**), so the transcript and the drawer can never disagree.

### Woken turn

A turn nobody typed - background tasks the model started ended and the server woke the agent (**`notify_on_finish`**, on by default) - shows **nothing of its own** in the transcript: no user bubble, which would put words in the operator's mouth, and no note either. The agent's answer follows the previous turn as the work carrying on, and the **bell** on the task's card in the Tasks panel says what woke it.

- The first message of the turn still arrives, as a **`background_wake`** item (**`chat/backgroundWake.ts`**) built from the relay frame live and from the message's **`background_wake`** field after a reload, and **`MessageList`** renders it as nothing.
- The item **opens a turn**: the live status line counts from it, the edit index of a later message counts it the way the server counts user messages, and a failed woken turn offers no retry.

### Subagent transcript (read-only)

A child session is the transcript of one delegated run. **`GET /coddy/sessions/{id}/messages`** marks it with **`subagent {parentSessionId, name, taskId}`** and **`readOnly: true`**; an ordinary session carries neither field, so their absence means a normal chat (**`parseSubagentTranscriptMeta`** in **`chat/subagentTranscript.ts`**). Either field alone is enough to lock the composer.

- **Composer slot.** **`ChatScreen`** renders **`SubagentReadOnlyNotice`** (**`.subagent-readonly-notice`**) in place of the **`Composer`**, in both the hero and the docked layout: *Read-only transcript of subagent `<name>`. Prompts go to the parent chat.* plus an **Open parent chat** link. The line under it names the effective model with its reasoning level in parentheses, **`codex/gpt-6.1-sol (High)`**: the level is **`selectedReasoning`** of the messages answer, capitalized as the composer's selector writes it, so a spawn override, a definition and the model's default all read alike. A model that offers levels with none chosen reads **`(Default)`**, which names the provider's own choice instead of inventing a level; a model without levels has no parentheses. The notice reuses the composer's glass card tokens so the bottom of the column keeps its weight, and it sits inside **`.chat-bottom-inner`**, so the transcript's bottom reserve is measured from it exactly as from the composer.
- **Nothing is sent.** With no composer there is nothing to submit; the shell additionally drops **`onSend`**, retry, message editing and the plan card's **Run plan** / **Discard** for such a session, because the server answers **409** to every prompt against a child. The plan handlers are withheld, not stubbed (the same conditional spread as **`onEdit`**), so a **`plan_document`** card on a child renders without its footer and with a read-only markdown editor (**`.plan-document-card--readonly`**) instead of showing controls that do nothing.
- **Back to the parent.** The link is a real **`#/s/<parentSessionId>`** href (middle-click and Ctrl/Cmd-click open a tab); a plain click goes through the same in-place session open as a History pick.
- **Header.** A child has no History row to name it, so the chat header falls back to *Subagent `<name>`* (**`chat.subagentTitle`**) instead of *New chat*.
- **Reaching it.** Child sessions are hidden from History, and nothing about a child's id sets it apart. They are reached from the Tasks panel (**Show transcript** on the run's card, which does not have to be opened for it) or by URL; the shell fetches any id it is given even when the sessions list does not carry it, and lets the messages endpoint answer. While the child runs the live state is served, afterwards the bundle, so the transcript shows the child's tool calls and its final answer through the ordinary renderer.

### Markdown line editor (shared)

Single implementation: **`MarkdownLineEditor`** in **`external/ui/src/ui/markdown/MarkdownLineEditor.tsx`**. Gutter math lives in **`external/ui/src/ui/markdown/markdownLineGutter.ts`**. Scheduler imports the same module via **`external/ui/src/ui/scheduler/MarkdownLineEditor.tsx`** (re-export only). Styles: **`.md-line-editor`** and **`.md-line-editor--plan`** in **`external/ui/src/styles/screens/_scheduler.scss`**.

**Consumers**

- Plan document card, markdown mode (**`PlanDocumentSection`**).
- Scheduler job editor **`body (markdown)`** (**`SchedulerJobEditorSheet`**).

**Layout**

- Horizontal flex: **gutter** (line numbers) + **stack** (highlight backdrop + **`textarea`**).
- Uses the **full width** of the parent. The **`textarea`** has **no vertical or horizontal scrollbar** (**`overflow: hidden`**, **`overflow-wrap: anywhere`**). **Height grows with content** (plus a **minimum logical row** count). When the surrounding UI needs scrolling (scheduler editor scroll region, long chat transcript), the **outer** container scrolls, not the inner editor.

**Line numbers**

- Numbers mark **logical** lines (split on `\n`).
- When a logical line **wraps** to multiple visual rows, only the **first** visual row shows a number; wrapped continuation rows keep an **empty** gutter cell at the same row height.
- When the document has fewer logical lines than **`minRows`**, pad the gutter with numbered blank rows up to **`minRows`** (scheduler default **10**, plan card **4**).

**Active line**

- The logical line that contains the caret is highlighted across **every** visual row it occupies: one **`md-line-editor-hl-band`** per visual row with **`is-current`** (semi-transparent background). The matching gutter number uses **`is-active`**.

**Measurement**

- A hidden probe (**`md-line-editor-measure`**, same font and wrap rules as the textarea) measures each logical line at the textarea **text width** (inside horizontal padding).
- Visual row count per logical line: **`ceil((measuredHeight - 1) / lineHeightPx)`** (see **`measureLineVisualRows`**). Gutter rows and highlight bands share the fixed band height **`--md-editor-line-px`** set on the editor root from computed line height.

**Typography**

- Default (scheduler): **12px**, line height **1.45** (**`--md-editor-fs`**, **`--md-editor-lh`**).
- Plan variant (**`.md-line-editor--plan`**): **13px**, line height **1.5**.

### Plan mode plan document card

**Component**: **`PlanDocumentSection`** (**`external/ui/src/ui/chat/PlanDocumentSection.tsx`**). Rendered from **`plan_document`** transcript items (**`MessageList`**).

**Collapsed**

- **Title**: frontmatter **`name`** or **`slug`**. **`title` attribute** (native tooltip) shows absolute file **`path`** when known (for example **`…/plans/<slug>.plan.md`**).
- **Description**: one line from **`overview`** or the first non-empty body line.
- **Footer**: **Discard** and **Run plan** stay visible; expand/collapse is on the header button only.

**Expanded**

- **Left accent**: **`box-shadow: inset 2px 0 0`** orange on **`.plan-document-card--expanded`** (not discarded).
- **Header**: title toggles expand; optional **Saving…** or save error after debounced PUT.
- **Body pane** (**.plan-document-pane**): one region for content. **Eye control** top-right (**`Toggle preview`**, **`aria-pressed`** when preview is on). **Default: Preview** ( **`Markdown`** on body text). Toggle switches to **Markdown** (**`MarkdownLineEditor`**, **`className="md-line-editor--plan"`**, **`minRows={4}`**, spellcheck enabled).
- **No fixed-height clip** on the pane: **preview** and **markdown** both **grow with content**; **no inner scrollbar** on **`.plan-document-pane-inner`**. The chat column scrolls when the card is tall.
- **Footer**: **Discard** (text link) and **Run plan** (orange, ▶ icon). **`min-width: 640px`**: CSS grid places **head** and **actions** on one row, **body** full width below; actions stack in a column on the right.

**Editing**

- The editor shows **markdown body only** (YAML frontmatter stripped via **`planEditorBody`** in **`planContent.ts`**). Autosave **`PUT /coddy/sessions/{id}/plans/{slug}`** with JSON **`{ "body": "…" }`**, about **600ms** debounce.

**Discard**

- **`DELETE`** marks the plan **`discarded`** in session state; the card **stays** in the transcript, muted (**`.plan-document-card--discarded`**), controls disabled. Server excludes discarded slugs from the plan-mode system prompt.

**Read-only transcript**

- **`onRunPlan`** and **`onDiscard`** are optional. **`MessageList`** forwards **`onPlanDocumentRun`** / **`onPlanDocumentDiscard`** only when the shell provides them, and a subagent child transcript provides neither (exactly like **`onEdit`**). With no handler at all the card carries **`.plan-document-card--readonly`**, renders **no footer**, keeps the preview and the eye toggle, opens the **`MarkdownLineEditor`** as **`readOnly`**, and schedules no autosave **`PUT`**. Each footer button is also rendered only when its own handler exists, so no stubbed handler can leave a dead **Run plan** or **Discard** on the screen.
