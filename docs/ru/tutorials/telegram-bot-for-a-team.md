# Telegram-бот для команды

Один процесс `coddy serve` опрашивает бота, отвечает в разрешённых вами чатах и хранит каждый диалог как обычную сессию, которую веб-интерфейс того же процесса может смотреть и продолжать. Полный справочник - [Telegram-шлюз](../surfaces/gateway.md); этот рецепт проводит через настройку для командного чата.

1. **Возьмите бинарник со шлюзом.** Релизные бинарники, пакеты и образ собраны с тегом `gateway`. Из исходников соберите только адаптер Telegram или полный набор.

   ```bash
   make build TAGS="gateway.telegram"
   # or the set a release ships
   make build TAGS="http ui scheduler memory cli gateway swarm"
   ```

   Если включить бота в бинарнике, собранном без тега, при запуске будет ошибка с именем тега, так что несоответствие не пройдёт незамеченным.

2. **Получите токен и id.** Создайте бота командой `/newbot` у [@BotFather](https://t.me/BotFather) и сохраните токен. Узнайте у [@userinfobot](https://t.me/userinfobot) свой id пользователя Telegram и id каждого коллеги, которого хотите внести в список разрешённых. Не держите токен в `config.yaml` - `~/.coddy/.env` читается до загрузки файла, а окружение процесса всегда главнее него.

   ```text
   TELEGRAM_BOT_TOKEN=8992982910:AAF...
   ```

3. **Опишите команду в конфигурации** ([Справочник по конфигурации](../surfaces/gateway.md#справочник-по-конфигурации)).

   ```yaml
   gateways:
     telegram:
       enable: true
       token: "${TELEGRAM_BOT_TOKEN}"   # may be omitted: an empty token reads TELEGRAM_BOT_TOKEN
       admins: [123456789]              # your own user id; admins pass every access check
       default_access: "admins"         # all | admins | group:<name>
       default_isolation: "shared"      # individual | shared | admin (group chats only)
       user_groups:
         - name: "devs"
           user_ids: [111222333, 444555666]
       chats:
         - chat_id: -1001234567890      # the team's group: every dev, one shared session
           access: "group:devs"
           isolation: "shared"
   ```

   `default_access` определяет, кто может говорить с ботом в чате без собственной настройки. `admins` отвечает только перечисленным id, `all` отвечает всем, кто может писать в чат, `group:<name>` отвечает участникам этой записи `user_groups` (администраторы проходят всегда). Запрещённые сообщения молча отбрасываются. `default_isolation` действует только в групповых чатах (в личном чате всегда одна сессия на пользователя) и выбирает область сессии - `individual` даёт каждому участнику собственную сессию, `shared` даёт всей комнате одну сессию, которую продолжают все, а `admin` отвечает только администраторам, и они делят одну сессию. `chats` переопределяет оба значения для отдельного чата; `chat_id` группы отрицательный. Добавьте `rich_messages: true`, чтобы на сервере Bot API 10.1 получить родной Markdown и сворачиваемые блоки инструментов.

4. **Проверьте файл, затем запустите в фоне** ([coddy serve и демон](../operate/serve.md)).

   ```bash
   coddy serve --dry-run   # checks the token against the Bot API and names the bot
   coddy serve --daemon    # or -d
   coddy serve status
   ```

   `--daemon` отсоединяется от терминала и оставляет диспетчер, который перезапускает рабочий процесс, когда тот завершается по любой причине, кроме `coddy serve stop`. Команда ждёт первого рабочего процесса и только потом возвращается, так что о конфигурации, с которой нельзя стартовать, вы узнаете в том же терминале, где набрали команду. Запись хранится в `~/.coddy/serve.json`, лог - в `~/.coddy/logs/serve.log`; `coddy serve restart` поднимает процесс снова с теми аргументами, с которыми он был запущен. Под `systemd`, Docker или другим супервизором, который уже управляет жизнью процессов, запускайте `coddy serve` на переднем плане и оставьте перезапуски супервизору. Запускайте один процесс на токен бота - Telegram отдаёт каждое обновление одному длинному опросу, и второй опрашивающий процесс крадёт сообщения у первого. Чтобы запустить только бота и ничего больше, задайте `--http=false` или `httpserver.enable: false`.

5. **Откройте тот же чат в браузере** ([Одна сессия в чате и в браузере](../surfaces/gateway.md#одна-сессия-в-чате-и-в-браузере)). Когда `httpserver.enable` включён (а по умолчанию так и есть), тот же процесс отдаёт веб-интерфейс по адресу `http://127.0.0.1:12345/`. Диалог в чате - обычная сессия того же вида и с тем же видом id, что и сессия, начатая во вкладке браузера или в терминале. Такие сессии видны в списке сессий в боковой панели, ход, на который отвечает бот, транслируется во вкладку, которая за ним следит, а ответ, набранный в браузере, попадает в историю чата к следующему сообщению. Запросы разрешений остаются в чате, и шлюз сам отвечает на них, чтобы бот работал без присмотра, поэтому дайте процессу рабочую папку, изменения в которой вы можете себе позволить (`coddy serve --cwd DIR`, иначе каталог, из которого его запустили). В сессии выполняется только один ход за раз; сообщение, пришедшее, пока идёт ход из браузера, получает уведомление о занятости и не перемешивается с ним. Чтобы открыть интерфейс с другой машины, задайте `httpserver.host: "0.0.0.0"` и токен, как в следующем рецепте.

6. **Пользуйтесь ботом из чата** ([Модель взаимодействия с ботом](../surfaces/gateway.md#групповые-чаты)). В личном чате бот отвечает на каждое сообщение. В группе он реагирует, только когда его упоминают через @, когда сообщение отвечает на одно из его собственных, или на `/clear`; при изоляции `admin` он ещё и игнорирует всех, кого нет в `admins`. `/agent`, `/plan` и `/ask` переключают режим сессии, `/model` открывает встроенную клавиатуру с настроенными моделями, `/context` показывает, чем заполнено окно контекста, а `/clear` начинает новую сессию для этого пользователя или чата - старый бандл остаётся на диске, и `coddy sessions list` по-прежнему его показывает. Изменённый токен пересобирает шлюз на месте, а переключённый `enable` запускает или останавливает его без перезапуска процесса. Если нажатие на кнопку будто ничего не делает, поднимите уровень лога одного компонента - `coddy serve --log-level "info,gateway.telegram=debug"` ([Отладка чата](../surfaces/gateway.md#отладка-чата)).
