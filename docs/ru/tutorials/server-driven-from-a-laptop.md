# Сервер, которым управляют с ноутбука

`coddy serve` работает на сервере, за которым стоят рабочая папка и модель; на ноутбуке только клиент. Консоль, редактор по ACP и веб-интерфейс работают с одним и тем же сервером, и сессии остаются на нём. Полное руководство - [Удалённый режим](../operate/remote.md); флаги ниже описаны на страницах [Консоль](../surfaces/console.md), раздел "Удалённый режим (`--remote`)", и [Аутентификация](../reference/http-api.md#аутентификация-необязательно).

1. **Дайте серверу токен и привяжите его к адресу не на loopback.** Bearer-аутентификация по умолчанию выключена. Задайте токен через окружение или `--auth-token`, а не записывайте его в файл; ссылка `${ENV}` в `httpserver.auth_token` тоже работает. `host` по умолчанию равен `127.0.0.1`, потому что один процесс запускает все включённые подсистемы, и включение бота не должно заодно открывать API в сеть. `cors` нужен для браузера в шаге 4.

   ```yaml
   httpserver:
     host: "0.0.0.0"
     port: 12345
     auth_token: "${CODDY_HTTP_TOKEN}"
     cors:
       enable: true
       allow_loopback: true   # the laptop's UI is served by its own coddy serve: any loopback address, any port
   ```

   ```bash
   export CODDY_HTTP_TOKEN="a-long-random-string"   # or a line in ~/.coddy/.env
   coddy serve --dry-run    # binds the address once, names a port somebody else holds
   coddy serve --daemon     # foreground `coddy serve` under systemd or Docker
   ```

   Баннер при запуске сообщает, что доступно и как, - `httpserver  http://0.0.0.0:12345  (bearer auth)`. Если привязать сервер к адресу не на loopback без токена, при старте в лог пишется предупреждение, а клиенты предупреждают, когда отправляют токен по открытому http на адрес не на loopback. Если путь проходит через сеть, которую вы не контролируете, поставьте перед сервером TLS, для этого достаточно обратного прокси.

   Доступ к ноутбуку извне не нужен, поэтому ноутбук за NAT или с меняющимся адресом работает так же - консоль сама подключается к серверу (шаг 2), браузер подключается к нему из собственного `coddy serve` ноутбука (шаг 4), а ноутбук, который присоединяется к рою, не указывает `advertise_url` в своей записи `swarm.join` и сам подключается к релею, а релей передаёт запросы обратно по этому соединению ([Рой, Два транспорта](../operate/swarm.md#два-транспорта)). Благодаря `allow_loopback` шаг 4 не зависит от того, как записан адрес ноутбука и какой у него порт. `http://localhost:12345`, `http://127.0.0.1:12345` и `http://localhost:5173` у Vite - три разных origin, и переключатель допускает их все. Он безопасен ровно настолько, насколько надёжен токен, заданный на этом шаге ([Безопасность и доверие](../operate/security.md)).

2. **Управляйте сервером из консоли ноутбука.** `--remote` принимает голый `host:port` (схема по умолчанию http), полный URL или имя удалённого сервера из `httpserver.remotes` в собственном `config.yaml` ноутбука. Токен берётся из `--remote-token`, затем из `token` записи этого удалённого сервера, если он там есть, затем из `CODDY_REMOTE_TOKEN`.

   ```bash
   export CODDY_REMOTE_TOKEN="a-long-random-string"
   coddy --dry-run --remote box.example:12345   # the target has to accept the token
   coddy --remote box.example:12345
   coddy -p "What changed in the last release?" --remote box.example:12345
   ```

   ```yaml
   httpserver:
     remotes:
       - name: "box"
         url: "https://box.example:12345"
   ```

   С записью выше достаточно `coddy --remote box`. Ход выполняется на сервере, в его рабочей папке. Блоки инструментов, рассуждения и счётчики токенов приходят потоком, модальные окна разрешений и вопросов отвечают через сервер, `/resume`, `-c` и `--session-id` выбирают из списка сессий сервера, а баннер показывает `remote: <url>`. `--permission-mode` и `/permissions` переключают сессию на сервере, и с этого момента новые сессии сервера начинают в этом режиме. Одна вещь в удалённом режиме намеренно запрещена - локальная оболочка `!!` (рабочая папка находится не на этой машине).

3. **Управляйте сервером из редактора.** `coddy acp` принимает те же два флага, поэтому ACP-клиент вроде Zed указывает удалённый сервер в команде своего агента; поместите `CODDY_REMOTE_TOKEN` в окружение редактора или передайте `--remote-token`.

   ```bash
   coddy acp --remote box.example:12345
   ```

4. **Управляйте сервером из браузера.** Окружение выбирается пунктом внизу боковой панели. На нём изображён ноутбук, пока страница управляет своим сервером, и два шеврона, направленные друг на друга, когда она управляет удалённым, а точка рядом показывает, отвечает ли этот хост; подсказка называет текущее окружение. В его меню перечислены удалённые серверы того `coddy serve`, который отдал страницу (`httpserver.remotes`), и пункт **Подключиться к…** (`Connect to…`), где вводят имя, URL и bearer-токен; выбор записи сразу подключается к ней и перезагружает страницу, а введённый там токен остаётся в браузере. Запись в `httpserver.remotes` может сама нести токен (`token: "${BOX_TOKEN}"`), и тогда каждый браузер, который открывает эту страницу, получает его из конфигурации ([Токен](../operate/remote.md#токен)). Удалённый сервер должен разрешать origin страницы через `httpserver.cors`, что и сделал шаг 1. Точка у каждой записи становится зелёной, когда кросс-доменный `GET /v1/models` с токеном проходит успешно, а под красной точкой строка поясняет, что случилось - сервер не отвечает, отклоняет токен или не включил этот origin в свой CORS ([Кросс-доменный доступ и удалённый интерфейс](../reference/http-api.md#кросс-доменный-доступ-и-удалённый-веб-интерфейс), [Веб-интерфейс](../surfaces/web-ui.md)). Если же открыть собственный адрес сервера, оболочка SPA загрузится без токена, потому что она публична, и страница спросит токен, прежде чем обращаться к API.

5. **Помните, что остаётся на сервере.** Сессии, расписки и дочерние сессии субагентов принадлежат серверу, поэтому файл проекта одобряется там - командами `coddy mcp trust`, `coddy hooks trust` и `coddy agents trust` на самом сервере или запросами `POST /coddy/mcp/{name}/trust`, `POST /coddy/hooks/trust` и `POST /coddy/subagents/{name}/trust` через API. Если соединение оборвётся, ход на сервере продолжится; `/resume` покажет результат, когда он закончится.
