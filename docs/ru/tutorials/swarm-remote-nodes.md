# Работа с удалёнными узлами

**Цель.** Управлять узлом за релеем из консоли, из редактора и из браузера так же, как локальным `coddy serve` - промпты, запросы разрешений, сессии, выбор модели. И знать, что остаётся на узле, что передаётся по сети и какие учётные данные к чему дают доступ.

**Окружение.** Релей хотя бы с одним узлом, например стенд из руководства [Релей и его узлы в Docker](swarm-relay-and-nodes.md) по адресу `http://127.0.0.1:12346` с клиентским токеном в `$T`. Общее руководство по удалённой работе - [Удалённый режим](../operate/remote.md); эта страница описывает его часть, относящуюся к рою.

## 1. Что такое точка монтирования

Релей монтирует каждый узел под `/swarm/nodes/<name>/`, и через точку монтирования доступен весь API узла - `/v1/*`, `/coddy/*`, маршруты роя только для чтения и дальнейшие переходы `/swarm/nodes/*`. Это обычный базовый URL с префиксом пути, ровно то, что принимает `--remote`, поэтому любой клиент, который уже работает с `coddy serve`, без изменений работает и с узлом через релей. Релей аутентифицируется на узле от вашего имени собственным токеном узла, а у вас есть только клиентский токен релея.

## 2. Консоль

```bash
export T=change-me-client
coddy --remote http://127.0.0.1:12346/swarm/nodes/node-a --remote-token "$T"
```

Баннер при запуске пишет `remote: <url>`; сессия, её рабочий каталог и каталог моделей принадлежат `node-a`. `-p` для разового ответа, `-c` для продолжения последней сессии этого узла и `/resume` работают со списком сессий узла.

```bash
coddy -p "List the files in the workspace." --remote http://127.0.0.1:12346/swarm/nodes/node-a --remote-token "$T"
coddy -c --remote http://127.0.0.1:12346/swarm/nodes/node-a --remote-token "$T"
```

Узел за вторым релеем отличается только более длинным путём - `--remote http://127.0.0.1:12346/swarm/nodes/inner/swarm/nodes/node-c` ([Цепочка релеев](swarm-multi-hop.md)).

Прежде чем что-то вводить, проверьте пробным запуском, верен ли путь и отвечает ли узел.

```bash
coddy --dry-run --remote http://127.0.0.1:12346/swarm/nodes/node-a --remote-token "$T"
```

Токен можно передать и через `CODDY_REMOTE_TOKEN`, а адрес релея, которым вы часто пользуетесь, можно один раз назвать в своём `config.yaml` в `httpserver.remotes` и дальше обращаться к нему по имени. Такая запись может хранить и клиентский токен, лучше в виде ссылки `${ENV}`, и тогда узел, смонтированный за этим релеем, получает токен без флага ([Имя для удалённого сервера](../operate/remote.md#как-указать-удалённый-сервер), [Токен](../operate/remote.md#токен)).

## 3. Редактор

`coddy acp` принимает те же два флага, поэтому Zed, VS Code, Obsidian или скрипт управляют узлом из поля ввода редактора, с режимами, моделями, запросами разрешений и скилами узла.

```bash
coddy acp --remote http://127.0.0.1:12346/swarm/nodes/node-a --remote-token "$T"
```

Настройте редактор так, чтобы он запускал эту командную строку вместо голого `coddy acp` ([Редакторы](../surfaces/editors.md)).

## 4. Браузер

Откройте сам релей, `http://127.0.0.1:12346/`. Релей, собранный с тегом `ui` (опубликованный образ собран с ним), отдаёт веб-интерфейс по своему адресу; интерфейс спрашивает клиентский токен и открывается на карте роя. Нажмите на узел - панель "История" покажет сессии этого узла, поле ввода покажет его рабочий каталог и модели, а ход, начатый там, выполнится на узле. Пункт **Рой** остаётся в боковой панели, пока вы внутри узла, так что до другого узла один клик, а каждый узел на карте показывает, сколько у него сессий, сколько ходов выполняется и ждёт ли какой-то из них вашего ответа.

Для веб-интерфейса, который отдаёт какой-то другой `coddy serve` (например, на ноутбуке), релей становится ещё одним окружением. Его добавляют записью в `httpserver.remotes` этого сервера или через пункт окружения внизу боковой панели - **Подключиться к…**, адрес релея и клиентский токен. Релей должен допускать origin этой страницы через `swarm.cors` - точным совпадением в `allowed_origins` или настройкой `allow_loopback: true` для страницы на loopback-адресе, на каком бы порту ни работал `coddy serve` ноутбука. Как только релей примет токен, меню окружений покажет его агентов, и до узла останется один клик; руководство [Рой на нескольких машинах](swarm-across-machines.md) проводит через эту настройку с нуля.

## 5. Что где выполняется

Вызовы модели, инструменты, рабочая папка, MCP-серверы, хуки и субагенты работают на узле, с провайдерами и ключами узла. Клиент отображает транскрипт и отвечает на запросы. Запрос разрешения или вопрос от узла проходит обратно через все переходы к клиенту, который начал ход, и ответ на него дают там, одинаково в консоли, в редакторе и в браузере.

Доверие решается на узле. Проектный MCP-сервер, файл хуков или определение субагента, пришедшие на узел вместе с чекаутом, одобряются на этом хосте - через CLI на нём (`coddy hooks trust ...`) или через точку монтирования с токеном (`POST /swarm/nodes/node-a/coddy/hooks/trust`); локальные подкоманды `--remote` не принимают ([Безопасность и доверие](../operate/security.md)).

## 6. Учётные данные и шифрование

Одни учётные данные открывают весь парк - тот, у кого есть клиентский токен релея, управляет каждым узлом, до которого дотягивается релей, транзитивно через все переходы. Отдельных клиентских разрешений по узлам в этой версии нет, поэтому клиентский токен открывает дверь ко всему парку, и обращаться с ним нужно соответственно - выпускать свой для каждого релея, менять перезапуском релея с новым значением и никогда не передавать по открытому HTTP за пределами частной сети.

Релей работает по TLS, когда `swarm.tls` указывает сертификат и ключ ([Шифрование и прокси](../operate/swarm.md#шифрование-и-прокси)); узлу собственный TLS не нужен, потому что к нему обращаются только через его туннель к релею. Без TLS подключайтесь к релею через SSH-туннель и держите адрес на loopback.

```bash
ssh -N -L 12346:127.0.0.1:12346 relay-host      # in one terminal
coddy --remote http://127.0.0.1:12346/swarm/nodes/node-a --remote-token "$T"
```

## Что обычно идёт не так

- **`--remote` отклоняется ещё до подключения.** Цель должна быть голым origin с префиксом пути - без строки запроса, без фрагмента и без учётных данных в URL. Токен передаётся в `--remote-token`, в `token` записи удалённого сервера или в `CODDY_REMOTE_TOKEN`;
- **`401` на каждый запрос.** Там, где нужен клиентский токен релея, использован собственный токен узла. Через точку монтирования вы предъявляете токен релея, а релей предъявляет токен узла;
- **Индикатор статуса в браузере остаётся красным при правильном токене.** Веб-интерфейс открыт с другого `coddy serve`, а релей не допускает origin этой страницы. Откройте вместо этого собственный адрес релея, задайте `swarm.cors.allow_loopback: true`, если страница открыта на loopback-адресе, или перечислите точный origin в `swarm.cors.allowed_origins`;
- **Обход разрешений, включённый с ноутбука, наутро пропал.** `/permissions bypass` меняет сессию узла для всех её клиентов, но только в памяти узла - после перезапуска узла сессия возвращается к своему `tools.permission_mode`. Постоянный выбор пропишите в `config.yaml` узла;
- **Транскрипт обрывается посреди хода после того, как ноутбук потерял сеть.** Ход продолжается на узле; `/resume` или `-c` покажут результат, когда он закончится, а ответ на запрос, который узел уже отозвал, игнорируется;
- **Второй клиент получает `409` на той же сессии.** В сессии выполняется один ход за раз, и первый клиент держит блокировку, пока его ход не закончится.
