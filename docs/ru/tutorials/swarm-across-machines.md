# Рой на нескольких ваших машинах

**Цель.** Рабочие узлы (воркеры) на нескольких машинах, один релей, к которому все они присоединяются, и ваш ноутбук, который управляет любым из них из собственного веб-интерфейса и собственной консоли. Релей виден в меню окружения ноутбука со списком своих агентов под ним, до воркера один щелчок, до карты всего роя тоже. Доступен извне должен быть только порт релея, воркеры сами подключаются к нему.

**Окружение.** Coddy 1.2.36 или новее на каждой машине ([Установка](../getting-started/install.md)) с тегом `swarm`, с которым собраны бинарники релиза. Модель, до которой может достучаться каждый воркер, и её ключ на этом воркере, потому что вызовы модели и инструменты выполняются там, где работает воркер. Устройство роя описано на страницах [Рой](../operate/swarm.md) и [Удалённый режим](../operate/remote.md), а та же схема в Docker на одной машине - на странице [Релей и его узлы в Docker](swarm-relay-and-nodes.md).

В примере используются такие машины, подставьте вместо них свои имена и адреса.

| Роль | Машина | Адрес, по которому к ней обращаются другие |
|---|---|---|
| релей | `relay` | `relay.lan`, порт 12346 |
| воркер | `gpu01` | не нужен |
| воркер | `gpu02` | не нужен |
| ноутбук | ваш | не нужен |

## 1. Три токена

Релей защищают токены, а не сеть ([Безопасность](../operate/swarm.md#безопасность)). Сгенерируйте три токена на любой машине и сохраните их для следующих шагов.

```bash
openssl rand -hex 24   # client token: what the laptop presents to use the relay
openssl rand -hex 24   # pairing token: what a worker presents to join it
openssl rand -hex 24   # one worker token per worker: its own API's bearer
```

Клиентский токен открывает доступ к каждому узлу за релеем, поэтому обращайтесь с ним как с паролем ко всем узлам сразу.

## 2. Релей

На машине `relay` токены лежат в `~/.coddy/.env` (`chmod 600`).

```bash
SWARM_CLIENT_TOKEN=<client token>
SWARM_PAIRING_TOKEN=<pairing token>
```

Файл `~/.coddy/config.yaml` запускает только релей. `cors` пропускает страницу, на которой открыт веб-интерфейс ноутбука, потому что эта страница будет обращаться к релею из браузера. `allow_loopback` покрывает все loopback-адреса и порты, с которых эту страницу может отдавать собственный `coddy serve` ноутбука.

```yaml
httpserver:
  enable: false

swarm:
  enable: true
  host: "0.0.0.0"
  port: 12346
  name: "office"
  auth_token: "${SWARM_CLIENT_TOKEN}"
  pairing_tokens: ["${SWARM_PAIRING_TOKEN}"]
  cors:
    enable: true
    allow_loopback: true   # http://localhost:12345, http://127.0.0.1:12345, any other loopback port
```

```bash
coddy serve --dry-run   # the address is free, the tokens and the file are right
coddy serve install     # a systemd user service; or `coddy serve` in a terminal
curl -s http://relay.lan:12346/swarm/info
```

`/swarm/info` не требует токена и отвечает `"swarm": true` с `node_count: 0`. Origin сравнивается точно, поэтому перечислите все адреса, по которым вы открываете страницу ноутбука. Правку этого файла релей подхватывает сам.

## 3. Воркеры

На каждом воркере файл `~/.coddy/.env` выглядит так.

```bash
OPENAI_API_KEY=sk-...
SWARM_PAIRING_TOKEN=<pairing token>
NODE_TOKEN=<this worker's token>
```

Файл `~/.coddy/config.yaml` описывает обычный `coddy serve` с моделью, bearer-токеном на собственном API и одной записью в `swarm.join`. Параметра `advertise_url` нет, поэтому воркер сам подключается к релею, и релей управляет им через это же соединение. Открытый порт воркеру не нужен.

```yaml
providers:
  - name: openai
    type: openai
    api_key: "${OPENAI_API_KEY}"

models:
  - model: "openai/gpt-5.6-terra"

agent:
  model: "openai/gpt-5.6-terra"

httpserver:
  auth_token: "${NODE_TOKEN}"

swarm:
  join:
    - url: "http://relay.lan:12346"
      name: "gpu01"                     # gpu02 on the second worker
      pairing_token: "${SWARM_PAIRING_TOKEN}"
      token: "${NODE_TOKEN}"            # the same value as httpserver.auth_token
```

```bash
coddy serve --dry-run   # the relay is reachable from here
coddy serve install
```

В журнале релея появляются строки `swarm node registered` и `swarm tunnel established` для каждого воркера. Запросите список узлов с любой машины.

```bash
curl -s -H "Authorization: Bearer <client token>" http://relay.lan:12346/swarm/nodes
```

В списке есть `gpu01` и `gpu02` с `"transport": "tunnel"` и `"online": true`.

## 4. Ноутбук

На ноутбуке работает собственный `coddy serve` для веб-интерфейса ([Быстрый старт](../getting-started/quickstart.md)), по умолчанию на `http://localhost:12345`. Релей добавляется в его `~/.coddy/config.yaml` как удалённый сервер, а клиентский токен хранится вне этого файла.

```yaml
httpserver:
  remotes:
    - name: "office"
      url: "http://relay.lan:12346"
      token: "${CODDY_RELAY_TOKEN}"
```

```bash
echo 'CODDY_RELAY_TOKEN=<client token>' >> ~/.coddy/.env
```

Строка `token` необязательна. Если она есть, меню окружения и `coddy --remote office` используют токен, ничего не спрашивая, и каждый браузер, открывший страницу этого ноутбука, получает токен из конфигурации. Если её нет, вы один раз в каждом браузере вводите токен в **Подключиться к…** ([Токен](../operate/remote.md#токен)). Можно и попросить агента добавить удалённый сервер. Агент подготовит такую же запись и применит её, а меню покажет новый сервер, когда вы откроете его в следующий раз.

![Меню окружения ноутбука с релеем и его воркерами](../../assets/swarm/across-machines-env-menu-dark-1280.png)

*Релей в меню окружения ноутбука, зелёный, под ним его воркеры*

Откройте меню окружения внизу боковой панели. У `office` зелёная точка и надпись `relay · 2 agents`, под ним `gpu01` и `gpu02`. Нажмите `gpu01`, и страница через релей перезагрузится на этот воркер. В панели "История" будут его сессии, в поле ввода его папка и модели, в "Настройках" его конфигурация. Ход, который вы начнёте, выполнится на `gpu01`.

Пункт **Рой** в боковой панели открывает карту релея поверх воркера, не уходя с него. Наверху ваш ноутбук, подписанный именем хоста, под ним релей, а под релеем воркеры. Воркер, на котором вы находитесь, обведён кольцом. Нажмите `gpu02`, чтобы перейти на него (карта остаётся открытой, кольцом теперь обведён `gpu02`, и страница не перезагружается), ноутбук, чтобы вернуться в окружение "Локальное", или релей, чтобы подключиться к самому релею.

![Карта роя, открытая поверх воркера](../../assets/swarm/map-over-node-dark-1280.png)

*Карта поверх `gpu01` - ноутбук, с которого начинается соединение, релей и оба воркера*

На самом релее его "Настройки" меняют развёртывание самого релея, в том числе origin для CORS, и сохранение применяется сразу ([Собственные настройки релея](../operate/swarm.md#где-находятся-настройки)).

## 5. Консоль

Консоль ноутбука обращается к воркеру через точку монтирования на релее. Запись релея в `httpserver.remotes` содержит токен, и для узла, смонтированного под этим релеем, используется тот же токен, поэтому флаг не нужен.

```bash
coddy --dry-run --remote http://relay.lan:12346/swarm/nodes/gpu01
coddy --remote http://relay.lan:12346/swarm/nodes/gpu01
coddy -p "What is in the workspace?" --remote http://relay.lan:12346/swarm/nodes/gpu02
```

`coddy --dry-run --remote office` сообщает, что `office` - релей, и выводит точки монтирования его агентов, потому что сам релей ничего не выполняет, а консоли нужен узел. `coddy acp` принимает тот же `--remote` для редактора ([Работа с удалёнными узлами](swarm-remote-nodes.md)).

## Что обычно идёт не так

- **Точка релея красная, и написано, что ответ заблокирован CORS.** Релей не пропускает адрес, на котором открыта страница ноутбука. Строка под релеем называет этот origin точно, а для страницы на loopback-адресе показывает ещё и переключатель. Задайте на релее `swarm.cors.allow_loopback: true` в его файле или в его собственных настройках, и релей начнёт пропускать любой loopback-origin на любом порту. Либо добавьте точный origin в `swarm.cors.allowed_origins` и помните, что `localhost` и `127.0.0.1` - два разных origin;
- **Точка красная, и написано, что релей отклоняет токен.** Токен, который предъявляет ноутбук, не совпадает с `swarm.auth_token` релея (или `--swarm-auth-token`). Если в записи ноутбука есть `token`, исправьте его там. Если нет, кнопка **Ввести токен** под релеем открывает форму, уже заполненную для этого релея;
- **Точка красная, и написано, что релей не отвечает.** С ноутбука по этому адресу никто не слушает. Проверьте `curl http://relay.lan:12346/swarm/info` с ноутбука, `host` релея и файрвол между ними;
- **Релей зелёный, но в списке нет ни одного воркера.** Ни один воркер не присоединился. В журнале воркера видно, отклонена ли его регистрация. Токен присоединения сравнивается точно;
- **Воркер есть в списке, но ход на нём падает с 401.** `token` в записи `swarm.join` воркера не совпадает с его собственным `httpserver.auth_token`, а релей предъявляет именно это значение, когда проксирует запрос;
- **`coddy --remote office` ни к чему не приводит.** `office` - релей, а релей не обслуживает сессий. Укажите в `--remote` точку монтирования воркера, пробный запуск их перечисляет;
- **Удалённого сервера, добавленного в конфигурацию ноутбука, нет в меню.** Список читается при открытии меню, поэтому закройте меню и откройте снова. Сервер ноутбука должен успеть загрузить файл, а он делает это сам в течение нескольких секунд после правки;
- **После сохранения настроек релея воркеры на мгновение пропадают.** Сохранение пересобирает релей, и воркеры за несколько секунд снова регистрируются и открывают туннели. Новый адрес прослушивания вступает в силу только после перезапуска релея.
