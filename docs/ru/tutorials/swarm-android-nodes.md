# Телефоны на Android как узлы роя

https://github.com/user-attachments/assets/c1e1d306-d5d3-40db-a84b-77e3cd5ddd46

*Двухминутная запись. Coddy в Termux на телефоне с Android присоединяется к релею, появляется на карте релея, запускает `getprop` и записывает на телефон файл по запросу из браузера на ноутбуке. В репозитории файл лежит как [android-swarm.mp4](../../assets/video/android-swarm.mp4).*

**Цель.** Телефон с Coddy в Termux присоединяется к релею, который вы запускаете на ноутбуке или сервере, и вы управляете им из веб-интерфейса релея или из консоли, как любым другим узлом, с промптами, инструментами, которые выполняются на телефоне, запросами разрешений и собственными сессиями телефона. Телефон сам открывает соединение, поэтому ему не нужны ни публичный адрес, ни открытый порт, ни VPN. Телефон в мобильной сети за NAT оператора присоединяется так же, как телефон в вашей сети Wi-Fi.

**Окружение.** Машина для релея с Coddy 1.2.31 или новее, то есть ноутбук в той же сети Wi-Fi или сервер с публичным адресом. Телефон на Android с [Termux](https://termux.dev), 64-битный, с Android 7.0 или новее. Модель, до которой телефон может достучаться, и ключ к ней, потому что вызовы модели и инструменты телефон выполняет сам, а релей только передаёт трафик. Подробности на страницах [Android (Termux)](../getting-started/android.md) и [Рой](../operate/swarm.md), а схема релея с узлами та же, что на странице [Релей и его узлы в Docker](swarm-relay-and-nodes.md).

## 1. Релей

Два токена решают, кто может пользоваться релеем и кто может к нему присоединиться ([Безопасность](../operate/swarm.md#безопасность)). Сгенерируйте их на машине релея.

```bash
mkdir -p ~/.coddy
printf 'SWARM_CLIENT_TOKEN=%s\nSWARM_PAIRING_TOKEN=%s\n' "$(openssl rand -hex 16)" "$(openssl rand -hex 16)" >> ~/.coddy/.env
chmod 600 ~/.coddy/.env
```

Файл `~/.coddy/config.yaml` релея запускает только релей.

```yaml
httpserver:
  enable: false

swarm:
  enable: true
  host: "0.0.0.0"
  port: 12346
  name: "home"
  auth_token: "${SWARM_CLIENT_TOKEN}"
  pairing_tokens: ["${SWARM_PAIRING_TOKEN}"]
```

```bash
coddy serve
```

Релей слушает на всех адресах машины, поэтому телефон находит его по адресу машины в сети Wi-Fi, например `http://192.168.1.10:12346`. В браузере телефона `http://192.168.1.10:12346/swarm/info` отвечает без токена и сообщает, что релей работает.

Релею на сервере, до которого телефон добирается через интернет, нужен сертификат (`swarm.tls`, [Шифрование и прокси](../operate/swarm.md#шифрование-и-прокси)), а телефон присоединяется по `https://...`. Токены передаются в заголовках запроса, а мобильная сеть может пропускать обычный HTTP через прокси, который его переупаковывает, и туннель этого не переживает ([Два транспорта](../operate/swarm.md#два-транспорта)).

## 2. Coddy в Termux

На телефоне в Termux выполните команды.

```bash
pkg install curl tmux
curl -fsSL https://coddy.dev/install.sh | bash
source ~/.bashrc
coddy -v
```

Скрипт скачивает сборку для Android под процессор телефона ([Установка](../getting-started/android.md#установка)).

## 3. Конфигурация телефона

На телефоне работает обычный `coddy serve` с моделью, токеном на собственном API и одной записью в `swarm.join`. Параметра `advertise_url` нет, поэтому телефон сам подключается к релею, а релей управляет телефоном через это соединение (туннельный транспорт). Файл `~/.coddy/config.yaml` в Termux выглядит так.

```yaml
providers:
  - name: openai
    type: openai
    api_key: "${OPENAI_API_KEY}"

models:
  - model: "openai/gpt-5.6-terra"

agent:
  model: "openai/gpt-5.6-terra"

httpserver:
  enable: true
  auth_token: "${NODE_TOKEN}"

swarm:
  join:
    - url: "http://192.168.1.10:12346"
      name: "pixel"
      pairing_token: "${SWARM_PAIRING_TOKEN}"
      token: "${NODE_TOKEN}"
```

Секреты лежат рядом, в `~/.coddy/.env`. Это ключ модели, токен присоединения релея и собственный токен телефона, который релей предъявляет, когда пересылает запрос телефону.

```bash
cat >> ~/.coddy/.env <<'EOF'
OPENAI_API_KEY=sk-...
SWARM_PAIRING_TOKEN=<the relay's pairing token>
NODE_TOKEN=<a token for this phone>
EOF
chmod 600 ~/.coddy/.env
```

Любой провайдер из раздела [Конфигурация](../getting-started/configuration.md) работает так же. `name` становится путём телефона на релее, поэтому дайте каждому телефону своё имя.

Прежде чем что-либо запускать, проверьте пробным запуском файл, модель и релей.

```bash
coddy serve --dry-run
```

## 4. Запуск и непрерывная работа

```bash
termux-wake-lock
tmux new -s coddy 'coddy serve'
```

Отключитесь от сеанса клавишами **Ctrl+B**, затем **D**, а `tmux attach -t coddy` вернёт журнал. Без tmux можно использовать `coddy serve --daemon` ([coddy serve](../operate/serve.md)).

Через несколько секунд после запуска в журнале телефона появляется `swarm: joining relay` с `transport=tunnel`, а в журнале релея - `swarm node registered` и `swarm tunnel established` для `pixel`. На машине релея выполните команды.

```bash
export T=<the relay's client token>
curl -s -H "Authorization: Bearer $T" http://127.0.0.1:12346/swarm/nodes
```

В списке есть `pixel` с `"transport": "tunnel"` и `"online": true`.

Android останавливает процессы приложения, которое считает неактивным. Блокировка сна не даёт Termux остановиться при выключенном экране. Кроме того, разрешите Termux работать без ограничений в настройках батареи, а на Android 12 и новее снимите ограничение на фоновые процессы, описанное в документации Termux ([Запуск coddy serve](../getting-started/android.md#запуск-coddy-serve)).

## 5. Управление телефоном

**Браузер.** Откройте релей, `http://192.168.1.10:12346/`. Страница сообщает, что релею нужен токен. Откройте меню окружения внизу боковой панели, выберите **Подключиться к…**, укажите имя, адрес релея и клиентский токен и нажмите **Подключиться**. Карта роя показывает `pixel` под релеем с отметкой узла, который подключается сам.

![Карта роя релея с телефоном в роли узла, который подключается сам](../../assets/swarm/android-node-map-dark-1280.png)

*Релей `home` и телефон `pixel` под ним. Пунктирная линия - соединение, которое открыл телефон.*

Нажмите `pixel`, и панель "История", поле ввода и настройки будут принадлежать телефону. Во всплывающей подсказке окружения написано `pixel`, а папкой служит домашний каталог Termux. Ход, начатый здесь, выполняется на телефоне, с его вызовами модели, его командами в `bash` из Termux и его файлами. Запросы разрешений приходят к вам в браузер.

![Команда на телефоне ждёт одобрения в браузере](../../assets/swarm/android-node-permission-dark-1280.png)

*На вопрос, на каком устройстве он работает, агент хочет запустить `getprop` в `bash` из Termux на телефоне, а одобрение запрашивается в браузере.*

**Консоль.** Точка монтирования телефона - базовый URL, как у любого другого удалённого сервера ([Работа с удалёнными узлами](swarm-remote-nodes.md)).

```bash
coddy --remote http://192.168.1.10:12346/swarm/nodes/pixel --remote-token "$T"
coddy -p "Which Android version is this? Use getprop." --remote http://192.168.1.10:12346/swarm/nodes/pixel --remote-token "$T"
```

Рабочая папка телефона - домашний каталог Termux, где был запущен `coddy serve`. Общее хранилище телефона (загрузки, фотографии) становится доступным после `termux-setup-storage`, которая один раз запрашивает у Android разрешение. После этого папка сессии может указывать внутрь `~/storage/shared`.

## Что обычно идёт не так

- **Релей завершается при запуске с сообщением о привязке не к loopback без клиентского токена.** `SWARM_CLIENT_TOKEN` до него не дошёл. Нужен файл `~/.coddy/.env` той учётной записи, под которой работает релей;
- **Телефон так и не появляется.** Его токена присоединения нет среди `pairing_tokens` релея, или телефон не может достучаться до адреса. Если с сетью всё в порядке, `curl http://192.168.1.10:12346/swarm/info` в Termux отвечает. Гостевая сеть Wi-Fi часто изолирует устройства друг от друга;
- **Телефон отваливается, когда гаснет экран.** Нет блокировки сна, или настройки батареи всё ещё ограничивают Termux. Релей помечает узел недоступным, когда истекает срок его аренды, а когда процесс снова работает, узел возвращается сам;
- **Запрос через точку монтирования телефона получает 401.** `token` в `swarm.join` не совпадает с `httpserver.auth_token` телефона. Именно поэтому в конфигурации выше оба значения берутся из `NODE_TOKEN`;
- **В мобильной сети за `swarm node registered` так и не следует `swarm tunnel established`.** Что-то между телефоном и релеем переупаковывает HTTP. Дайте релею TLS и присоединяйтесь по `https://...`;
- **Два телефона претендуют на одно имя.** Имя остаётся только за первым, потому что релей подтверждает имя секретом аренды, а не общим токеном присоединения. Дайте каждому телефону своё имя.
