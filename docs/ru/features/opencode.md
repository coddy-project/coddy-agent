# OpenCode

Провайдер `type: opencode` даёт Coddy модели шлюза [OpenCode](https://opencode.ai) - подписки **Go** или **Console** (Zen) с оплатой по мере использования - со входом в аккаунт или по ключу сервисного аккаунта. OpenCode здесь работает только как бэкенд. Во всех интерфейсах - в консоли, веб-интерфейсе, ACP-редакторах и Telegram-шлюзе - работает агент Coddy со своим системным промптом, инструментами, проверкой разрешений и циклом ReAct.

OpenCode собирает каталог моделей для кода (Grok, GPT, Claude, Qwen, GLM, Kimi, DeepSeek, MiniMax, MiMo, Gemini и остальные) и обслуживает каждую через подходящий ей протокол. Coddy выбирает протокол по модели и шлюзу. Модели Jev для принятия решений в Console используют отдельный System One API и не подходят для диалогов в Coddy.

## Вход в аккаунт

Выполните команду входа в терминале на машине, где работает Coddy.

```bash
coddy providers login opencode
```

Coddy выводит короткий код и открывает страницу аккаунта в OpenCode Console. Войдите, подтвердите код и выберите организацию. Адрес из терминала можно открыть в браузере на другой машине. Этот способ повторяет [вход по коду устройства в клиенте OpenCode](https://github.com/anomalyco/opencode/blob/f394d9d410bc6bb7cafcebfc5e3180a9b80ebed9/packages/core/src/plugin/provider/opencode.ts).

Команда сохраняет access- и refresh-токены в `$CODDY_HOME/providers/opencode/opencode-auth.json` с правами `0600`. Если не указан `--no-config`, она также добавляет в `config.yaml` строку провайдера, модели шлюза и `agent.model`, если он пуст. Для отдельного именованного профиля укажите `--type opencode`, а для Console вместо Go - `--api-base https://opencode.ai/inference/v1`.

Перед каждым запросом каталога или генерации Coddy обновляет токен, если до истечения его срока осталось не более 60 с, и атомарно сохраняет новые токены. Запросы передают выбранную организацию в `x-org-id`. После отзыва refresh-токена нужно войти заново. `coddy providers list` показывает организацию аккаунта без токенов. Сохранённые учётные данные используются во всех интерфейсах Coddy. Работающий сервер читает их для уже загруженной строки провайдера; после добавления новой строки перезапустите сервер.

Явный `api_key`, `api_key_command` или `NAME_API_KEY` строки имеет приоритет над сохранёнными учётными данными. `coddy providers logout opencode` удаляет локальный файл. Чтобы завершить доступ на сервере, отзовите сессию аккаунта или ключ сервисного аккаунта в Console.

## Ключ сервисного аккаунта

1. Войдите в [консоль OpenCode](https://opencode.ai/console);
2. Оформите подписку **Go** (или **Go Plus**) либо добавьте кредиты для **Console** и укажите платёжные данные;
3. Создайте ключ сервисного аккаунта и укажите его в строке провайдера.

```yaml
# yaml-language-server: $schema=https://coddy.dev/config.schema.json
providers:
  - name: opencode
    type: opencode
    api_key: "${OPENCODE_API_KEY}"   # or a literal key, or empty to read OPENCODE_API_KEY
    # api_base: https://opencode.ai/inference/v1   # Console; omit for the Go default
models:
  - model: opencode/glm-5.3
  - model: opencode/gpt-6-luna
  - model: opencode/claude-haiku-5-5
agent:
  model: opencode/glm-5.3
```

Если `api_key` пуст, Coddy читает переменную окружения `NAME_API_KEY` для этой строки, а если она не задана, использует сохранённые учётные данные. Строка с именем `opencode` читает `OPENCODE_API_KEY`. Форма `${OPENCODE_API_KEY}` раскрывается при загрузке файла; просто пустое значение читается в момент вызова.

### Сохранение ключа сервисного аккаунта

```bash
coddy providers login opencode --api-key -
```

С `--api-key -` команда читает ключ из терминала без отображения ввода или из строки стандартного ввода. `--api-key KEY` передаёт его напрямую. Ключ сохраняется в том же файле учётных данных, а конфигурация обновляется так же, как при входе в аккаунт. Ранее сохранённые API-ключи продолжают работать.

## Два шлюза

`api_base` выбирает шлюз генерации. Вход в аккаунт для обоих шлюзов использует один сервис авторизации Console по коду устройства; доступ зависит от выбранной организации, её подписки или кредитов.

| Шлюз | `api_base` | Что это |
|---------|-----------|------------|
| **Go** (по умолчанию) | `https://opencode.ai/inference/go/v1` | месячная подписка Go / Go Plus |
| **Console** | `https://opencode.ai/inference/v1` | кредиты с оплатой по мере использования (Zen) |

Пустой `api_base` означает Go. Если значение не соответствует ни одному из этих шлюзов, Coddy использует Go, так что ключ OpenCode никогда не уходит на произвольный хост. В веб-интерфейсе в разделе **Настройки → Провайдеры LLM** в строке провайдера вместо поля для ввода базового адреса отображается список выбора шлюза. `CODDY_OPENCODE_BASE_URL` переводит весь процесс на другой адрес - для стенда или теста.

## Протокол обмена для каждой модели

Шлюз OpenCode отдаёт разные модели по разным протоколам. Список `/models` содержит только id моделей и не указывает их протоколы. Coddy выбирает протокол по id модели.

| Протокол | Эндпоинт | Семейства моделей |
|----------|----------|----------------|
| OpenAI Responses | `/openai/v1/responses` | `grok-*`, `gpt-*`, `muse-*` |
| Anthropic | `/anthropic/v1/messages` | `claude-*`, `qwen*`, `minimax-m3` в Go |
| Google | `/google/v1beta/models/<id>:generateContent` | `gemini-*` |
| OpenAI-совместимый | `/openai/v1/chat/completions` | `glm-*`, `kimi-*`, `deepseek-*`, `longcat-*`, `mimo-*`, `hy*`, `space-bunny`, бесплатные модели для чата и неизвестные id |

Эти пути добавляются к `https://opencode.ai/inference/go` для Go или к `https://opencode.ai/inference` для Console. Адрес каталога - этот префикс с путём `/v1/models`. Console обслуживает `qwen3.8-max` и все модели `minimax-*` через Chat Completions; Go обслуживает `qwen3.8-max` и `minimax-m3` через Anthropic. Более старые модели MiniMax используют Chat Completions.

Если id модели отсутствует в этой таблице, Coddy использует Chat Completions. Соответствие следует [документации OpenCode Go](https://opencode.ai/v2/docs/console/go/) и [эндпоинтам моделей Console](https://opencode.ai/v2/docs/console/models/); когда OpenCode меняет протокол модели, обновите `opencodeProtocolForGateway` в `internal/llm/opencode.go`.

Уровни рассуждения передаются как `reasoning.effort` в OpenAI Responses, бюджет размышлений в Anthropic, `reasoning_effort` в OpenAI-совместимом протоколе или `thinkingConfig.thinkingLevel` в Google - по протоколу модели. Gemini передаёт поток через `:streamGenerateContent?alt=sse`; Coddy сохраняет подписанные части ответа между вызовами инструментов и частичный текст, если поток оборвался до получения причины завершения. Встроенные изображения поддерживаются; удалённые URL изображений обозначаются как вложения без скачивания.

## Обязательные заголовки клиента

Шлюз отслеживает злоупотребления и просит каждый клиент представляться и держать диалог на одном маршруте. Coddy отправляет следующие заголовки в запросах генерации и каталога по всем четырём протоколам:

- `User-Agent: coddy/<version>` - собственное имя, а не типовое имя SDK или HTTP-библиотеки;
- `x-opencode-session: <session id>` - стабильный id диалога, чтобы OpenCode мог оптимизировать маршрутизацию и повторно использовать свой кэш промптов. Вызов вне диалога (список моделей, проба `--dry-run`) отправляет сгенерированный id.

Coddy добавляет оба заголовка к запросам генерации и каталога через транспорт строки провайдера. Запросы аккаунта также передают имя Coddy в `User-Agent`.

Отправляются только учётные данные OpenCode этой строки. Ключи SDK по умолчанию, такие как `OPENAI_API_KEY` и `ANTHROPIC_API_KEY`, отбрасываются, а перенаправления на другой origin отклоняются до пересылки ключа.

## Прокси

`providers[].proxy` маршрутизирует каждый запрос к OpenCode - авторизацию по коду устройства, получение данных аккаунта и организаций, обновление токенов, генерацию по всем четырём протоколам и список моделей - точно так же, как у любого другого провайдера. При `inherit` используется прокси из окружения, при `none` запросы идут напрямую, а если указан URL, запросы идут через этот прокси. См. [Прокси провайдера](../getting-started/configuration.md#прокси-провайдера).

## Лимиты использования

OpenCode учитывает расход каждой модели по месячному долларовому бюджету (с подлимитами на 5 часов и на неделю), и вы можете следить за ним в [консоли](https://opencode.ai/console). Coddy не получает данные о расходе аккаунта OpenCode, поэтому панель расхода для строки `opencode` не показывается. Окно контекста модели берётся из `max_context_tokens`, затем из метаданных каталога, если они есть, затем используется 128000.

## Тестирование

- Модульные тесты. `internal/llm/opencode_test.go` проверяет точные пути запросов для обоих шлюзов, заголовки, изоляцию ключей, отказ от перенаправлений и сохранённые учётные данные. `opencode_google_test.go` покрывает диалоги Gemini с инструментами, подписанные части, расход и обрывы потока;
- `features/provider_proxy.feature` проверяет все четыре семейства API, получение списка моделей, вход в аккаунт, обновление токенов и конфигурации с каждым значением прокси. `opencode_oauth_test.go` проверяет маршрут через HTTPS CONNECT, смену токенов, одновременное обновление и ошибки авторизации; `cmd/coddy/opencode_test.go` проверяет вход из терминала;
- Транспорт Responses общий с бэкендом Codex (`internal/llm/responses_stream.go`); его покрывает `internal/llm/codex_test.go`.
