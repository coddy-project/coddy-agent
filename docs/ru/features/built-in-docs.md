# Встроенная документация

Coddy носит документацию с собой. Каждая её страница при сборке компилируется в бинарник, поэтому и человек, и агент читают документацию именно того бинарника, который запущен. Запросов к сайту нет, текст и программа не расходятся, и всё работает на машине без сети.

Одни и те же страницы открываются из любого интерфейса.

| Где | Как | Что вы получаете |
| --- | --- | --- |
| Веб-интерфейс | **Документация** на боковой панели, **F1**, `/docs [words or page]` в поле ввода или адрес `#/docs/<page>#<section>` | Окно документации: содержание, страница, разделы страницы, поиск, предыдущая и следующая страницы, **Спросить агента** |
| Консоль | **F1** или `/docs [words or page]` | Экран справки поверх редактора: поиск, затем страница, открытая на найденном разделе |
| Командная строка | `coddy docs list`, `coddy docs search <words>`, `coddy docs show <page>[#section]` | Содержание, лучшие разделы, страница или раздел в Markdown |
| Агент | инструменты `coddy_docs_search` и `coddy_docs_read` | Поиск и чтение в любом режиме |
| Промпт | `@coddy:<page>#<section>` | Страница или раздел, прикреплённые к сообщению |

## Страницы и разделы

Страницу называет её путь в `docs/` без `.md`, например `features/mentions` или `reference/config`. Это имя служит её адресом везде - `@coddy:features/mentions`, `coddy docs show features/mentions`, `#/docs/features/mentions` в окне документации и публичная копия по адресу `https://coddy.dev/docs/features/mentions`. Раздел добавляет к имени якорь, который GitHub даёт его заголовку, например `features/mentions#completion`.

Когда страницу или раздел запрашивают по имени, Coddy понимает и другие написания: путь к файлу с `docs/` и `.md` или без них, ссылку `coddy:` или `@coddy:`, адрес `coddy.dev/docs`, имя файла страницы, если оно есть только у одной страницы (`mentions`), и заголовок страницы (`Mentions`). На имя, которому ничего не соответствует, Coddy отвечает ближайшими страницами, а на раздел, которого на странице нет, - списком разделов, которые есть.

В странице, прочитанной из бинарника, ссылка на другую страницу записывается как `coddy:<page>#<section>`. Окно документации открывает её на месте, а агент передаёт её в `coddy_docs_read`. В веб-интерфейсе страница, названная в любом месте диалога, открывается в окне документации, будь то `@coddy:<page>#<section>` в отправленном вами сообщении или ссылка `coddy:` либо упоминание `@coddy:` в ответе. Именно так агенту велено указывать вам на страницу.

Изображения, видео и ссылки на файлы репозитория ведут на GitHub, на релиз, из которого собран бинарник (`main` для сборки разработчика). Текст лежит в бинарнике, а скриншоты и записи нет, поэтому они видны, когда машина в сети, а без сети вместо них показывается подпись. Запись, которую GitHub встраивает из вложения, проигрывается в окне документации из своей копии в репозитории.

## Языки

Документация написана на английском и переведена на русский. У каждой страницы есть перевод в `docs/ru/` по тому же пути, и бинарник несёт оба языка. Переключателя языка в окне документации нет: каждый интерфейс показывает тот язык, которым вы уже пользуетесь.

| Интерфейс | Язык документации |
| --- | --- |
| Веб-интерфейс (и Telegram Mini App) | язык интерфейса, **Настройки → Оформление** или язык браузера |
| Консоль, `coddy docs` | `CODDY_LANG`, иначе локаль терминала - `LC_ALL`, затем `LC_MESSAGES`, затем `LANG`; для одной команды `coddy docs --lang ru` |
| Инструменты агента | `lang`, указанный в вызове, иначе язык интерфейса, из которого пришёл ход, иначе язык поискового запроса (чтение без того и другого идёт на английском) |
| `@coddy:` в промпте | язык интерфейса, из которого пришёл ход, иначе язык, на котором написан промпт |

Язык, на который документация не переведена, читается как английский. Адрес страницы в обоих языках один и тот же, как и адрес раздела: русский заголовок отзывается на якорь английского заголовка, стоящего на том же месте. Поэтому `coddy:features/mentions#completion`, `@coddy:features/mentions#completion` и `#/docs/features/mentions#completion` открывают один и тот же раздел на любом языке, а ссылка, которую агент написал на одном языке, открывается и на другом. Публичная копия русской страницы лежит по адресу `https://coddy.dev/ru/docs/<page>`.

## Поиск

Поиск ранжирует разделы, а не страницы, поэтому результат ведёт к абзацу, где есть ответ. Каждый раздел оценивается по BM25 по трём полям - названию страницы, заголовку раздела и тексту, - причём заголовок и название весят больше текста, поэтому запрос с названием главы находит эту главу. Слова сравниваются без учёта регистра после стемминга: лёгкого английского (`sessions` находит `session`) и стеммера Snowball для русского (`сессиями` находит `сессия`, а `ё` читается как `е`). Идентификатор ищется целиком и по частям (`max_turns` и `turns` оба находят `agent.max_turns`), а слово из трёх и более букв находит и слова, которые с него начинаются, поэтому запрос, набираемый по букве, находит страницы ещё до того, как его допишут. С одной страницы показывается не больше трёх разделов, чтобы длинная страница не вытесняла остальные. У каждого результата есть фрагмент - участок текста раздела, где больше всего найденных слов, и эти слова выделены.

Индекс строится при первом поиске, примерно за десятую долю секунды, и хранится, пока работает процесс.

## Окно документации в веб-интерфейсе

![Окно документации - слева содержание, затем страница, справа разделы страницы](../../assets/built-in-docs/reader-page-dark-1280.png)
*Окно документации на ширине 1280 px - содержание с открытой страницей, сама страница и разделы страницы, где отмечен читаемый.*

**Документация** на боковой панели открывает окно документации на той странице, где его закрыли в прошлый раз, **F1** открывает и закрывает его из любого места приложения, **Escape** закрывает его, как и ×, `/docs` в поле ввода работает так же, как в консоли (`/docs telegram proxy` открывает окно с этим поиском, `/docs features/mentions#completion` - на этом разделе, и агенту ничего не уходит), а адрес вида `#/docs/features/mentions#completion` сразу открывает этот раздел, в новой вкладке или по присланной кем-то ссылке. Каждая страница, раздел и результат поиска - настоящая ссылка. Кнопки браузера "Назад" и "Вперёд" переходят между прочитанными страницами, щелчок средней кнопкой открывает ссылку в новой вкладке, а `#` рядом с заголовком раздела и есть адрес этого раздела. Шапка с поиском остаётся на месте, а страница прокручивается под ней; правая колонка следит за читаемым разделом.

![Результаты поиска под полем поиска, найденные слова выделены](../../assets/built-in-docs/reader-search-dark-1280.png)
*Поле поиска в шапке показывает под собой найденные разделы по мере ввода. Up и Down выбирают раздел, Enter открывает страницу на этом разделе, Escape очищает поиск, а следующий Escape закрывает окно документации.*

- **Читать как книгу.** Внизу каждой страницы есть ссылки на предыдущую и следующую страницы в порядке содержания;
- **Спросить агента** открывает новый чат с упоминанием страницы (`@coddy:<page>#<section>`, с читаемым разделом, если он есть). Если на странице выделен текст, кнопка спрашивает о выделенном - чат открывается с цитатой выделенного текста и упоминанием раздела, в котором он находится, и ждёт вашего вопроса;
- **Изображения** по щелчку открываются поверх страницы, вписанные в окно; `+`, `-` и кнопки увеличивают их до 300%, щелчок по изображению переключает между вписанным и двойным размером, а увеличенное изображение прокручивается. Escape закрывает его;
- **coddy.dev** над страницей открывает публичную копию той же страницы, чтобы поделиться ею с тем, у кого нет Coddy;
- `/` ставит курсор в поле поиска.

Окно документации следует теме и языку приложения: если переключить интерфейс на русский, содержание, страница и поиск тоже будут на русском. На узком экране содержание сворачивается в кнопку над страницей.

## Справка в консоли

![Справка в консоли - список результатов поиска с фрагментом выбранного раздела](../../assets/cli-tui/19-docs-search.png)
*F1, затем `telegram proxy` - найденные разделы, у выбранного показаны адрес и фрагмент.*

**F1** открывает справку на месте редактора, на содержании; ввод текста запускает поиск. **Enter** открывает выбранный пункт, прокрученный до его раздела. Некоторые терминалы оставляют F1 себе (GNOME Terminal открывает собственную справку); `/docs` открывает тот же экран, `/docs telegram proxy` - сразу с этим поиском, а `/docs features/mentions#completion` - прямо на этом разделе.

![Справка в консоли - страница, открытая на найденном разделе](../../assets/cli-tui/20-docs-page.png)
*Страница, открытая на разделе, с положением читателя на странице и подсказкой по клавишам.*

| Клавиша | В списке | На странице |
| --- | --- | --- |
| буквы, Backspace | правят поиск | - |
| Up, Down | выбирают пункт | прокручивают на строку |
| Enter | открывает пункт на его разделе | прокручивает на строку |
| PgUp, PgDn, Space | - | прокручивают на экран |
| Home, End | - | в начало, в конец |
| Tab, Shift+Tab | - | следующий раздел, предыдущий |
| `n`, `p` | - | следующая страница, предыдущая |
| `/` | - | назад к поиску |
| Escape | закрывает справку | назад к списку |
| F1, Ctrl+C | закрывают справку | закрывают справку |

Изображения показываются своей подписью. Справка читает бинарник, в котором работает консоль, поэтому с `--remote` она показывает документацию самой консоли, а не сервера. Справка идёт на языке терминала (см. [Языки](#языки)), а надписи самой консоли остаются английскими.

## Инструменты агента

Когда вопрос касается самого Coddy - как настроить Telegram-бота, что делает ключ `config.yaml`, какие инструменты разрешены в режиме "Чат", - агент обращается к своей документации, а не отвечает по памяти.

| Инструмент | Аргументы | Возвращает |
| --- | --- | --- |
| `coddy_docs_search` | `query` (на английском или на русском), `limit` (по умолчанию 8, не больше 20), `lang` (`en` или `ru`) | Лучшие разделы, у каждого адрес для чтения, названия страницы и раздела и фрагмент |
| `coddy_docs_read` | `page` (адрес, ссылка `coddy:` или название; без него возвращается содержание), `offset`, `lang` | Страница или раздел с адресом для чтения, строками и публичным адресом |

Обоим инструментам не нужно разрешение, и они доступны в режимах "Агент", "План" и "Чат", субагентам и встроенному субагенту `explore`. В чате вызов подписан тем, что он делает, а рядом стоит запрос или страница - *ищу в документации* и *читаю документацию* в веб-интерфейсе, *Searching the docs* и *Reading the docs* в консоли. Страница читается частями примерно по 24 тысячи символов. Длинная страница заканчивается строкой, с которой нужно продолжить, и списком её разделов, поэтому модель читает нужный раздел, а не всю страницу.

Отсылая пользователя к странице, агент пишет упоминание `@coddy:<page>#<section>` или ссылку `coddy:`, а не адрес, потому что оба открывают страницу в окне документации того самого бинарника, который ответил. Публичный адрес `https://coddy.dev/docs/<page>` нужен для того, что уходит за пределы Coddy, а в командной строке агент пишет только то, на что отвечает бинарник, - `coddy docs show <page>[#section]` вместе с `coddy docs search` и `coddy docs list`.

## Упоминание страницы

`@coddy:` в промпте прикрепляет к сообщению страницу или один её раздел.

```text
set this up for me like @coddy:surfaces/gateway#proxy says, the machine needs socks5
```

Страница или раздел с подразделами передаётся в сообщении как `<coddy_attachment kind="doc">` ([Упоминания](mentions.md)) объёмом до 64 тысяч символов, на языке хода (см. [Языки](#языки)). Более длинная справочная страница приходит своим началом со строкой, с которой нужно продолжить, и списком разделов, а нужную часть модель дочитывает через `coddy_docs_read`. Автодополнение работает во всех интерфейсах. `@coddy:` перечисляет страницы, `@coddy:prox` находит страницы по имени и разделы по словам из них, а `@coddy:features/mentions#` перечисляет разделы этой страницы. Названия показываются на языке интерфейса, а вставляется адрес, общий для обоих языков.

## Из командной строки

```bash
coddy docs                                   # the contents
coddy docs search telegram proxy --limit 3   # the best sections
coddy docs show features/mentions#completion # one section, as Markdown
coddy docs show features/mentions --lang ru  # the same page in Russian
```

`coddy docs` работает в любой сборке, включая сборку без консоли, и не требует конфигурации. Автодополнение оболочки предлагает страницы после `coddy docs show`.

## Что входит в бинарник

В бинарник встроены страницы групп из `docs/nav.yaml` (`docs/embed.go`) на английском и на русском (`docs/ru/`); записи о проектных решениях из `docs/plans/`, изображения из `docs/assets/` и страницы, которые карта держит в корне репозитория (руководство для контрибьюторов, контракт дизайна веб-интерфейса, заметки для агентов), в него не входят. К бинарнику добавляется около 1,9 МБ английского и 3,1 МБ русского Markdown (кириллическая буква занимает два байта). Новую папку группы в `docs/` нужно добавить в шаблон встраивания для обоих языков, иначе тесты `internal/docs` упадут на странице карты, которой нет в бинарнике на одном из них.

Реализация - `internal/docs` (библиотека, разделы, поиск, чтение, переписывание ссылок; `lang.go` отвечает за языки, `stem_ru.go` за русский стеммер), `internal/tools/docs_search.go` и `docs_read.go`, `internal/session/mentions.go` (`resolveDoc`) и `mention_search.go` (`docCandidates`), `external/httpserver/docs_http.go` (`GET /coddy/docs`, `/coddy/docs/page`, `/coddy/docs/search`, [HTTP API](../reference/http-api.md)), `external/ui/src/ui/docs/`, `external/cli/docs_modal.go` и `cmd/coddy/docs.go`. Спецификация - `features/builtin_docs.feature`.
