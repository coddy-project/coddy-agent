# Экспорт сессии (`/export`)

Встроенная команда `/export` записывает текущий диалог в файл внутри рабочей папки сессии. Она работает так же, как `/compact` и `/plugin`, - детерминированно, без хода модели, в любом интерфейсе, где вводятся промпты (TUI консоли, редакторы через ACP, поле ввода веб-интерфейса, `POST /v1/responses`). Команда повторяет `/export` из qwen-code, а опции сокращения повторяют диалог экспорта в инструментах на основе OpenCode, например в Kilo Code.

## Использование

```text
/export [md|html|json|jsonl] [path] [--no-tools] [--no-thinking]
```

| Команда | Результат |
|---------|--------|
| `/export` | `coddy-export-<timestamp>.md` в рабочей папке |
| `/export json` | `coddy-export-<timestamp>.json` в рабочей папке |
| `/export md chat.md` | `chat.md` |
| `/export chat.html` | `chat.html`; формат выбирается по расширению |
| `/export notes/` | markdown в `notes/`, папка создаётся, если её нет |
| `/export md chat.md --no-tools --no-thinking` | только текст диалога |

Ответ называет файл относительно рабочей папки и даёт его полный путь. Метка времени указывается в UTC, например `coddy-export-2026-09-06T12-34-56Z.md`. Сгенерированное имя резервируется эксклюзивным созданием файла, поэтому, если оно уже занято (второй экспорт в ту же секунду, даже из другой сессии с той же рабочей папкой), файл получает следующий свободный суффикс (`-2`, `-3`, ...) перед расширением. Слова после команды разделяются пробельными символами, поэтому несколько пробелов или табуляций подряд внутри пути схлопываются в один пробел.

### Формат

Первое слово после `/export` задаёт формат, если это имя формата - `md` (или `markdown`), `html`, `json`, `jsonl`. Без него формат определяет расширение цели (`.md`, `.markdown`, `.html`, `.htm`, `.json`, `.jsonl`); при пустой цели или папке экспортируется markdown. Отдельное слово, которое не называет ни формат, ни существующую папку, отклоняется, поэтому `/export yaml` перечисляет поддерживаемые форматы и не создаёт файл с именем `yaml`.

### Путь

- Относительный путь отсчитывается от рабочей папки сессии (той папки, которую показывает чип рабочей папки в поле ввода или нижняя строка консоли). Абсолютный путь принимается, если он указывает внутрь этой рабочей папки;
- существующая папка, путь, оканчивающийся на `/`, или `.` получают сгенерированное имя файла. Любой другой путь задаёт имя файла; недостающие родительские папки создаются;
- цели, которые выходят за рабочую папку через `..` или через символическую ссылку, отклоняются. Каждый шаг в файловой системе идёт через `os.Root`, открытый на рабочей папке, и Go в момент каждой операции отказывается проходить по символической ссылке, ведущей за пределы корня, поэтому ссылка, появившаяся между предварительной проверкой и записью, тоже отклоняется. По контракту `os.Root` границы файловых систем и bind mount внутри рабочей папки не проверяются;
- файл с явно заданным именем записывается в новый временный файл, который затем переименовывается поверх цели, поэтому существующий обычный файл заменяется и никогда не сохраняет более широкие права. Цель, которая оказывается папкой, символической ссылкой или любым другим файлом, кроме обычного, отклоняется;
- в POSIX-системах файл создаётся с правами только для владельца (`0600`). В Windows аналогичных битов режима нет, и там файл наследует ACL своей папки.

### Опции

- `--no-tools` убирает вызовы инструментов и их результаты. Строка ассистента, в которой были только вызовы инструментов, исчезает вместе с ними;
- `--no-thinking` убирает рассуждения модели;
- опции могут стоять где угодно после команды. Неизвестная опция `--option` отклоняется со строкой использования.

## Что содержит файл

Экспорт собирается до того, как строка `/export` попадает в транскрипт, поэтому файл содержит диалог до этой команды. Команда и её ответ добавляются после, как у любой другой встроенной команды; чтобы они попали в файл, экспортируйте ещё раз.

**Заголовок.** Id сессии, название (закреплённое или выведенное из первого промпта), путь к рабочей папке, ветка git, если рабочая папка - чекаут, модель, время первого сообщения, время экспорта, число сообщений и ходов пользователя, а также итоги по токенам из `stats.json` сессии, если он есть.

**Записи** в порядке транскрипта.

| Тип | Содержимое |
|------|---------|
| `user` | Текст промпта дословно. Раскрытые упоминания `@` (блоки `<coddy_attachment>`) и загруженные файлы сводятся к списку вложений с путями и именами; их содержимое не копируется, а пробел, который после них остаётся, убирается. |
| `assistant` | Рассуждения, текст и вызовы инструментов, сопоставленные с результатами по `tool_call_id`; вызов, который показал модели картинку (`read` на файле изображения, [Изображения](images.md)), перечисляет её в `pictures` по копии, сохранённой среди ресурсов сессии. Путь к копии картинки или загруженного файла указывается по тому месту, где папка сессии находится сейчас, даже если папка переехала после сохранения файла. Строка без текста, рассуждений и вызовов (отменённый ход) пропускается. |
| `tool_result` | Результат, вызова которого нет в транскрипте. |
| `compaction_summary` | Строка сводки, вставленная `/compact` или автоматическим сжатием контекста. |
| `plan_document` | Строка документа плана с его slug, именем и путём к файлу. |

## Форматы

**Markdown** (`md`) - список полей заголовка, затем разделы `## User` и `## Assistant · <model> · <time>`. Рассуждения лежат в свёрнутом блоке `<details>`, каждый вызов инструмента превращается в `### Tool call: <name>` с входными данными (JSON с форматированием) и результатом в блоках кода. Ограждения блоков удлиняются, если в самом содержимом есть обратные кавычки, поэтому код в выводе инструментов остаётся целым.

**HTML** (`html`) - одна самодостаточная страница со встроенным CSS, светлой и тёмной палитрами через `prefers-color-scheme` и без скриптов. Каждое значение экранируется, а текст показывается в блоках с сохранением переносов строк; markdown в ответах ассистента сохраняется дословно и не отрисовывается.

**JSON** (`json`) - один документ.

```json
{
  "version": 1,
  "session": {
    "id": "sess_...", "title": "...", "cwd": "/path", "git_branch": "main", "model": "openai/gpt-5.6-terra",
    "started_at": "2026-09-06T10:00:00Z", "exported_at": "2026-09-06T12:00:00Z",
    "message_count": 8, "user_turns": 3,
    "token_usage": {"input_tokens": 1200, "output_tokens": 300, "total_tokens": 1500}
  },
  "entries": [
    {"type": "user", "created_at": "...", "text": "...", "attachments": [{"path": "README.md", "name": "README.md"}]},
    {"type": "assistant", "created_at": "...", "model": "...", "reasoning": "...", "text": "...",
     "tool_calls": [{"id": "call_1", "name": "read", "input": {"path": "README.md"}, "result": "..."},
                    {"id": "call_2", "name": "read", "input": {"path": "shot.png"}, "result": "...",
                     "pictures": [{"path": "/home/me/.coddy/sessions/<id>/assets/shot-1a2b3c4d5e6f7a8b.png", "name": "shot.png"}]}]},
    {"type": "compaction_summary", "created_at": "...", "model": "...", "text": "..."},
    {"type": "plan_document", "created_at": "...", "text": "...", "plan": {"slug": "...", "name": "...", "path": "..."}}
  ]
}
```

Пустые поля опускаются, за одним исключением. `tool_calls[].result` присутствует как `""`, если инструмент ничего не вернул, и отсутствует, если в транскрипте нет результата для этого вызова (отменённый или ещё идущий ход). `tool_calls[].input` содержит JSON-аргументы вызова или JSON-строку, если модель выдала аргументы, которые не разбираются как JSON. Записи `tool_result` несут `tool_call_id` и `text`.

**JSON Lines** (`jsonl`) - первая строка содержит заголовок `{"type":"session","version":1,...}` с теми же полями, что у `session` выше; каждая следующая строка содержит одну запись.

## Из оболочки - `coddy sessions export`

Тот же экспорт доступен без работающего агента, так же как `coddy plugin` дублирует `/plugin`.

```bash
coddy sessions export <session-id> [--format md|html|json|jsonl] [--out <path>] [--no-tools] [--no-thinking] [--sessions-dir <path>]
```

- `<session-id>` - id папки из `coddy sessions list` или префикс, который совпадает ровно с одной сохранённой сессией; при неоднозначном префиксе команда перечисляет кандидатов;
- по умолчанию файл создаётся в текущей папке. `--out` задаёт файл или папку где угодно (включая абсолютные пути); недостающие папки создаются. Формат берётся из `--format`, иначе из расширения `--out`, иначе выбирается markdown, по тем же правилам, что у команды в чате;
- `--no-tools` и `--no-thinking` сокращают документ точно так же, как опции в чате. `--sessions-dir` указывает на другой корень сессий;
- команда печатает `Session exported to <format>: <full path> (<n> transcript entries)` и завершается с ненулевым кодом при неизвестной сессии, неверном формате или ошибке записи. Флаги можно указывать до или после id;
- документ такой же, как при экспорте из чата. Название, модель и ветка git берутся из сохранённого `session.json` и рабочей папки, которую он называет, а итоги по токенам - из его `stats.json`.

## Где команда перечислена

`skills.BuiltinCommands` публикует `export` рядом с `compact` и `plugin`, поэтому команда без дополнительной настройки попадает в каталог ACP `available_commands_update`, в `GET /coddy/commands`, в группу **Команды** поля ввода и в консоль в режиме `--remote`.

## Ограничения

- Файл создаётся на машине, где работает агент. Если `coddy serve` запущен на другом хосте или консоль работает в режиме `--remote`, ищите файл в рабочей папке сервера; ответ печатает полный путь;
- Telegram-шлюз отвечает только на свои команды (`/clear`, `/help`, `/model`, `/context`, `/resume`, `/start`) и команды настроек (`/agent`, `/plan`, `/ask`, `/reasoning`, `/think`, `/nothink`), а остальные слэш-команды отбрасывает, поэтому `/export` там недоступна;
- сессии субагентов никогда не выполняют встроенные команды - промпт, который получает субагент и который начинается с `/export`, для него обычная задача.

## Код

- `internal/session/transcript_export.go` - документ (`BuildExportDocument`), рендереры (`RenderExport`), разрешение цели (`ResolveExportRequest`, `ResolveExportTarget`) и защищённая запись (`WriteExportFile`, `ExportSession`);
- `internal/agent/export_command.go` - разбор команды и ответ; `Agent.Run` обрабатывает команду до цикла ReAct;
- `cmd/coddy/sessions.go` - подкоманда `coddy sessions export` (`PrepareExportOutput` отображает `--out` на корень вывода, `FileStore.ResolveSessionID` принимает уникальный префикс id); спецификация `features/session_export_cli.feature`, харнес `cmd/coddy/bdd_sessions_export_test.go`;
- `features/session_export.feature` - спецификация основного сценария, которую через `POST /v1/responses` прогоняет `external/httpserver/bdd_session_export_test.go` (запускается под `-tags http`); выходы за пределы рабочей папки, символические ссылки, неизвестные форматы и опции покрыты модульными тестами рядом с кодом.
