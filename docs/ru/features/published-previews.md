# Опубликованные предпросмотры

[Сервер предпросмотра](preview-server.md) нужен, пока вы с агентом правите страницу: свободный порт на loopback, файлы проекта читаются с диска на каждый запрос, правка видна после перезагрузки. Он исходит из того, что браузер стоит на той же машине, где работает Coddy.

Опубликованные предпросмотры решают другую задачу. Coddy работает на сервере, люди приходят к нему через HTTPS-прокси, который уже знает, кто они такие, и готовую сборку - отчёт, демо, статический сайт - надо кому-то показать через этот прокси. На случайный порт на loopback маршрут не настроить, а публиковать наружу диапазон портов ради этого никто не хочет.

Поэтому канал сделан отдельным: Coddy поднимает маленький статический сервер только на чтение по **одному адресу, который не меняется**, над **одним корнем артефактов**, а инструмент `preview_publish` копирует туда каталог проекта и возвращает адрес, по которому ваш прокси его отдаёт. Прокси аутентифицирует посетителя и передаёт запрос дальше; Coddy отдаёт байты и больше ничего.

Канал выключен, пока его не включит оператор, и включение ничего не меняет в работе `preview_server`.

## Публикация

Попросите своими словами:

```text
Опубликуй собранный сайт, я отправлю ссылку команде.
```

Агент вызывает `preview_publish`, инструмент сначала спрашивает разрешение - то, что он создаёт, прочитает каждый, кого пускает ваш прокси, - и отвечает адресом.

| Аргумент | Что значит |
|---|---|
| `path` | Каталог для публикации относительно рабочей папки сессии. Без него публикуется сама рабочая папка. Можно указать и файл: публикуется его каталог, а возвращённый адрес открывает этот файл. |
| `name` | Короткое имя, чтобы повторная публикация заменила артефакт **по тому же адресу**. Это то, что нужно, когда ссылка у человека уже есть. Без имени каждая публикация получает свой адрес. |
| `ttl_seconds` | Сколько предпросмотр держится. `0` оставляет его до снятия с публикации; без аргумента действует `tools.preview_publish.ttl_seconds`. |

`preview_unpublish` снимает предпросмотр по имени (`name`) или по `id` из адреса. Сессия заменяет и удаляет только то, что опубликовала сама: идентификатор именованного артефакта выводится из сессии и имени, поэтому две сессии, попросившие `site`, получают два адреса и ни одна не перезапишет чужой.

Адрес всегда заканчивается слэшем, поэтому относительные файлы, модули ES, `fetch` и воркеры опубликованной страницы разрешаются внутри её собственного артефакта и нигде больше.

## Публикуется копия

Опубликованный предпросмотр - это копия, снятая в момент публикации. Ссылка отвечает тем же, чем отвечала раньше, сколько бы ветка ни ушла вперёд, и в этом весь смысл, когда её читают на другом конце света. Публикуйте снова под тем же именем, когда человек должен увидеть новую сборку.

Копия снимается по своим правилам:

- **только проект**: источником может быть рабочая папка сессии или каталог внутри неё, симлинки разрешаются;
- **никаких dot-файлов**: `.git`, `.env`, `.coddy` и всё, что под ними, не копируется, и симлинк на такой файл тоже, поэтому их нельзя случайно опубликовать под именем, которое на них не похоже;
- **без ссылок наружу**: симлинк на файл внутри источника копируется как байты этого файла, а симлинк куда-то ещё или симлинк на каталог в копию не попадает. Публикуйте собранный каталог, а не тот, который ссылается на свои файлы в другом месте. Всё, что осталось за пределами копии, инструмент пересчитывает и называет в ответе;
- **без частичной публикации**: копия собирается в промежуточном каталоге и одним переименованием встаёт на место. Публикация, которая не удалась (источник больше `max_bytes`, кончилось место), оставляет прежний артефакт по этому адресу ровно таким, каким он был, и не оставляет ничего нового;
- **с ограничениями**: один артефакт вмещает не больше `max_bytes` (по умолчанию 100 МиБ) и не больше 20000 файлов.

## Статический сервер

Статический сервер - подсистема [`coddy serve`](../operate/serve.md), она запускается при `tools.preview_publish.enable`. Сервер отдаёт корень артефактов и отказывает во всём остальном:

- `GET` и `HEAD`, на остальное отвечает 405;
- сам корень **никогда не перечисляется**: тот, у кого есть адрес одного артефакта, получает этот артефакт, а не список чужих;
- путь с элементом на точку (`..`, `.git`) получает 404, во что бы он ни разрешался. Файлы открываются через `os.Root`, поэтому и ссылка не выведет за пределы корня;
- артефакт, у которого вышло время жизни, отвечает 404 с момента истечения, даже если сборщик до него ещё не дошёл; раз в минуту сборщик удаляет его с диска;
- `Cache-Control: no-store`, поэтому переопубликованный артефакт никогда не читается из устаревшего кеша;
- при привязке к loopback запрос, у которого в `Host` не loopback-имя, не заданный хост и не хост из `public_url`, отклоняется: это та же защита от DNS rebinding, что и у сервера предпросмотра.

Смена адреса требует нового процесса, как и у HTTP-сервера; корень и публичный адрес подхватываются перезагрузкой конфигурации.

Один корень артефактов принадлежит одному работающему серверу. Процессы не договариваются между собой о том, кто в нём убирает и кто в него пишет, поэтому не направляйте на один каталог два процесса `coddy serve`.

## Конфигурация

```yaml
tools:
  preview_publish:
    enable: true
    host: 127.0.0.1                        # keep the origin private
    port: 8081                             # fixed: the proxy needs a stable upstream
    root: /var/lib/coddy/previews          # the only directory it serves
    public_url: https://coddy.example/preview/
    ttl_seconds: 86400
    max_bytes: 104857600
```

По умолчанию сервер слушает loopback. Прокси на другой машине нужен адрес, до которого он дотянется, а привязка не к loopback отдаёт все опубликованные артефакты каждому, кто доберётся до адреса: выберите приватный адрес и закройте его сетевой политикой или аутентифицированным туннелем. `0.0.0.0` здесь не безопасное значение по умолчанию, и Coddy не делает вид, что это не так. Поля перечислены в [справочнике по конфигурации](../reference/config.md).

## За вашим обратным прокси

Аутентификация, TLS, ограничение частоты запросов и публичная маршрутизация остаются за прокси. Токен API Coddy статическому серверу не передаётся и до браузера не доходит, а `/preview/*` не должен проваливаться на апстрим API.

Caddy:

```caddyfile
coddy.example {
    handle /preview/* {
        forward_auth auth.internal:9091 {
            uri /api/verify
            copy_headers Remote-User
        }
        uri strip_prefix /preview
        reverse_proxy 127.0.0.1:8081
    }
    handle {
        reverse_proxy 127.0.0.1:12345
    }
}
```

Nginx:

```nginx
location /preview/ {
    auth_request /auth;
    proxy_pass http://127.0.0.1:8081/;
    proxy_set_header Host $host;
}
```

Traefik, метками на сервисе Coddy:

```yaml
traefik.http.routers.coddy-preview.rule: Host(`coddy.example`) && PathPrefix(`/preview`)
traefik.http.routers.coddy-preview.middlewares: coddy-auth@file,coddy-preview-strip
traefik.http.services.coddy-preview.loadbalancer.server.port: "8081"
traefik.http.middlewares.coddy-preview-strip.stripprefix.prefixes: /preview
```

В любом из них проверьте три вещи: аутентификация срабатывает **до** статического апстрима, до `127.0.0.1:8081` достаёт только прокси, а в `public_url` записан адрес с тем префиксом, который посетитель набирает на самом деле, - именно его выдаёт агент.

Прокси, который передаёт `Host` посетителя, получит ответ, потому что хост из `public_url` есть в списке разрешённых; прокси, который переписывает `Host` на апстрим, получит ответ, потому что там же есть и хост привязки.

## Чего он не делает

- **Не заменяет хостинг.** Он отдаёт статические файлы и сам никого не аутентифицирует. Кто может прочитать предпросмотр, решает ваш прокси.
- **Не хранит секреты.** Артефакт прочитает каждый, кого прокси пускает. Публикация - осознанное действие, поэтому инструмент каждый раз спрашивает разрешение.
- **Не отменяет `preview_server`.** Тот на месте, по-прежнему занимает свободный локальный порт, читает проект на каждый запрос и остаётся тем, чем вы пользуетесь, пока правите страницу вместе с агентом.
