# Devin

Провайдер `type: devin` даёт Coddy модели аккаунта Devin (Cognition) - Claude, GPT, Gemini, SWE, Kimi, GLM и остальные семейства, которые обслуживает тарифный план аккаунта. Вход выполняется так же, как в Devin CLI, через браузер, либо переиспользуется вход, который уже хранит `devin auth login`. Devin здесь служит только бэкендом - агент остаётся собственным агентом Coddy, с его системным промптом, инструментами, проверкой разрешений и циклом ReAct, в каждом интерфейсе - в консоли, веб-интерфейсе, редакторах с ACP и Telegram-шлюзе.

Использование оплачивается с аккаунта Devin так же, как сессия Devin CLI.

## Вход

```bash
coddy providers login devin
```

Команда открывает страницу входа Devin в браузере и ждёт. После входа страница отправляет браузер обратно на `http://127.0.0.1:<port>/callback` на этой машине, где Coddy получает код авторизации, обменивает его на токен сессии (PKCE, тот же обмен, что делает `devin auth login`) и проверяет токен, выпуская с ним пользовательский JWT. Затем команда печатает аккаунт и записывает три вещи:

- токен сессии - в `$CODDY_HOME/providers/devin/devin-auth.json` с правами `0600`;
- строку провайдера и по одной модели на каждое семейство, доступное аккаунту, - в `config.yaml`;
- `agent.model`, если в конфигурации его ещё нет.

```text
$ coddy providers login devin
Open https://app.devin.ai/auth/cli/continue?...
Sign in there; the page then sends the browser back to this machine.
If the browser runs on another machine, that last page will not load: copy its address from the address bar and paste it here.
Waiting for the sign-in to finish...
Signed in as Jane <jane@example.com>. Credential stored at /home/jane/.coddy/providers/devin/devin-auth.json
Updated /home/jane/.coddy/config.yaml: provider devin, agent.model devin/claude-opus-5, 39 models (devin/claude-opus-5, devin/claude-fable-5-1, devin/claude-sonnet-5, ...)
```

На машине, куда вы зашли по SSH, нет браузера, который можно открыть, а браузер на вашем ноутбуке не достучится до loopback-порта сервера. Откройте напечатанный адрес на ноутбуке, войдите, а когда браузер окажется на странице `127.0.0.1`, которая не загружается, скопируйте её адрес из адресной строки и вставьте в терминал - в нём есть код, и вход завершается так же. Строку, которая не похожа на такой адрес, команда отвергает с пояснением и продолжает ждать. Ожидание заканчивается через десять минут или раньше по Ctrl-C.

`--no-config` сохраняет токен и не трогает `config.yaml`. Повторный вход только добавляет недостающее - строки и модели, которые уже есть в файле, остаются такими, как вы их написали.

### Переиспользовать вход Devin CLI

```bash
coddy providers login devin --devin-cli
```

Если Devin CLI установлен и в нём выполнен вход, браузер не нужен - команда проверяет собственный вход CLI, выпуская с ним пользовательский JWT, и публикует каталог в `config.yaml`. Вход Devin CLI соответствует одному аккаунту, поэтому обслуживает одну строку, а именно единственную строку devin или строку с именем `devin`, если их несколько ([Несколько профилей одного типа провайдера](../getting-started/configuration.md#несколько-профилей-одного-типа-провайдера)); для другой строки `--devin-cli` отказывает, такая строка входит со своим собственным входом. Токен остаётся там, где его хранит Devin CLI; Coddy читает его при каждом запросе и никогда не пишет в этот файл. Поэтому `devin auth logout` завершает вход и для Coddy.

## Откуда берётся токен сессии

Запрос использует первый из этих источников, в котором есть токен:

1. `api_key` строки, `api_key_command` или переменная `DEVIN_API_KEY` (для строки с именем `devin`; имя подчиняется обычному правилу `NAME_API_KEY`). Значение - токен сессии Devin, `devin-session-token$...`; к голому токену этот префикс добавляется;
2. вход под управлением Coddy, `$CODDY_HOME/providers/<name>/devin-auth.json`;
3. вход Devin CLI для той единственной строки, которую он обслуживает (единственной строки devin или строки с именем `devin` среди нескольких), - `credentials.toml` в `$XDG_DATA_HOME/devin` или `~/.local/share/devin` (на macOS ещё и `~/Library/Application Support/devin`, на Windows `%LOCALAPPDATA%\devin`). `CODDY_DEVIN_CLI_CREDENTIALS` явно задаёт путь к файлу.

`coddy providers list` показывает, какой источник использует строка, с замаскированным токеном.

```text
  devin (devin): signed in to Devin (jane@example.com, devin-session-token$…Q2xw)
```

`coddy providers logout devin` удаляет только файл, которым управляет Coddy. Если есть вход Devin CLI, строка продолжает работать через него, и команда об этом сообщает. Сама сессия на стороне Devin остаётся действительной, пока вы не завершите её там.

При старте `coddy acp` и HTTP-сервер `coddy serve` пишут в лог по одной строке `devin credential` на каждую строку devin. В ней назван источник, который будет использован (переменная вида `DEVIN_API_KEY`, если она задана, потому что она идёт первой), или стоит предупреждение, что источника нет, а для строки, которую вход Devin CLI не обслуживает, - какую строку он обслуживает.

## Модели и уровни рассуждения

Каталог Devin перечисляет каждый вариант модели под своим идентификатором - Claude Opus 5 приходит как `claude-opus-5-low`, `-medium`, `-high`, `-xhigh` и `-max`, а также платные варианты вроде `-fast`. Coddy предлагает одну модель на семейство и выбирает варианты через уровень рассуждения, поэтому при входе в конфигурацию попадают записи вроде этой.

```yaml
models:
  - model: devin/claude-opus-5
    reasoning_levels: [low, medium, high, xhigh, max]
    reasoning_default: medium
    max_context_tokens: 1000000
    multimodal: true
```

Ход на `devin/claude-opus-5` с уровнем `high` отправляется как `claude-opus-5-high`. Уровни, значение по умолчанию, окно контекста и поддержка изображений берутся из каталога, для каждого семейства свои; семейство с одним вариантом получает `reasoning_levels: []`, и селектор рассуждения для него скрыт. Если у семейства есть вариант `none`, селектор предлагает `off` рядом с `none`, и оба выбирают этот вариант. Уровень, которого у семейства нет, откатывается к варианту семейства по умолчанию; `minimal` берёт `minimal`, `none` или `low` - первый, который есть у семейства.

Любой полный идентификатор варианта тоже работает как модель, например `devin/claude-opus-5-high-fast` - идентификатор, известный каталогу, отправляется как написан, при любом уровне рассуждения. Работает и идентификатор, которого нет в каталоге, и тогда за него отвечает сервер Devin API.

`max_tokens` в записи модели ограничивает вывод; без него используется собственный лимит варианта из каталога. Ограничение снижается, если промпт вместе с ним не помещается в окно контекста, потому что на превышение сервер отвечает невнятной внутренней ошибкой, которую не исправляет никакой повтор. `temperature`, настроенная для модели, отправляется, если не действует уровень рассуждения; без неё запрос несёт `1.0`, как это делают клиенты Devin.

Рассуждение идёт в транскрипт потоком, как у любого другого провайдера. Подписанные блоки рассуждения (Claude, Gemini) хранятся вместе с сообщением ассистента и воспроизводятся в следующем запросе к тому же варианту, поэтому модель продолжает собственную цепочку рассуждений между вызовами инструментов.

## Использование аккаунта

Строка `type: devin` также сообщает квоту аккаунта. Её читает RPC управления местами `GetUserStatus` сервера Devin API (тот же вызов, что делает редактор) с собственным токеном сессии строки и **без** пользовательского JWT - сервер убирает `plan_status` (поля квоты) из ответа всякий раз, когда метаданные запроса несут JWT, поэтому это чтение - единственный вызов Devin, который не должен выпускать JWT. Ответ доходит до всех интерфейсов через общую панель лимитов - нижнюю строку консоли и `/usage`, всплывающее окно контекста и баннер веб-интерфейса, `GET /coddy/providers/{name}/usage` и обновления `provider_usage` ([Консоль](../surfaces/console.md#визуальная-модель), [Конфигурация](../getting-started/configuration.md)).

Панель показывает то, что сообщает план:

- план с **квотой** показывает шкалы `day` и `week` с временем сброса; сервер сообщает *оставшиеся* проценты, поэтому панель пересчитывает их в использованные. Если план скрывает окно квоты, эта шкала пропускается;
- план **ACU** показывает одну шкалу `acu` из пары "израсходовано/лимит", без часов сброса;
- план с **кредитами**, неизвестная стратегия оплаты или статус, в котором назван только план, показываются просто как план - Coddy не придумывает шкалу, число запросов или сброс, которых сервер не прислал, а отсутствующая квота показывается как `quota unavailable`, а не как `0%`.

`usage_limits_panel: false` в строке скрывает панель везде и прекращает чтения `GetUserStatus`. Cognition не публикует протокол, поэтому чтение следует текущему формату обмена редактора (дескрипторы 3.10.31) и может сломаться, когда Devin его изменит.

## Конфигурация

```yaml
providers:
  - name: devin
    type: devin
    # api_key: devin-session-token$...   # optional, wins over the logins
    # proxy: none                        # the route of every request of the row

models:
  - model: devin/claude-sonnet-5
    reasoning_levels: [low, medium, high, xhigh, max]
    reasoning_default: medium
```

Для `type: devin` поле `api_base` игнорируется - токен сессии уходит только на сервер Devin API. Адрес сервера определяет сам вход. Аккаунт, который обслуживает выделенное развёртывание, записывает этот адрес вместе с токеном, а пользовательский JWT может перевести чат на собственный сервер аккаунта. `proxy` одинаково направляет вход, каталог и чат ([Прокси провайдера](../getting-started/configuration.md#прокси-провайдера)).

`coddy --dry-run` запрашивает у каждой строки devin её каталог и сверяет настроенные модели со списком семейств; полный идентификатор варианта там выдаётся как предупреждение, потому что список семейств не называет вариантов.

## Как это работает

Провайдер говорит на протоколе, которым Devin CLI и Devin Desktop общаются с сервером Devin API, - Connect-RPC с сообщениями protobuf. Токен сессии обменивается на пользовательский JWT (`GetUserJwt`, кешируется до момента незадолго до истечения), каталог приходит из `GetCliModelConfigs` (кешируется на тридцать минут для каждого аккаунта), а ход - это один серверный поток `GetChatMessage` из сжатых gzip кадров, которые несут текст, рассуждение, фрагменты вызовов инструментов, данные об использовании и причину остановки. Системный промпт Coddy передаётся как системный промпт запроса, его инструменты - как определения инструментов, а результаты инструментов - как сообщения инструментов. Учёт использования включает кеш промпта - сообщаемый ввод складывается из некешированной части, записи в кеш и чтения из кеша, а чтение из кеша сообщается как кешированный ввод.

Строки protobuf должны быть корректным UTF-8, и запрос, который нарушает это правило, сервер отвергает с `HTTP 400 invalid_argument: an internal error occurred` - тем же ответом, что и при любой другой причине. Поэтому перед отправкой Coddy заменяет на U+FFFD каждую последовательность байтов, которая не образует корректный UTF-8, откуда бы она ни пришла - из совпадения `grep` или вывода команды из файла в устаревшей кодировке либо из вложения, отличного от изображения. JSON-провайдеры получают ту же замену от JSON-кодировщика.

Cognition не публикует протокол. Coddy повторяет то, что отправляют официальные клиенты, поэтому изменение на стороне Devin может сломать провайдер, пока Coddy его не догонит.

Поток, который сервер завершает ошибкой до того, как вызывающая сторона получила хоть какой-то текст, повторяется по обычным правилам (ограничение частоты, `resource_exhausted`, считается как HTTP 429); если текст уже пошёл, повтора нет, поэтому ни одна дельта не показывается дважды. Поток, оборванный до завершающего кадра, сохраняет доставленный текст и отбрасывает вызовы инструментов незаконченного ответа.

## Стенды и тесты

`CODDY_DEVIN_API_SERVER_URL`, `CODDY_DEVIN_WEBAPP_URL` и `CODDY_DEVIN_API_URL` переносят сервер API, страницу входа и обмен кода для всего процесса; `internal/devinfake` - офлайн-стенд, который играет роль всех трёх, а `features/devin_provider.feature` прогоняет против него вход, вход Devin CLI, полный ход агента и результат инструмента не в UTF-8, без аккаунта и без сети.
