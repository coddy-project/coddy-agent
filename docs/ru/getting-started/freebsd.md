# FreeBSD

Coddy работает на FreeBSD из релизной сборки для неё: **`coddy_X.Y.Z_freebsd_amd64.tar.gz`** для
x86-64 и **`coddy_X.Y.Z_freebsd_arm64.tar.gz`** для 64-битной ARM. Это Coddy целиком - консоль,
**`coddy serve`** с веб-интерфейсом, боты Telegram и Pachca, релей роя, экспортёр Prometheus,
**`coddy acp`** и окно рабочего стола - собранный с тем же набором тегов, что и архивы для Linux и
macOS.

Бинарник написан на чистом Go и слинкован статически, рядом не нужен ни один порт, и работает он на
FreeBSD 13 и новее. Части Coddy, которые обращаются к ядру, используют интерфейсы BSD, а не Linux;
это единственное, что здесь нужно объяснить.

## Установка

Скрипт установки распознаёт FreeBSD и забирает нужный архив. Сам он написан на bash и вызывает
**`curl`**, а в базовой системе нет ни того, ни другого.

```sh
pkg install -y bash curl
curl -fsSL https://coddy.dev/install.sh | bash
```

Скрипт кладёт **`coddy`** в **`~/.local/bin`**, man-страницу и автодополнения в
**`~/.local/share`**, а блок, который добавляет их в **`PATH`** и **`MANPATH`**, пишет в rc-файл
той оболочки, которую называет **`$SHELL`**: **`~/.profile`** для стандартного **`sh`** во FreeBSD,
**`~/.bashrc`** для bash, **`~/.zshrc`** для zsh.

Вручную это делается так, заменив **`X.Y.Z`** на нужный релиз, а **`amd64`** на **`arm64`**, если
**`uname -m`** печатает **`arm64`**.

```sh
fetch https://github.com/coddy-project/coddy-agent/releases/download/X.Y.Z/coddy_X.Y.Z_freebsd_amd64.tar.gz
tar -xzf coddy_X.Y.Z_freebsd_amd64.tar.gz
mkdir -p ~/.local/bin ~/.local/share/man/man1
install -m 0755 coddy ~/.local/bin/coddy
install -m 0644 coddy.1 ~/.local/share/man/man1/coddy.1
```

Для первого запуска нужен ключ провайдера в **`~/.coddy/config.yaml`**, как и на любой другой
системе; смотрите [Конфигурация](configuration.md). **`coddy update`** заменяет бинарник на месте
из архива FreeBSD следующего релиза, вместе с man-страницей и автодополнениями рядом; смотрите
[Обновление](update.md).

Пакета или порта FreeBSD пока нет, поэтому **`coddy update`** не спрашивает у **`pkg`**, кому
принадлежит файл, который он собирается заменить, как спрашивает у **`dpkg`** и **`rpm`** в Linux.
Ставьте Coddy в свой префикс, как выше, а не поверх файла, который положил в **`/usr/local/bin`**
какой-нибудь порт.

## Запуск `coddy serve`

**`coddy serve`** работает так же, как везде, веб-интерфейс открывается на
**`http://127.0.0.1:12345/`**. Systemd во FreeBSD нет, поэтому **`coddy serve install`** там
недоступен и прямо об этом говорит. Остаются три пути:

- **`coddy serve --daemon`** - держит один процесс и перезапускает его после изменения
  конфигурации, которому нужен новый процесс. Управляют им **`coddy serve status | stop | restart`**.
  Обычный выбор для рабочей машины;
- **`tmux`** (**`pkg install -y tmux`**) - консольная сессия переживёт закрытый терминал или
  оборванное SSH-соединение;
- собственный скрипт **`rc.d`** для машины, где агент должен вернуться после перезагрузки.
  Состояние Coddy лежит у каждого пользователя в **`~/.coddy`**, поэтому сервис работает от имени
  этого пользователя, а не от root. Короткий вариант кладут в **`/usr/local/etc/rc.d/coddy`**.

  ```sh
  #!/bin/sh
  #
  # PROVIDE: coddy
  # REQUIRE: LOGIN
  # KEYWORD: shutdown
  . /etc/rc.subr

  name="coddy"
  rcvar="coddy_enable"
  load_rc_config $name
  : ${coddy_enable:="NO"}
  : ${coddy_user:="coddy"}
  : ${coddy_home:="/home/coddy"}

  pidfile="/var/run/${name}.pid"
  command="/usr/sbin/daemon"
  command_args="-p ${pidfile} -u ${coddy_user} -r \
      /home/coddy/.local/bin/coddy serve"
  run_rc_command "$1"
  ```

  Дальше **`sysrc coddy_enable=YES`** и **`service coddy start`**. Флаг **`-r`** перезапускает
  процесс, если тот завершился, - это та часть, которую **`--daemon`** делает сам.

Что сервер умеет после запуска, описано в [coddy serve](../operate/serve.md).

## Окно рабочего стола

**`coddy desktop`** открывает окно во FreeBSD так же, как в Linux, - браузером семейства Chromium
из дерева портов (**`www/chromium`**, **`www/ungoogled-chromium`** и прочими) в режиме приложения,
с отдельным профилем под **`~/.coddy/desktop/profiles/`**. Под X11 системная рамка снимается, углы
скругляются, а полоса вкладок двигает окно; под Wayland окно остаётся с рамкой, которую рисует
композитор, как и в Linux. Иконка в трее - это StatusNotifierItem на сессионной шине, а
**Open at login** пишет XDG-запись автозапуска в **`~/.config/autostart`**.

Смотрите [Окно рабочего стола](../surfaces/desktop.md).

## Чем FreeBSD отличается от Linux

Настраивать ничего не нужно. Ниже перечислены места, где сборка для FreeBSD идёт другим путём,
чтобы сообщению о проблеме было куда указать:

- **свободное место на диске**, которое показывают страница состояния и **`--dry-run`**, берётся из
  **`statfs`** по полю **`f_bsize`**, тогда как Linux читает **`f_frsize`**;
- **локальный управляющий сокет** проверяет, что процесс на другом конце запущен тем же
  пользователем, через **`LOCAL_PEERCRED`** и **`struct xucred`**, тогда как Linux читает
  **`SO_PEERCRED`**. Эта проверка не пускает в работающий агент другую учётную запись на машине;
- **хранилище учётных данных Kimi** идёт тем же путём с блокировкой и защитой от потери при сбое,
  что в Linux и macOS: проверка владельца и прав каталога хранилища, **`flock`** вокруг обновления
  токена и сброс каталога на диск после него;
- **окно рабочего стола** находит запущенный им процесс браузера, поднимаясь по дереву процессов
  через sysctl **`kern.proc.pid`**, потому что **`procfs`** во FreeBSD по умолчанию не смонтирована
  и читать **`/proc`** негде;
- **открытие ссылки или папки** - вход к провайдеру или показ созданного агентом файла в файловом
  менеджере рабочего стола - идёт через **`xdg-open`** (**`devel/xdg-utils`**), как и в Linux.

## Ограничения

- Публикуются только две 64-битные архитектуры, **`amd64`** и **`arm64`**;
- пакета или порта FreeBSD нет, установить или обновить Coddy через **`pkg`** нельзя;
- **`coddy serve install`** требует systemd и потому доступен только в Linux; чем его заменить,
  написано в разделе выше;
- пакеты **`.deb`** и **`.rpm`**, cask Homebrew и образ контейнера сделаны для Linux и macOS, и
  аналогов для FreeBSD у них нет.

## Сборка своими руками

Машина с FreeBSD собирает Coddy так же, как любая другая. Нужны Go и, для встроенного
веб-интерфейса, Node.

```sh
pkg install -y go node npm gmake git
gmake build TAGS="http ui scheduler memory cli gateway swarm metrics browser desktop"
```

**`gmake`** - это GNU make, который нужен **`Makefile`**; собственный **`make`** во FreeBSD его не
прочитает.

С любой машины **`make check-freebsd`** проверяет типы сборки FreeBSD для обеих публикуемых
архитектур вместе с файлами тестов, а **`make lint-freebsd`** прогоняет по ней линтер. CI запускает
обе команды на каждом пул-реквесте, а затем гоняет наборы тестов платформы на настоящей FreeBSD;
смотрите [Сборка из исходников](../contributing/build.md#freebsd).
