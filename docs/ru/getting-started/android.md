# Android (Termux)

Coddy работает на Android внутри [Termux](https://termux.dev) из релиза, собранного для Android.
Для 64-битного ARM (aarch64), процессора телефонов и планшетов, это
**`coddy_X.Y.Z_android_arm64.tar.gz`**, а для x86-64 (x86_64), на котором Android работает в
эмуляторах, на Chromebook и на ПК, - **`coddy_X.Y.Z_android_amd64.tar.gz`**. Это полный Coddy -
консоль, **`coddy serve`** с веб-интерфейсом, Telegram-бот и **`coddy acp`**. Нужен Android 7.0 или
новее, как и для самого Termux.

## Установка

Скрипт установки распознаёт Termux и скачивает сборку для Android под процессор устройства.

```bash
pkg install curl
curl -fsSL https://coddy.dev/install.sh | bash
```

Он устанавливает **`coddy`** в **`~/.local/bin`**, man-страницу и автодополнения в
**`~/.local/share`** и записывает блок, который добавляет их в **`PATH`**, в **`~/.bashrc`** - этот
файл читает login-оболочка Termux. Повторный запуск скрипта заменяет бинарник, который он установил
раньше, в том числе сборку для Linux, оставшуюся от прошлой попытки. Откройте новую сессию или
перечитайте файл и проверьте.

```bash
source ~/.bashrc
coddy -v
```

Вручную это делается так (замените **`X.Y.Z`** на нужный релиз, а **`arm64`** на **`amd64`**, если
**`uname -m`** выводит **`x86_64`**).

```bash
curl -fsSLO https://github.com/coddy-project/coddy-agent/releases/download/X.Y.Z/coddy_X.Y.Z_android_arm64.tar.gz
tar -xzf coddy_X.Y.Z_android_arm64.tar.gz
install -m 0755 coddy "$PREFIX/bin/coddy"
```

**`$PREFIX/bin`** уже есть в **`PATH`** Termux. Держите бинарник в собственном хранилище Termux, как
в обоих примерах. Android монтирует общее хранилище (**`/sdcard`**, **`~/storage`**) без права
что-либо из него запускать.

Для первого запуска нужен ключ провайдера в **`~/.coddy/config.yaml`**, как и на любой другой
системе; см. [Конфигурация](configuration.md).

## Почему не запускается архив для Linux

В архивах для Linux лежит статический исполняемый файл Linux, и Termux может запустить его не везде.
Android 10 и новее запрещают приложению, нацеленному на эти версии, запускать файлы из собственного
каталога данных, поэтому Termux, нацеленный на них (например, сборка из Google Play), запускает
каждую программу через компоновщик Android, **`/system/bin/linker64 <program>`**. Компоновщик
загружает только позиционно-независимые исполняемые файлы и отвергает статический.

```text
error: "/data/data/com.termux/files/home/.local/bin/coddy" has unexpected e_type: 2
```

Там, где Termux запускает файлы напрямую (сборки из F-Droid и GitHub), бинарник для Linux стартует,
но нужных ему путей Linux нет. Он не находит ни сертификатов CA, ни **`/etc/resolv.conf`**, поэтому
каждый запрос к провайдеру завершается ошибкой, а на версиях Android, чей фильтр seccomp отвергает
системный вызов **`faccessat2`**, процесс убивается с **`Bad system call`**, как только впервые ищет
программу.

Архивы для Android собираются с **`GOOS=android`** и компонуются Android NDK с Bionic, библиотекой C
в Android. Получается позиционно-независимый исполняемый файл, у которого интерпретатором указан
**`/system/bin/linker64`** и которому нужны только библиотеки, имеющиеся в любом Android
(**`libc`**, **`libdl`**, **`liblog`**), и его запускают оба вида Termux. Как и любая программа
Termux, он разрешает имена хостов через сам Android, поэтому действуют и DNS сети, и Private DNS, и
DNS VPN. Дальше на этой странице описано, что эта сборка делает иначе во время работы.

## Что Coddy подстраивает на Android

Ничего настраивать не нужно - Coddy читает окружение Termux при запуске.

- **Программы, которые он запускает.** **`run_command`**, фоновые задачи, хуки, MCP-серверы по stdio,
  git и ripgrep запускаются так же, как Termux запускает собственные программы. Если Termux идёт
  через **`/system/bin/linker64`**, Coddy делает так же, а скрипт передаётся своему интерпретатору;
  скрипт, в первой строке которого указан **`/usr/bin/env`** или **`/bin/sh`**, получает программу
  Termux с тем же именем. Для собственных программ Termux то же самое делает библиотека
  **`termux-exec`**; Coddy, как любая программа на Go, запускает процессы системным вызовом, которого
  библиотека не видит, поэтому делает это сам. Команда оболочки выполняется в **`bash`** Termux и
  ведёт себя так же, как в вашей сессии;
- **Собственный путь.** Если Coddy запущен через компоновщик, он находит свой бинарник по командной
  строке, а не по **`/proc/self/exe`**, который указывает на компоновщик, поэтому **`coddy update`** и
  **`coddy serve --daemon`** обращаются к нужному файлу;
- **Сертификаты.** Coddy доверяет набору сертификатов пакета Termux **`ca-certificates`**,
  **`$PREFIX/etc/tls/cert.pem`**, наряду с системным хранилищем Android. Он делает это через
  **`SSL_CERT_FILE`**, поэтому набор, который вы экспортируете сами, имеет приоритет;
- **Временные файлы.** Если **`TMPDIR`** не задан, используется **`$PREFIX/tmp`**, потому что
  стандартный для Android **`/data/local/tmp`** приложению недоступен для записи;
- **Открытие браузера.** Процедуры входа, например **`coddy providers login`**, открывают браузер
  телефона через **`termux-open-url`**, и браузер попадает на callback, который Coddy слушает на
  loopback-адресе устройства;
- **Обновления.** **`coddy update`** скачивает архив нового релиза для Android и заменяет бинарник на
  месте; см. [Обновление](update.md).

## Запуск `coddy serve`

**`coddy serve`** работает как везде, а веб-интерфейс открывается по адресу
**`http://127.0.0.1:12345/`** в браузере телефона. В Android нет systemd, поэтому
**`coddy serve install`** недоступен. Запускайте сервер в сессии Termux, в **`tmux`**
(**`pkg install tmux`**) или в фоне через **`coddy serve --daemon`** (см. [coddy serve](../operate/serve.md)).

Android останавливает процессы приложения, которое считает бездействующим. Пока сервер должен
работать, включите блокировку сна Termux (**`termux-wake-lock`** или из уведомления Termux) и
разрешите Termux работать без ограничений в настройках батареи. Android 12 и новее к тому же убивают
фоновые процессы приложения сверх лимита ("phantom process killer"); как снять это ограничение,
описано в документации Termux.

Телефон может быть и узлом роя. Он сам подключается к релею на ноутбуке или сервере, а веб-интерфейс
релея и консоль управляют им, как любой другой машиной, и открытый порт на телефоне не нужен. Весь
путь описан на странице [Телефоны на Android как узлы роя](../tutorials/swarm-android-nodes.md).

## Ограничения

- публикуются только 64-битные сборки, arm64 и x86_64, поэтому 32-битные устройства Android на ARM
  или x86 не поддерживаются;
- программа, которая сама по себе статический исполняемый файл, не может работать там, где Termux
  запускает программы через компоновщик, кто бы её ни запускал; таково правило Android, и ошибка та
  же - **`unexpected e_type`**.

## Самостоятельная сборка

**`make android`** кросс-компилирует **`build/coddy-android-arm64`** и **`build/coddy-android-amd64`**
с **`TAGS`**, как у **`make build`**, а **`make check-android`** проверяет типы в сборке для Android.
Обеим командам нужен Android NDK, который компонует бинарники с Bionic; см.
[Сборка из исходников](../contributing/build.md#android-termux).
