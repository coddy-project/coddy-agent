# Хуки OpenCode для правил проекта

Эта страница для контрибьюторов, которые работают с этим репозиторием через OpenCode. Она не описывает, как Coddy сам находит правила - бинарник `coddy` вставляет их через `{{.Rules}}`, как описано на странице [Правила](../features/rules.md).

## Зачем нужен плагин

OpenCode читает корневой `AGENTS.md`, так что карта репозитория и заметки для контрибьюторов, нужные всегда, уже попадают в сессию. OpenCode умеет и загружать инструкции по glob-шаблонам из `opencode.json`, но все подходящие файлы инструкций он склеивает в промпт, а пофайловая семантика `globs` из Cursor к frontmatter `.mdc` не применяется.

Этот репозиторий хранит правила в родном формате Cursor в `.cursor/rules/*.mdc`. Плагин проекта `.opencode/plugins/project-rules.js` читает этот frontmatter напрямую и подключает только те правила, которые нужны текущей сессии. Дерево Cursor служит лишь входными данными адаптера и не задумано как универсальный формат политик; отдельной копии тела правила для OpenCode никто не ведёт.

OpenCode автоматически загружает файлы JavaScript и TypeScript из `.opencode/plugins/`. Этому плагину не нужны ни запись в `opencode.json`, ни установка пакетов. Он пользуется только совместимыми с Node API, которые даёт среда выполнения OpenCode.

## Соответствие хуков

| Хук OpenCode | Поведение |
|---|---|
| `experimental.chat.system.transform` | Добавляет к каждому запросу модели все правила с `alwaysApply: true` и активные правила сессии с областью действия. |
| `tool.execute.before` | Извлекает пути файлов из аргументов инструментов и заголовков патчей, затем активирует правила, чьи `globs` совпадают с этими путями. |
| `experimental.session.compacting` | Добавляет выбранные правила в контекст сжатия, чтобы они явно остались в сводке, с которой продолжается сессия. |
| событие `session.deleted` | Освобождает хранимый в памяти набор правил с областью действия для удалённой сессии. |

Чтение файла, на который распространяются правила с областью действия, активирует их для следующего запроса модели. Обычно это значит, что правила окажутся в контексте раньше, чем модель начнёт править файл.

Стабильный хук OpenCode `tool.execute.before` может заблокировать или изменить вызов инструмента, но не может добавить к текущему вызову сообщение, которое увидит модель. Поэтому если `edit`, `write`, `apply_patch` или другой распознанный инструмент записи оказывается первой операцией, которая открывает правило с областью действия, плагин намеренно отклоняет этот вызов один раз. Ошибка просит OpenCode повторить вызов; следующий запрос модели получает только что активированное правило через `experimental.chat.system.transform`, и повторная правка проходит. Так первая запись становится детерминированной и не зависит от того, откроет ли модель файл правила, на который ей сослались.

## Разбор и сопоставление правил

Реализация читает из frontmatter Cursor поля `description`, `globs` и `alwaysApply`. `globs` может быть скаляром, однострочным или многострочным flow-списком или блочным списком YAML; запятые в кавычках, удвоенные одинарные кавычки, экранированные символы в двойных кавычках и комментарии YAML декодируются, и список при этом не обрезается. Транслятор glob-шаблонов держит `*` внутри одного сегмента пути и считает `**/` нулём или больше каталогов, поэтому `external/httpserver/**/*.go` совпадает и с `external/httpserver/server.go`, и с файлами глубже.

Аргументы инструментов просматриваются рекурсивно. Среди распознаваемых ключей с путями есть `filePath`, `path`, `filename`, `target` и их распространённые варианты. В унифицированном патче распознаются заголовки `*** Add File:`, `*** Update File:`, `*** Delete File:` и `*** Move to:`. Абсолютные пути вне репозитория игнорируются.

Правила перечитываются для каждого подходящего хука, поэтому правка или добавление файла `.mdc` не требует настройки плагина. Некорректный или нечитаемый файл правила пропускается, а остальные правила продолжают работать.

## Состояние сессии и сжатие контекста

Активированные правила с областью действия хранятся в памяти процесса плагинов OpenCode с ключом по id сессии. Они переживают обычное сжатие контекста и очищаются, когда OpenCode сообщает `session.deleted`. Перезапуск OpenCode очищает этот кеш. После перезапуска чтение файла, на который распространяется правило, снова его активирует; прямая первая правка может ещё раз получить однократный отказ с просьбой повторить.

Плагин намеренно добавляет выбранные правила при каждом преобразовании системного промпта и не отслеживает, был ли их текст уже отправлен. После сжатия контекста запросы к модели независимы друг от друга, и повторяемый системный контекст - самое надёжное место для долговременных ограничений.

## Проверка

Набор тестов адаптеров репозитория проверяет frontmatter со скалярами и списками YAML, вставку постоянных правил, рекурсивное сопоставление glob-шаблонов Cursor, активацию через `read`, повтор первой записи, извлечение путей из патчей, совпадение поведения с хуком на Python и очистку сессий.

```bash
make test-agent-rules
```

Чтобы прогнать только тесты OpenCode, запустите следующее.

```bash
make test-opencode-rules
# or: node --test .opencode/tests/project-rules.test.js
```

Тестам не нужны ни подключение к провайдеру, ни установленный OpenCode. Чтобы проверить настоящую интеграцию, начните в репозитории новую сессию OpenCode, попросите прочитать `external/httpserver/server.go` и посмотрите следующий запрос модели с включённым отладочным логом OpenCode.

## Совместимость и безопасность

Хуки преобразования системного промпта и сжатия контекста сейчас помечены в OpenCode как `experimental`. При обновлении OpenCode заново прогоните модульные тесты и настоящую дымовую проверку.

Плагины проекта - исполняемый код, и OpenCode загружает их автоматически. Открывая чекаут, которому вы не доверяете, просмотрите `.opencode/plugins/`. Этот плагин не запускает команды, не обращается к сети и не загружает сторонние зависимости; он только читает файлы правил внутри текущего worktree и хранит в памяти имена правил по сессиям.

Подробнее в документации OpenCode, разделы [Правила OpenCode](https://opencode.ai/docs/rules/) и [Плагины OpenCode](https://opencode.ai/docs/plugins/).
