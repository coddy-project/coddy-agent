# Архитектура Coddy Agent

## Обзор

Coddy - **ACP-харнес, удобный для distroless**, написанный на Go. В основе это протокольная обвязка
(STDIO-сервер JSON-RPC, сессии, конфигурация, подключение MCP) и цикл выполнения **ReAct** поверх
подключаемых провайдеров LLM. Поставляйте его одним бинарником, который подходит для образов scratch и distroless,
сайдкаров, песочниц CI и локальных установок.

Набор инструментов и промпты по умолчанию настроены так, чтобы харнес выглядел как **интерактивный агент для программирования**
(ACP-клиенты запускают `coddy acp`; пользователи получают файловую систему, команды, MCP, правила проекта из деревьев правил `.coddy`/`.cursor`/`.claude`/`.codex` вместе с вложенными файлами `AGENTS.md` под cwd сессии и скилы из `skills.dirs`).
Этот интерфейс агента для программирования - **готовый продуктовый профиль поверх харнеса**, и запускать Coddy можно не только так.

## Описание компонентов

### Слой ACP-сервера (`internal/acp`)

Реализует сервер JSON-RPC 2.0, который говорит по протоколу ACP через stdio.
Обрабатывает:
- `initialize` - согласование версии, обмен возможностями;
- `session/new` - создать сессию, подключить серверы MCP, вернуть режимы и Session Config Options (селекторы модели и режима);
- `session/load` - восстановить сохранённый бандл с диска (по умолчанию **`$CODDY_HOME/sessions`**, обычно **`~/.coddy/sessions`**) и воспроизвести историю через `session/update`;
- `session/list` - перечислить сохранённые сессии (ACP `sessionCapabilities.list`);
- `session/prompt` - принять сообщение пользователя и запустить цикл ReAct;
- `session/cancel` - отменить идущий ход;
- `session/set_mode` - переключиться между режимами `agent`, `plan` и `ask` (устаревший метод, синхронизируется с параметрами конфигурации);
- `session/set_config_option` - сменить режим или модель сессии (предпочтительный API ACP).

### Менеджер сессий (`internal/session`)

Хранит состояние каждой сессии диалога:
- История диалога (сообщения, результаты инструментов);
- Текущий режим работы (`agent` / `plan` / `ask`);
- Необязательная замена модели для сессии (когда пользователь выбирает модель через ACP);
- Подключённые клиенты серверов MCP;
- Рабочий каталог;
- Активный контекст (скилы и правила проекта в отдельных разделах промпта);
- Пункты плана в памяти для инструментов todo (**`session.Plan`**), которые дублируются в **`todos/active.md`**, когда включено сохранение (**`filesystem.go`**);
- Дочерние сессии для запусков субагентов (**`subagent.go`**) - **`CreateSubagentSession`**, **`RunSubagentTurn`** и **`RetireSubagentSession`** реализуют **`agent.SubagentRuntime`**, поэтому дочерняя сессия создаётся, выполняет свой единственный ход и закрывается через менеджер и никогда не собирается внутри агента. У дочерней сессии обычный идентификатор **`sess_`**, а её бандл пишется **внутрь бандла родителя**, в **`session.ChildSessionsDirName`** (**`subagents/`**), методом **`FileStore.EnsureChildLayout`**; **`FileStore.SessionPath`** находит вложенный идентификатор по индексу, который хранилище заполняет по мере создания бандлов, а для бандла, записанного прежним процессом, - обходом корня. Любой путь промпта к дочерней сессии отвечает **`ErrSubagentReadOnly`** (**409** по HTTP), и решается это по метаданным бандла **`subagentRun`**, а не по виду идентификатора; **`ListSnapshotsWith(ListOptions{IncludeSubagents: true})`** - единственное перечисление сессий, которое спускается во вложенные бандлы; **`SessionTree`** / **`DeleteSessionTree`** обходят это дерево каталогов и удаляют родителя вместе с потомками, сначала остановив их задачи. См. **`docs/features/subagents.md`**.

### Цикл агента ReAct (`internal/agent`)

Основной движок рассуждений (**`react.go`**):

1. Загружает определения инструментов из **`internal/tooling.Registry.AllToolDefinitions`**, применяет **`ToolSet`** сессии из **`internal/agent/toolsets.go`** (пустой набор означает отсутствие фильтра), затем добавляет определения инструментов MCP от подключённых серверов, если режим **`agent`** или **`plan`** (в режиме **`ask`** никогда). В режиме **`ask`** вызов, который называет отфильтрованный инструмент (например, воспроизведённый из истории), к тому же отклоняется при выполнении;
2. Собирает системный промпт через **`internal/prompts.Render`** из встроенных шаблонов по умолчанию или из файлов в **`prompts.dir`**, названных в **`prompts.agent_prompt`**, **`prompts.plan_prompt`** и **`prompts.ask_prompt`** (по умолчанию **`agent.md`**, **`plan.md`** и **`ask.md`**). Данные шаблона включают **`CWD`**, markdown инструментов, markdown скилов, markdown правил (**`{{.Rules}}`** через **`internal/rules`**), необязательные **`TodoList`** и **`Memory`**, **`ModelSwitch`** (предлагается ли ходу **`switch_model`**; встроенные шаблоны описывают инструмент только в этом случае, поэтому субагенту или конфигурации, в которой нечего переключать, о нём не говорят), **`BackgroundWake`** (может ли завершившаяся фоновая задача разбудить сессию; там, где не может, - у субагента, запуска по расписанию, `coddy -p` - шаблоны велят модели собрать результаты до конца хода, а не обещают пробуждение), а также **`UTCNow`** (RFC3339 UTC, обновляется при каждой отрисовке). Затем Coddy добавляет блок **`<environment_context>`** с **`<os>`**, **`<arch>`** и обнаруженным **`<shell>`**, даже когда используется собственный шаблон промпта. Сообщение отрисовывается **один раз за ход** и затем замораживается, поэтому кэш промптов провайдера сохраняет диалог за ним; встроенные шаблоны не выводят ни **`UTCNow`**, ни **`TodoList`**, а то, что меняется в течение хода, отправляется после истории в блоке **`<turn_context>`** (**`internal/agent/turn_context.go`** и *Блок контекста хода* в **`docs/contributing/react-agent.md`**);
3. Ставит это системное сообщение в начало списка сообщений сессии и добавляет в конец последний ход пользователя;
4. **Перед каждым вызовом LLM** внутри одного **`session/prompt`** добавляет после истории блок **`<turn_context>`** (**`internal/agent/turn_context.go`**) - текущее время, чек-лист todo после вызова **`coddy_todo_*`**, правила, которые активировал вызов файлового инструмента с момента заморозки промпта, отчёт субагента памяти и фоновые задачи сессии, которые ещё выполняются. **Само сообщение `system` не трогается** - его перезапись выбросила бы кэшированную у провайдера копию диалога за ним. Исключение - шаблон в **`prompts.dir`**, который сам выводит **`{{.UTCNow}}`** или **`{{.TodoList}}`**. Такой шаблон, как и раньше, перерисовывается при каждом вызове и блока не получает;
5. Получает ответ LLM потоком, выполняет вызовы инструментов (каждый проходит через хуки оператора из **`internal/hooks`** - `PreToolUse` до проверки разрешений, `PostToolUse` или `PostToolUseFailure` после инструмента) и добавляет сообщения ассистента и инструментов;
6. Повторяет цикл, пока не кончатся вызовы инструментов, не будет достигнут предел **`max_turns`** (по умолчанию 165; явный 0 его отключает), защита от зацикливания не остановит вышедший из-под контроля ход или не придёт отмена. Ход, остановленный по **`max_turns`** или **`max_tokens`**, оставляет об этом уведомление в UI-журнале сессии и в **`SessionPromptResult.StopNotice`**. Шаг, который остановился по **`max_tokens`** без текста и без вызова инструмента, сначала повторяют словами (6b), поэтому ход так заканчивается только после повторного обрыва или если оборванный шаг уже написал текст;
6a. Защита от зацикливания (**`agent.loop_guard`**, включена по умолчанию, **`internal/agent/loopguard.go`**). Если потоковый канал вырождается в повтор одного и того же фрагмента, его поток отменяется и повторённый кусок вырезается из сохранённого сообщения, а вызов инструмента, повторённый с идентичными каноническими аргументами, перестаёт выполняться. Модель подталкивают сменить курс до **`agent.loop_nudge_max`** раз, после чего ход завершается с **`StopReasonRefused`** и уведомлением в UI;
6b. Восстановление и повторы транспорта делят **`agent.llm_retry_max`** дополнительных попыток на шаг модели (по умолчанию 3, явный 0 их отключает). Первый запрос не засчитывается; вызов инструмента, который продвинул работу, или новое продолжающее сообщение открывает новый запас. В пределах запаса тайм-аут первого токена без вывода можно повторить один раз, а ответ без текста и без инструментов можно повторить один раз, а затем подтолкнуть до двух раз. Каждое восстановление занимает обычную итерацию **`max_turns`**; повторы транспорта остаются внутри итерации. Шаг, остановленный по **`max_tokens`** без текста и без вызова инструмента, не повторяют как есть, потому что тот же запрос упрётся в тот же предел. Модели отправляют короткое сообщение с просьбой рассуждать короче и разбить большую запись на несколько вызовов поменьше, до двух раз подряд. Шаг, который уже написал видимый текст, по-прежнему завершает ход. Повторы и подталкивания не включают пустое сообщение ассистента в историю для LLM, но сохраняют его подписанное рассуждение в транскрипте. Любая история, собранная из транскрипта (в том числе для следующего хода), пропускает сообщение ассистента без текста, без вызова инструмента и без подписанного рассуждения: воспроизводить в нём нечего, а оставшись, оно дало бы два хода ассистента подряд. У защиты от зацикливания, хуков Stop, резервных моделей и необязательного ожидания сброса квоты свои лимиты, поэтому этот запас не ограничивает все вызовы LLM за ход;
7. При **`session/cancel`** (или HTTP **`POST /coddy/sessions/{id}/cancel`**), пока поток LLM активен, потоковые провайдеры возвращают **`context.Canceled`** вместе с телом **`Response`**, накопленным к этому моменту; **`react.go`** добавляет этот **`content`** ассистента в историю сессии, если он не пуст, и завершает ход с **`StopReasonCancelled`**. **`GET /coddy/sessions/{id}/messages`** может ненадолго отставать от этого добавления, пока бандл на диске не будет прочитан заново.

### Провайдер LLM (`internal/llm`)

Абстрактный интерфейс для бэкендов LLM. Настраивается через `config.yaml`.
Сериализатор Anthropic пропускает строку истории ассистента, если в ней нет воспроизводимого непробельного текста, вызова инструмента или подписанного блока thinking и за ней следует другое сообщение. Подпись без текста thinking воспроизвести нельзя, и она не должна превращаться в пустой текстовый блок. Завершающая невоспроизводимая строка ассистента или результат инструмента сразу после неё отклоняются ещё до обращения к Anthropic. Если её пропустить, более ранний ответ ассистента мог бы превратиться в префикс продолжения, а у результата инструмента нет воспроизводимого вызова инструмента, на который он отвечает. Строка остаётся в транскрипте сессии; эта проекция для передачи не меняет восстановление агента и запас повторов.

Каждая ошибка, которую возвращает провайдер, начинается с **`providers[].name`**, откуда она пришла, и адреса, до которого запрос на самом деле дошёл (**`provider_label.go`**), потому что адрес не всегда тот, о котором думает пользователь, - **`type: openai`** без **`api_base`** обращается к **`https://api.openai.com/v1`**. Метка стоит снаружи устойчивой обёртки, поэтому классификация повторов по-прежнему читает нетронутую ошибку вышестоящего сервера, а сама метка оборачивает причину, не заменяя её, поэтому **`errors.Is`** и **`errors.As`** продолжают работать.

Устойчивая обёртка (**`resilient.go`**) повторяет вызов, когда **`isRetryableLLMError`** решает, что сбой относится к попытке, а не к запросу; каждый повтор берёт один слот из общего бюджета шага **`agent.llm_retry_max`** (шаг 6b выше). Повторяемыми считаются HTTP **`429`**, **`408`**, **`500`**, **`502`**, **`503`** и **`504`**; сбой транспорта без статуса, пока до вызывающей стороны ничего не дошло (неожиданный EOF, сброс соединения, поток HTTP/2, сброшенный другой стороной, - `stream error: stream ID N; INTERNAL_ERROR; received from peer`, как его печатает net/http, без префикса `http2:`, - **`GOAWAY`**, соединение, закрытое из-за того, что ping проверки живости остался без ответа, поток, который защита от простоя оборвала до первой дельты, или кадр либо событие, которые пришли целым кадром, но оборвались внутри своего JSON до первой дельты); и запрос, который так и не покинул клиента, - TLS-рукопожатие, истёкшее по тайм-ауту, или незавершённое установление соединения (**`isDialFailure`** - тайм-аут, нет маршрута, временный сбой DNS). Проверка соединения выполняется раньше проверки **`context.DeadlineExceeded`**, потому что тайм-аут установления соединения совпадает с этим маркером так же, как собственный таймер вызывающей стороны; таймер вызывающей стороны исключается раньше проверкой **`ctx.Err()`** в **`callWithRetry`**. Отмена, неизвестный хост и любой сбой после того, как дельты уже отданы, остаются окончательными. Обрыв внутри события фиксирует декодер, транспорт тут ни при чём. Это `*json.SyntaxError` с диагностикой конца ввода, которую читатели потока OpenAI-совместимого API, Codex и Anthropic классифицируют как усечение через **`streamDecodeTruncation`**, и никогда - сопоставлением текста сообщения произвольной ошибки JSON. У OpenAI-совместимого читателя есть кадр, поэтому ошибка к тому же должна стоять в его конце; потоки SDK у Codex и Anthropic не отдают полезной нагрузки и судят только по диагностике. Это ограниченная эвристика, которая принимает за обрыв и искажённое событие с пробелом внутри токена, и это безопасная сторона сомнения - текст сохраняется, ни один вызов инструмента не выполняется, а запрос повторяется до вывода или продолжается после него, но никогда не воспроизводится заново. OpenAI-совместимый читатель (**`openai_stream.go`**) также обрабатывает последний кадр, который сервер закрыл без пустой строки, поэтому тело, оборванное внутри строки `data:`, там считается тем же усечением; кадр, который вообще не JSON (`undecodable SSE frame: ...`), окончателен и никогда не повторяется, ни до вывода, ни после, какой бы статус или фразу транспорта ни содержал его текст. Типизированные ошибки потока сопоставляются раньше, чем **`httpStatusFromError`** просматривает текст сообщения, поэтому байты сервера никогда не читаются как статус.

Транспорты, на которых строится HTTP-клиент каждого провайдера, живут в **`transport.go`**, по одному на настройку прокси (пустой **`providers[].proxy`** и **`inherit`** делят транспорт, который спрашивает **`HTTPS_PROXY`** из окружения, у **`none`** транспорт вообще без функции прокси, у каждого URL прокси свой), и они общие для провайдеров, которые создаются на каждый ход, поэтому запрос переиспользует TLS-сессию предыдущего хода, а не открывает собственную. Запросы, которые строка провайдера делает помимо completions (список моделей, расход аккаунта, вход), берут тот же транспорт через **`HTTPClientForProviderProxy`**, поэтому маршрут строки решается в одном месте. От **`http.DefaultTransport`** они отличаются двумя вещами. Первая - проверка живости HTTP/2. Соединение, по которому 30 с не прошло ни одного кадра, получает PING, а соединение, которое не ответило за 15 с, закрывается, поэтому туннель или путь через прокси, умерший без FIN или RST, проявляется как `http2: client connection lost` и повторяется, вместо запроса, который ждёт вечно. Прокси на пути (`HTTPS_PROXY`, **`providers[].proxy`**) сам отвечает на TCP keepalive, и только сквозной кадр доказывает, что другая сторона на месте. Вторая - защита от зависания. При заданном **`agent.llm_stream_idle_timeout_ms`** (по умолчанию пять минут) тело `text/event-stream`, которое после первых байтов столько времени ничего не присылает, обрывается ошибкой, которую распознаёт **`IsStreamStalled`**. Бэкенд Codex отвечает на поток вообще без `Content-Type`, поэтому успешный ответ без него считается потоком событий, если запрос просил его в `Accept` (**`isEventStream`**), а провайдер Codex просит его, как и Codex CLI. Поток каждого провайдера сохраняет уже доставленные текст и рассуждение рядом с этой ошибкой, ровно как при усечении, а цикл ReAct сохраняет их, прежде чем завершить ход с указанием зависания; обёртка повторяет запрос, только пока до вызывающей стороны ничего не дошло. Ожидание первого байта - дело защиты первого токена, а блокирующий (**`stream: false`**) ответ, который приходит одним куском, ограничен только **`providers[].timeout_ms`**.

Поддерживаемые бэкенды (форматы описаны в **`docs/getting-started/configuration.md`**):
- OpenAI и OpenAI-совместимые HTTP API (**`type: openai`**);
- Anthropic (**`type: anthropic`**);
- Ollama и другие локальные OpenAI-совместимые стеки (**`api_base`**).

### Реестр инструментов (`internal/tools`)

**Типы инструментов и механика реестра** живут в **`internal/tooling`** (`Tool`, `Env`,
`Registry`, JSON `ParseArgs`, **`AllToolDefinitions`**). Пакет **`internal/tools`** - корень
композиции (`NewRegistry` связывает всё вместе), и он отдаёт те же API через псевдонимы типов, поэтому
места вызова вроде **`internal/agent`** по-прежнему импортируют только **`tools`**.

- **`internal/tools/web`** - **`http_request`** (`http_request.go` - инструмент в духе curl, `ParseHTTPRequest` - то единственное проверенное значение, которое инструмент отправляет и по которому решает проверка разрешений в **`internal/permission/http.go`**; `client.go` - общий клиент с транспортом на каждый маршрут (прокси, проверка сертификата), политикой редиректов и защитой на каждом переходе), **`websearch`** (несколько поисковых движков, которых опрашивают параллельно за швом `searchFn`, и каждый сообщает `ok` / `empty` / `blocked` / `error`, поэтому отказавший бэкенд называется по имени, а не засчитывается как пустой результат; объединение с дедупликацией по нормализованному URL, фильтр релевантности против подставных наборов результатов) и **`webfetch`** (загрузка публичных страниц `http(s)`, readability + Markdown; защита от SSRF).

Встроенные реализации сгруппированы по подпапкам в **`internal/tools/`**:

- **`internal/tools/fs`** - вспомогательные функции для путей (`paths.go` с `ResolvePath`, `CheckInsideCWD`,
  `PathEscapesCWD`, `ToolPathsEscapeCWD`) и инструменты (`read.go` **`read`**, **`glob.go`** **`glob`**,
  **`grep.go`** **`grep`**, **`print_tree.go`** **`print_tree`** (дерево каталогов, только чтение),
  **`write.go`** **`write`**, **`edit.go`** **`edit`**, **`patch.go`**
  **`apply_patch`**, **`mkdir`**, **`rmdir`**, **`touch`**, **`rm`**, **`mv`**).
  **`grep`** использует системный **`rg`**, если он есть (шаблон передаётся ему без изменений),
  а иначе переходит на встроенный обходчик и сопоставитель на Go из **`search.go`**. **`glob`** использует
  тот же встроенный обходчик, когда **`rg`** недоступен, поэтому поиск по файловой системе работает и в
  Windows, и в distroless-бинарниках без вспомогательных исполняемых файлов;
- **`internal/platform`** - общее определение оболочки хоста, **`pwsh` → `powershell` → `cmd`** в Windows и **`bash` → `sh`** в остальных системах; также отрисовывает контекст окружения для промпта;
- **`internal/tools/shell`** - **`run_command`**, привязанный к общей обнаруженной оболочке и описанный модели с примерами команд для своей платформы;
- **`internal/tools/todo`** - список todo и плана (**`coddy_todo_plan_read`**, **`coddy_todo_plan_replace`**,
  **`coddy_todo_plan_archive`**, **`coddy_todo_item_add`**, **`coddy_todo_item_remove`**,
  **`coddy_todo_item_update`**, **`coddy_todo_item_move`**);
- **`internal/tools/spawn_agent.go`** - **`spawn_agent`**, передача самодостаточной задачи субагенту
  (регистрируется при **`subagents.enable`**). Инструмент только передаёт вызов хуку **`tooling.Env.SpawnAgent`**,
  который подключает **`internal/agent`**, поэтому реестр остаётся ниже слоя сессий; среда выполнения, проверка
  доверия к проекту и дочерняя сессия живут в **`internal/agent/subagent.go`**, **`internal/subagents`** и
  **`internal/session`**. См. **`docs/features/subagents.md`**.

**Доступность инструментов** - **`internal/agent/toolsets.go`** задаёт для каждого режима список разрешённых имён **`ToolSet`**. **Пустой** `ToolSet` означает **отсутствие фильтра** (все инструменты, зарегистрированные в реестре сессии, плюс определения MCP). Режим **"План"** использует фиксированный список разрешённых встроенных инструментов **реестра** (**`read`**, **`glob`**, **`grep`**, **`print_tree`**, **`websearch`**, **`webfetch`**, **`run_command`**, **`question`**, **`spawn_agent`**, а также перечисленные в этом файле инструменты фоновых задач, конфигурации, плана и скилов, которые только читают), после чего так же, как в режиме "Агент", добавляются инструменты MCP от подключённых серверов. Режим **"Чат"** использует меньший список только для чтения - без оболочки, без инструментов плана, конфигурации и MCP и без **`spawn_agent`**. Сессия, которая сама служит запуском субагента, фильтруется ещё раз до набора инструментов, который для неё вычислила среда выполнения, и в режиме "Агент", и в режиме "План".

Агенты видят:

- режим **`agent`** - все встроенные инструменты, которые регистрирует **`internal/tools.NewRegistryFor`** (файловая система, оболочка, todo, необязательные инструменты планировщика, **`websearch`**, **`webfetch`**, **`question`**, **`plan_exit`**, **`spawn_agent`** и т. д.), плюс инструменты MCP от подключённых серверов;
- режим **`plan`** - разрешённые встроенные инструменты из списка выше плюс инструменты MCP. Встроенные инструменты записи, todo и планировщика модели не предлагаются. Инструментов памяти нет ни в одном реестре обычной сессии - они регистрируются только в реестре субагента памяти (**`internal/agent/memory_hooks.go`**).

`run_command`, необязательные пути записи, пути вне дерева и интерактивные сценарии **`question`** по-прежнему согласуются с клиентом (**`session/request_permission`** для разрушающих путей; потоковая передача по HTTP использует **`event: question`** и **`POST /coddy/sessions/{id}/question`**).

### Шлюз мессенджеров (`external/gateway`)

Шлюз - подсистема `coddy serve` (`gateways.telegram.enable`), через которую боты мессенджеров (сейчас Telegram, другие через тот же интерфейс) управляют тем же менеджером сессий и циклом ReAct, что используют HTTP API и `coddy acp`. Когда в том же процессе включён HTTP-интерфейс, ход чата публикуется ещё и в релей поля ввода этой сессии, поэтому браузер может следить за ним, пока он идёт.

Компилируется только при сборке с **`-tags gateway.telegram`** (Telegram) или **`-tags gateway`** (все адаптеры). Без этих тегов `gateways.telegram.enable: true` приводит к ошибке запуска, в которой назван тег.

**Основные пакеты.**

| Пакет | Роль |
|---------|------|
| `external/gateway` | Интерфейс `Adapter`, `Hub`, точка входа `Start()` |
| `external/gateway/access` | Контроль доступа - `CanAccess`, `EffectiveAccess`, `EffectiveIsolation` |
| `external/gateway/sessionstore` | `Store` сопоставляет стабильные ключи чата и пользователя с идентификаторами сессий Coddy; `Reset` по `/clear` |
| `external/gateway/telegram` | `Bot` (опрос, правила срабатывания, ACL), `Sender` (реализует `acp.UpdateSender`) |

**Поток данных для одного входящего сообщения:**

1. Адаптер получает сырое обновление и нормализует его в `IncomingMessage`;
2. `access.CanAccess` отклоняет сообщение, если пользователь не проходит настроенный уровень доступа;
3. `sessionstore.SessionKey` выводит детерминированный строковый ключ из имени шлюза, ID чата, ID пользователя и режима изоляции;
4. `store.Get(key)` возвращает текущий ID сессии Coddy для этого ключа (и создаёт сессию при первом использовании);
5. `manager.EnsureHTTPSession` загружает или создаёт бандл сессии;
6. `manager.HandleSessionPromptWithSender` запускает цикл ReAct с `Sender` адаптера;
7. `sender.Flush()` отправляет накопленный текст обратно в чат.

**Новый адаптер** - реализуйте `gateway.Adapter`, добавьте `Sender`, который удовлетворяет `acp.UpdateSender`, пометьте файлы `//go:build gateway || gateway.<name>` и добавьте адаптер в `Start()`. Подробное пошаговое описание - в [`docs/surfaces/gateway.md`](../surfaces/gateway.md).

### Необязательные пакеты инструментов в `external` (планировщик, память)

Часть функций живёт в **`external/`** и определяет инструменты, которые **не** регистрируются через **`internal/tools.NewRegistry`**, но используют ту же форму **`internal/tooling.Tool`**, что и ядро харнеса.

**Контракт (по образцу `external/scheduler/tools/job_get.go`):**

1. **Один инструмент на файл** - локальный для пакета конструктор возвращает **`*tooling.Tool`** с **`Definition`** (имя, описание, **`InputSchema`**) и **`Execute`** в одном месте. **`Execute`** принимает **`context.Context`**, JSON-аргументы строкой и **`*tooling.Env`** (используйте **`CWD`** или другие поля, когда инструменту нужен контекст сессии; передавайте **`&tooling.Env{}`**, когда он не нужен);
2. **JSON-схемы в виде map** - предпочитайте **`map[string]interface{}`** для **`InputSchema`** и **`[]interface{}`** для **`required`** и списков enum, чтобы сериализация для OpenAI и Anthropic оставалась согласованной с существующими инструментами планировщика;
3. **`register.go`** - собирает конструкторы. **`external/scheduler/tools`** отдаёт **`RegisterTools`** для основного реестра агента. **`external/memory/tools`** отдаёт **`PersistTools`** и **`RecallTools`**, которые **`external/memory.Tools`** передаёт в **`internal/agent`** для реестра субагента памяти (дочерней сессии, которую среда выполнения запускает на каждый ход пользователя) и никогда - для обычной сессии;
4. **Именование** - файлы планировщика используют префикс **`job_*.go`**, тела инструментов памяти - префикс **`mem_*.go`**, а **`external/memory/tools`** держит **`env.go`**, **`names.go`** и **`register.go`** без префикса **`mem_`**.

### Клиент MCP (`internal/mcp`)

Подключается к внешним серверам MCP, объявленным в двух файлах (глобальном
`${CODDY_HOME}/mcp.json` и проектном `./.coddy/mcp.json`, который перекрывает одноимённые серверы),
а также к серверам, указанным в `session/new`. `config.yaml` серверов не объявляет - старый
список `mcp_servers` при загрузке переносится в глобальный файл (`internal/config/legacy_keys.go`),
а менеджер сессий следит за этим файлом (`ReloadMCPDeclarations`).
Транспорты (их выбирает `mcp.Connect` через общий интерфейс `transport`):
- stdio - локальный подпроцесс, JSON-RPC с разделением по строкам; временем жизни процесса
  владеет транспорт (ctx подключения ограничивает только рукопожатие);
- streamable HTTP (`type: http`) - POST-запросы JSON-RPC, на которые отвечают JSON или
  фрагментами SSE, `Mcp-Session-Id` туда и обратно, автоматический откат на устаревший SSE
  (возможность `mcpCapabilities.http`);
- устаревший HTTP+SSE (`type: sse`) - поток событий по GET, который объявляет эндпоинт
  для POST (возможность `mcpCapabilities.sse`).

`mcp.Probe` стоит за API управления `/coddy/mcp` (подключение, `tools/list`,
закрытие); `manage.go` определяет, какому файлу принадлежит сервер, чтобы сохранить его
включение или выключение. Инструменты серверов MCP добавляются в список инструментов LLM в режимах
**`agent`** и **`plan`** (никогда в режиме **`ask`**; см.
**`internal/agent/react.go`**) и на каждом ходу фильтруются выключателями.

### Загрузчик скилов (`internal/skills`)

Загружает `SKILL.md` из папок скилов по умолчанию, а затем из дополнительных `skills.dirs` (см. `docs/features/skills.md`). Папки по умолчанию читаются всегда, от низшего приоритета к высшему - **`${HOME}/.agents/skills`** (общая с `npx skills`/`npx skillsbd`), **`.agents/skills`** проекта, **`${CODDY_HOME}/skills`** (собственная папка Coddy), **`.coddy/skills`** проекта; каждый элемент `skills.dirs` идёт после них (`config.Skills.SearchDirs`, папка, названная дважды, читается на последнем своём месте). **Стандартная поставка** (скилы, которые бинарник несёт в **`internal/skills/bundled/`**) ставится ниже всех и при первой встрече записывается в **`~/.coddy/skills`** (**`internal/skills/seed.go`**), поэтому сессия на деле читает копию на диске, а встроенная в бинарник служит запасной для домашней папки, в которую не удалось записать.

### Субагенты (`internal/subagents`)

Загружает определения субагентов (markdown-файлы с YAML frontmatter, тело которых задаёт роль дочернего агента) из четырёх папок по умолчанию, которые читаются всегда (**`${HOME}/.agents/agents`**, **`${CWD}/.agents/agents`**, **`${CODDY_HOME}/agents`**, **`${CWD}/.coddy/agents`**), а затем из дополнительных **`subagents.dirs`** (**`config.Subagents.SearchDirs`**; более поздние каталоги перекрывают более ранние по имени, папка, названная дважды, читается на последнем своём месте, а три встроенных определения **`general`**, **`explore`** и скрытое **`crossreview`** стоят ниже всех). Определяет **область** каждого файла по каноническим путям (**`project`** внутри рабочей папки, **`user`** в остальных местах), хранит **расписки** для файлов проектной области (**`TrustStore`**, **`<home>/subagents-trust.json`**, с ключом из канонической рабочей папки, имени и дайджеста файла; политика **`subagents.project_trust`**), ограничивает параллельные запуски общим для процесса **`Limiter`** и отрисовывает **каталог** (блок промпта для родительской модели, таблицу для **`coddy agents list`**, строки для **`GET /coddy/subagents`**). Ему же принадлежат чистые правила сужения - режим разрешений никогда не расширяется, набор инструментов дочернего агента получается пересечением с набором родителя, тайм-ауты вычисляются так же, как в пуле. Пакет ничего не знает о сессиях и цикле; **`internal/agent/subagent.go`** применяет его решения, запускает дочернего агента через менеджер сессий и регистрирует запуск в **`internal/bgtask`** через **`Pool.Launch`**. Руководство - **`docs/features/subagents.md`**.

### Хуки (`internal/hooks`)

Загружает **хуки жизненного цикла** оператора (команды, которые читают один JSON-документ из stdin и отвечают кодом выхода и необязательным JSON в stdout) из файлов **`hooks.files`** (по умолчанию **`${CODDY_HOME}/hooks.json`**, для совместимости **`.claude/settings.json`** и **`.claude/settings.local.json`** рабочей папки, **`${CWD}/.coddy/hooks.json`**) в формате файлов Claude Code (**`definition.go`** - событие → группы matcher → обработчики-команды с `timeout`, `async`, `failClosed`, `args` для формы exec, `commandWindows`). **`matcher.go`** применяет правила matcher из Claude Code (точный список или регулярное выражение без якорей) с псевдонимами имён инструментов, поэтому `Bash` совпадает с **`run_command`**, а `mcp__server__tool` - с инструментом MCP. **`loader.go`** определяет **область** каждого файла по каноническим путям (**`project`** в рабочей папке или ниже, **`user`** в остальных местах) и придерживает файлы проекта под **`hooks.project_trust`** так же, как придерживаются объявления MCP и определения субагентов. **`trust.go`** хранит расписки (**`<home>/hooks-trust.json`**, с ключом из канонической рабочей папки, пути файла относительно неё и дайджеста; **`coddy hooks list|trust|untrust`**, **`GET /coddy/hooks`**, **`POST /coddy/hooks/trust|untrust`**), **`catalog.go`** отрисовывает строки, которые показывают эти интерфейсы, а о придержанном файле один раз за сессию сообщает строка UI-журнала уровня `notice`. **`runner.go`** собирает полезную нагрузку (поля сессии и поля события), по очереди запускает подходящие обработчики с cwd сессии, окружением `CODDY_*` / `CLAUDE_PROJECT_DIR`, тайм-аутом и отсоединённой группой процессов через **`internal/platform`** и сводит их ответы в один **`Outcome`** (побеждает самое строгое решение; `updatedInput` передаётся по цепочке; каждый `additionalContext` сохраняется; падение или тайм-аут дают неблокирующую ошибку, если обработчик не настроен на отказ при сбое). Пакет ничего не знает о сессиях и цикле; **`internal/agent/hooks.go`** собирает исполнитель на каждый ход, а **`executeToolCall`** обращается к нему - `PreToolUse` перед проверкой разрешений (запретить, разрешить без запроса, принудительно запросить, переписать аргументы, добавить контекст), `PostToolUse` / `PostToolUseFailure` после инструмента. **`Run`** вызывает `UserPromptSubmit` до того, как промпт станет сообщением (блокировка отклоняет промпт, контекст попадает в блок `## Hook context` системного промпта), цикл вызывает `Stop` перед `end_turn` (блокировка отправляет причину следующим сообщением пользователя, не более `hooks.stop_loop_limit` раз за ход), **`CompactSession`** вызывает `PreCompact` (вето) и `PostCompact`, а **`session.Manager`** вызывает `SessionStart` при `session/new` и `session/load` и сохраняет возвращённый контекст в сессии (`hookContext` в `session.json`). **`subagent.go`** вызывает `SubagentStart` (блокировка отклоняет запуск, контекст добавляется перед задачей дочернего агента) перед стартом дочернего агента и `SubagentStop` после его хода, а проверка разрешений вызывает `Notification` (`permission_prompt`), прежде чем спросить клиента. Руководство - **`docs/features/hooks.md`**; проектная запись - **`docs/plans/hooks.md`**.

### Движок правил (`internal/rules`)

Находит правила `.mdc` / `.md` в одной папке проекта под CWD сессии - первой из `.coddy/rules`, нейтральной к инструментам `.agents/rules` (системный id `agents-dir`), `.cursor/rules`, `.claude/rules` и `.codex/rules`, где есть файл правила, поэтому зеркало тех же правил от другого агента никогда не загружается рядом с ней, - а также в собственной папке оператора **`${CODDY_HOME}/rules`** (системный id `user`), которая действует в каждой рабочей папке и уступает проекту при совпадении имён файлов. Документы `AGENTS.md` и `DESIGN.md` (соглашение [agents.md](https://agents.md/)) приходят тремя слоями, которые не отключает ни одна настройка (**`project_docs.go`**, **`agents.go`**). Это пара из домашней папки агента, затем пара рабочей папки, обе в системном промпте, и вложенная пара каждой папки на пути вниз к файлу, до которого доходит файловый инструмент или упоминание, прикреплённая к этому результату инструмента или сообщению пользователя. Правила, которые действуют всегда, попадают в **`{{.Rules}}`** отдельно от скилов, после первых двух слоёв, а файлы из `instructions.files` - в **`{{.Instructions}}`** после них; каждый файл попадает один раз, по своему реальному пути (**`DocKey`**). Постоянные части отрисовываются один раз за поколение правил сессии (следующее начинают сжатие контекста, перезагрузка конфигурации или смена рабочей папки), поэтому они не сдвигают кэшированное системное сообщение, а **`internal/agent/system_prompt.go`** размещает их в том шаблоне, на котором идёт ход, и дописывает документы, которые шаблон не вывел. См. **`docs/features/rules.md`**.

Диалект выбирается по расширению (**`markdown.go`**). `.mdc` читается как правило Cursor (`description`, `globs` строкой через запятую или списком, `alwaysApply`, по умолчанию ручное), `.md` - как правило Claude Code (`paths`; без них безусловное). Заголовки сначала читаются как YAML, а затем снисходительным построчным читателем, потому что собственный `globs: **/*.go` из Cursor - невалидный YAML. Глобы используют синтаксис doublestar с привязкой к cwd сессии (`Rule.Root`, **`MatchGlob`**).

Активация использует глобы, **`alwaysApply`**, **`@mention`** и пути файловых инструментов (`MatchScoped` - `read`/`edit`/... по подходящему файлу или путь внутри поддерева вложенного `AGENTS.md` активирует правило); см. **`docs/features/rules.md`**. Правило, которое активировал вызов инструмента, едет в результате этого вызова (**`llm.Message.Rules`**, **`internal/agent/rules_activation.go`**), а правило, которое приносит упоминание (названное пользователем или активированное упомянутым путём), - в этом сообщении пользователя (**`internal/agent/mentions.go`**); ни то, ни другое не попадает в **`{{.Rules}}`**, и каждое приходит один раз, пока сжатие контекста его не свернёт.

### Упоминания (`internal/mention`)

Единая грамматика ссылок **`@`** (**`grammar.go`** - пути относительные, абсолютные, под **`~`** или выше рабочей папки, пути в кавычках, диапазоны строк **`:N-M`** и **`#L`**, папки, **`@session:`** / **`@rule:`** / **`@agent:`** / **`@coddy:`**, веб-страницы; все прочтения неоднозначного токена, начиная с самого длинного, и побеждает то, что существует на диске), разрешение путей относительно рабочей папки сессии (**`paths.go`**), индекс рабочей папки для автодополнения (**`index.go`** - **`git ls-files`** в чекауте, обход в остальных случаях, кэш на каждый корень, пересборка при начале упоминания), нечёткое ранжирование (**`fuzzy.go`**) и элемент **`<coddy_attachment>`**, которым записывается разрешённое упоминание, с его двойником для отображения **`ForDisplay`** (**`attachment.go`**). Пакет чистый, без сессий. **`internal/session/mentions.go`** разрешает упоминания промпта один раз, когда сообщение отправляется (файл, список папки, дайджест другой сессии, правило, субагент, план, страница встроенной документации, веб-страница через загрузчик, который регистрирует **`internal/tools/web`**), а **`mention_search.go`** отвечает на автодополнение для консоли, веб-интерфейса и удалённой консоли (**`GET /coddy/mentions`**); **`mention_check.go`** прогоняет тот же резолвер вхолостую, ничего не читая, поэтому поле ввода веб-интерфейса подсвечивает только то упоминание, которое отправка действительно прикрепит (**`POST /coddy/mentions/check`**). **`internal/agent/mentions.go`** отрисовывает вложения в сообщение пользователя и добавляет в то же сообщение правила, которые активируют упомянутые пути, поэтому ни одно упоминание не сдвигает системный промпт. Двойник грамматики в поле ввода веб-интерфейса - **`external/ui/src/ui/skills/draftAt.ts`**; обе реализации проверяются на **`internal/mention/testdata/grammar_cases.json`**. См. **`docs/features/mentions.md`**.

### Встроенная документация (`internal/docs`)

Страницы **`docs/nav.yaml`** встраивает **`docs/embed.go`** (пакет **`docs`** в корне дерева, единственное место, откуда до них дотягивается шаблон embed) на английском и в русском переводе из **`docs/ru/`**, а читает **`internal/docs`**. **`LoadLang`** / **`For`** (**`Default`** для английского) собирают **`Library`** одного языка из групп и страниц, каждая страница разбита на заголовки с якорями, которые им даёт GitHub (**`Anchor`**, которым пользуется и проверка ссылок **`internal/docsgen`**, поэтому якорь, принятый проверкой, найдёт любой читатель), а её ссылки переписаны для читателя вне репозитория (**`coddy:<slug>#<anchor>`** между страницами, GitHub на теге релиза для картинок и файлов репозитория). **`Search`** ранжирует разделы по BM25F по заголовку страницы, заголовку раздела и тексту, а индекс строится один раз на язык при первом использовании; **`Resolve`** превращает любое написание страницы в страницу и её якорь; **`Page.Read`** возвращает страницу или раздел в пределах бюджета символов вместе со смещением, с которого продолжать. Пакет чистый и читает только встроенное дерево. Им пользуются инструменты **`coddy_docs_search`** / **`coddy_docs_read`** (**`internal/tools`**), упоминание **`@coddy:`** (**`internal/session/mentions.go`**, **`mention_search.go`**), **`GET /coddy/docs*`** (**`external/httpserver/docs_http.go`**), справка консоли (**`external/cli/docs_modal.go`**) и **`coddy docs`** (**`cmd/coddy/docs.go`**). См. **`docs/features/built-in-docs.md`**.

### Конфигурация (`internal/config`)

Конфигурация на основе YAML. При её поиске учитываются **`CODDY_HOME`** (по умолчанию **`~/.coddy`**), **`CODDY_CWD`**, **`CODDY_CONFIG`**, необязательный **`config.yaml`** в рабочем каталоге процесса, когда нет **`$CODDY_HOME/config.yaml`**, и флаги CLI (см. **`docs/getting-started/configuration.md`** и **`README.md`**).

## Режимы сессии

### Режим `agent` (по умолчанию)
- Полный доступ к инструментам (чтение, запись, запуск команд);
- Выполняет задачи от начала до конца;
- Запрашивает разрешение перед разрушающими операциями;
- Подходит для генерации кода, рефакторинга и отладки.

### Режим `plan`
- Узкий набор инструментов **реестра**, который обеспечивает **`internal/agent.ToolSetForMode("plan")`**;
- **`read`**, **`glob`**, **`grep`**, **`print_tree`**, **`websearch`**, **`webfetch`**, **`run_command`**, **`question`**, **`spawn_agent`** (дочерний агент родителя в режиме "План" остаётся в режиме "План"), а также любые инструменты **MCP** от настроенных серверов;
- В предлагаемом наборе нет встроенной записи в рабочую папку и инструментов todo **coddy** (для них переключитесь в режим **"Агент"**);
- Подходит для проектных документов, спецификаций, планирования архитектуры, внешних исследований и лёгкой проверки через оболочку или MCP без полного набора изменяющих встроенных инструментов.

### Режим `ask`
- Набор только для чтения и исследования, который обеспечивает **`internal/agent.ToolSetForMode("ask")`**;
- **`read`**, **`keep_result`**, **`glob`**, **`grep`**, **`print_tree`**, **`websearch`**, **`webfetch`**, **`question`**, **`load_skill`**, **`coddy_docs_search`**, **`coddy_docs_read`** - без оболочки, без инструментов плана и todo, без инструментов конфигурации и без инструментов MCP;
- В отличие от режима **"План"**, список разрешённых инструментов действует и при выполнении - вызов инструмента вне набора (например, воспроизведённый из истории) не выполняется, а отклоняется с уведомлением о режиме только для чтения; одобрение такого ожидающего вызова через **"Всегда разрешать"** тоже не записывает разрешения;
- Упоминание **`@plans/<slug>.plan.md`** или метаданные **`runPlanSlug`** в режиме "Чат" никогда не запускают выполнение плана (упоминание встраивается как материал для чтения, короткий путь через метаданные отклоняется), а субагент памяти работает только на извлечение, без записи в память;
- Подходит для вопросов о кодовой базе, ревью кода и диагностики, а также веб-исследований без каких-либо средств изменения.

Переключение режима:
- Клиент вызывает `session/set_config_option` с `configId` `mode` (предпочтительно) или `session/set_mode` с `agent`, `plan` или `ask`;
- Агент отправляет `current_mode_update` и `config_option_update` при смене режима.

## Структура каталогов

Верхний уровень после **`git clone`** (имя папки произвольное, обычно **`coddy-agent`**).

```
.
├── cmd/coddy/                   # CLI entry (acp, http, sessions, skills)
├── internal/                    # core harness (acp, session, agent, config, tools, …)
├── external/
│   ├── memory/                  # long-term memory subagent (`-tags memory`)
│   ├── httpserver/              # optional REST gateway (build tag http)
│   ├── ui/                      # Vite SPA sources (embedded when built with http+ui)
│   ├── scheduler/               # optional cron runner (build tag scheduler)
│   └── gateway/                 # messenger gateway (build tag gateway | gateway.telegram)
│       ├── access/              # ACL: CanAccess, EffectiveIsolation
│       ├── sessionstore/        # chat/user → session ID mapping
│       └── telegram/            # Telegram bot adapter (tgbotapi v5)
├── examples/                    # ACP and HTTP Python harnesses
├── docs/                        # guides (see docs/README.md)
├── Dockerfile
├── docker-compose.yml
├── docker-compose.dev.yml
├── config.example.yaml
├── go.mod
├── go.sum
└── README.md
```

Необязательные слои **`external/httpserver`**, **`external/ui`**, **`external/scheduler`** и **`external/memory`** не попадают в бинарник, если не передать соответствующие **теги сборки Go**; см. **`docs/contributing/build.md`** и **`README.md`**. Долговременная память включается во время работы ключом **`memory.enable`**, если бинарник собран с **`memory`**.
