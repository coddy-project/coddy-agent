# Протокол браузера

Протокол связи между `coddy serve` и расширением [Coddy for Browser](../features/browser.md). Его реализуют два
репозитория - эндпоинт и инструмент `browser` в `external/browser` этого репозитория и расширение в
[coddy-project/coddy-for-browser](https://github.com/coddy-project/coddy-for-browser). Изменение протокола вносится в
оба, и эта страница меняется вместе с ним.

Текущая версия - **1**.

## Транспорт

Расширение открывает один WebSocket к HTTP-серверу `coddy serve`, своему домашнему серверу, и держит его открытым.
Сервер к браузеру никогда не подключается. Всё, что Coddy просит у браузера, идёт по этому сокету, поэтому Coddy
добирается до браузера, к которому у него нет маршрута. Эндпоинт отвечает, пока `browser.enable` включён и задан
`browser.token`, а иначе возвращает `404`.

| | |
| --- | --- |
| Адрес | `ws://<host>:<port>/browser/v1/connect` на HTTP-сервере, по адресу веб-интерфейса; `wss://` за HTTPS-прокси |
| Origin | `chrome-extension://<id>` (Chrome, Яндекс Браузер) или `moz-extension://<uuid>` (Firefox); с любым другим заголовком `Origin` или без него сервер отказывает в переходе |
| Сообщения | Один объект JSON-RPC 2.0 в текстовом кадре, в обе стороны |
| Размер | 16 КиБ, пока не получен ответ на `initialize`, затем 8 МиБ |
| Живость | Расширение шлёт `$/ping` каждые 20 с, сервер закрывает сокет, молчащий 60 с |

Маршруты эндпоинта не проходят через собственную проверку HTTP API, потому что расширение само предъявляет ключ, в
`initialize` и при каждой передаче файла. Чат другого процесса Coddy этим сокетом не пользуется и добирается до
браузера через API домашнего сервера ([Другие процессы Coddy](#другие-процессы-coddy)).

Обе стороны отправляют запросы, ответы и уведомления. Идентификаторы запросов Coddy - строки из 48 шестнадцатеричных
цифр, у расширения свои. Ответ на идентификатор, который другая сторона не отправляла, игнорируется.

## Рукопожатие

Первым сообщением идёт запрос `initialize` от расширения. Ключ передаётся в нём, потому что браузер не может задать
заголовки WebSocket. На любое другое первое сообщение сервер отвечает `-32600` и закрывает сокет.

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": 1,
    "key": "<browser.token>",
    "browser": { "id": "6f1c0a9e-2d4b-4b8e-9a51-3c7e0f2d9b10", "name": "Chrome - laptop", "version": "0.1.0" },
    "actions": ["open_tab", "close_tab", "release", "snapshot", "screenshot", "navigate", "click", "type", "press", "hover", "scroll", "drag", "upload_file", "download_file"],
    "grant": "b0f3a5d2-..."
  }
}
```

- `browser.id` постоянен для одной установки и состоит из 8-80 букв, цифр и знаков `-`. Второе подключение с тем же
  id заменяет первое, а ожидающие запросы первого завершаются ошибкой с неизвестным исходом;
- `browser.name` (от 1 до 100 символов) различает браузеры, когда их подключено несколько;
- `actions` перечисляет действия, которые реализует расширение. Других действий Coddy не отправляет;
- в `grant`, как и в `browser/tabs`, указан текущий выбор расширения, поэтому команда, отправленная до первого
  списка вкладок, содержит правильное значение.

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": 1,
    "server": { "name": "coddy", "version": "1.4.0" },
    "limits": { "maxFileBytes": 33554432 }
  }
}
```

| Ошибка | Значение |
| --- | --- |
| `-32001` | Ключ не совпадает с `browser.token`. |
| `-32002` | Другая версия протокола; `data.supported` перечисляет версии, которые знает сервер. |
| `-32600` | Первым сообщением был не `initialize`. |
| `-32602` | Неверные параметры, в том числе неправильные id или имя браузера. |

После ошибки сервер закрывает сокет. Сразу после ответа расширение отправляет `browser/tabs`, даже пустой.

## Вкладки

Расширение решает, до каких вкладок дотягивается Coddy, и при каждом изменении присылает весь список.

```json
{
  "jsonrpc": "2.0",
  "method": "browser/tabs",
  "params": {
    "tabs": [
      { "id": 41, "url": "https://example.com/", "title": "Example Domain" },
      { "id": 77, "url": "https://example.org/report", "title": "Report", "sessionId": "sess_8f2c..." }
    ],
    "grant": "b0f3a5d2-..."
  }
}
```

- Вкладка без `sessionId` общая, в ней может действовать любой чат, и его первое действие переносит её к этому чату.
  Вкладка с `sessionId` принадлежит этому чату, и команду другого чата для неё сервер отклоняет, не отправляя;
- не больше 100 вкладок, только страницы `http` и `https`, URL не длиннее 8192 символов и заголовок не длиннее 1000.
  Список, который нарушает эти правила, закрывает соединение;
- в `grant` указан текущий выбор. Расширение меняет его, когда пользователь нажимает Stop, и отклоняет команду со
  старым значением. Пустой `grant` оставляет прежний;
- расширение отправляет `browser/tabs` раньше ответа на команду, которая изменила список, поэтому ответ на
  `open_tab` никогда не называет вкладку, которой Coddy ещё не знает.

В Coddy for Browser этот список - содержимое его групп вкладок браузера, общей группы **Coddy** и групп чатов с их
названиями.

## Команды

На каждое действие чата Coddy отправляет один запрос `browser/command`.

```json
{
  "jsonrpc": "2.0",
  "id": "9a1f...",
  "method": "browser/command",
  "params": {
    "action": "click",
    "tabId": 41,
    "params": { "ref": "4c1d9e2a:7" },
    "grant": "b0f3a5d2-...",
    "session": { "id": "sess_8f2c...", "title": "Check the release notes" }
  }
}
```

`params` содержит параметры самого действия в том виде, в каком их написала модель чата. `session.title` называет
чат для группы вкладок и индикатора на странице. Для `open_tab` и `release` поле `tabId` не передаётся.

Чат другого процесса Coddy передаёт в `session.node` имя, которым называет себя машина, где он работает, а его
`session.id` имеет вид `<node>/<session id>`. В id сессии домашнего сервера символа `/` не бывает. Перед первым
действием такого чата расширение спрашивает пользователя и добавляет узел к названию его группы вкладок.

```json
"session": { "id": "laptop/sess_31d0...", "title": "Plan the trip", "node": "laptop" }
```

| Действие | Параметры | Результат |
| --- | --- | --- |
| `open_tab` | `url` | `tabId`, `url`, `title` новой вкладки после загрузки; вкладка сразу в группе чата |
| `close_tab` | - | `closed` |
| `release` | - | `released` - сколько вкладок чата вернулось в общую группу |
| `snapshot` | - | `url`, `title`, `text` (до 20000 символов), `elements` (до 500, у каждого `ref`, `tag`, `name`, `x`, `y`, а также `role`, `type`, `href`, `value`, `checked`, `disabled`, `offscreen`, когда они есть), `viewport` |
| `screenshot` | - | `dataUrl` (`data:image/png;base64,...`, один пиксель изображения на CSS-пиксель), `width`, `height` |
| `navigate` | `url` или `back` / `forward` | `url`, `title` после загрузки |
| `click` | `ref` или `x` и `y`; `button` (`left`, `right`, `middle`), `count` (от 1 до 3) | `ok`; `trusted: false`, если ввод шёл через страницу |
| `type` | `text`; `ref`, `clear` | `ok` |
| `press` | `key` (`Enter`, `Tab`, `Escape`, `Backspace`, `Delete`, стрелки, `Home`, `End`, `PageUp`, `PageDown`, `Space`, буква или цифра, с `Ctrl+`, `Alt+`, `Shift+`, `Meta+`) | `ok` |
| `hover` | `ref` или `x` и `y` | `ok` |
| `scroll` | `dx`, `dy`; `x`, `y` (без них - середина области просмотра) | `ok` |
| `drag` | `x`, `y`, `to_x`, `to_y` | `ok` |
| `upload_file` | `ref` поля выбора файла, `transfer_id`, `filename` | `filename`, `bytes` |
| `download_file` | `url`, `transfer_id`, `filename` | `bytes`, `filename` |

- Координаты задаются в CSS-пикселях области просмотра. `ref` берётся из последнего `snapshot` той же страницы и
  перестаёт работать, когда страница меняется;
- каждый результат, кроме `open_tab`, `close_tab` и `release`, содержит ещё `tab` - `id`, `url` и `title` вкладки
  после действия;
- расширение без отладчика браузера (Firefox) создаёт события `click`, `type`, `press`, `hover`, `scroll` и `drag`
  прямо на странице и добавляет к их результату `trusted: false`, потому что страница может отличить их от ввода
  человека;
- неудачное действие возвращает ответ с ошибкой с кодом `-32000`, сообщением, которое читает чат, и `data.reason`
  из списка `not_shared`, `other_chat`, `stopped`, `chat_declined`, `chat_prompt_timeout`, `site_declined`, `cross_origin_frame`,
  `site_prompt_timeout`, `page_changed`, `cancelled`, `unsupported`, `invalid_params`, `too_large`,
  `transfer_failed`, `download_failed`.

Coddy ждёт ответа 2 минуты, а `download_file` - 10 минут. Когда ход чата отменяют или ожидание истекает, Coddy
отправляет `$/cancelRequest` и сообщает чату, что исход неизвестен, а сам действие никогда не повторяет.

```json
{ "jsonrpc": "2.0", "method": "$/cancelRequest", "params": { "id": "9a1f..." } }
```

## Одобрение сайта

Перед первым действием на сайте (схема, хост и порт) расширение спрашивает пользователя в своём окне или в боковой
панели, если она открыта, разрешить ли его для этого чата, разрешить всегда или отказать. `open_tab`, `navigate` и
`download_file` спрашивают о сайте, куда они идут. Если на вопрос не ответили за 110 с, команда завершается
ошибкой `site_prompt_timeout`, а после отказа - ошибкой `site_declined`. Вопрос до Coddy не доходит, ответ пользователя остаётся в браузере.

Про чат с `session.node` расширение сначала один раз спрашивает, разрешить ли этот чат или отказать (`chat_declined`,
`chat_prompt_timeout`). "Always allow" действует только для чатов домашнего сервера, поэтому для чата другого
процесса расширение спрашивает про каждый новый сайт заново, а Stop отзывает всё, что было разрешено таким чатам.

Локальные origin - `localhost` и `*.localhost`, `127.0.0.0/8`, `[::1]` - на любом порту считаются разрешёнными
всегда для чатов домашнего сервера, если пользователь этого не отключил. Это правило не распространяется на порт
домашнего сервера, по какому бы локальному имени к нему ни обращались, а для чата с `session.node` расширение
спрашивает о локальных origin так же, как о любых других.

## Файлы

`upload_file` и `download_file` не передают содержимое файла по сокету. Coddy открывает одноразовый тикет на время
вызова и отправляет его id как `transfer_id`, а расширение передаёт байты по HTTP на том же сервере с ключом в
качестве bearer-токена.

| Запрос | Направление | Ответ |
| --- | --- | --- |
| `GET /browser/v1/files/<transfer_id>` | от Coddy к браузеру - файл для поля выбора | `200` с байтами |
| `POST /browser/v1/files/<transfer_id>` | от браузера к Coddy - скачанные байты | `204` |

Тикет обслуживает один запрос в течение 2 минут, а потом отвечает `410`, неверный ключ получает `401`. Файл не
больше 32 МиБ. Скачивание расширение делает с cookie браузера и отклоняет редирект, поэтому чат передаёт конечный
адрес.

## Уведомления

| Метод | Направление | Параметры | Значение |
| --- | --- | --- | --- |
| `browser/tabs` | от расширения к Coddy | `tabs`, `grant` | Полный список вкладок, до которых дотягивается Coddy. |
| `browser/stop` | от расширения к Coddy | - | Пользователь нажал Stop, ожидающие команды завершаются с ошибкой, и до следующего `browser/tabs` у Coddy нет доступа ни к одной вкладке. |
| `$/ping` | от расширения к Coddy | - | Держит живым сокет, а вместе с ним и service worker Chrome. |
| `browser/turnEnded` | от Coddy к расширению | `sessionId` | Ход чата закончился, расширение снимает отметки работы. Coddy шлёт его только браузеру, у которого есть вкладка этого чата. |
| `$/cancelRequest` | от Coddy к расширению | `id` | Остановить команду с этим id. |

Неизвестное уведомление сторона игнорирует, а на неизвестный запрос отвечает `-32601`, поэтому в пределах одной
версии протокола обновлять можно любую сторону первой.

## Боковая панель

Боковая панель расширения показывает веб-интерфейс домашнего сервера во фрейме. Тикет для него она запрашивает по
сокету.

```json
{ "jsonrpc": "2.0", "id": 7, "method": "panel/open", "params": {} }
```

```json
{ "jsonrpc": "2.0", "id": 7, "result": { "ticket": "3f9c...64 hex digits" } }
```

Тикет годится для одного входа в течение минуты и привязан к ключу, для которого выдан. Панель загружает
`<server>/?coddy_panel=<ticket>&coddy_panel_origin=<origin расширения>` (`chrome-extension://<id>` или
`moz-extension://<uuid>`), веб-интерфейс убирает оба параметра из адреса и обменивает тикет в
`POST /coddy/auth/browser` на собственную cookie сессии, которая перестаёт действовать,
когда меняется `browser.token` ([HTTP API](http-api.md#вход-в-веб-интерфейс-необязательно)).

Дальше фрейм и панель обмениваются сообщениями через `postMessage`, каждая сторона пишет только на origin другой и
принимает сообщение только от окна другой стороны с этим origin.

| Сообщение | От кого | Поля | Значение |
| --- | --- | --- | --- |
| `{source: "coddy-web-ui", type: "turn"}` | веб-интерфейс | `requestId`, `sessionId`, `title` | Перед отправкой хода - из какой вкладки пишет человек? |
| `{source: "coddy-for-browser", type: "turn"}` | панель | `requestId`, `tab` (`browser_id`, `tab_id`, `url`, `title`) или `null`, `error` | Вкладка, уже перенесённая в группу чата. Веб-интерфейс отправляет её как `metadata.browser` в `POST /v1/responses`. |
| `{source: "coddy-web-ui", type: "theme"}` | веб-интерфейс | `theme` - `scheme` и цвета `bg`, `surface`, `border`, `text`, `muted`, `accent` в вычисленном виде, `rgb()` или `color(srgb ...)` | Полоска панели берёт тему веб-интерфейса, любое другое значение отклоняется. |
| `{source: "coddy-for-browser", type: "open"}` | панель | `sessionId` | Показать этот чат сервера (`#/s/<sessionId>`). Принимается только id вида `sess_...` и только пока в веб-интерфейсе открыт сервер, к которому подключена панель. |

Веб-интерфейс ждёт ответа панели 3 с и, если ответа нет, отправляет ход без вкладки. Чат другого окружения
веб-интерфейса вкладки не получает.

Если панель открыта на вкладке, которая принадлежит чату домашнего сервера, она открывает этот чат в
веб-интерфейсе, по адресу `<server>/?coddy_panel=...&coddy_panel_origin=...#/s/<session id>`.

## Другие процессы Coddy

Чат, который работает не в процессе домашнего сервера, будь то консоль или редактор на той же машине или узел роя,
добирается до его браузеров через HTTP API домашнего сервера с обычными учётными данными сервера, пока включён
`browser.serve_remote`. Через релей роя маршруты доступны как `<relay>/swarm/nodes/<node>/coddy/...`.

| Запрос | Что делает |
| --- | --- |
| `GET /coddy/browser/v1/browsers?node=&session_id=` | подключённые браузеры и их вкладки так, как их видит этот чат |
| `POST /coddy/browser/v1/call` | одно действие - `browser_id`, `action`, `tab_id`, `params`, `caller` (`node`, `session_id`, `title`), а для `upload_file` и `download_file` ещё `file` (`name`, `data` в base64) |

Домашний сервер отправляет действие по сокету с `session.id` вида `<node>/<session id>` и `session.node` и отвечает
`result`, а для `download_file` ещё байтами в `file`. Отклонённое или неудачное действие возвращает `409` с
сообщением расширения. Чтобы отменить действие, вызывающая сторона обрывает свой запрос, и домашний сервер
отправляет `$/cancelRequest`. Домашний сервер не видит, где заканчивается ход удалённого чата, поэтому отправляет
`browser/turnEnded` для этого чата через 45 с после его последнего вызова. Поля и коды ответов описаны в
[HTTP API](http-api.md).
