# Инструменты

Встроенные инструменты, которые может вызывать модель, их аргументы, разрешения и режимы, в которых они доступны. Имена инструментов, имена аргументов и флаги разрешений взяты из конструкторов в `internal/tools` и в необязательных пакетах; `internal/tools.NewRegistryFor` собирает из них реестр, а `internal/agent.ToolSetForMode` в `internal/agent/toolsets.go` решает, какие определения каждый режим отправляет модели. Режим "Агент" ничем не ограничен, у режимов "План" и "Чат" фиксированные белые списки, а режим "Чат" перепроверяет свой список при выполнении, чтобы вызов, повторённый из истории, не мог выйти за его пределы. Почему режимы устроены именно так, объяснено в разделе [Режимы работы](../features/modes.md#три-режима), а как добавить инструмент, описано в разделе [Собственные инструменты](../contributing/custom-tools.md).

## Разрешения

Столбец "Разрешение" использует классы, которые применяет проверка разрешений в `internal/agent/react.go` при заданном `tools.permission_mode` (`ask` по умолчанию, `accept_edits`, `bypass`; см. [Безопасность и доверие](../operate/security.md#режимы-разрешений-и-запросы)):

- `none` - никогда не спрашивает;
- `write` - класс записи файлов. При `ask` спрашивает, если путь не был разрешён в этой сессии, при `accept_edits` и `bypass` одобряется автоматически;
- `command` - `run_command`. Спрашивает, если команду не покрывает `tools.command_allowlist` или разрешение, выданное в сессии (включая разрешения на всю программу, которые сохраняет ответ на запрос, см. [Фоновые задачи](../features/background-tasks.md#разрешения)); `bypass` пропускает запрос;
- `config` - `config_commit` и `config_rollback`. Спрашивает при `ask` и `accept_edits`, потому что коммит может запустить процессы MCP и изменить саму политику разрешений; запрос пропускает только `bypass`;
- `http` - `http_request`. Спрашивает при `ask` и `accept_edits`, кроме случаев, когда адресат есть в `tools.http_request.allowlist` или уже одобрен в этой сессии и вместе с ним одобрено всё, что несёт запрос (локальные файлы, прокси, непроверяемый сертификат, а при `ask` и файл, который он сохраняет); `bypass` пропускает запрос ([HTTP-запросы](../features/http-requests.md#разрешения));
- `always` - инструменты, которые задают `RequiresPermission` вне этих классов. Режим разрешений на них не влияет, и пропустить запрос может только хук PreToolUse, который отвечает `allow`.

## Оболочка и фоновые задачи

Инструменты `background_*` регистрируются, только пока включён `tools.background` (по умолчанию он включён), а `preview_server` - только если вдобавок включён `tools.preview_server`. Подробное руководство - [Фоновые задачи](../features/background-tasks.md#интерфейс-для-модели).

| Инструмент | Назначение | Аргументы (кратко) | Разрешение | Режимы |
|---|---|---|---|---|
| `run_command` | Выполняет команду в рабочей папке через оболочку хоста; необязательный `cwd` меняет каталог только для этой команды. `background: true` возвращает идентификатор задачи и по умолчанию будит агента по завершении, где это возможно. Команда переднего плана, которая не уложилась в свой тайм-аут, передаётся в пул и тоже по умолчанию будит агента по завершении; `notify_on_finish: false` отключает оба пробуждения | `command`, `cwd`, `permission_rationale`, `timeout_seconds`, `background`, `notify_on_finish`, `expected_seconds` | command | Агент, План |
| `share_file` | Копирует один обычный файл, не символическую ссылку, из рабочей папки в текущую сохранённую сессию как неизменяемый артефакт для скачивания. Копия адресуется по содержимому, ограничена 25 МиБ (100 МиБ на сессию) и не попадает ни в промпты модели, ни в экспорт транскрипта. Субагентам инструмент недоступен. | `path` | always | Агент |
| `worktree_create` | Делает fetch из origin, создаёт или переиспользует [worktree для ветки фичи](../features/worktrees.md) от ветки по умолчанию (для создания нужен доступный `origin`) и переносит в него сессию; `branch` в виде `<remote>/<name>` открывает локальную ветку `<name>`, которая отслеживает эту удалённую ветку | `branch` | always | Агент |
| `background_list` | Выводит фоновые задачи сессии со статусом, прошедшим временем и оценкой | нет | none | Агент, План |
| `background_output` | Возвращает собранные stdout и stderr задачи | `task_id`, `tail_lines` | none | Агент, План |
| `background_wait` | Ждёт завершения задачи; ожидание ограничено значением по умолчанию и максимумом | `task_id`, `timeout_seconds` | none | Агент, План |
| `background_stop` | Завершает задачу и всё, что она запустила | `task_id` | none | Агент, План |
| `background_reap` | Находит и завершает процессы этой сессии, которые пережили запустивший их запуск | нет | always | Агент |
| `preview_server` | Раздаёт каталог проекта как статический сайт на свободном порту localhost и возвращает адрес, который пользователь может открыть; сервер работает как фоновая задача, пока его не остановят ([Сервер предпросмотра](../features/preview-server.md)) | `path`, `timeout_seconds` | none | Агент |
| `ssh_run_command` | Выполняет команду на удалённом хосте по SSH, используя сокет SSH-агента, а затем файлы ключей ([Конфигурация](../getting-started/configuration.md#удалённое-выполнение-по-ssh)) | `host`, `command`, `port`, `timeout_seconds`, `permission_rationale` | always | Агент |

## Веб

| Инструмент | Назначение | Аргументы (кратко) | Разрешение | Режимы |
|---|---|---|---|---|
| `websearch` | Ищет сразу в нескольких поисковиках, объединяет результаты и сообщает, чем закончился запрос к каждому поисковику | `query`, `page`, `max_results`, `site` | none | Агент, План, Чат |
| `webfetch` | Скачивает публичную страницу и возвращает её основной текст в Markdown; частные сети и localhost отклоняются, в том числе после любого перенаправления | `url`, `timeout_seconds`, `max_chars` | none | Агент, План, Чат |
| `http_request` | Отправляет любой HTTP- или HTTPS-запрос, как curl, и возвращает строку статуса, заголовки и тело или сохраняет тело в файл ([HTTP-запросы](../features/http-requests.md)) | `url`, `method`, `query`, `headers`, одно из `body` / `body_base64` / `body_file` / `json` / `form` / `form_data`, `output_file`, `follow_redirects`, `proxy`, `verify_tls`, `timeout_seconds`, `permission_rationale` | http | Агент |

`websearch` опрашивает поисковики из `tools.websearch.engines` (по умолчанию Brave, затем Bing) и рядом с результатами сообщает, чем закончился запрос к каждому из них. Поэтому поисковик, который ответил страницей с проверкой на бота, называется по имени и не считается поисковиком, который ничего не нашёл, а поиск, в котором отказали все поисковики, завершается ошибкой вместо пустого списка. Какие поисковики есть, как фильтр релевантности отбрасывает набор результатов, не связанный с запросом, и как направить поиск на собственный SearXNG, описано в разделе [Веб-поиск](../features/web-search.md).

`http_request` служит для всего остального, что идёт по HTTP, то есть для API, сервисов на localhost, загрузки и скачивания файлов. Он не отклоняет ни один адрес, поэтому и требует разрешения; `webfetch` использует тот же клиент и отличается защитой от SSRF, фиксированным методом `GET` и преобразованием в Markdown ([HTTP-запросы](../features/http-requests.md#webfetch-на-том-же-клиенте)). Заголовки, которые оператор хочет видеть в каждом запросе, например браузерный `User-Agent`, задаются в `tools.http_request.default_headers`; их отправляет только `http_request`, а собственные `headers` вызова их переопределяют ([Заголовки по умолчанию](../features/http-requests.md#заголовки-по-умолчанию)).

## Планировщик

Эти инструменты входят в сборку с тегом `scheduler` и регистрируются, только пока планировщик включён (`internal/tools/scheduler_hook.go`, `external/scheduler/tools/register.go`). `job_id` - базовое имя файла. Каждый инструмент для отдельного задания принимает `scope`, равный `user` (по умолчанию, `${CODDY_HOME}/scheduler`) или `project` (`<session cwd>/.coddy/scheduler`, задание, которое запускается только после одобрения оператором; ни один инструмент такое задание не одобряет). Поля задания совпадают с полями frontmatter ([Планировщик](../operate/scheduler.md#инструменты-когда-планировщик-включён)). Только режим "Агент".

## Субагент памяти

С тегом `memory` каждый ход пользователя запускает субагента памяти, дочерний агент в пуле фоновых задач, и это его инструменты. Они регистрируются только в реестре этого дочернего агента (`internal/agent/memory_hooks.go`, `external/memory/tools`), поэтому основная модель их никогда не видит. Дочерний агент, который только вспоминает (ход в режиме "Чат"), получает первые три инструмента, любой другой - все шесть. Пути записываются как `scope:relative/path.md` ([Долговременная память](../features/memory.md#инструменты)).

| Инструмент | Назначение | Аргументы (кратко) | Разрешение | Режимы |
|---|---|---|---|---|
| `coddy_memory_search` | Ранжирует заметки в выбранных корнях по запросу | `query`, `scope` | none | дочерний агент памяти |
| `coddy_memory_list` | Выводит каталоги и заметки на один уровень ниже пути | `path` | none | дочерний агент памяти |
| `coddy_memory_read` | Читает одну заметку | `path` | none | дочерний агент памяти |
| `coddy_memory_mkdir` | Создаёт вложенные папки в области | `path` | none | дочерний агент памяти |
| `coddy_memory_save` | Записывает или перезаписывает заметку | `title`, `body`, `scope`, `relative_path` | none | дочерний агент памяти |
| `coddy_memory_delete` | Удаляет заметку или папку со всем содержимым, но никогда не корень | `path` | none | дочерний агент памяти |

## Инструменты MCP

Каждый включённый инструмент каждого подключённого MCP-сервера попадает в тот же список вызываемых функций под именем `server__tool`, с собственной входной схемой сервера и описанием с префиксом `[server]` (`internal/mcp/client.go`; [MCP-серверы](../features/mcp.md#пространства-имён-инструментов)). Раз разделителем служит `__`, в имени сервера его быть не может. Определения добавляются в режимах "Агент" и "План" и никогда в режиме "Чат", где вызов с таким именем отклоняется при выполнении. Вызов, в имени которого есть `__`, идёт в обход реестра: агент направляет его серверу-владельцу и применяет к результату ограничение вывода `default`. Встроенного запроса разрешения для вызовов MCP нет. Может ли сервер запуститься, решает доверие к рабочей папке, а выключатели отдельных серверов и инструментов ограничивают то, что может делать уже запущенный сервер ([MCP-серверы](../features/mcp.md#модель-разрешений)).

Такой вызов, как и любой встроенный, читается как действие, а не как идентификатор из реестра. Строка транскрипта и блок консоли пишут *запускаю browser_navigate на MCP-сервере playwright* (по-английски *calling `browser_navigate` on the MCP server `playwright`*), а в живой строке статуса на месте цели стоит `playwright/browser_navigate`, потому что общий глагол не может сказать, что делает вызов. Написание `mcp__server__tool`, которое используют другие агенты, читается так же. Рядом с подписью строка называет объект вызова и берёт его, как у встроенного инструмента, из аргумента `path`, `url` или `name`; если сервер называет аргументы иначе, берётся первый аргумент, который годится в подпись, то есть однострочный и не тело ([Веб-интерфейс](../surfaces/web-ui.md#карточка-вызова-инструмента-встроенный-spa-текущая-версия)).

## Что выполняется перед вызовом инструмента

Хуки оператора видят каждый вызов, включая инструменты MCP, до проверки разрешений и при любом режиме разрешений ([Хуки](../features/hooks.md#что-отвечает-хук)). Хук `PreToolUse`, который отвечает `permissionDecision: deny`, останавливает вызов, инструмент не выполняется, а модель получает как результат инструмента `blocked by hook: <reason>`. `allow` пропускает запрос разрешения, который иначе показал бы инструмент, `ask` вызывает запрос даже при `accept_edits` или `bypass`, а `updatedInput` подменяет объект аргументов перед вызовом. Если подходят несколько хуков, выполняются все, и побеждает самое строгое решение.

Набор инструментов субагента получается сужением набора родителя ([Субагенты](../features/subagents.md#как-сужаются-возможности)). `tools` и `disallowed_tools` в определении только убирают имена, а `question`, пять инструментов редактирования конфигурации и `plan_exit` исключены у любого дочернего агента, поэтому он не может ни спросить пользователя, ни переписать конфигурацию, ни выйти из режима "План". Результаты обрезаются по `tools.output_limits` до того, как попадут к модели, одинаково для встроенных инструментов и инструментов MCP.
