Local wallpapers - server files and browser selection

Upload adds or reuses a server file. Each browser chooses its own background. All operations use the selected environment.

1. Selected server

${CODDY_HOME}/wallpapers
Local galleryFirst HTTP startup claims a marker before copying four embedded pictures into a missing gallery. Existing galleries stay untouched; deletions are not restored. GET never creates the folder.
Confined originalsRegular files only, no links or traversal. Recognize image headers, stream without pixel decoding or whole-file buffering. No image-size caps.
SHA-256 while writingReuse identical bytes under any name. Otherwise add a file, suffixing name collisions without overwrites. Clean temporary files on failure.
Delete the named fileRemove the server file only on DELETE. Clearing a browser background leaves this gallery unchanged.

2. Authenticated API

Bearer header or browser cookie
GET /coddy/wallpapersNames only. Normal authentication on local, remote and relay-mounted requests; no credentials in image URLs.
GET /coddy/wallpapers/{name}Stream the opened original. HEAD returns headers without the image body. The browser determines renderability.
POST /coddy/wallpapers/{name}Raw binary body. Return the actual name in {wallpaper:{name},created}. 201 for new bytes; 200 for a duplicate.
DELETE /coddy/wallpapers/{name}204 on deletion. No request until the person confirms the thumbnail's delete dialog.

3. This browser

Compact gallery stays visibleTwo columns with filenames. Thumbnails load near the viewport. The active border marks selection. IndexedDB commits before applying; failed writes keep the previous background.

Delete "filename"? Yes / NoYes has initial focus. Delete the selected file and clear this background; delete another file and keep it. The separate clear icon never deletes files.

The server owns the gallery files. The browser owns its background selection. Upload and confirmed delete change server files; Clear changes only this browser.
