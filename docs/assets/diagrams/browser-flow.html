Coddy for Browser: one socket, every chat

The extension dials out to the HTTP server of coddy serve on its own machine and keeps one WebSocket open. Every action of every chat reaches the browser down that socket; the person at the browser approves websites and chats there.

1. The browser

Coddy for Browser
Side panel the web UI of the home server in a frame; Chrome's side panel, Firefox's sidebar, a window in Yandex Browser
Background of the extension opens the socket and keeps it open; the tab groups, the approvals, the key in its storage
The person decides allow a website for this chat, always, or decline; allow a chat of another machine
Tabs in the Coddy tab groups the shared Coddy group, one group per chat; nothing else is reached

Clicks and keys go through the debugger in Chrome and Yandex Browser, so a page sees trusted input. Firefox has no debugger for extensions: the events are dispatched in the page, and the result says trusted: false.

2. coddy serve, the home server

outside the API gate, opened by the extension's key
GET /browser/v1/connect WebSocket, JSON-RPC 2.0 both ways; chrome-extension:// or moz-extension:// origin, the key in initialize
/browser/v1/files/{ticket} one-time file tickets, 32 MiB at most
the web UI of the panel
POST /coddy/auth/browser redeems the one-time ticket the socket handed out (panel/open) for a session cookie
POST /v1/responses with metadata.browser the tab the person writes from, in the turn context block: the system prompt does not move
behind the API gate, under browser.serve_remote
GET /coddy/browser/v1/browsers, POST /coddy/browser/v1/call a chat of another process owns tabs as <node>/<session id>
Hub and the browser tool one connection per browser; the tool asks this hub, the server of this machine, then browser.remotes

3. Elsewhere

A console or an editor on the same machine coddy, coddy acp: the server at httpserver.host and port, with auth_token
Another machine, a node of the swarm names the home server in browser.remotes; a relay mount such as /swarm/nodes/home works too

A process that only uses the browsers of other servers needs no key of its own. The marks of a remote chat's tabs go away 45 s after its last call.

Model provider page text and screenshots reach it as tool results, like any other

4. One action, end to end

The chat calls browser snapshot, click, type, open_tab, upload_file...
Hub.Call a tab in another chat's group is refused before sending; the call is never retried
browser/command down the socket a cancelled turn sends $/cancelRequest; its end sends browser/turnEnded
a chat of another machine: allowed?
this website: allowed for this chat?
the tab is in the chat's group
The extension acts and answers with the result and the tab after it

Stop on the page Coddy works in, and Disconnect on the extension's settings page, cancel every action, ungroup every tab and take back what the chats of other machines were allowed. The answers about websites and chats stay in the browser and never reach Coddy.
