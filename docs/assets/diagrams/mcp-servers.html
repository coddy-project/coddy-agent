The life of a configured MCP server

Where a server is declared, what lets it start, and how one running server serves every session that needs it.

1. Where servers are declared

config.yaml declares no server an old mcp_servers list moves into the home file
<home>/mcp.json scope global: written by the operator, never gated, watched for edits
<workspace>/.coddy/mcp.json scope local: comes with the checkout; a name it shares overrides the global entry
ACP client, session/new no file and no trust gate: straight to the pool (3)
Values resolve as the server starts
config.ExpandMCPValue, in every file
${CWD}the session's workspace ${NAME}that variable of the Coddy process, also ${env:NAME} and ${NAME:-default} $${a literal ${; any other $ is literal

The file keeps the reference, never the token.

2. Trust gate for project declarations

merged list for the workspace switches applied, a broken file skipped with a warning
TrustGate.Acquire checks, then takes a lease from the pool with nothing in between, also when another session started the server
Project entries follow mcp.project_trust:
allowevery project server starts
ask (default)starts on a matching receipt, else held
denynone starts, nothing to approve
<home>/mcp-trust.json receipts keyed by project (TrustWorkspace: a linked git worktree uses its main checkout), name and a SHA-256 digest of transport, command, args, env, url and headers. An edit withdraws the approval, a switch does not.
The operator approves coddy mcp trust <name>, Settings -> MCP servers or the console's /mcp, each after showing the whole declaration; never from a chat

3. One running server per resolved declaration

pool.go: one connection per PoolKey - name, transport, the resolved command line and env (or URL and headers), the bound workspace.

global, no ${CWD}: one per process Keep starts it with coddy serve, the console and coddy acp, and holds it with no lease
project, no ${CWD}: one per project keyed by TrustWorkspace, so a main checkout and its worktrees share it
session in the main checkout
session in a worktree
a subagent of either
names ${CWD}: one per workspace global or project, never started ahead of a session
ACP client server no gate; one for the sessions that send the same declaration
  • Nothing holds it: it runs on for mcp.idle_timeout_seconds (300 by default, 0 stops it at once) for the next session to find.
  • Switched off, approval withdrawn, removed or redeclared: it stops as soon as no session holds it.
  • A stdio server runs in a process group of its own: a stop closes stdin, waits 2 s, then ends the group, the child of npx or uvx included.

4. A session dials, and its next turn repairs

dial every admitted server at once each under its own 20 s bound: the session waits for its slowest server, not the sum
answered: tools/list, its tools join the session
no answer in 20 s: one more try when the next turn starts a first npx -y can install past the bound; the retry starts from the cache
no answer again: down until an edit, its switch, a new trust policy or a new session
connection ended process exited, remote dropped, 404 for its session
parked, started again when the next turn begins: one new process for every session that held it
<home>/mcp.json edited by anyone; polled every 2 s
ReloadMCPDeclarations refreshes only the servers whose declaration or switch moved; the rest keep running. A file that does not read stops none.

A turn in flight keeps the tool list it handed the model, and a change lands when it releases its lock. A project .coddy/mcp.json is not watched: it reaches a session when it starts, switches to that workspace, or the server is saved, switched or approved through /mcp or Settings.

5. What the model is given

tools array of every request
built-in tools of the mode
server__tool for every enabled tool the server's inputSchema, the description prefixed with [server]; in agent and plan mode
ask mode: no MCP tools at all

disabledTools: hidden, refused at dispatch, re-read every turn. No permission prompt guards a call: the gate decides what starts, the switches what may be called.

blocks of a call's result
text, embedded resource text, resource links: the tool result
images: kept with the call, shown to a model that reads images
audio, other binary: a file in the session's assets/, named in the result; no model is sent it

At most 20 files, and 20 MB of pictures and files together, per call.
