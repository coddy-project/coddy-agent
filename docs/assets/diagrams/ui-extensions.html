JavaScript extensions and incoming turn data

The server stores the package and its approval. The browser runs the code and processes live payloads.

1. Load an approved package

Install one ZIP
manifest.json + JS / CSS / HTML
Store disabled
<home>/extensions/<id>.json
Accept risk and enable
Approval names the exact SHA-256
Verify entry digest, then import
activate(coddy) in the app origin

Code has the origin's authority. The SDK is not a sandbox.

2. Process incoming turn payloads

POST response or composer relay
Wait up to 11 s for initial loading
stream.registerIncoming
Extension id order, then registration order
Synchronous transform(data, context)
Return a string, or observe with undefined
Apply the last valid payload
Assistant text, tools and other turn events

The context is frozen. Empty keepalives, [DONE] and desync bypass the chain.

3. Remove or revoke

Throw, promise or invalid result
Remove that processor; report in Settings
Keep the previous valid payload
Continue with the next processor
Handle remove() or lifetime abort
Stop the owned registration
Disable, remove or switch environment
Reload evaluated extension code

The server keeps the original history. A REST refresh can replace the transformed display.
