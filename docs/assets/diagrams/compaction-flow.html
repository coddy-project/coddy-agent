How one compaction runs

Every trigger ends in CompactSession: it cuts at a boundary, lets hooks veto, folds the head through a chain of summarizers in passes and inserts one summary row there.

1. What starts it

manual: folds whatever exists

trigger manual, down to no kept turn

/compact [-m id] [-r level] [text] console, ACP, web composer, /v1/responses
the Context popover's button POST /coddy/sessions/{id}/compact
the model calls compact_context agent and plan mode; the call itself stays
automatic: needs compaction.auto_enable

trigger auto, for all three

threshold reached threshold_percent (80) of the window, checked before every model call
fold inside the long turn only this turn is left: its earlier steps
provider: the request is too large context_length_exceeded, nothing streamed
recovery: fold, ask the same step again once per step, under the limit the refusal reveals

Each compaction draws one compact_context row that follows the passes; the model's own call reuses the row of that call.

3. Where the cut goes

between turns at the keep_recent_turns-th latest user message (2): from it on, everything stays verbatim
  • nothing there: fewer kept turns, down to 0 for a manual one and 1 for an automatic one;
  • automatically only up to the turn's opening prompt, never at a follow-up.
inside the turn at a step: one assistant message with its tool results, so a parallel batch is never split
  • keeps the latest steps that fit, at most 4, aiming the request at half the threshold share (40% at 80);
  • the latest step stays; a recovery may keep none, and first tries the cut between turns;
  • the row opens with the turn's prompt verbatim;
  • a fold that stays over the threshold ends the automatic folds of the turn.
nothing to compact no boundary, nothing new since the last summary row, or only /compact commands; the threshold then tries the fold inside the turn
