# OpenAI-compatible HTTP API

The HTTP surface ships only when the binary is built with **`go build -tags=http`** (`make build TAGS=http`). It exposes OpenAI-shaped routes plus **`/coddy/*`** helpers, backed by the same session manager and ReAct agent as **`coddy acp`**.

It is not a command of its own. **`coddy serve`** runs it whenever **`httpserver.enable`** is true, which it is unless the file says otherwise, alongside every other subsystem the configuration enables - the Telegram gateway, the swarm relay, the cron scheduler. They share one session manager, so a conversation a bot started is a session this API lists, streams and can continue.

The bundled SPA is included only when you also set the **`ui`** tag (for example **`make build TAGS="http ui"`** or **`go build -tags=http,ui`**). With **http** only, **`GET /`** returns **404** with a plain-text hint.

## OpenAPI and Swagger UI

Specs are regenerated on each request so they stay aligned with handlers.

- **`GET /openapi.yaml`** - OpenAPI 3.0 (YAML); **`GET /openapi.json`** mirrors it in JSON (both **`Content-Disposition: inline`**).
- **`GET /docs/`** - Swagger UI (static assets bundled in the binary, no CDN). **`GET /docs`** redirects to **`/docs/`**.

## Authentication (optional)

Authentication is **off by default** (historical behavior). There are two credentials, and either
one closes the same gate:

- a **bearer token** for API clients (`coddy --remote`, `coddy acp --remote`, a swarm relay, scripts);
- a **password sign-in form** for browsers, described under [Web UI sign-in](#web-ui-sign-in-optional) below.

Set a bearer token to protect the API when exposing it beyond loopback:

- `httpserver.auth_token` in `config.yaml` (supports `${ENV}`), or
- `--auth-token <token>` on `coddy serve`, or
- the `CODDY_HTTP_TOKEN` environment variable.

When a token is configured, every `/v1/*` and `/coddy/*` route requires
`Authorization: Bearer <token>` and returns `401` with a `WWW-Authenticate: Bearer` challenge
otherwise. The SPA shell and static assets stay public so a client can load and prompt for the
token; `/docs` and `/openapi.*` are protected unless `httpserver.public_docs: true`. The token is
never returned by `GET /coddy/config` (redacted; the DTO only reports `auth_configured`). Tokens
passed via `--auth-token` / `CODDY_HTTP_TOKEN` are never written to `config.yaml` and survive
`PUT /coddy/config` hot reloads. Prefer TLS (or a TLS-terminating proxy) when using auth over a
network. Binding a non-loopback address without a token logs a startup warning unless
`httpserver.allow_insecure: true`.

Without a token the surface is unauthenticated; run behind appropriate network controls.

### Web UI sign-in (optional)

A bearer token protects the API but gives a browser no way in: the SPA shows `Unauthorized (401)`
and has no field to type a token into. The sign-in form is the browser's credential for the same
gate. It is **off by default**, and a configuration that does not mention it behaves exactly as
before.

```yaml
httpserver:
  host: 0.0.0.0
  auth_token: "${CODDY_HTTP_TOKEN}"   # unchanged: for API clients
  login:
    enable: true
    user: "pasha"
    password_hash: "$$argon2id$$v=19$$..."   # written by `coddy serve set-password`
    session_ttl_hours: 720                   # 0 = until the browser closes
```

Write the account with the command rather than by hand:

```bash
coddy serve set-password --user pasha
```

It asks for the password twice (once, without a prompt, when standard input is a pipe), stores an
argon2id hash and switches the form on, editing `config.yaml` in place so comments and key order
survive. A hash typed in by hand needs every `$` doubled - `$$argon2id$$v=19$$...` - because this
file expands `$NAME` as an environment reference when it loads; `coddy -t` says so when it finds a
hash that no longer parses.

The account can also live entirely in the environment, which is the route for a container or a
systemd unit: `CODDY_HTTP_USER` and `CODDY_HTTP_PASSWORD` (plaintext, hashed as the server starts,
never written to the file) enable the form on their own, the way `CODDY_HTTP_TOKEN` enables the
bearer gate without `auth_token`. `$CODDY_HOME/.env` is their natural home. When both the file and
the environment carry an account the environment wins, and an explicit `login.enable: false` in the
file switches the form off with the variables still set. There is no `--login-password` flag: a
password on a command line is visible in `ps`.

Three routes serve the form, and all three are reachable without a credential, because they are the
way through the gate:

| Route | What it does |
|---|---|
| **`GET /coddy/auth/me`** | `login_required`, `auth_required`, `authenticated`, and `user` / `expires_at` for a signed-in browser. The SPA calls it on boot to choose between the sign-in screen and the app. |
| **`POST /coddy/auth/login`** | `{user, password}`. On success sets an `HttpOnly`, `SameSite=Strict` `coddy_session_<host digest>` cookie (`Secure` when the request arrived over TLS or through a proxy sending `X-Forwarded-Proto: https`), living for `session_ttl_hours`; with `0` the browser drops it on close and the server expires its own record after 30 days. The name carries a digest of the host the request was addressed to, because cookies are not scoped by port: without it two Coddy servers on one machine - a relay and the node behind it, say - would sign each other out at every login. |
| **`POST /coddy/auth/logout`** | Drops the session on the server and expires the cookie. Idempotent. |

Once signed in, the cookie opens every `/v1/*` and `/coddy/*` route, the SSE streams included - a
same-origin `EventSource` sends cookies, so no `?access_token=` is needed. The cookie is
`SameSite=Strict`, which costs nothing here (the page itself is public and every call the loaded
page makes is same-origin) and means the browser never attaches it to a request another site caused.
On top of that, cookie-authenticated requests that **change state** are refused with `403` unless
`Sec-Fetch-Site` says `same-origin` (or `none`) or `Origin` matches the request host - so a script
driving this API with a cookie has to send an `Origin` header, or, better, present a bearer token.
Bearer requests are never subject to that check, which is what keeps `coddy --remote`, an editor and
a relay working unchanged.

A wrong password and an unknown user get the same `401` and the same body, compared in constant
time. Repeated failures from one address are answered progressively more slowly, doubling from
250 ms to a cap of five seconds and forgotten after fifteen quiet minutes; the attempt is counted
before it is judged, so a burst arriving together pays the growing wait rather than each member
reading a clean slate. Loopback is never throttled, so the machine cannot lock itself out of its own
agent - and because that exemption would otherwise cover the whole internet behind a reverse proxy,
a request that arrives *from* loopback is counted against the address in `X-Forwarded-For` (or
`X-Real-IP`) when one is present. A request that arrives from anywhere else is counted by where it
actually came from, headers ignored. Sessions live in memory: a
configuration reload (saving settings from the page, for instance) keeps them, and restarting the
process ends them. Rotating the password or renaming the account ends every session it opened, on
the next request, with nothing to invalidate by hand. The store is bounded at 512 live sessions,
oldest first.

`GET /coddy/config` never returns `password_hash`; it reports `httpserver.login_configured` and
`httpserver.login_source` (`config` or `env`), and a save from the settings screen preserves the
hash the way it preserves `auth_token`. The neighbouring `auth_configured` means what it says - a
bearer token is set - so a server closed with a password and no token reports
`auth_configured: false` next to `login_configured: true`; ask `GET /coddy/auth/me` when the
question is "does this server want a credential at all". The document keeps describing the file, so an account that
came from the environment is never written into `config.yaml` by a save.

The sign-in form is for this origin. The environment selector still reaches a **remote** server with
a bearer token, because a cookie of this origin does not travel cross-origin.

One note on `${VAR}` references. `login.user` and `login.password_hash` take them like every other
value in `config.yaml`, and like every other value they are expanded when the file loads - so a save
from the settings screen writes the **expanded** value back, turning `user: "${CODDY_HTTP_USER}"`
into `user: pasha`. That is how this file has always treated `${VAR}`; if the point is to keep the
credential out of the document entirely, use `CODDY_HTTP_USER` and `CODDY_HTTP_PASSWORD`, which
never enter it.

### Cross-origin access and the remote UI

The bundled UI can point at a **remote** `coddy serve` server (an environment selector switches
the API base URL and sends the remote's bearer token). Because that is a cross-origin call, the
remote server must opt into CORS:

```yaml
httpserver:
  auth_token: "${CODDY_HTTP_TOKEN}"
  cors:
    enable: true
    allowed_origins: ["http://localhost:12345", "https://my-ui.example"]   # or ["*"]
  remotes:                       # optional: offered in the UI environment selector
    - name: "prod box"
      url: "https://box.example:12345"
```

When `cors.enable` is true, preflight `OPTIONS` requests for an allowed origin return `204` with
`Access-Control-Allow-Origin` (echoed origin, or `*` when configured) and
`Access-Control-Allow-Headers: Authorization, Content-Type, X-Coddy-Session-ID`; disallowed origins
receive no CORS headers. Bearer auth still applies to the actual request. Tokens for remotes are
**not** stored in `httpserver.remotes`; the UI keeps them client-side per remote.

Because `EventSource` cannot send an `Authorization` header cross-origin, the two SSE
subscription routes - **`GET /coddy/sessions/{id}/composer-stream`** and **`GET /coddy/events`**
- also accept the token as a `?access_token=` query parameter. No other route does; prefer the
header where the client can set one, since a query token reaches proxy access logs.

## Embedded web UI (**`-tags=http,ui`**)

- **`GET /`** serves **`index.html`**, **`styles.css`**, **`app.js`** and **`events-worker.js`** (the SharedWorker the tabs of one environment share **`GET /coddy/events`** through) from **`external/ui/`** (`go:embed`) when **`ui`** is set at link time with **`http`**. Responses for **`/`**, **`/index.html`**, **`/app.js`**, **`/events-worker.js`** and **`/styles.css`** include **`Cache-Control: no-cache`** so a normal reload picks up assets after you rebuild the binary (fixed URLs, no fingerprint).
- **API-only mode**: set **`ui.enable: false`** in config to run the server without the SPA even when the **`ui`** tag is compiled in. **`GET /`** then returns a short plaintext notice (HTTP 404) instead of the UI; every **`/v1/*`** and **`/coddy/*`** route keeps working and keeps requiring **`httpserver.auth_token`** when set. Useful for a headless remote box other UIs connect to.
- Recommended session URL pattern: **`#/s/<sessionId>`** (client-only history). For **`POST /v1/responses`** and **`POST /v1/chat/completions`**, send **`X-Coddy-Session-ID`** with a **`sess_<hex>`** id that satisfies server-side validation (`internal/session/validate.go`).
- **`GET /coddy/sessions`**, **`PATCH /coddy/sessions/{id}`**, and other **`/coddy/sessions/{id}/...`** routes identify the session **only** by the **`{id}`** path segment (no duplicate header in OpenAPI; clients may still send **`X-Coddy-Session-ID`**, it is not used to pick the resource for those URLs).
- The bundled UI calls **`POST /v1/responses`** with **`stream: true`**. On session open and reconnect, it reads **`GET /coddy/sessions/{id}/activity`** and **`GET /coddy/sessions/{id}/queue`** without requiring a row in the filtered or paginated **`GET /coddy/sessions`** listing. Server activity drives Stop and queue controls separately from the local stream reader; a lost reader does not prove the turn ended. The existing **`GET /coddy/sessions/{id}/composer-stream`** relay (SSE) lets the UI replay bytes already emitted for a running turn and continue receiving live chunks until **`data: [DONE]`** or an error event. Starting a new **`POST /v1/responses`** cancels that relay subscription client-side. For ReAct (**`model`** **`agent`**, **`plan`**, or **`ask`**), it sends optional **`metadata.model`** with the selected YAML **`models[].model`** **`id`** and optional **`metadata.runPlanSlug`** to implement a saved design plan (**`coddy.dev/runPlanSlug`** on ACP **`session/prompt`**; answered with **`409`** before the turn starts when **`model`** is **`ask`**) (from **`GET /v1/models`**, **`owned_by`** not **`coddy`**); default is its remembered pick in **`coddy_llm_model`**, else the alphabetically first row. When the selected model exposes **`reasoning_levels`**, it also sends optional **`metadata.reasoning`** with the chosen level; default follows the model's **`reasoning_default`**, persisted choice in **`coddy_llm_reasoning`**. It sends the **`@`** mentions of **`input`** as typed: the server resolves them when the turn starts - a file anywhere on disk, a line range (**`@Dockerfile:21-31`**, reaching the model as **`<coddy_attachment ... lines="21-31">`** holding only those lines), a folder listing, another session, a rule, a subagent, a page of the built-in documentation, a web page - the way it resolves every surface's prompt (see **`docs/features/mentions.md`**). **`GET /coddy/mentions`** powers the **`@`** picker, **`POST /coddy/mentions/check`** tells the composer which typed mentions resolve so only those are highlighted, and **`GET /coddy/workspace/file`** powers the line-range picker that opens after the **`:`**. SSE **default** chunks follow **`chat.completion.chunk`** deltas (**`delta.content`** for assistant text, **`delta.reasoning_content`** for streamed model reasoning so the UI can keep the **thinking** foldout separate). Named **`event:`** lines (**`tool_call`**, **`tool_call_update`**, **`plan`**, **`token_usage`**, **`turn_progress`**, **`available_commands`**, **`message_queue`**, **`user_message`**) expose tool progress and incremental token totals between LLM rounds; **`message_queue`** carries the whole message queue of the session on every change and **`user_message`** carries a queued follow-up the agent has just read, at the point it entered the conversation (see **`docs/features/message-queue.md`**); the turn stream reserves **`provider_usage`** for a snapshot emitted mid-turn (nothing emits one today; the account usage of a finished turn is read from **`GET /coddy/providers/{name}/usage`** or arrives on **`GET /coddy/events`**); when **`memory.enable`** is **true**, the server also emits **`memory_run`** for the memory subagent of the turn (**`started`** with the task and child session ids, **`finished`** with the task status, the duration, whether the report was **`delivered`** to the model in this turn and, for a failed run, the error it ended with as **`reason`**, or **`skipped`** with a reason); no text travels on it, and the run's record is the task row with **`agent.system`** true under **`GET /coddy/sessions/{id}/background-tasks`** plus the child transcript it names (see **`docs/features/memory.md`**). A turn the server started on its own because background tasks the model started ended with their wake on (**`notify_on_finish`**, on by default) opens with **`background_wake`**: **`tasks`** names each with **`id`**, **`kind`**, **`label`**, **`agent`**, **`status`**, **`exitCode`**, **`durationMs`** and **`error`**, and the turn's first message is persisted with the same tasks, so no client shows the instruction as a user bubble, live or after a reload; the bundled UI shows nothing in its place, and the task row says **`woke_agent`** (see **`docs/features/background-tasks.md`**). **`coddy_meta`** JSON follows the usual rule immediately before **`data: [DONE]`**; for agent/plan/ask turns it also carries **`stop_reason`** (`end_turn`, `cancelled`, `max_turns`, ...) so remote clients recover the ACP stop reason. A prompt that starts with settings commands has them applied before the turn ([Session settings](../features/session-settings.md)); a prompt of commands only runs no turn, streams the notice of each change as the answer, and ends with **`coddy_meta`** **`settings_only: "true"`**, so a client can drop the rows it drew for the exchange and re-read the transcript, where the change is one **`uiLog`** notice. **`event: session_settings`** carries the settings snapshot whenever the session's settings change during the stream (a command, the permission dialog's session switch, the model's **`switch_model`**). **Stop generation** in the composer calls **`POST /coddy/sessions/{id}/cancel`** with **`X-Coddy-Session-ID`** matching **`{id}`**. Right after sending it, the UI triggers **`AbortSignal`** on its own streamed **`fetch`** of that turn (the POST or the relay): a browser keeps six HTTP/1.1 connections per host across all of its tabs, and the cancel could otherwise wait for the one that stream holds. The turn runs on without the stream; a failed cancel shows an error, keeps the running controls available for a retry and rejoins the turn through **`GET /coddy/sessions/{id}/composer-stream`**. Success acknowledges cooperative cancellation, while **`turn_ended`** or a fresh activity snapshot reporting idle confirms completion. That maps to ACP **`session/cancel`** for the agent turn (**`TurnCtx`** propagation for direct **`models[].model`** completions uses the same cancel hook). Cancel mid-stream still **persists** accumulated assistant **`content`** for that turn; **`GET /coddy/sessions/{id}/messages`** can briefly trail that write, so the SPA **merges** fetched rows with its per-session shadow or on-screen transcript (**`mergeTranscriptPreferLocalSuffix`** in **`external/ui/src/ui/chat/transcriptServerSnapshot.ts`**). More than one session may stream in parallel (**`pickStreamMutationBase`** in **`streamMutationBase.ts`** keeps SSE mutations scoped per **`X-Coddy-Session-ID`**).
- On the first user message of a brand-new chat (no session in the rail yet), the UI **`POST`**s **`/coddy/describe`** in parallel with **`/v1/responses`**. When **`short`** arrives, the header and session list titles update **immediately**; **`PATCH /coddy/sessions/{id}`** still runs once headers expose the canonical session id (**retries PATCH** briefly if persistence lags describe), carrying the **`tags`** the same answer proposed, so naming and filing a new chat cost one model call between them. That PATCH carries **`titleIfUnpinned`**, which makes the title a suggestion: a session already named during the first turn - in the chat header, or by the agent's **`session_describe`** tool - keeps its name, and only the tags land.
- The bundled UI exposes **Settings** at **`#/settings`**. It loads **`GET /coddy/config/schema`** (JSON Schema for the editor) and **`GET /coddy/config`** (current values, including **API keys**, optional per-provider **`proxy`** URLs, and the **`gateways.telegram.token`** bot token), then **`POST /coddy/config/validate`** and **`PUT /coddy/config`** on save. The provider form's **Models** list and the logical-model form's **Context window** field call **`POST /coddy/providers/models`** with the provider row as the form holds it (an automatic fetch leaves **`api_key_command`** out; only the refresh control sends it), so a provider that has not been saved yet (for example right after an OAuth device sign-in) lists its models too; the logical-model form additionally calls **`GET /coddy/config/reasoning-levels`** behind **Fetch reasoning levels**, which fills **`models[].reasoning_levels`** with the tiers detected for the model id being edited (the type of the provider row it points at is sent as **`provider_type`**, so an unsaved provider is honoured). The **`gateways`** block round-trips through this API, so editing settings in the UI no longer drops the Telegram configuration. There is no separate auth on these routes - expose **`coddy serve`** only on trusted networks.

- **Turn progress** is the named SSE event **`turn_progress`** with **`startedAt`** (RFC3339, when the turn was admitted), **`elapsedMs`** (the same fact as a duration, so a client whose clock disagrees with the server's counts from its own now minus it), **`outputTokens`** and **`estimated`**. It is sent when the turn starts - zero tokens, which a client renders as the clock and "waiting for the model" - at most once a second while a model call streams, and after every call. **`outputTokens`** sums what the provider reported for the turn's completed calls and an estimate (characters / 4) of what the call in flight has streamed, tool-call argument fragments included as they arrive (or once the call completes for providers without fragments); **`estimated`** is true while an estimate is part of the number, and stays true for a provider that reports no usage. The composer relay does not replay a frame the client's transcript snapshot already covers, so a client that joins late reads the same numbers from **`GET /coddy/sessions/{id}/activity`**. The OpenAI-strict **`POST /v1/chat/completions`** stream replaces it with an SSE comment like every named event.
- **File input progress**: `tool_call_update` with `status: "pending"` may carry `_meta.coddy.toolInputProgress` for `write`, `edit`, and `apply_patch`. Fields: `path` (bounded to 512 bytes, empty until received), `bytes` and `lines` (decoded content received), `argumentBytes` (raw JSON bytes received), and `preview` (latest six lines, at most 1 KiB, possibly a partial line). This is a draft, never executable arguments or a tool result. Updates are throttled to five per second per call plus a final flush. A terminal status supersedes the draft. Clients must sanitize terminal controls before displaying model-generated paths or previews. The OpenAI-strict stream suppresses this named event like other tool updates.

- **Current context usage** is a separate named SSE event, **`usage_update`**, with **`used`** and **`size`**. It is re-emitted after manual or automatic compaction. **`token_usage`** remains the completed model-call counter and is not used as the context-window numerator.

## Endpoint summary

| Method | Path | Notes |
|--------|------|-------|
| GET | `/` | Embedded web UI (**`-tags=http,ui`**) or **404** with a hint (**`http` only**). **`Cache-Control: no-cache`** on **`/`**, **`/index.html`**, **`/app.js`**, **`/events-worker.js`**, **`/styles.css`** when the UI module is linked. |
| GET | `/openapi.yaml`, `/openapi.json` | Spec. |
| GET | `/docs`, `/docs/` | Swagger UI. |
| GET | `/v1/models` | Merged list: **`agent`**, **`plan`**, **`ask`** (each **`owned_by`**: **`coddy`**), then every YAML **`models[].model`** row (**`id`** is the selector; **`owned_by`** is the provider prefix). Ordering is **`agent`**, **`plan`**, **`ask`**, then **`models`** in configuration order (same ordering the server emits). Use any returned **`id`** as **`model`** on POST. The row a session that selects no model runs on carries **`default: true`**: the configured **`agent.model`**, or the first **`models[]`** row when **`agent.model`** names a model the configuration does not list; while **`agent.model`** is empty no row carries it. The remote console shows that model for a session with none of its own; the bundled UI picks its default from its remembered choice (**`coddy_llm_model`**) or the alphabetically first row instead. Every row carries **`max_context_tokens`**, the context window a session on that model measures its usage and its automatic compaction threshold against: the model's **`max_context_tokens`**, else the window its provider's model listing reports, else **`128000`** (the profile rows carry the window of **`agent.model`**; the bundled UI draws its context ring against it). Each **`models[].model`** row also carries **`multimodal`** (**`true`** when **`models[].multimodal: true`** in YAML; the bundled UI shows a file attachment button in the composer when the selected model has **`multimodal: true`**). Reasoning models also carry **`reasoning_levels`** (array, e.g. **`["minimal","low","medium","high"]`**; absent for non-reasoning models) and optional **`reasoning_default`** (level pre-selected for new chats); the bundled UI shows a reasoning-level selector in the composer when **`reasoning_levels`** is non-empty. Models served by a **`type: codex`** provider report **`none`** where the model id alone would imply **`minimal`**, because the Codex backend rejects that tier. |
| POST | `/v1/chat/completions` | **`stream`**, **`messages`** (last **`user`**), optional **`stream_options.include_usage`**. With **`stream: true`** the body is the strict OpenAI **`chat.completion.chunk`** stream described under [Two stream dialects](#two-stream-dialects). **`409`** when another **agent**, **plan**, or **ask** turn already holds the session turn lock (exclusive per persisted bundle), and **`409`** when **`X-Coddy-Session-ID`** names a child session spawned by **`spawn_agent`**: those transcripts are read-only for every model kind, and the error names the parent session to prompt instead. |
| POST | **`/v1/responses`** | **`model`**, **`input`**, optional **`stream`**, optional **`attachments`** ( **`path`** workspace-relative under session cwd - except with **`source.literal`**, where it only names the body and may be an editor's **`file://`** URI or an absolute path - **`agent`** / **`plan`** / **`ask`** only; file bodies are hydrated as text - a file stored in another detected encoding, such as Windows-1251, is converted to UTF-8; server rejects traversal, oversized, non-text (binary or undetectable encoding), and folder **`path`**; optional **`source.startLine`** / **`source.endLine`** narrow a file to a 1-based inclusive line range that the model sees as **`lines="N-M"`**, and a range the file cannot honour is a **`400`**; optional **`kind: "stdin"`** with a **`source.literal`** marks the body as data piped into a one-shot run - what **`coddy -p --remote`** sends for its stdin - which the model reads as a **`kind="stdin"`** attachment that no mention or command is read from, and any other **`kind`** is a **`400`**), optional **`inline_files`** (array of **`{name, data_url}`**; **`data_url`** is a `data:<mime>;base64,...` URI; works for all modes — direct YAML model and **`agent`** / **`plan`** / **`ask`**). For **`agent`** / **`plan`** / **`ask`**: each file is saved to the session **`assets/`** directory (`~/.coddy/sessions/<id>/assets/`) with **`0o444`** (read-only) permissions; the model receives a `<coddy_session_assets>` annotation in the user message so it can `read` or `cp` the files without re-transmitting their bytes over the API. For direct YAML model: each entry becomes an image content part on the user message so multimodal models receive the file inline. **`input`** remains the full composer text, and its **`@`** mentions are resolved by the server when the turn starts (an attachment already sent for the same path and range is not read twice). Keeps history between turns when using headers. **`409`** when another **agent**, **plan**, or **ask** turn already holds the session turn lock, for streaming and non-streaming calls alike, and **`409`** when **`X-Coddy-Session-ID`** names a child session spawned by **`spawn_agent`**: those transcripts are read-only for every model kind, and the error names the parent session to prompt instead. Every **agent** / **plan** / **ask** turn is published to the session's composer relay whatever **`stream`** is set to, so other clients can watch it over **`GET /coddy/sessions/{id}/composer-stream`**; with **`stream: false`** the response body is unchanged. A **`stream: false`** turn is cancelled when its HTTP request is dropped, a streamed one keeps running. A streamed response that has produced no frame for 15s sends an SSE comment keepalive, so a turn on a YAML model with **`stream: false`** - silent on the wire until the whole answer is generated - is not dropped by an idle-timeout proxy. Note the two unrelated meanings of **`stream`**: this request field selects the response shape for the client, while **`models[].stream`** in **config.yaml** selects the transport coddy uses to reach the LLM. |

| GET | **`/coddy/sessions`** | Pagination via **`limit`/`cursor`** (cursor is numeric offset token). ### Stop and queue control snapshots

On session open and reconnect, clients read **`GET /coddy/sessions/{id}/activity`** and **`GET /coddy/sessions/{id}/queue`** for the selected id. These reads do not depend on a matching row in a filtered or paginated History listing, a live turn reader, or another queue mutation. The UI and interactive remote console track server activity separately from their own prompt/stream lifetime. The browser skips both hydration reads during its own POST admission and confirms a **`turn_ended`** overlapping a pending or admitted POST through fresh REST before declaring idle.

The session manager's **`QueueSnapshot`** reads the queue list and its **`version`** under one lock. Queue HTTP responses (**GET**, **POST**, and **DELETE**) and **`message_queue`** events use that pair, so a response cannot label an older list with a newer version. Ordinary deliveries keep the highest version per session. For browser restart recovery, a fresh queue GET captures the delivery revision and recovery epoch before the request. The browser rejects a snapshot crossed by any queue delivery; otherwise it may establish a lower version, including **`0`**. That recovery advances the local epoch and rejects mutation responses and own/relay stream queue frames captured in earlier epochs. Replayed **`turn_started`** notifications do not clear the waiting list or reset its version.

These controls retain the existing routes, JSON shapes, and status codes. They do not change non-interactive prompt handling or permission/question ownership, and do not attach the remote console to another client's live transcript. Shared queues require clients of the same **`coddy serve`** process; separate local console or ACP processes sharing only a sessions directory retain separate queues and answer channels. Cross-process cancellation still uses the bundle's cancel marker.

### Two stream dialects

The two streaming endpoints carry the same turn in two shapes, chosen by who reads them. **`POST /v1/chat/completions`** with **`stream: true`** is the surface a third-party client points at (VS Code Copilot through `chatLanguageModels.json`, the openai SDKs, anything that parses `chat.completion.chunk` literally), so it is the strict OpenAI contract and nothing else: a first chunk with **`delta.role`** `assistant`; **`delta.content`**, **`delta.reasoning_content`** and **`delta.tool_calls`** deltas, each choice with **`finish_reason: null`**; a final chunk whose **`finish_reason`** is **`stop`**, **`length`** when the turn ended on **`max_turns`** / **`max_tokens`**, **`tool_calls`** when a direct model called one of the client's tools, or **`content_filter`** when the provider's content filter cut a direct answer short; with **`stream_options.include_usage: true`** one more chunk with an empty **`choices`** array and the turn's **`usage`** (**`prompt_tokens`**, **`completion_tokens`**, **`total_tokens`**, from the provider's own counters, zero when it reported none); then **`data: [DONE]`**. No named **`event:`** frame appears on it - such a client would read one as a chunk without choices - though each leaves an SSE comment in its place, so the connection stays as busy as the turn through a tool phase; a turn that produced no text still opens and finishes one choice, because a stream that never finishes a choice is what VS Code reports as "Response contained no choices." **`POST /v1/responses`** is coddy's own channel, read by the SPA, the remote console (**`--remote`**, **`coddy acp --remote`**) and the swarm relay: the same chunks plus every named event below, **`coddy_meta`** last.

  A direct **`models[].model`** id on **`POST /v1/chat/completions`** is coddy standing in for the provider, and the client brings what it would bring to the provider. Its **`tools`** (OpenAI function tools) are offered to the model as they are; **`tool_choice`** `none` withholds them, and any other value leaves the choice to the model, because the providers take no forcing parameter. A call the model makes comes back as **`delta.tool_calls`** chunks on the stream - one chunk per call, arguments complete, **`index`** counting the calls - and as **`message.tool_calls`** on a JSON answer, with **`finish_reason`** **`tool_calls`**; the client runs the tool, replays the assistant message with its **`tool_calls`** and answers with a **`tool`** message under the **`tool_call_id`**, and that request may end on the tool message. Message **`content`** may be a string, `null` or an array of parts: **`text`** parts are joined, **`image_url`** parts (a data URL or an https address) reach a model whose **`models[].multimodal`** is true as images and are dropped for any other model, never flattened into text; they are accepted on user messages only, as at OpenAI, and refused with **`400`** on any other role, as are other part types. What a client may hand over is bounded: at most 128 tools, a tool's **`parameters`** up to 256 KiB, 16 images per message and 20 MiB per image URL string (a data URL carries the picture itself), past which the request is refused with **`400`**; an https image address is handed to the provider as it is, coddy never fetches it. A JSON answer made of tool calls has **`content`** `null`, as OpenAI renders it. The **agent** / **plan** / **ask** profiles run coddy's own tools and never read the client's, and take no trailing **`tool`** message, though the pictures of the last user message reach a multimodal profile model. An **agent** / **plan** / **ask** turn started over either endpoint is published to the composer relay in the rich shape whatever the caller received, so a browser watching the session sees its tool calls either way.

### Session memory REST (**`-tags=http,memory`**)

These **`/coddy/sessions/{id}/memory/*`** routes register only when **`coddy`** is built with **`memory`** (**`external/httpserver/memory_http.go`**). A plain **`http`** build without **`memory`** returns **`404`** (**`memory_http_stub.go`**).

| Method | Path | Notes |
|--------|------|-------|
| GET | **`/coddy/sessions/{id}/memory/tree`** | Without **`root`**, lists **`global`** and **`workspace`**. Otherwise lists allowed **`.md` / `.txt`** children (traversal guarded). |
| GET | **`/coddy/sessions/{id}/memory/file`** | Query **`root`** + **`path`**. UTF-8 content. |
| PUT | **`/coddy/sessions/{id}/memory/file`** | JSON **`{"root","path","content"}`**. |
| POST | **`/coddy/sessions/{id}/memory/dir`** | JSON **`{"root","path"}`** for new subdirectory. |
| DELETE | **`/coddy/sessions/{id}/memory/file`** | Query **`root`** + **`path`**. Removes a **`.md` / `.txt`** file or deletes a directory tree recursively. **`400`** when **`path`** targets the memory root itself. |

### Scheduler REST (**`-tags=http,scheduler`**)

Paths are **missing** from a plain **`http`** build and from OpenAPI when **scheduler** is not linked (client **404**). When linked, responses use the same **`ErrorEnvelope`** JSON as other **`/coddy`** routes. **`503`** when **`scheduler.enable`** is false for that process. Handlers plus merged scheduler OpenAPI fragments live in **`external/httpserver/scheduler_http.go`** (**`http`**,**`scheduler`**); **`scheduler_http_stub.go`** registers nothing when **scheduler** is omitted.

| Method | Path | Notes |
|--------|------|-------|
| GET | **`/coddy/scheduler/jobs`** | JSON **`{ scheduler, jobs[] }`**. Envelope **`scheduler`** includes **`enabled`**, resolved **`dir`**, **`timeout`**, **`max_queue`**, **`runs_active`**, **`retain_sessions`**. Optional query **`include_body=true`** embeds each job instruction body. Each row carries **`running`** (**true** while this process has a run of the job in flight), **`session_id`** (the **job session** every run is a child of, empty until the first run) and **`last_run`** (the newest run row, see **`…/runs`**), besides the frontmatter fields including **`agent`** and **`permission_mode`**. |
| POST | **`/coddy/scheduler/jobs`** | Create job. JSON body **`job_id`**, **`description`**, **`schedule`** (5-field UTC cron), optional **`paused`**, **`cwd`**, **`model`**, **`mode`**, **`agent`** (a subagent definition name), **`permission_mode`** (**`ask`**, **`accept_edits`**, **`bypass`**), **`body`**. **`201`** + **`Location`**. **`409`** when **`job_id`** already exists, **`400`** for a permission mode or an agent name that cannot be. |
| GET | **`/coddy/scheduler/jobs/{job_id}`** | Full **`SchedulerJob`** including **`body`**. |
| PUT | **`/coddy/scheduler/jobs/{job_id}`** | Replace entire job file. |
| PATCH | **`/coddy/scheduler/jobs/{job_id}`** | Merge fields (e.g. **`paused`**, **`schedule`**, **`body`**, **`agent`**, **`permission_mode`**). Optional **`job_id`** in the body renames the on-disk job (moves **`.md`** and **`.state`**; the run history follows, since the sidecar names the job session). Response **`job_id`** is the effective id after the patch. **`409`** if the target id exists or a run of the job is in flight. |
| DELETE | **`/coddy/scheduler/jobs/{job_id}`** | Remove **`.md`**, **`basename.state`** and the job session with every run under it. **`409`** while a run is in flight. |
| POST | **`/coddy/scheduler/jobs/{job_id}/pause`** | Sets YAML **`paused: true`**. |
| POST | **`/coddy/scheduler/jobs/{job_id}/resume`** | Sets **`paused: false`**. |
| POST | **`/coddy/scheduler/jobs/{job_id}/run`** | Starts one run now, the way the cron tick does: a background task of kind **`agent`** under the job session, backed by a run session. **`202`** with **`task_id`**, **`session_id`** (the job session) and **`run_session_id`** (the transcript). Does **not** advance cron **`.state`**. **`409`** when paused, while a run of the job is in flight, when **`scheduler.max_queue`** runs are already going, or when the job's definition is not trusted for its workspace. |
| POST | **`/coddy/scheduler/jobs/{job_id}/cancel`** | Stops the run in flight through the pool; the run is recorded as **`stopped`**. JSON **`{ cancelled: bool }`**, **false** when the job was not running. |
| GET | **`/coddy/scheduler/jobs/{job_id}/runs`** | The runs of the job, newest first: **`{ object, job_id, session_id, runs[] }`** where **`session_id`** is the job session and each row carries **`task_id`** (the task under the job session), **`session_id`** (the **run** session, read-only; **`GET /coddy/sessions/{session_id}/messages`** is its transcript and names the job in its **`subagent.scheduler`** block), **`job_session_id`**, **`trigger`** (**`cron`** / **`manual`**), **`status`** (**`running`**, **`succeeded`**, **`failed`**, **`timed_out`**, **`stopped`**, **`orphaned`**), **`running`**, **`started_at`**, **`ended_at`**, **`elapsed_seconds`**, **`error`**, **`label`**. **`limit`** query (default **50**, max **100**). The same rows are the **`kind: "agent"`** tasks of **`GET /coddy/sessions/{job session}/background-tasks`**, which is what the runs panel polls (and whose **`…/stop`** is the panel's Stop). |
| DELETE | **`/coddy/scheduler/jobs/{job_id}/runs`** | Clears every finished run of the job, task records and transcripts: **`{ cleared: n }`**. A run in flight stays. The session's own **`DELETE …/background-tasks`** would leave the transcripts behind, so the panel's Clear comes here. |

Process logs for scheduler stay short; a run's full trace is its run session under the job session's bundle (**`<job session>/subagents/<run session>/`**), and the job session itself answers **`409`** to any prompt.

> **Inline-file capability:** `POST /v1/responses` accepts `inline_files` only when the effective YAML model has **`multimodal: true`**. Entries supplied for a non-multimodal model are ignored and are neither forwarded to its provider nor persisted in session assets/history.

## **`model`**, profiles, and direct completion

- **`POST /v1/chat/completions`** and **`POST /v1/responses`** require **`model`** to be exactly one **`id`** from **`GET /v1/models`** (session operating profiles **agent** / **plan** / **ask** or a **`models[].model`** entry).
- **agent** / **plan** / **ask** selects the Coddy agent (ReAct, tools). Optional JSON **`metadata.model`** (**`models[].model`** selector) updates the session **`SelectedModelID`**. Omit **`metadata`** or omit **`metadata.model`** to follow **`EffectiveModelID`** (session **`selectedModelId`** then **`agent.model`**). **`metadata.model`** set to **`null`**, **`""`**, or an unknown selector is **400**. Optional **`metadata.settingsVersion`** is the version of the last settings snapshot the client applied: when the server has published a newer one since, the request's **`metadata.model`**, **`metadata.reasoning`** and mode are ignored and the session's own settings stand, so a tab that has not seen a change made elsewhere cannot undo it. Optional **`metadata.reasoning`** sets the session reasoning level (resolved after any **`metadata.model`** change); it must be one of the effective model's **`reasoning_levels`** (**`null`** / **`""`** clears it; any other unsupported value is **400**). The agent maps the level to OpenAI **`reasoning_effort`** or Anthropic extended-thinking **`budget_tokens`**; **`qwen3*`** models on OpenAI-compatible providers (including **`neuraldeep`**) also send **`chat_template_kwargs`** **`{"enable_thinking": true}`** so the chat-template thinking switch stays on; **`codex`** providers send it as Codex **`reasoning.effort`** (**`minimal`** becomes **`none`**) together with **`summary: auto`** and encrypted reasoning replay.
- **`model`** listing a **`models[].model`** YAML selector runs **one direct LLM request** per call (no ReAct); **`metadata`** with a **`model`** key on that branch is rejected with **400** (use **`model`** as the routing field only).
- On **`POST /v1/chat/completions`** a direct model takes the generation options of the request for that one request. **`max_tokens`**, or its newer OpenAI name **`max_completion_tokens`** (a request may carry both only when they agree), replaces the model's **`max_tokens`**, and **`temperature`** replaces its **`temperature`**, **`0`** included. Without them the configured values apply, and no request changes the configuration or leaks into another request. A value the provider cannot send as asked is refused with **400** before a session is created or the provider is contacted: a cap below 1, a temperature outside 0-2 (0-1 for an **`anthropic`** provider), and either option on a **`codex`** model, since the Codex backend rejects both. A requested temperature is sent next to a reasoning level as well, where a configured one is left out: whether the model takes both is the backend's answer (Qwen3 thinking on vLLM does, OpenAI's reasoning models refuse).
- **`reasoning_effort`** on the same request picks the reasoning level, and it must be one of the **`reasoning_levels`** **`GET /v1/models`** lists for that id; any other value, or any value for a model that lists none, is **400**, never a quiet downgrade. Omitted, **`null`** or **`""`**, the model's **`reasoning_default`** applies, and a model without a default gets no reasoning parameter at all - not the same request as the level **`none`**, which a **`codex`** model offers and receives as such. The level travels as OpenAI **`reasoning_effort`**, as Anthropic extended thinking (where a **`max_tokens`** of the request that leaves no room above the thinking budget is **400** rather than silently raised) or as Codex **`reasoning.effort`**, and the JSON answer reports it as **`metadata.reasoning_effort`**.
- The **agent** / **plan** / **ask** profiles read none of these fields: a profile turn is a series of LLM calls, each on the profile model's configured values, and its reasoning level comes from **`metadata.reasoning`**.
- A direct answer is finished only by the provider's own terminal signal: a **`finish_reason`** or **`[DONE]`** from an OpenAI-compatible server, a **`stop_reason`** from Anthropic, **`response.completed`** or **`response.incomplete`** from Codex. Codex's **`response.incomplete`** keeps the text written so far and reports its reason (**`max_output_tokens`** as **`finish_reason`** **`length`**, **`content_filter`** as **`content_filter`**; any other reason is an error), and **`response.failed`** is an error carrying the backend's code and message. A stream that closes before any terminal signal is an error naming the truncation (**`500`** on a JSON answer, an error frame and no finished choice on a stream), never a **`stop`**, and a failure after text reached the client is not retried into a second copy of it.
- A failure the model's provider answered with an HTTP status keeps that status on its way to the client, on a direct completion and on an **agent** / **plan** / **ask** turn alike, so a client can tell a request the provider will never accept from an outage. A provider **4xx** is answered with the same status: a request over the plan's input limit is **400**, a rejected key **401**. **429** carries **`Retry-After`** when the provider named a pause, or when Coddy chose not to wait for a usage-limit reset. A provider **5xx** becomes **502 Bad Gateway**, with the provider's **`Retry-After`** when a **503** named one, and a provider **504** or a request timeout becomes **504 Gateway Timeout**. The error object names the provider's status: **`{"error":{"message":"...","type":"upstream_error","upstream_status":400}}`**, and a streamed request carries the same object in its error frame. **500** is left for failures of Coddy itself, a stream cut before its terminal signal among them.

Non-stream replies include **`metadata`** with **`model`** set to the effective YAML backend selector (**`api_model`** may expose the REST model id).

## Sessions and headers

### Without **`X-Coddy-Session-ID`**

`POST /v1/chat/completions` / **`POST /v1/responses`** allocate a random session bundle for that flow (ACP **`session/new`**).

### With **`X-Coddy-Session-ID`**

1. Active in-memory bundle wins.
2. Otherwise load from disk when **`session.json`** exists.
3. Otherwise pin **`session/new`** with the supplied identifier (fresh empty bundle folders).

Malformed ids (**HTTP 400**). Dedicated **`/coddy/*`** helpers return **503** if persistence is unavailable (`Manager` lacked a **`FileStore`**, primarily in tests).

### Per-session model (bundled UI)

- **`GET /coddy/sessions/{id}/messages`** returns **`model`** (effective YAML backend for the session), **`selectedModelId`** (stored override in **`session.json`**, may be empty), **`selectedReasoning`** (effective reasoning level for the session, empty when the model has none), and **`mode`** (session profile `agent`, `plan`, or `ask`; remote clients restore it on load).
- **`PATCH /coddy/sessions/{id}`** accepts **`selectedModelId`** to set the YAML **`models[].model`** selector for that session (unknown ids **400**) and **`selectedReasoning`** to set the reasoning level (must be one of the model's **`reasoning_levels`**; empty clears it; unsupported value **400**).
- The SPA restores **Model** from **`model`** when opening a chat. Changing **Model** writes cookie **`coddy_llm_model`** (default for the next **New chat**) and **`PATCH`**es the active session.

## Memory roots

Matches `external/memory/README.md`: **`global`** uses configured **`memory.dir`** (fallback **`$CODDY_HOME/memory`**). **`workspace`** resolves to **`$CWD/memory`** for that session bundle. **`agentMemory`** placeholders remain agent-only (`session.json`), not REST-editable here.

Interactive tool permission prompts are bypassed when **`tools.permission_mode`** is **`bypass`**. Otherwise the bundled UI shows **`event: permission`** during **`POST /v1/responses`** (**`stream: true`**) and completes the turn via **`POST /coddy/sessions/{id}/permission`** (same pattern as **`question`**).

## CLI flags

Equivalent to **`coddy acp`**: **`--config`**, **`--home`**, **`--cwd`**, **`--sessions-dir`**, **`--session-id`**, **`--log-*`**, optional **`--scheduler`** and **`--mcp-project-trust ask|allow|deny`** (overrides **`mcp.project_trust`** for this process; see [mcp-integration.md](../features/mcp.md)).

Networking flags: **`-H` / `--host`**, **`-P` / `--port`**, falling back to YAML **`httpserver.host` / `httpserver.port`**, and from there to **`127.0.0.1:12345`**. The bind default is loopback because one process now starts every enabled subsystem: an operator who asked for a Telegram bot must not find the agent API on every interface as a side effect. Pass **`-H 0.0.0.0`** (or set **`httpserver.host`**) to accept connections from other machines, and expect the "reachable without authentication" warning if you do so without a token.

Auth: **`--auth-token <token>`** (also **`CODDY_HTTP_TOKEN`**) enables bearer authentication without writing the secret to **`config.yaml`**.

Subsystem switches: **`--http=false`** runs everything else without the API, **`--gateway`**, **`--swarm`** and **`--scheduler`** override their **`enable`** keys for one run, and the relay's own settings are **`--swarm-host`**, **`--swarm-port`**, **`--swarm-auth-token`**, **`--swarm-pairing-token`** and **`--swarm-allow-insecure`**.

## Build

```bash
# HTTP API only (no npm, no embedded SPA root)
make build TAGS=http

# HTTP API plus embedded SPA (**make ui-build** runs first)
make build TAGS="http ui"
```

`go test ./...` skips **`external/httpserver`** unless **`go test -tags=http`**. SPA-specific tests compile under **`go test -tags=http,ui`** (Makefile **`make test`** runs **`ui-build`** once, then a single **`go test`** with every tag; the per-combination matrix is **`make test-matrix`**, which CI runs).

For a manual gateway check against a disposable **`coddy serve`** process, **`examples/test_httpserver.sh`** runs the Python demos under **`examples/httpserver/`** (see **`examples/README.md`**). Steps that call chat or responses expect a working **`models`** backend.
